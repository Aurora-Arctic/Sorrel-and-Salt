# Loading Audit

This audit checks every wait in the app against the loading standard in `claude-docs/loading.md` (M12.33), for task M11.9. It changes no code. The fixes it proposes are listed in the Gaps section at the end, each marked with the commit that closed it. Parts 1 and 2 describe the app as it was when the audit was read; the fixes replaced the target mechanism they name with the registry in `claude-docs/design-decisions/m11.9-skeletons-beside-pages.md`.

## How to Read This

The standard has three parts. A wait should show all the parts that fit it.

- **Control** is the thing the person pressed showing that it is working: `BusyButton`, `ConfirmedAction`, `FormActions`, a field spinner, `MenuButton busy`, or the `LinkHint` dot on a link.
- **Region** is a `Skeleton` standing where the new content will go. `SwapPanel` (used by `ListFrame` and `TabbedPage`), `MainBody` and `SectionBody` hold the old page beneath it.
- **Page** is the navigation bar, shown after 100 ms for any navigation that goes through `usePendingNavigation` or `PendingLink`.

Each cell is **Has**, **Lacks** or **N/A** (not applicable). **N/A** means the part does not fit that wait. For example a `refresh()` after a save changes the page in place, so it needs the Page bar and a Control, and no Region.

Two points hold for the whole app and are not repeated in each table:

- `FormActions` and `ConfirmedAction` both render a `BusyButton`. Every form and every confirm dialog built on them has a Control by construction. Both live in `src/components/Field/form-actions.tsx` and `src/components/UserList/confirmed-action.tsx`.
- No route has a `loading.tsx` or a route-level `<Suspense>`, and none may ([`loading.md`](loading.md), "Why there is no `loading.tsx` and no route-level Suspense"). Every route wait is a client transition held by `useOptimistic`, so the Region column describes the skeleton the link's target names, not a route file.

Some Region cells say "Has, see Part 2". That means a skeleton is drawn, and whether it matches the real page is judged in Part 2.

### Reuse Against Redraw

Read from `Skeleton/index.tsx`, `AppShell/main-body.tsx` (`MainBody`) and `SectionBody/index.tsx`. Neither skeleton host reuses a layout component from the page. They reuse CSS class names only.

- **Frame.** `MainBody` redraws the frame as a bare `<main className=...>` with `page-column` or `page-frame page-frame--narrow skeleton-frame` from its own `FRAME_CLASS` table (`main-body.tsx:17-22`). The page uses the `PageColumn` markup and `ListFrame` (`ListFrame/index.tsx:92`) directly. `SectionBody` draws `<main>` with no class and passes the section's `className` to `SkeletonCover` (`SectionBody/index.tsx:67-72`); `TabbedPage` draws `<main className="tabbed-page ...">`. Redraw.
- **Head.** The skeleton draws `skeleton__eyebrow`, `skeleton__title`, `skeleton__lede` and a `page-header skeleton__header` wrapper (`Skeleton/index.tsx:218-228`). The page uses the `PageHeader` component (`PageHeader/index.tsx:41-58`: `p.eyebrow`, `h1`, `.page-header`, `p.lede`). Redraw, sharing the `page-header` class only. The eyebrow and lede have different sizes, which is the measured eyebrow difference.
- **Tabs.** `skeleton__tabs` against `TabbedPage`'s `nav.tabbed-page__tabs` and `TabAction`. Redraw.
- **Filter.** `skeleton__filter` with `skeleton__field` and `skeleton__switch` (`Skeleton/index.tsx:247-266`) against `FilterForm`'s `form.filter-row` (`FilterForm/index.tsx:142`) with the real combobox and Filters button. Redraw.
