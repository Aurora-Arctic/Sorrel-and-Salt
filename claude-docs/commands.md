# Commands — summary

Every command the repo runs, and where it runs. `CLAUDE.md` keeps the ten a
task reaches for; this is the rest.

**Two places run them.** `make help` lists every target from the **host**.
Neither `make` nor `docker` is installed in the devcontainer, so a session
running inside it calls the npm scripts directly, and the `make` column below is
the host equivalent. **There is no Python in the devcontainer** either: neither
`python3` nor `python` exists, so quick scripting, JSON munging or arithmetic
goes through Node (`node -e`), the npm scripts, or `jq`, `grep` and `sed`.

**Verify with `test:coverage`, not `test`.** A plain `npm run test` pass can
still fail CI on the 80% threshold (lines, branches, functions, statements)
alone.

**`npm run test` and `npm run test:coverage` take the Vitest lock themselves.**
Each runs under `flock /tmp/sorrel-vitest.lock`, so two runs from different
sessions wait for each other instead of colliding on the shared Postgres. Do
not wrap either in `flock` yourself: the outer `flock` holds the lock, the
inner one waits for it, and the run deadlocks forever. A direct
`npx vitest run …` takes no lock, so wrap that one by hand:
`flock /tmp/sorrel-vitest.lock npx vitest run …`. `test:debug` and `test:ui`
take no lock. [`testing/e2e.md`](testing/e2e.md) explains the locks.

**Deploys are CI-only (M0.26).** `.github/workflows/deploy.yml` deploys via the
Vercel CLI (`vercel pull`/`build`/`deploy --prebuilt`/`alias`) on a push to
`main` (production) or `staging` (preview, aliased to the staging domain), and
on a `hotfix/** → main` PR (a per-PR preview, commented on the PR and torn down
on close). `vercel.json` sets `deploymentEnabled: { "**": false }`, so Vercel's
Git integration deploys nothing and the workflow is the only path. There is no
local deploy command ([`ci/deploy.md`](ci/deploy.md), "Deploy").

**Seeding an environment by hand (M14.26).** `.github/workflows/seed-environment.yml`
runs the six reference seeds below on staging or production without a deploy,
in one transaction, through `db:seed:reference`.
A site admin starts it from the Actions tab, choosing `environment` (`preview`
is staging), `dry-run` (on by default: everything is decided and rolled back)
and `force` (off by default: passes `--force`, which reaches the compendium seed). It
waits for any migration running, and its summary lists every `UPDATED`,
`REFUSED`, `ADOPTED`, `RETIRED` and `PENDING` line ([`ci/deploy.md`](ci/deploy.md),
"Seeding an environment by hand").

**Pre-commit** (M11.23) checks only the files that changed, so a one-line fix
doesn't pay for checking the whole repo. A tool called lint-staged works out
the file list and hands it to each check; `lint-staged.config.mjs` says which
check gets which files. It runs two ways:

| Run                           | Files checked                                                                                                                                                                                                                               |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The git hook, on `git commit` | The staged files, through `npm run pre-commit:staged`, which `package.json`'s `"pre-commit"` array names. Every unstaged edit is set aside while the checks run and put back afterwards, so the hook checks exactly what is being committed |
| By hand, `npm run pre-commit` | Every tracked file changed since the last commit, staged or not. A new file needs `git add` first                                                                                                                                           |

Three things are not narrowed:

- **Typecheck runs whole or not at all.** `tsc` can't check a single file on
  its own terms: changing an exported type can break a file nobody touched. So
  it runs over the whole project, once, and only when a TypeScript file,
  `tsconfig.json`, `package.json` or `package-lock.json` changed. A commit
  touching only Markdown skips it.
- **A check's own config reruns that check over everything.** Changing
  `.oxlintrc.json` or `lint/` runs `oxlint .`; `.prettierrc` or
  `.prettierignore` runs `prettier --check .`; `.stylelintrc.json` or
  `package.json` (which holds `browserslist`) runs `lint:css`. A narrowed run
  would miss what the new rule now flags.
- **`lint`, `format:check` and `typecheck` stay whole-repo.** They are what
  CI's `checks.yml` runs, so the local narrowing gives up no protection.

Every check runs to the end even when another fails (`--continue-on-error`),
so one run lists every problem. Prettier still honours `.prettierignore` for a
file passed by name, so a staged file under `src/gql/` is not flagged.

**Oxlint** (`.oxlintrc.json`, MB.275) exits 0 on a warning, so a rule that only warns is a rule nothing enforces. The repo holds 0 warnings and 0 errors. A disable is `// oxlint-disable-next-line <rule> -- <reason>` (`{/* … */}` among JSX children), and the reason is required.

- **Errors**: `no-console` (output goes through a logger; `scripts/**` and a few named files are exempt), `no-unused-vars` (dead code hides mistakes), `no-unsafe-optional-chaining` (it throws on undefined), `react-hooks/exhaustive-deps` (a missing dependency is a stale value), `react/set-state-in-effect` (state set in an effect draws twice), and the `jsx-a11y` rules `click-events-have-key-events`, `no-static-element-interactions`, `no-noninteractive-element-interactions`, `interactive-supports-focus`, `no-noninteractive-tabindex`, `control-has-associated-label` and `anchor-is-valid` (each is a keyboard or screen-reader failure).
- **Warnings**: `jsx-a11y/aria-role`, set to `ignoreNonDOM` so a component with a `role` prop is not judged as an element, and the advisory rules below.
- **Advisory, disabled where deliberate**: the React Compiler rules (`react/refs`, `react/immutability`, `react/preserve-manual-memoization`) because the compiler is off in `next.config.ts`; they are off in `tests/**`, where fixtures write and read freely, along with `react/globals` and `react/incompatible-library`. `jsx-a11y/prefer-tag-over-role` is disabled per site where the native tag would change the layout or the meaning.

**Stylelint** (`.stylelintrc.json`, MB.116) carries one binding rule,
"only `_variables.scss` may name a raw hue" ([`styling.md`](styling.md),
"Binding rules"): `color-no-hex` and `color-named: "never"`, cleared for
`src/scss/_variables.scss` alone. A group colour is a hex on its
`category_groups` row, set inline from data, so the linter never sees it; a
hex in a comment is not a colour to it either. It extends
`stylelint-config-standard-scss`, adjusted where that set fights Prettier or
the repo's Sass. It also runs `stylelint-plugin-use-baseline` with
`available: "widely"` (M10.24), which refuses CSS past the browser floor
([`styling.md`](styling.md), "Binding rules"); a feature that is an
enhancement carries a disable comment saying what is lost and when it becomes
widely available.

- **Configured rather than off**: `selector-class-pattern` takes the repo's
  BEM names (`block__element--modifier`, each part kebab-case) where the
  default allows kebab-case only; `scss/at-function-pattern` allows the
  leading `_` Sass gives a private function (`_assert-theme`);
  `value-keyword-case` leaves `currentColor` and the font stacks' family
  names as written; `number-max-precision` is 5, for `$control-height`'s
  `2.78125rem`, which is exactly 44.5px.
- **Off, because Prettier owns blank lines and line breaks**:
  `at-rule-empty-line-before`, `declaration-empty-line-before`,
  `custom-property-empty-line-before`, `scss/dollar-variable-empty-line-before`
  and `scss/double-slash-comment-empty-line-before` (a comment sits directly
  on what it explains, an `@include` directly after a declaration),
  `scss/operator-no-newline-after` (Prettier breaks a long `@error` string
  after its `+`), and `scss/comment-no-empty` (a bare `//` is a paragraph
  break inside a comment).
- **Off, because the repo writes the other form on purpose**:
  `color-hex-length` (a brand hex is copied six digits long, as the provider
  publishes it), `color-function-notation`, `color-function-alias-notation`
  and `alpha-value-notation` (the two shadows are Sass's `rgba()` with an
  alpha fraction), `scss/at-if-no-null` (the accessors test `== null`, which
  says what they mean), and `media-feature-range-notation` (both notations
  sit inside the browser floor; the repo writes `max-width:`).
