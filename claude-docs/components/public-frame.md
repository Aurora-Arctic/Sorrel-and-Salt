# PublicFrame

`src/components/PublicFrame/` is the chrome round a public page for a visitor who is not signed in: a skip link, the site name, a nav holding the Compendium and the way in, and the page in a wrapper after the skip link's target. It takes only `children`. The `(public)` route group's layout (`src/app/(public)/layout.tsx`) uses it for a signed-out request and draws [`AppShell`](app-shell.md) for a signed-in one, so `/compendium` looks right to both from one layout. Nothing in it is workspace-shaped: no coven link, no Admin, no Add Ingredient.

## Contracts

- **A skip link** ("Skip to Content") comes first, targeting `#main`: an empty `span` with `tabindex="-1"` just before the page's wrapper, as in [`AppShell`](app-shell.md), which says why it is not the wrapper itself. `.skip-link` and `.skip-target` come from AppShell's stylesheet, which the layout always loads.
- **The bar** holds the site name linking to `/` (heading face at `$brand-size`, as the shell's is), a `nav` named "Site", a Sign In link (`/sign-in`, `.btn--solid.btn--medium`, the size the shell's Add Ingredient button takes) and the inline theme toggle.
  - The nav holds the Compendium link, a `PendingLink` carrying `siteLinkTarget('/compendium')` so a press draws the list's skeleton. It carries `aria-current="page"` at or beneath `/compendium`, and not on a path that only begins with its letters.
  - At or under `$shell-brand-width` the brand reads "S&S" (the full name stays for a screen reader), as the shell's does, so the bar holds at 375px. Both frames draw the two brand spans with `BrandName` (`src/components/AppShell/brand-name.tsx`).
- **The frame does not own the `main` landmark.** The `(public)` layout renders `<main>` round the page, in `.page-column`, the top-left wide column `/curator/compendium` uses. The frame draws `.app-shell__main`, a wrapper `div` with the shell's [`MainBody`](app-shell.md) inside it. A frame-owned `main` would nest with the one `MainBody` swaps in for the skeleton's during a wait. The wrapper has no id and no `tabIndex`: the skip link's target is the span before it.
- **A wait draws the destination's skeleton under the bar.** A press of a link that names a `main` target (the Compendium link, `cards`; an ingredient card's name or an entry's own links, `page` with its jump menu) swaps the page for that skeleton, with one `main` and one status, as the shell does ([`loading.md`](../loading.md)). There is no `loading.tsx` and no route-level Suspense, so a direct request keeps its 404 or 308.
- **Server-rendered.** The frame is a server component. Its client parts are `ThemeToggle`, a button after hydration, and the shell's `SiteNav` (`AppShell/site-nav.tsx`), which reads `usePathname()` to mark the current page. Both render on the server too, so the chrome is in the HTML a crawler or a script-less browser receives. No client island fetches and there is no `me` call ([`design-decisions/mb.80-public-compendium.md`](../design-decisions/mb.80-public-compendium.md)).
- **One theme disc.** The root layout's corner theme toggle is hidden when `.public-frame` is present, as for `.app-shell` (`src/components/ThemeToggle/index.scss`).

## Styling

Tokens only: the shell bar's height and hairline, `$surface-card`, `$wide-column`, the control height and `$brand-size`. Mixins: `heading-face` (the brand), `list-reset`, `focus-ring` (inset on a nav link, which fills the bar and would clip an outside ring), `theme-transition` on the nav link, and `nav-current` for the current page: weight and a `$rule-heavy` accent rule drawn as a border, which forced colours keeps and a box-shadow it drops. The shell's nav draws the same mark from the same mixin.

The bar's parts shared by both frames (the sticky bar and its `--sticky-top`, inner row, brand with its right padding, initials, end group, and their narrow-window rules) are one mixin, `frame-bar($block)` in `src/scss/_frame-bar.scss`. The nav (`.app-shell__nav`, link padding at `$shell-phone-width` included), the theme-toggle wrapper (`.app-shell__theme`) and the page wrapper (`.app-shell__main`) are the shell's, styled in AppShell's sheet, which `PublicFrame` imports. What stays here is one override, `.public-frame .app-shell__nav { display: block }`: the nav stays in the bar under `$shell-tablet-width`, where the shell hides it. The page rules that keep content clear of the sticky bar (the root's `scroll-padding-top`, the `.page-frame` minimum height, and the `scroll-margin-top` of `.page-frame__section` and the ingredient entry's sections) are keyed on `:is(.app-shell, .public-frame)`, so they apply in both frames.
