# IngredientForm

`src/components/IngredientForm/` holds every property of an ingredient, on react-hook-form with the Zod resolver: a coven's new ingredient, or a compendium entry, new or edited. It validates with the shared `LocalIngredientInput`, or `CompendiumIngredientInput` on the compendium, before the mutation is sent, sends `createWorkspaceIngredient` or the compendium mutations, and puts an error from either side beside the field it names. It is built standalone: the add and edit modals and the admin compendium page wrap it rather than containing their own form. The file layout is the directory; each file's top comment says what it holds.

## Contracts

### Props and tiers

- **`workspaceId` is a union** (`IngredientFormProps`, `types.ts`): a coven's id writes to that coven, a new ingredient or the coven's own `entry` saved over itself through `updateIngredient`; `null` writes the compendium, a new entry or the `entry` given, and every lookup then asks about the compendium alone ("On the compendium", below).
- **Either tier's edit offers Delete Ingredient**, drawn in the foot as the bin icon (`BinButton`, named and tipped "Delete Ingredient") at the far end in `FormActions`' `aside` ([`ingredient-entry.md`](ingredient-entry.md), "Edit").
- **`onSaved` says which save was pressed**: `'open'` (Save Ingredient, the page opens the ingredient) or `'another'` (Save & Add Another, after which the form clears). An edit's one save is `'open'`. A save moves no jar, so a coven's new ingredient comes back with an empty `stock`.
- **`duplicateHref` is required.** It is where the duplicate warning links a near match: the admin's compendium page opens its modal, the shell's add button goes to `/coven/[slug]/ingredients/[id]`.
- **`quickLookOf` is optional.** Given, each near match offers its Quick Look. The admin compendium's form passes it; the public search's and the coven's leave it out.
- **`entryHref` is where a linked substitute's summary links its ingredient**, in a new tab. Left out, a summary links nothing.
- **`mayPromote` shows the promote arrow** on a saved folk name, on an edit only. The compendium's edit mounts pass true, and a coven's edit when the member's role may promote.
- **`sourcesIntro` is content at the start of the Sources section.** The compendium edit dialog passes the entry's sourcing score; the form knows nothing of scores.
- **`workspaceName`** (a coven's id only) is said in "Added to <coven>." after the duplicate warning's + adds an entry; left out, the sentence says "My Ingredients".

### The fields and their sections

- **Fields**: name, classification, formal name, folk names, description, element, celestial bodies, zodiac signs, colours, deities, substitute ingredients, categories, safety notes, the toxic flag and references, then the variants, each a form with its own description, safety notes, toxic flag, elements, celestial bodies, zodiac signs, colours, categories, substitutes and references. That is every field `IngredientInput` takes. The ingredient has no form of its own: its forms are its variants.
- **Six titled sections**, each a `<section>` under a small `h3` (the dialog's title being the `h2`) with no accessible name, so it is no landmark: Identity (name, classification, formal name, folk names); Details & Care (description, safety notes, the Toxic toggle); Correspondences (element, celestial bodies, zodiac signs, colours, deities); Relations (categories, then substitute ingredients); Sources (references); Variants. A fieldset named by its heading holds the Variants section's New Form box and cards. In Details & Care both labels are visible, since the heading names the section, not either field.
- **An open variant's fields run in the same sections**, as `h4`s under the Variants `h3`: Identity (its form), Details & Care (description, safety notes, its own Toxic toggle), Correspondences (element, celestial bodies, zodiac signs, colours), Relations (categories, substitute ingredients), Sources (references). Deities are the ingredient's alone.
- **Every empty field shows a short action as its placeholder** ("Add a name", "Add a folk name", "Search references"), and what the field is for, where its label does not say it, sits in its hint. `SuggestField`, `ListField` (and so `LookupListField`) and `CategoryPicker` take `placeholder`; a reference field's spec carries its own. A date field shows none: the browser draws its own format.
- **Name is the one field always required**, shown by `aria-required` on the control and a red `aria-hidden` asterisk against the label, so the field's name stays "Name". It is `aria-required`, not `required`, whose `:invalid` would mark the empty field before anyone tried to save.
- **The formal name is marked required while a named kind is chosen**, so the coupling's first half shows before a save. A typed formal name does not mark the classification, since a name with no kind saves as `unknown`; under Unknown the formal name is optional. The schema's message still refuses a save that ignores it.
- **A field's hint is an info tip beside its label** ([`info-tip.md`](info-tip.md), "When a field gets a tip"), kept only where the label cannot carry a rule, flow or format with a trap: classification (what Unknown and None mean), colours (each is a correspondence, not the colour the thing is), the Variants list, References and a reference's locator. A field's `note` is the one line kept beneath a label, for a state that must stay in view; only the formal name's reason for being shut uses it.
- **Closed sets use the combobox's select-only box**, `ComboboxSelect` ([`combobox.md`](combobox.md), "The select-only box"), held by `SelectField` through `useController`. The classification is over `NOMENCLATURE_KINDS` from `schema/ingredient-enums.ts`, so the options cannot drift from the schema. It starts at `''`, shown as the placeholder "Choose a classification", which is not in the list, so it cannot be chosen back; "None" is itself a kind. A choice is made before the field revalidates, so choosing None empties the formal name first. "Classification" is the label for `nomenclature` (DESIGN.md §5), the word a practitioner reads.
- **The element is a list on the multi-select box**, `ComboboxMultiSelect` over `INGREDIENT_ELEMENTS` (`MultiSelectField`), since an ingredient holds several, in the order chosen. It offers only elements not yet chosen. None chosen is the answer "none", so there is no None option. It is a labelled field erring through its one error element, not a list's fieldset: its values are the enum's strings, so it is not one of `LIST_FIELDS`.
- **A variant's `form` is one free-text `SuggestField`** (the [`Combobox`](combobox.md) over `useController`). Picking a curated form links its row as well, and the box shows the row's group beside the text until the text is edited ("The form's pick").
- **Celestial bodies, zodiac signs and colours are list fields** with boxes "Celestial Body", "Zodiac Sign" and "Colour". Celestial bodies, signs, deities and substitutes have lookups, folk names theirs; colours take none.
- **The six lists are one combobox each, with the entries inside it.** Add, or Enter with no suggestion highlighted, adds the trimmed text and empties the box, as does picking a suggestion; a blank box adds nothing. Each × is labelled with its entry ("Remove Hedge Fixture"), and a "Clear Folk Names" control empties the list. The box is labelled by the singular ("Folk Name"), its button "Add Folk Name". Entries are a `useFieldArray` of `{ value }` objects, since react-hook-form refuses bare strings. A box's text is the form's own `drafts`, held through `useController`, which `toInput` leaves out. A list's info tip sits in its legend and the fieldset is named by the legend alone through `aria-labelledby`, or the tip's button would join the name ("Folk Names About Folk Names").
- **A substitute entry is typed text or a link**: `{ value, link }`, `value` the ingredient's label, `link` its id, formal name, `forms` (`[]` for none), description and tier. A link is made only by picking from the substitutes' lookup. `toInput` sends a link as `{ ingredientId }` and typed text as `{ name }`. A linked pill reads label and formal name ("Mugwort (Artemisia vulgaris)"), and so do its × and any error naming it, since two ingredients can share a label; one naming a form adds it after a dot ("… · Dried leaf", `entryText`). Its `detail` (`entryDetail`) is the form linked or "Any form" (the ingredient's own list only; a variant's link always names a form), then "Compendium entry" or "This coven’s entry", so two same-looking pills are told apart. The detail shows in the pill's tooltip and describes its ×, and stays one short line; a typed entry has none.
- **A deity entry has the same shape**: `value` the name, `link` its id, tradition and description. A linked deity's pill reads "Hecate (Greek)", as does its × and any error naming it, so Greek and Roman Hecate read differently; its `detail` is its description. `toInput` sends `{ deityId }` or `{ name }`.
- **A list's suggestions span the field** (the box and Add together, the combobox's `listAnchor`) and open above the box when there is more room there ([`combobox.md`](combobox.md), "Where the list opens").
- **Text left in a box stops the save.** The form's resolver adds 'Press Add to keep "Hedge Fixture", or clear the box' on the list's error element, so a save never sends a list the user thinks holds an entry it does not. The schema never sees a box, so the rule is the form's own.
- **A repeat is refused at the box.** Add, or Enter with nothing highlighted, on text repeating a listed entry adds nothing: the box keeps its text, the list's one error element reads `"Mars" is already listed` (a folk name repeating the name reads `"Testwort" is already the name`), the box takes `aria-invalid` and the message as its description, the changes region announces it, and focus stays. The error is the box's, `drafts.<list>` with type `repeat`, set by `setError`; changing the text or adding anything clears it. `repeatOf` (`values.ts`) decides what a repeat is, on the schema's keys: text trimmed and case-folded for every list; a deity or substitute link by its id; a typed deity or substitute among typed entries alone, so typed "Hecate" beside a linked Greek Hecate is added, as at save. Colours refuse a repeat the same way. The schema stays the backstop for an API caller.
- **Each add, removal and clear is announced** by a visually hidden `<output>` named "Folk Names changes" ("Added Hedge Fixture", "Removed …", "Cleared Folk Names"), distinct from the box's own "Folk Name suggestions" region (WCAG 4.1.3).
- **Celestial bodies, zodiac signs, colours and deities keep the order entered** (DESIGN.md §5): their `ListField` takes `ordered` and draws the combobox's sortable list ([`combobox.md`](combobox.md), "A sortable list"), moved by grip, pointer or keyboard. A move is the field array's `move`, keyed by `id`, so a deity's link and an error naming the entry travel with its pill; once a submit has shown errors the list revalidates. The "changes" region is left to adds, removals and clears, since the sortable list says each move. Folk names and substitutes read alphabetically, so their chips have no handle.

### Sections fold

- **Each of the six sections is a `CollapsibleSection` at `h3`** ([`collapsible-section.md`](collapsible-section.md)): its heading is the toggle, a muted line says what a closed one holds, and its fields stay in the page while closed. The Variants section's ⓘ is its `info`.
- **A closed section's line is `SectionSummary`** (`summaries.tsx`), each section watching its own fields so a keystroke redraws one line. A list of one is named and a longer one counted ("Mercury · 2 colours"); categories are always counted; forms are always named ("2 forms: Dried leaf, Whole root", an empty one "Unnamed Form"); Details & Care reads the description's first words, then the safety notes', then "Toxic" (`detailsLine`); Identity reads the name, classification and the formal name in italics; Relations says both lists once either has an entry ("1 category · No substitutes"); an empty section says "Nothing yet".
- **A new entry opens with every section open**, as does the form Save & Add Another clears; an edit opens with every one closed. Sections open each on their own.
- **Open All / Close All** is a small quiet button under the modal's × (under the heading on a phone, [`modal.md`](modal.md), "A control in the header"), or at the end of the line above the first section where the form is in no modal. It reads Close All while any section is open and Open All once all are closed.
- **Validation runs on leaving a field, and on each change once a field is in error** (`mode: 'onTouched'`, `reValidateMode: 'onChange'`), as well as on submit. An error is _shown_ only after a submit, or on a field the person has both left (`touchedFields`) and edited since the form started (`useEditedFields`; typing a name and deleting it still counts, which `dirtyFields` would not, and `clear()` runs beside each `reset`). The rule lives once in `errorShown` beside `useField` (`src/components/Field/use-field.ts`) and the section flags read it too, so a section is never flagged for an error no field in it draws. A field merely passed through, or flagged by another field's change, stays quiet until edited and left or a submit. The error is the element the submit sets, linked by `aria-describedby`. The check is asynchronous, so a test that moves focus settles before it ends.
- **Save opens every section holding an error**, the schema's or the server's, and focus moves to the first invalid field. `sectionsWithErrors` (`values.ts`) finds them by each error's first key, a box's draft by its list; a save held on the duplicate warning counts as Identity's. The submit's last update carries its count, so the sections open in the commit that draws the errors, which is when the focus effect runs. A section holding an error is flagged "Has an error to fix" beneath its heading, open or closed.
- **Delete and the redirect question replace the saves beneath the sections**, so they work whatever is closed.
- **A variant's five `h4` sections fold the same way** (`CollapsibleSection` at `level={4}`), inside the card's own one-open-at-a-time disclosure. A variant added this session opens with every section open; one an edit opened with opens, by its pencil, with every section closed. Each variant keeps what was opened while its card is closed. Closed lines come from the same functions through `variantSectionSummary` (Correspondences without deities; Identity its form with the group after it, "Dried leaf (Plant part)").
- **The form holds the variants' fold state**, beside its own sections', through `useVariantFolds` (`variants.tsx`): a list by each variant's place, kept in step as the New Form box adds a variant first and Remove takes one out, a place past the end reading every section closed. The form holds it, not each card, so Save and Open All / Close All reach it.
- **Save opens, in each variant holding an error, each section holding one**: `variantsWithErrors` (`values.ts`) reads `errors.variants` by the first key beneath the variant, its Form and kept `id` being Identity's. A variant's substitute link naming no form opens its Relations.
- **Open All / Close All reaches every variant's sections** but opens and closes no card. Its label keeps reading Close All while any section is open, so a section open inside a card the Variants section hides never keeps it reading Close All.
- **Copy From Ingredient is an icon-only button** (tip "Copy From Ingredient") on the shared `.field__label-action` primitive at the right end of its field's label row, so it is hidden with its section. The skipped notice stays in the page with the list, so it outlasts its section closing and opening.

### The lookups

- **Six boxes suggest through `/api/graphql`** with TanStack Query ([`graphql/client.md`](../graphql/client.md)): `formSuggestions`, `commonNameSuggestions`, `celestialBodySuggestions`, `zodiacSuggestions`, `deitySuggestions` and `ingredientSuggestions`. Colours take none. `suggestions.tsx` holds them on one hook, `useLookup`.
- **Each asks for ten rows under the form's `workspaceId`** (null on the compendium), debounced 300 ms (`useDebouncedValue`, `src/lib/debounce.ts`), keeps the last answer on screen while the next is fetched, and never throws: a failed lookup offers nothing. None asks until its box has been focused, so opening the form sends no request; the first ask is a blank query (the vocabulary and the names in use), which the chevron opens.
- **`FormField` and `LookupListField` watch their box's text** with `useWatch` and hand each field its `Suggestions`, so `fields.tsx` knows nothing of the network. `LookupListField` is every suggesting list, given its lookup hook as `useSuggestions`.
- **A form suggestion's row is "Wax (Animal)"**, the group beside the value so two same-named forms are told apart, with a second line of the curated row's description and "Used by Testwort (Fixtura testalis), Mockleaf". Curated rows and rows in use sit under "From Compendium" and "From Coven". A common-name row is the value and its claimants in one bucket. Each list opens with "Use what you typed: rhizome". A curated form's row carries its `id` as `link`; a form only in use, and a common name, link nothing. Free text outside the vocabulary saves with no warning.
- **A celestial body or sign row is the value plus the curated description**, under the same two headings. A curated value is the admin's list; a value only in use outside it is this coven's. A deity row is "Hecate (Greek)"; a curated one adds its value linked through the row's `id`, one only in use adds typed text.
- **Substitute rows** read "Mockwort (Fixtura vulgaris)" with a second line, "Compendium entry" or "This coven’s entry", under "Your Ingredients" then "Compendium", each best match first. The heading comes from the edge's `group`, and a form ranking never lifts a compendium row above a cupboard one. Each row's key and `link` is the ingredient's id, since a compendium entry and a coven's copy can read alike (a name match hides nothing); the lookup also asks for `description` and `variants`, which the link and ranking read. The typed row, Add and Enter add `{ name }`.
- **A lookup leaves out what its list holds**, through `repeatOf`: celestial bodies, signs and folk names by folded text (a folk-name lookup also leaves out the ingredient's name); a curated deity by id, so listed Greek Hecate still offers Roman; a deity only in use by text against typed deities; an ingredient by id. The filter is `ListField`'s, so every lookup shares it, and "Use what you typed" is not offered for text the list would refuse (the combobox's `offerTyped`). A pick is therefore never a repeat; only Add and Enter refuse one.
- **On the compendium, substitutes link only the compendium**: the box reads `compendium(query)` (`useCompendiumSubstitutes`), each row an entry with its forms joined as its note, leaving out the entry being edited.
- **On the compendium, the form, celestial body, sign and deity boxes are pick-only**, since the compendium services refuse any other value ([`validation.md`](../validation.md), "The two ingredient variants"; "On the compendium", below).

### A linked substitute's summary

In both substitute lists (`holdsSubstitutes`, `values.ts`):

- **A linked chip is a button, a typed one is text**, so they differ by shape, not colour alone: the linked chip's text is a button led by a link mark, underlined while its summary is open. A screen reader hears the linked one as a button that opens a dialog (`aria-haspopup`, `aria-expanded`), described by the chip's detail; the typed one as its text followed by a visually hidden "(name only)" (`NAME_ONLY`). Each × keeps its name ("Remove Mockwort (Fixtura vulgaris)").
- **Pressing it opens a non-modal `<dialog>` beneath the chip**, named "About" and the chip's text, which is [`Combobox`](combobox.md)'s "A linked entry's summary". It shuts on a second press, Escape, a press elsewhere, or focus leaving. Escape hands focus back to the chip and is cancelled, so the compendium's modal does not take it as its own cancel and ask about unsaved changes.
- **`SubstituteSummary` (`substitute-summary.tsx`) shows** the name and formal name, the description cut to three lines (`line-clamp`, read whole by a screen reader), Classification, the Form named, Elements, Celestial Bodies, Zodiac Signs and Colours (each left out when empty), and whose entry it is. With a form named, each list is the ingredient's and the form's together, since a form adds to its ingredient and never takes away.
- **It is read when the panel opens, not before**: the `IngredientSummary` document runs the existing `ingredient(id, workspaceId)` query through `/api/graphql`, with the coven the lookups ask about, or none on the compendium. That query already reads a compendium entry by id, or a coven's own and the compendium's, never another coven's. TanStack Query keeps the answer. While it reads, a one-line skeleton at a tip's width (`entry-summary__loading`) holds the panel's size; a failure shows the server's sentence, or the generic one, as an alert with Try Again.
- **It links the entry's page where `entryHref` is given**, in a new tab so unsaved changes stay. The admin's page gives `/curator/compendium?edit=<slug>`. The shell's add button gives `/compendium/ingredients/[slug]` for a compendium substitute and nothing for a coven's own, since the summary is given a slug and a coven's page is addressed by id.

### The categories

- **The form reuses [`CategoryPicker`](category-picker.md) and knows nothing else about categories** (`design-decisions/mb.126-categories-on-the-combobox.md`). `CategoryField` (`categories.tsx`) reads the public `categories` query as the form opens and holds the picker on `categoryIds` through `useController`.
- **One page holds them all**: the query asks `first: 100`, written out because `lib/pagination.ts` is the server's. Each comes with its group's id, name and colour pair, so a group a keeper adds needs no deploy. The box narrows them itself, with no debounce.
- **It is read once, without waiting for a focus**, since the picks are the field. While it loads the box says so; a failed read says "The categories could not be loaded." beneath the box and the form still saves, with no categories.
- **Nothing typed is a category**: there is no Add and no "Use what you typed" row; Enter adds only the one category the text names whole.
- **A pick's error names it**: an issue at `['categoryIds', i]` is `fieldNameOf`'s `categoryIds.i` and reads after the category's name ("Fixture Shield: No such category"). The box takes `aria-invalid` and the message as its description, so the submit's focus lands on it. Changing the picks revalidates; Save & Add Another's reset empties them.

### The references

`ReferencesField` (`references.tsx`) is a fieldset named "References", its info tip in the legend (DESIGN.md §5, "References").

- **One box searches and never adds what was typed.** It is the [`Combobox`](combobox.md), labelled "Reference", over `referenceSuggestions` through `useLookup` (debounced, nothing asked until focused). A row is the source's plain `citation` with "Compendium source" or "This coven’s source" as its note, in the search's ranked order. A source already listed is not offered again. There is no "Use what you typed" row; the last row is "New Reference", the combobox’s action row ([`combobox.md`](combobox.md), "The action row"), which opens the panel. One control both finds and makes a source, since a source is far more often picked than written. Enter with nothing highlighted only closes the list and never reaches the form.
- **Each picked source is a one-line row beneath the box**, not a chip inside it: the Chicago short form (`renderShortCitation`, [`db/references.md`](../db/references.md), "The short form"; italics are real `<i>`), the locator in muted ink after a comma, then two icon buttons, an edit (a pencil) named "Edit" and the short form, and a remove (×) named "Remove" and the short form. The short form is made from the four fields each row's `link` carries; a row too narrow is cut with an ellipsis. The whole citation is each button's description, through a hidden element, and the `title` tooltip. Announcements and an error naming the row use the short form.
- **A source just added opens at once**, its Locator focused, picked or saved through the panel alike; the box empties and does not keep the focus.
- **The edit opens the row** (`aria-expanded`, controlling what it opens): the citation whole, wrapping and broken anywhere so an address never runs the page sideways at 320px; its tier; and a "Locator" box, focused as the row opens, described by the citation, with an info tip saying every place the source is cited goes in the one box ("pp. 12–19, 40; chap. 3"), since a source is listed once. The locator is tidied as it is left (`formatLocator`, ranges dashed). One row is open at a time. A row whose locator, Name Basis or Supports is in error stays open whatever was pressed, so the focus after a save can reach it. The × asks first; once removed the box takes the focus ("Removing a variant or a reference"). Unlike chip lists, Backspace and Delete in the empty box take no row. Each add and removal is announced in a "References changes" region. Rows keep the order picked; the service reads them back alphabetical by citation.
- **An open row whose source the form may change has Edit Source** ("Editing a source").
- **On the compendium's form an open row also has Name Basis and Supports** under its Locator: a select of `stated`, `resolved`, `unresolved` and `unaudited` ([`db/references.md`](../db/references.md), "Citation attributes"), and a multi-pick of the fields the source backs (an entry's from `CITED_ENTRY_FIELDS`, a form's from `CITED_VARIANT_FIELDS`), each with an info tip. A coven's form renders neither, since a coven's citation carries neither and the service refuses them. Neither is sent until chosen. Copy From Ingredient brings the name basis, and of the supports only the fields a form has.
- **Entries are a `useFieldArray` of `{ value, link, locator, nameBasis, supports }`**: `value` is the citation (describes the row, never sent); `link` is the source's id and tier plus `kind`, `authors`, `title`, `container`, which `referenceSuggestions`, `createReference` and `entry-values.ts` each read; `nameBasis` is `''` until chosen. They are not one of `LIST_FIELDS`, which are free text. The box's text is `drafts.references`; whether the panel is open is `referencePanelOpen`, both the form's own.
- **A search left in the box stops the save** ('Pick a source for "grimm", or clear the box'), **and so does an open panel**, new or editing ("Save the source, or cancel it"), both from the resolver on the field's one error element.

### The new reference panel

`ReferencePanel` (`reference-panel.tsx`) opens inline beneath the field, not as a dialog, because the whole form is already in a modal and a dialog there would stack two. It is a fieldset named "New Reference", not a `<form>` (which cannot nest), running its own react-hook-form under its own `FormProvider`. Its fields are the form's own `TextField` and `SelectField`, which take whichever form provides them, and errors render through `FieldError`.

- **Kind first**, a `SelectField` over `REFERENCE_KINDS` (Book, Chapter in a Book, Journal Article, Reference-Work Entry, Web Page), focused as the panel opens. No other field shows until a kind is chosen.
- **Then only the fields that kind needs**, in the order its citation prints them: `FIELDS_OF`, read off what `renderCitation` prints for each kind (`src/lib/citation.ts`), so the panel offers nothing the citation would drop. The title and container take each kind's own label ("Chapter Title" and "Book", "Article Title" and "Journal", "Entry" and "Reference Work", "Page Title" and "Site"). Required ones are marked as Name is: the title always, a book's date, a chapter's, article's or entry's container, a web page's address and day read. A printed work's online fields follow its publication: Read Through (`host`), Address, Last Modified, Accessed, Note. The two days are `<input type="date">`.
- **Scholarly, on a compendium source alone**: an on-or-off switch after the kind's fields, marking a work scholars edited or reviewed (`references.scholarly`, [`db/references.md`](../db/references.md)), with an info tip. It is absent from a coven's panel, whose sources the service refuses the mark. An edited source opens with its stored mark, so Save stays off until something changes.
- **One How to Cite tip replaces a hint per field**, at the end of the panel's head just before its ×, in New Reference and Edit Source alike ([`info-tip.md`](info-tip.md), "When a field gets a tip"). It states the rules once, one per line, each ending in a full stop with any example in brackets before it: first author inverted, edition and volume as printed, contributors as a sentence, a date as precise as the source gives it, underscores round a title inside a title to italicise it, a note printing after the citation in brackets. The bubble is a `<span>` and may not hold a `<ul>`, so the rules are spans with `list` and `listitem` roles. The panel's `aria-describedby` names it after an edit's reach note. A field whose format matters shows an example as its placeholder instead of an action (Authors "Shelley, Mary", Edition "2nd ed.", Volume "Vol. 2", Place "London", Published "1985", Pages "112–30", Address "https://", Read Through "Perseus Digital Library").
- **A kind change keeps what was typed**, but only the chosen kind's fields are sent: `toReferenceInput` sends the rest, and a blank day, as null (`LocalDate` takes no empty text). The resolver is the shared `ReferenceInput` schema over that input, so its refusals (a date with no year, non-numeric pages or volume, an address with no named host, a day not yet come, "Name the book this chapter is in") land beside their fields ([`db/references.md`](../db/references.md), "Formatting and checks").
- **Each field is tidied as it is left**, the way the server stores it: `TextField`'s `format`, from the same module the schema formats with (spacing collapsed, a title's wrapping quotes dropped, ranges en-dashed, `https://` added to a bare address, "second edition" written "2nd ed."). A showing error is judged again on the tidied text.
- **Save Reference sends `createReference` for this coven.** A `VALIDATION` error's field errors land beside the fields they name, if the kind shows them; anything else is an alert at the panel's top. A failed save focuses the first invalid field. A saved source is added as a row by its id, announced, the panel closes, the box takes the focus, and the cached searches are dropped.
- **Enter in one of its fields saves the source**, not the ingredient. Cancel closes it, the box taking the focus.
- **A × at its top does exactly what Cancel does** (saves nothing, asks nothing, held with Cancel while a save is in flight), so a panel taller than the dialog can be left without scrolling. It is named for the panel ("Close New Reference", "Close Edit Source"; the modal's own × is "Close") and comes before Kind in Tab order. The panel's Undo and Redo, the How to Cite ⓘ and the × stand at the right end of the panel's top border, level with the legend, on the dialog's surface colour so the line stops short of them. The legend's words and the group's marks stop the border the same distance short, `$panel-head-gap`. The group goes onto the border only where the panel's content is at least 18rem wide (a container query). Narrower, the head is one line, note at the start and group at the end; where the note would be squeezed under 14rem the group drops to its own line beneath it, still at the right.
- **Save & Add Another closes the panel** with the rest, since `EMPTY_VALUES` holds `referencePanelOpen: false`.
- **Asked for again while open, it takes you back**: "New Reference" scrolls the panel's top into view, legend clear of the edge, and focuses Kind again, keeping everything typed. The field counts each request and the panel focuses on each new count.
- **On the compendium** the search and the panel ask with a null `workspaceId`: the search offers the compendium's sources alone, and Save Reference writes one to the compendium under the admin proof.

### Editing a source

A recorded source is changed in the same panel. The edit changes the source, not the row's link, so it reaches every entry citing it.

- **Edit Source is a second, deliberate step** in the open row: a small quiet button beside the tier, named "Edit Source" and the short form, described by the whole citation. It is separate from the pencil because the pencil opens the row for its Locator, and an edit reaching every citing entry should not be one press away.
- **Only where the form may change the source.** A coven's form edits its own sources; a compendium source there has no Edit Source and its tier line adds that only the site's keepers can edit it (not a disabled button, which takes no focus so its tip could not be reached by keyboard). The compendium's form edits every source it lists. Another coven's source never appears.
- **The panel opens on the whole source.** A row carries only the short form's four fields, so the panel reads the rest by id through the `reference` query in the source's tier (the coven's for a coven's own, none for the compendium's; [`db/references.md`](../db/references.md), "Reading and writing them"). It says it is loading until the read lands, then shows the prefilled fields with Kind focused. The read is kept only while the panel is open (`gcTime: 0`).
- **Its legend is "Edit Source", its save Save Source** (Saving Source in flight, off until a field changes). A line under the legend, which also describes the group, says a change reaches every entry citing the source.
- **Save Source sends `updateReference`** with the id, tier and every field, since an update replaces the source. Saved, every row in the form citing it (the ingredient's and each variant's) takes the new citation and short form in place, the change is announced, the panel closes, the row stays open and its Edit Source takes the focus. The rows are rewritten without marking the ingredient changed (the source is saved already and the links sent are as they were), so Save Ingredient and the unsaved-changes guard ([`modal.md`](modal.md), "Unsaved changes") are left as they were. Rows on other ingredients read the new text on their next load.
- **Cancel, or the ×, closes it without saving**, focus back on the row's Edit Source. Its edits live in its own form, so closing discards only them. New Reference while an edit is open, or Edit Source on another row, starts that panel afresh.
- **A panel's edits count as unsaved changes** to the ingredient form: each panel reports its `isDirty` through `PanelChangesContext` (`panel-changes.ts`) and the form counts itself changed while any panel does, which is what the promotion question reads (`panels.changed`). The form draws no unsaved-changes question of its own, because Close saves first; a panel left open stops the save ("Save the source, or cancel it"). A closed panel reports nothing.
- **Known limitation**: rows rewritten after an edit hold a citation the form's defaults do not, so once another field is changed the ingredient counts as changed until saved even if that change is undone. Fixing it needs react-hook-form's private `control._defaultValues`, or a `reset` that would drop the field arrays' keys.

### The variants

An ingredient comes in forms, and each form adds to the ingredient and never overrides it: the oil's safety note sits beside the herb's description, not in place of it ([`design-decisions/mb.215-ingredient-variants.md`](../design-decisions/mb.215-ingredient-variants.md)). The Variants section follows the ingredient's own fields.

- **Each variant is one summary line until opened**, a card: the form as typed ("Unnamed Form" while empty) with its curated group after it in muted ink ("Dried leaf (Plant part)"); beneath, `variantSummary` in its sections' order ("1 celestial body · 2 categories · Safety note · 1 reference") or "Nothing yet"; at the end a pencil and a × named for the form ("Edit Oil", "Remove Oil"). The card is a fieldset named by the form alone through `aria-labelledby`.
- **Remove asks first and only removes.** It never opens or closes the card; Cancel leaves the variant as it was, Remove takes it, focus going to the New Form box.
- **Edit opens it in place, one at a time.** Edit carries `aria-expanded` and `aria-controls` naming the region of the variant's fields, and is described by the summary while closed. Opening one closes any other. Focus moves to its Form box while Identity is open, else to Identity's heading. A Done at the foot ("Done with Oil") folds it back and returns focus to its Edit; Edit pressed while open folds it too. A variant added from the New Form box opens first of the cards, closing the one open, while the New Form box keeps focus. An edit opens with every variant closed, in the read's order by form.
- **A closed variant's fields stay in the page, hidden**, not unmounted, so nothing is lost by closing it (a box's text, a sortable list's place, an open reference panel and what was typed in it).
- **An error in a closed variant opens it.** A save (resolver or server) finding an error under a variant opens the first such variant, unless the open one has an error too, and the variant's sections holding one, in the same commit that draws the error, since the focus runs as it lands. Any other variant with an error stays closed, its card edged in the error red and its line saying it has an error to fix, read with its Edit.
- **Its fields** are Form, Description, Safety Notes, Toxic, Element, Celestial Bodies, Zodiac Signs, Colours, Categories, Substitute Ingredients and References: the ingredient's own field components at the variant's place in the values (`variants.1.celestialBodies`), so each validates, errs, focuses and is held by text left in its box as the ingredient's is. Deities and folk names stay on the ingredient alone.
- **The New Form box adds one**: a list's box for whole variants at the head of the section, under its heading and the compendium's no-form prompt, above the cards, its label hidden and its placeholder "Add a form". A pick from the form vocabulary adds a variant carrying the pick; on a coven, Add or Enter adds the typed text. A form the ingredient already comes in, folded as `ingredient_variants_form_unique` folds it (trimmed, case aside), is refused at the box with its text kept and the reason on the box's error (`repeatedForm`); the lookup leaves those forms out. Text left in the box holds a save.
- **On the compendium a form is a pick**: the box offers curated rows alone, with no typed row and no Add, and a Form box typed away from its pick is refused beside the box at save. While an entry has no form the section says one is wanted: an entry with none saves, as information only, which nothing can stock.
- **A variant's substitutes are picked form by form** (`formRows`). The box shows each ingredient found as a row per form ("Mockwort · Dried leaf (Plant part)"), which links that form and is sent as the entry's `substituteVariantId`. A variant's link always names a form (a form stands in for a form), so there is no whole-ingredient row, and an ingredient in no form (only a coven's information-only entry) is not offered. The pill names what was picked ("Mockwort · Dried leaf"). Typed text is still added as a name only. The variant itself is never offered (`ingredient_substitutes_not_itself`); its sibling forms are. Once an ingredient is listed, every row of it leaves the box (`ingredient_substitutes_variant_link_unique` holds one link per ingredient in a form's list). The search matches ingredients by name, not by form.
- **A link naming no form is refused at save.** Old data can hold one; its chip reads as the ingredient alone, and the save is refused with an error on that entry (`errorId` on the chip's ×, its line in the list's error element). The refusal is the schema's `formLinkRules` (`validation/ingredient.ts`), on a variant's substitutes alone, at `['variants', i, 'substitutes', j, 'substituteVariantId']`, which `fieldNameOf` places on the same entry ([`validation.md`](../validation.md)).
- **The rows rank for the variant's form** (`rankForForm`): an ingredient with a form that folds alike first, then one with a form in the same curated group, then the rest, each tier in the search's order, and an ingredient's forms in the same order. Every form's row stays.
- **The ingredient's own substitutes keep a second picker**, `SubstituteForms`: a linked ingredient in forms gets "Form of Mockwort", Any Form until one is chosen, sent as `substituteVariantId`.
- **An edit opens with its variants**, each carrying its row's id as `variantId` (not `id`, which `useFieldArray` keys rows by), sent back as the input's `id` so a respelt form keeps its row.
- **A server issue on a variant is pathed beneath it** (`['variants', 1, 'form']`) and `fieldNameOf` places it on that variant's field, list entry or reference row; one on the variant as a whole, or its kept `id`, is its Form box's.

### Removing a variant or a reference

A variant's × and a reference row's × ask before removing, since both take more typing to put back than a chip. The question is the form's usual card ([`ConfirmQuestion`](modal.md)), drawn by `RemoveQuestion` (`remove-question.tsx`): "Remove "Oil"? …" with **Remove** and **Cancel**, focus on Cancel.

- **Nothing is lost until the save**: Remove takes the row from the form; Cancel on the form still discards the removal with the rest.
- **Cancel hands focus back to the ×; Remove hands it to the list's box** (New Form or Reference), since the × went with its row. The removal is committed at once (`flushSync`) so the card's own hand-back comes first and the box's second.
- **One question at a time**: a removal question steps aside while `DiscardAskingContext` is true. Nothing in the form provides it, so it is always false here; it exists for a form that draws the shared unsaved-changes question.
- **The question holds the row's field-array id**, not its place, which an add while asking would move.
- **A chip's × still removes at once**, and Backspace in a chip list's empty box still takes the last chip.

### Promoting a folk name

- **A saved folk name's chip carries an up arrow ahead of its ×**, named "Make <name> the Display Name". It makes that folk name the ingredient's name and the old name a folk name, in one step on the server (`promoteFolkName`). The arrow is a button in the tab order, drawn by the Combobox entry's `action` ([`combobox.md`](combobox.md), "An entry") that `ListField` fills per row through `rowAction`, so the chips' sortable and Backspace behaviour are untouched. A name typed and not yet saved has no id on the server, so no arrow.
- **It always asks first**, in the form's usual card (`PromoteFolkNameQuestion`, `promote.tsx`; the lines beneath the question are `ConfirmQuestion`'s `details`, [`modal.md`](modal.md)). The question "Make this folk name the display name?" is the card's larger heading and names no name, since the swap beneath names both: a `dl` on a tinted panel, each term ("New Display Name", "Becomes a Folk Name") a small uppercase overline with its name larger beneath. On the compendium a muted caption says every coven sees the change at once. A form with changes adds "You have other unsaved changes. Save them, or discard them?", ruled off above the buttons.
- **A form with changes is offered Save & Promote, Discard & Promote and Cancel.** Save & Promote runs the form's own save first, with the same validation and errors; if it does not land, nothing is promoted, the question closes and the first invalid field takes focus. Discard & Promote resets to the saved values, then promotes. An open reference panel's edits survive Save & Promote; Discard & Promote closes the panels with the reset.
- **One round trip**: the mutation answers the new name and the full folk-name list with ids. The form resets from that answer, clears its edited marks and undo history, calls `onSaved`, says "Saved" in the status line, and focuses Name, since the pressed chip is gone. A refusal (a name already taken) shows in the form's alert and the question closes.
- **Both tiers**: `usePromoteFolkName(workspaceId, ingredientId)` and the question take a null `workspaceId` for the compendium or a coven's id.

### Copying from the ingredient

A form often says much of what its ingredient says, so each of an open variant's fields but its Form has a **Copy From Ingredient** icon button (`copy.tsx`): Description, Safety Notes, Element, Celestial Bodies, Zodiac Signs, Colours, Categories, Substitute Ingredients and References. The ingredient's own fields have none, and nor has a form's Toxic toggle: its flag is its own, never the ingredient's. Neither Toxic toggle carries a hint: the ingredient's is on when any part of it is poisonous, a form's when that form is, and the label says so.

- **It sits** at the right end of the field's label row or legend, after its tip, through the field's `action` slot (`FieldShell`, `TextField` ([`field.md`](field.md)), `MultiSelectField`, and a legend on `ListField`, `ReferencesField` and `CategoryPicker` ([`category-picker.md`](category-picker.md)), the last three handing it their announcer). It is a small quiet `type="button"`. In a variant, label rows span the card and wrap, so on a phone it drops beneath a long label.
- **Its name starts with the visible words** ("Copy From Ingredient: Celestial Bodies"), so the nine are told apart (WCAG 2.5.3).
- **It is `disabled` while the ingredient's field, as the form holds it now, is empty** (read through `useWatch`). `disabled` rather than `aria-disabled`, since a press never empties the ingredient's field, so focus is never stranded on a shut button.
- **It adds and never takes away.** A list gains the ingredient's entries it lacks, after its own, in the ingredient's order: celestial bodies, signs and colours by text folded as a save folds it, elements and categories by value, references by source with their locators. An empty text box takes the ingredient's text; one holding text gains it after a blank line unless it holds it already. **Substitutes copy "the same form"**: each linked substitute links the linked ingredient's form that folds alike to this variant's form (Oil for Oil); a name copies as a name; one already listed, by link or folded name, is left out. **One in no such form is skipped**, since a variant's link must name a form: the announcement adds "Skipped 1 with no Oil form" and a notice names them.
- **The skipped notice** (`SkippedNotice`, `useSkippedCopy`) is a block `warn` `Notice` taking no role, inside an always-present status region labelled "Substitute Ingredients skipped" (as the duplicate warning is), empty and with its gap cancelled until a copy skips something. It reads "No Oil form to link, so not copied: Mockwort." beside a small quiet **Copy Anyway** (adds them as typed names with no link) and a × "Dismiss". Either takes the notice away and returns focus to Copy From Ingredient. Any other change to the list removes it too: the variant keeps the list as the copy left it (`listKey`) and the notice goes once the list no longer matches. It sits in `ListField`'s `after` slot, beneath the box and its error.
- **After a press** the form is dirty and, once a save has been tried, the field is revalidated. A polite announcement says what was copied ("Copied 3 celestial bodies from the ingredient", or "Nothing new to copy from the ingredient") through the list's live region, else a hidden `output` beside the button. Focus stays on the button.

### The form's pick

Two curated forms may share a name (Wax under _Animal_ and under _Substance_, DESIGN.md §5), and both fill the box with "Wax". So a pick of a curated row is kept beside the text as `formLink` in the form's values: the row's id, the name picked, its group, the group's `icon` and its description.

- **Every form wears its group's icon**, resolved once as `<FormIcon name={icon ?? null} />` (the salt spoon for a null): before each curated suggestion and the typed row, before the name in the Form box while it holds a pick (the combobox's `icon`), before the variant card's head and before the substitute summary's Form line (from `formChoice { group { icon } }`). The icon is decoration, outside every accessible name.
- **The box shows the group** as the combobox's `qualifier` ([`combobox.md`](combobox.md), "A qualifier"): "Wax" stays editable text with "(Substance)" after it in muted ink. The form's description is the qualifier's tooltip, opening on hover and while the box has focus, above the box from its right edge so the label stays in view, closing on Escape, at the first printable key and when the list opens. The group and description are also the box's accessible description after its hint.
- **An edit away from the picked name drops the link, and the group with it.** `FormField` hears each edit through `SuggestField`'s `onEdit`. Typing the name back does not restore it: what is left is typed text. A pick of the typed row, or of a form only in use, clears the link too.
- **It is sent as the variant's `formId`**, `""` for typed text. The service refuses an id naming no curated form at `['variants', i, 'formId']`, which `fieldNameOf` (server) and the resolver (schema) place on that variant's Form field, beside the box that made the pick.
- **A pick a keeper has since renamed asks the member.** A coven's variant keeps the text it was saved with, so after a keeper renames the curated form ("Wax" to "Beeswax") the text no longer matches the pick's name, which `renamedTo` (`values.ts`) notices. Beneath the box the form says "This form is now called "Beeswax"." with Use "Beeswax" (takes the new name, keeps the link) and Keep "Wax" (keeps the text, drops the link). The save is held, with the error "Use "Beeswax" or keep "Wax" before saving" on the Form field, until one is pressed, since the service would refuse the mismatched pair. Only a coven's variant can hold one: a rename rewrites the compendium's own.
- **Save & Add Another clears it**, since `EMPTY_VALUES` holds no variants. An edit is given its picks back in its values: the compendium page reads the curated form with its group and each deity with its tradition, as `IngredientVariant.formChoice` and `IngredientDeity.deity` resolve them. A pick retired since reads as typed text.

### The duplicate warning

A "did you mean" on `possibleDuplicates` ([`graphql/schema.md`](../graphql/schema.md), "possibleDuplicates"). The form owns `useDuplicateWarning` (`duplicates.tsx`), since its save waits on it; `NameField` draws it.

- **It asks for the three closest entries** in the compendium and this coven (on the compendium, the compendium's alone, less the entry being edited), once the name has settled through `useDebouncedValue`. It asks nothing for a blank name, a one-letter name, or the name the form opened with until it has been typed in, so a save that never touched the name is never held. The threshold is the server's 0.4, so "no warning" is an empty answer. Nothing refuses the create on the server: the warning is the form's alone.
- **The warning is a block `warn` `Notice`** ([`notice.md`](notice.md), "The block form") beneath the field: "Did you mean one of these?", one match per row (`.ingredient-form__matches`), then a medium accent-outline **Create Anyway**. Each match is a plain anchor named by its label and formal name, to where `duplicateHref` says, in a new tab so the typed form stays ("(opens in a new tab)"); the caller hands back a plain string, and a typed `<Link>` wants a route the build contains.
- **In a coven's form the matches come in two groups**: **In This Coven** (`!isGlobal` or `inCupboard`), then **In the Compendium**, each in the answer's order. An empty group is not drawn; a lone group keeps its heading. Headings are `h4`s set as `.fieldset__legend`, each `<ul>` named by its heading through `aria-labelledby`. The compendium's form draws one plain list.
- **Rows never jump.** While another answer is on its way each row stands as the skeleton's shape (`skeleton-shape`, `_mixins.scss`); shapes wait 200 ms before fading in, so a quick answer never shows them, and the region is `aria-busy`. Rows are slots by place and the height slides with `useSlidingRows` (script-set, since `auto` cannot animate); reduced motion swaps at once. The name field shows the lookup through `busy` on its `TextField` ([`field.md`](field.md)).
- **An exact compendium name is a question, not a warning.** A new coven entry's save also asks `compendiumMatches` ([`graphql/schema.md`](../graphql/schema.md), "compendiumMatches") for entries bearing the typed name exactly (case aside; the formal name too). If any come back that the person has not set aside, the save waits and the notice reads "The compendium already has an entry of this name." ("entries" with several). Each row has a **+** (`add-icon`, [`add-icon.md`](add-icon.md)) named "Add to My Ingredients: " plus the label and formal name, which adds the entry to this coven with no menu of covens, or the **Quick Look** eye where the cupboard already holds it; one **Create Anyway** sits beneath the list. A near match gets the same + or eye when it is a compendium entry (`isGlobal`); the coven's own entry gets the eye, never a +. Both need `onUse`, which the compendium's form leaves out.
- **The + calls `addCupboardEntry`** (no jar, no form) and adds the entry under its own name: the typed name is never sent as a `label`, since it could clash with a label the coven already gives another entry. It sends whichever of the description, safety notes, elements, celestial bodies, signs and colours were filled as the coven's overrides, then reports the entry through `onSaved` as `'another'`, so the modal stays open with what was typed. A refusal is said at the form's head. Once the add lands both lookups are asked again (`added` on `useDuplicateWarning`), since cached answers would say the coven still lacks it.
- **The + becomes the Quick Look eye where it stands.** While sent it shows the spinner and is `aria-busy` and `aria-disabled` (not `disabled`, so focus stays). On success it shows AddIcon's check for `ADDED_HOLD_MS` ([`add-icon.md`](add-icon.md)), then the same button becomes "Quick Look" plus the label and formal name. Only then is the cache refreshed and the row moved from In the Compendium to In This Coven. Focus on the + moves to the eye. "Added to the coven." is said once through the status region (`useAnnounce`, [`click-feedback.md`](click-feedback.md), "The status region"); no Saved notice. The page beneath is not refreshed until the next navigation. A refusal leaves an idle +.
- **An edit's warning holds nothing.** Renaming makes nothing new, so on an edit the warning names and links its matches but offers no Create Anyway and never holds Save: the form skips `check`, and `NameField` takes `holds={false}`.
- **Quick Look in the admin compendium's form**: every match is a compendium entry, so each row gets the eye (`DetailsLink`, [`ingredient-entry.md`](ingredient-entry.md)) and no +. The form takes `quickLookOf`, which `CompendiumDialog` builds when the page passes `lookUnder`: the list's address with `?entry=<slug>` plus the form's parameter, so details open over the form and close back to it. The form stays mounted, so typing survives. Escape closes the details alone. Details over another entry's form offer no Edit; details under their own entry's edit keep it. The public search's form opens details by id and offers no Quick Look.
- **In the coven's form** (the shell's Add Ingredient dialog) the eye is a button (`QuickLookButton`, [`icon-tip.md`](icon-tip.md)), not a link, since that dialog opens over any shell page by `?new` and most have no details modal to route to. It opens `DuplicateQuickLook` (`quick-look.tsx`), the details modal over the form, reading the entry through the existing `ingredient(id, workspaceId)` query; it opens at once, `aria-busy`, with the head the details will have so nothing moves when they arrive. A failed read says so with Try Again. Escape closes it alone.
- **The eyes are the add's green** (`$accent`, scoped to `.ingredient-form__group`) in every state, and as non-text controls clear 3:1 in both themes and on both notice tints (measured at least 3.96:1).
- **The warning has to be answered before the form saves.** While only typed against, it is a warning and the name is not marked. A new entry's save that passes validation asks about the very name it sends, through the query client's `fetchQuery` (cached when typing had settled, asked there and then when not, so a save inside the debounce cannot slip past). If a match not yet set aside comes back, nothing is sent: the notice turns `error` and reads "Your save is on hold, as these entries have a similar name" (colour alone must not say it), the name is marked invalid and described by it, and focus goes to Create Anyway. A failed check holds nothing. The check runs after validation, so an error elsewhere takes focus first.
- **The hold belongs to the name it was set for.** Editing the name lifts it. Focus goes to the button through a layout effect declared after the one that focuses the first invalid field, so it wins when both run.
- **Create Anyway answers it**: it saves nothing, sets the named matches aside by id, and lets the next save go. The name takes focus before the button goes, found through the button's form rather than `setFocus`, which waits a tick with focus on the body; the name's error goes with the warning.
- **A screen reader hears it two ways**: the warning sits in a `<div role="status">` named "Possible duplicates", always in the page, and its sentence is in the name field's `aria-describedby` while showing. The notice inside takes no role of its own (`inRegion`, [`notice.md`](notice.md), "Inside a live region, a notice takes no role").
- **A save shows it is busy** from press to answer, the duplicate check included: both saves disabled, the pressed one `aria-busy` with a spinning ring, its label "Saving Ingredient" until the answer. The ring is slowed, not stopped, under reduced motion.

### The classification and formal name

The schema's rule has three cases: a botanical, fungal, zoological, mineral or chemical entry needs a formal name, a `none` entry takes none, and an `unknown` entry takes either ([`validation.md`](../validation.md), "The two ingredient variants").

- **The form enforces the second case by construction.** Choosing "None" empties the formal name and disables it, with a note beneath its label: 'A "none" entry records no formal name.' (a note, not a tip, since a shut field that does not say why reads as broken). It is shut with the HTML attribute, not react-hook-form's `disabled` option, which would also drop the value from what is validated and sent; emptying it keeps the value out. The schema's refusal stays the service's, for other callers. "Unknown" leaves it open and optional, so a name typed before the kind is settled is kept.
- **The first case stays a message**: a named kind with no formal name gets "A botanical entry needs its formal name" beside the formal name; a formal name with no kind is no error (it saves as `unknown`). The kind decides the formal name's error, so the classification registers the formal name as a `deps`, and nothing registers the other way. Once a submit has shown the error, changing either field revalidates the formal name and the error clears as soon as the pair agrees. The classification's info tip states the rule before anyone breaks it.

### What it sends

`toInput` (`values.ts`) reshapes the values as typed into the input the mutation and the schema take; the resolver runs with `raw: true`, so what it validated is exactly what is sent. Nothing is trimmed or parsed: a blank field goes as `''` and the service's run of the same schema turns it into an absence.

- **Forms go as `variants`**, the only place a form is sent: every field but `id` present, `""` or `[]` for none, since an entry replaces the forms it names; the form as its text with `formId` (the picked form's id, or `""` for typed text); `id` when an edit opened it. Every input type requires the list, so a form with none sends `[]`.
- **A deity** goes as `{ deityId }` when picked, `{ name }` when typed. **A substitute** goes as `{ ingredientId }` (with `substituteVariantId` when a form is chosen) when linked, `{ name }` when typed. **A reference** goes as `{ referenceId, locator }`, the locator as typed, never its citation.
- **Each toxic flag** goes as `toxic`, `true` or `false`: the ingredient's at the top, each form's on its variant, neither ever read from the other (DESIGN.md §5, "The toxic flag is the one exception").
- **Categories** go as `categoryIds` in the order picked, `[]` for none (an update needs it to clear them). The form cannot send a repeat: a chip is on or off. **Elements** go as chosen, `[]` for none.
- **Unanswered closed sets are `null`.** A stub with only a name goes with `nomenclature: null`, which `LocalIngredientInput` reads as `none`, so a one-field entry is whole.
- **The boxes are left behind**, since a save is refused while one holds text. An entry's index in an issue's path is its place in the list shown: Add refuses a blank and a moved entry goes in its new place, so every entry sent is one the user can see, in order (a deity's place is its stored `position`).
- **A variant's issues also include the stale-pair refusal at `form`**, for a pick whose id and text no longer agree.
- **Pills** read their text beside what tells a same-named one apart: a linked substitute's formal name, a deity's tradition ("Hecate (Greek)"), a substitute naming a form with that form after a dot ("Rosemary · Dried leaf"). A pill's tooltip leaves out what the chip's summary shows.
- **A variant's substitute rows** are one per form each found ingredient comes in ("Rosemary · Dried leaf (Plant part)"), since a link names a form. An ingredient in no form (only a coven's information-only entry) is not offered; typed text is the box's own row, a name only. The variant's own saved row is never its own substitute (`ingredient_substitutes_not_itself`). Ranking: forms folding alike first, then the curated group, then the rest.
- **Duplicate checks** read the schema's keys: a link by id, typed text folded among the typed entries alone (so a name beside a link is no repeat), and the ingredient's `name` counts for a folk name.
- **An edit's default values give each linked substitute a `variantId`** (`""` for Any Form), because its Form box registers that key as it mounts; react-hook-form counts a key added against defaults lacking it as a change, and React's development double mount re-checks, so an untouched entry would be asked about unsaved changes.

### Autosave

The form saves itself through `useAutosave` ([`autosave.md`](../autosave.md)): 3 s after the last change, at least every 30 s while changes keep coming. `SaveStatus` ([`autosave.md`](../autosave.md#save-status)) beside the main button shows Saving, Saved, "Could not save." with Retry, or the conflict notice.

- **A new ingredient is created at its first save, once it has a name** (a "none" or "unknown" entry has no formal name, so the display name alone opens the gate). The create returns id, slug and revision; every later save is an update sending `expectedRevision`, an explicit Save included (a stale Save hands over to the conflict notice). The host moves the address through `onCreated` ([`modal.md`](modal.md#add-ingredient)). After a create by Save the form is clean, so Save waits for a change.
- **Save is disabled once an autosave has filed every edit.** A test that edits then waits for Save to enable depends on the autosave pause; the stories hold the save request until after the click (`holdSaves`).
- **A new entry with near-duplicate matches showing is not autosaved** until they are dismissed or the name changes (`heldBack` in `values.ts`).
- **Writes are serialised** through one write path, each waiting for the one before, so a create is never raced by a second. **An identical write is skipped** once the row exists, when the input matches the last sent and no revision was named (a compendium end-redirect save is never skipped). `persist` hands the id to `onCreated` only for the write that created the row.
- **The blur flush is held while Save is submitting**: pressing Save disables it, moving focus out of the form, and the autosave must not create the row before Save has asked about duplicates.
- **An autosave of an existing ingredient calls `onAutosaved`** with the saved row (not on Close). The admin compendium dialog replaces its address with the saved slug (`replace`, no scroll) and fetches again; the coven entry dialog only fetches again (its address names the id). The form is keyed by entry id and reads `entry` only for starting values, so what was typed after the autosave stays.
- **Conflict**: "This ingredient was changed elsewhere." with **Reload Latest** (reloads the page or calls `onReload`) and **Keep My Version** (sends over the newer revision). **Offline**: a failed save retries after 2, 5 and 15 s, then shows Retry; the local mirror stays until a save lands, and a reopened form with a newer mirror shows `RecoveryNotice` with Keep and Discard.
- **No Discard question and no Cancel**: Close saves first, so the form draws neither in any dialog ([`modal.md`](modal.md#unsaved-changes)). A viewer's form has no autosave and writes nothing.

### After a save

A new ingredient has two saves; an edit has the first alone. **Save Ingredient** is the `.btn--solid`, first, so Enter in a field presses it; it passes `'open'` to `onSaved`. **Save & Add Another** is a plain `.btn`, passes `'another'` and leaves the form blank. Which was pressed is the submit event's `submitter` value; a submit with none is Save Ingredient's. The form navigates nowhere itself: the host does (the shell's add button pushes `/coven/[slug]/ingredients/[id]` on Save Ingredient only; its form is about to go, so it keeps its values).

- **The form says "Saved Testwort."** in a `success` `Notice` (`<output>`) above the fields, where a refusal's alert goes; the next submit drops it. The message is the form's, since only it knows a save landed.
- **After Save & Add Another the form resets to its empty values** (every field, list and box), nothing is marked invalid, and Name takes the focus. A refused save keeps everything as typed. The reset is an effect on a count of landed saves, not on `isSubmitSuccessful` (which a save held on the duplicate warning sets too), and runs after react-hook-form's own end-of-submit update. Name is found in the page, not by `setFocus`, which reads a ref the reset has just dropped.
- **An edit's save resets to what it saved** (`reset(getValues())`), so Save is off until the next change.

### Undo and redo

The form uses `useFormHistory` ([`field.md`](field.md#undo-and-redo)) on its own `<form>` ref, off while a question is asked over the form and while a save is in flight (its success handler resets over the values). `FormHistoryButtons` sit in the modal's header row after Open All; the pair's `margin-inline-start: auto` carries it to the end.

- **An add and its draft clear are one step**: adding a variant or picking a reference clears its typing box first, then adds the row (the field array reports its new row in an effect, `setValue` at once), so one undo removes the row and returns the typed text.
- **Two resets clear the history** (`history.clear()`): after Save & Add Another's `reset(EMPTY_VALUES)` and after an edit's save, since a step past a save would undo what the server now holds.
- **A restore opens what holds the field it wrote**: `onRestored` turns changed paths into sections with `sectionsRestored(names)` (`values.ts`): a box's draft counts as its list (`drafts.colors` is Colours); a path under `variants.N` opens Variants and then that variant's section, through `reveal(index, sections)` from `useVariantFolds`.
- **A restored variants list is reconciled with the folds** (`reconcile(from, to)`): rows match by `variantId`, else by form text folded, each old row matched at most once, and a matched row keeps its open sections. An unmatched row (returning from a removal) opens fully and becomes the open card; if nothing returns, the open card stays on its variant, or none if gone. A redo swaps `before` and `after` so `from` is always the list as it stood.
- **Focus after a restore**: a classification pick that empties the formal name focuses Classification (`onRestored` returns `'nomenclature'`). A changed list focuses its typing box (`listBoxOf` in `values.ts`: `drafts.<list>` or `variants.N.drafts.<list>`; the categories picker names its box `boxName`). A step on the variants list focuses `variants.<i>.form` of a row that came back, or `drafts.variants` (New Form) after a removal. Otherwise the hook focuses the field itself.
- **The reference panel has a history of its own**: the outer hook has `skip: isPanelState` (keeping the `referencePanelOpen` paths out) and `ignore: inReferencePanel` (a target inside `.ingredient-form__panel`; the backstop for the panel's loading shell). `PanelForm` (`reference-panel.tsx`) runs its own `useFormHistory`, provider and `FormHistoryButtons` in `PanelHead` before How to Cite and Close, under a `HeaderSlotContext` set to `null` (exported by `Modal`) so they never portal into the modal's header. Ctrl+Z in the panel undoes a panel edit alone.

### Forms are shown in title case

A variant's `form` is stored as typed. Wherever the site shows one it passes through `formLabel` (`src/modules/ingredients/validation/form-label.ts`), which calls `titleCase` (`src/lib/text.ts`): each word and hyphenated part capitalised, the small words (of, and, in, on, the, a, an, or, for, to, with, at, by, from) lowercase unless first, a word with an inner capital left alone. Display only: a field being typed into keeps the text, and GraphQL, services and seeds are unchanged. A label folds (`lower(btrim(x))`) to the stored text's identity, apart from a run of inner spaces, which it collapses. The lint rule `sorrel/form-shown-through-form-label` flags a component rendering `.form` without it.

### On the compendium

With a null `workspaceId` the form writes a compendium entry through the compendium mutations ([`graphql/schema.md`](../graphql/schema.md), "The compendium mutations").

- **An edit says so under the dialog's title**: a plain `Notice`, "Changes are made to the Compendium, for everyone." (`COMPENDIUM_EDIT_NOTICE`, `compendium-notice.ts`, the one place the wording lives), wherever the form opens (admin Compendium, an entry's page, the public search for a curator). An add carries none, and nor does a coven's edit. In a modal it portals into the header's note line (`useModalHeaderNote`, [`modal.md`](modal.md), "A control in the header"), `space(2)` below the title and above the Open All and Undo row, so it stays in view as the form scrolls; outside a modal it sits above the form.
- **The classification is required**: `compendiumResolver` validates with `CompendiumIngredientInput`, whose `nomenclature` has no default (every compendium entry declares one, DESIGN.md §5), and the select is marked required.
- **The form, celestial body, sign and deity boxes are pick-only.** Each offers the curated rows alone (a value only in use is one the services refuse), flat, under no From Compendium heading (`curated` dropped, so the combobox draws one bucket), with no typed row (`offerTyped`) and, on a list, no Add (`ListField`'s `pickOnly`). Enter on unpicked text adds nothing and says `Pick "Moon-ish" from the list` at the box. A save is refused while such a box holds text (`Pick "Moon-ish" from the list, or clear the box`) and while the form is typed rather than picked ("Pick a form from the list"), by the resolver, beside the box. Folk names and colours stay free text, having no curated list.
- **Every lookup reads the compendium alone**: folk names, references and their panel, and the duplicate warning ask with a null `workspaceId`; substitutes search `compendium(query)`.
- **A new entry** has both saves and sends `createCompendiumIngredient`. **An edit** opens on the `entry` given with one save, Save Ingredient, off until something changes, sending `updateCompendiumIngredient` with the whole entry (every field present, `formId: ""` for no pick). Categories are sent in full, so those left alone stay ([`m5.5-admin-compendium.md`](../design-decisions/m5.5-admin-compendium.md)).
- **Delete Ingredient** stands apart at the far end of an edit's actions (`.btn--destructive`, `.form__aside`). It asks "Delete **Testwort**? It leaves the compendium, but any spell that uses it keeps it." (a coven's: "It leaves the coven, ..."), with Delete (destructive) and Cancel (quiet) as [`GroupedValueForm`](grouped-value-form.md) asks: on a `ConfirmQuestion` card over the form ([`modal.md`](modal.md), "Asking over the form"), the form dimmed and held, focus on Cancel and back on Delete Ingredient once Cancel puts it away. Delete sends `deleteCompendiumIngredient`, or `deleteIngredient(id, workspaceId)` for a coven, busy until the answer, then calls `onDeleted`; a refusal drops the question and shows the server's message as an alert above the fields. A deleted coven entry is deleted from that coven alone. On a compendium entry `DeleteUsers` reads `compendiumEntryUsers` when the question opens and shows a status line with how many covens use it only once the number arrives; a slow or failed read leaves the question as it was, the count is never kept, never names a coven, and Delete stays unconditional.
- **The end-redirect question**: a save taking an address another entry still redirects from is refused at `['endRedirect']` ([`db/ingredient-slugs.md`](../db/ingredient-slugs.md), "Ingredient slugs"). That is no field's, so the form asks over itself: the server's message, **End Redirect & Save** (sends the same input with `endRedirect: true`) and **Cancel** (sends nothing, entry left as typed).
- **Questions the form asks over itself** share `ConfirmQuestion` and the modal's `.modal__actions` row (the form's `.form__actions` stays beneath), and no unsaved-changes question comes before them: the form calls neither `useDiscardGuard` nor `useLeaveGuard`, since Close saves first ([`modal.md`](modal.md#unsaved-changes)). `panel-changes.ts` reports a panel's typed edits to the form's `changed`, which the promote question reads. A removal question (Remove and Cancel; `RemoveQuestion`, `remove-question.tsx`) runs `onRemove` (`flushSync`, so the card's cleanup commits first), then `afterRemove` once the card has gone, moving focus where the list says, since the pressed × went with its row. The promote question and a removal question would step aside while `DiscardAskingContext` is true, which nothing sets.
- **On the admin page** `/curator/compendium` opens the form in `Modal`'s default width from its address: `?new` an empty form, `?edit=<slug>` the entry (through `resolveCompendiumSlug`). An old address redirects to the entry's current `?edit=`; one naming nothing opens nothing and says so in an alert above the list. An edit's head is the eyebrow "Edit Ingredient" over the saved name and formal name, italic for a binomial (`editHeading` in `page.tsx`; [`modal.md`](modal.md), "An edit dialog's head"). The edit's values are built on navigation by `entryValues(entry, session)` (`src/app/entry-values.ts`, `server-only`) from the services `Ingredient`'s fields resolve through (folk names, categories, substitutes (a linked one carrying the forms its second picker offers), deities with traditions, references with citations, variants with their picks, groups, categories, substitutes and references), so opening sends no browser read (CLAUDE.md rule 1). `compendium-dialog.tsx` draws it through [`CompendiumEntryForm`](#compendium-entry-form) in a `RouteModal` that closes back to the list, with a router of its own: Save Ingredient replaces the address with the saved entry's `?edit=`, Save & Add Another stays on `?new`, a delete and the close replace it with the list's (filter and cursor kept), and each refreshes. A near match opens its own modal over the same list in a new tab. Why: [`m5.5-admin-compendium.md`](../design-decisions/m5.5-admin-compendium.md).

### Reading another entry in the form

The substitute summary and Quick Look both make one read of the `ingredient` query through `/api/graphql`, which already serves an entry by id in the compendium's tier or a coven's own and the compendium's, never another coven's. Quick Look is not the list's `DetailsDialog` (a route modal its server page fills): it has no route to change, and its answer is cast to the entry page's shape so the head and body are the details modal's own components. Its head before the entry arrives is the details' own with the formal name known; with it unknown a line skeleton stands there while the read is out, or nothing after a failed read. It never reads "Not yet looked up", which would say the entry has none.

### Section summaries

An empty section and a variant carrying nothing both read "Nothing yet". A variant's section line reads its Identity as its Form, "Dried leaf (Plant part)". Each section's summary watches only its own fields, so a keystroke re-renders one line.

### Suggestion lists

- The form, folk-name, celestial-body, sign, deity and substitute lookups each wait for typing to settle and shape the answer into combobox rows. Celestial bodies, signs and deities suggest from their curated vocabularies and values in use (a curated deity's pick is also a link to it); substitutes from the compendium and this coven, a pick adding a link to the ingredient.
- Celestial bodies, signs, colours and deities keep the order entered, so their entries move; folk names and substitutes read alphabetically, so theirs do not.
- `SuggestField`, `ToggleField`, `MultiSelectField` and `ListField` live in this form, not `../Field`; `CupboardEntryForm` imports `ListField` and `MultiSelectField`. A multi-select's chips sit inside the control, as a list's entries do.

### Variant fields and their folds

A form is added from the New Form box as a list's entry is, refused there when the ingredient already comes in it, and removed by its own Remove. Each variant's fields stay in the page while closed (`hidden`), so nothing typed in them, an open reference panel included, is lost by closing. They are the ingredient's own field components at the variant's place in the values (`variants.1.celestialBodies`), so they validate, err and focus alike. The open state of each variant's sections is a list beside the variants, by place, held by the form (like its own sections') so a save opens the section holding an error and Open All / Close All reaches each variant's. A variant added here opens with every section open; one an edit opened with, past the list's end, opens closed. Restored lists follow "Undo and redo".

### Submitting and focusing the first error

`useOnEachSubmit` runs while rendering, once per new `submitCount` (React's pattern for state that follows a value), and a save's last update carries its count with every error found, so a fold is open in the same commit that draws its error and the form never paints a closed fold with an error inside. `useFocusFirstInvalid` is a layout effect, so focus moves in the commit that draws the error; it replaces react-hook-form's `shouldFocusError`, which focuses in registration order and only a registered field. An issue naming a picked category lands on the picker's one error element, named by the pick.

### One error element, two sources

`FieldError` is the one element any field's error renders through: a `.field__error` paragraph whose id the control lists in `aria-describedby`, with `aria-invalid` beside it. Resolver issues and the server's `fieldErrors` both reach it through react-hook-form's error state, so a server-only rule draws as a schema rule does. Both go through **`fieldNameOf`**:

| Path                            | Field                                                                 |
| ------------------------------- | --------------------------------------------------------------------- |
| `['name']`                      | `name`                                                                |
| `['folkNames', 2]`              | `folkNames.2.value`, the third entry                                  |
| `['elements', 1]`               | `elements`, the whole control: its chips are not rows                 |
| `['variants', 1, 'formId']`     | `variants.1.form`, the Form box that made the pick                    |
| `['categoryIds', 1]`            | `categoryIds.1`, the second category picked: the picker's             |
| `['references', 1]`             | `references.1.value`, the second reference's row                      |
| `['references', 1, 'locator']`  | `references.1.locator`, its locator                                   |
| `[]` or any path it cannot name | none: the root alert, rather than an unseen error (`drafts` included) |

- **The form's resolver wraps `zodResolver`** and moves an entry's issue (`folkNames.2`) onto the entry's `value`, where `fieldNameOf` puts the server's; an element's issue (a repeat, which a caller can make) arrives at the element (`elements.1`) and is moved onto the field likewise.
- **A list's errors are the list's.** An entry is not a control, so the list has one `FieldError` beneath its box, reading each entry's message after the entry ("hedge fixture: This folk name is already listed"). The named entry takes the error edge and its × lists the message as description; the box takes `aria-invalid` and the same description, so a failed submit focuses it. The categories' errors are the picker's the same way.
- **Rejections are read by the shared `readGraphqlIssues`** (`src/lib/graphql-failure.ts`): `VALIDATION` with `fieldErrors` gives the field errors, each pathed to the input; any other GraphQL error one empty-path issue with the error's own message; no GraphQL answer (a failed fetch) one empty-path issue, `GENERIC_FAILURE`, "That didn't work. Please try again." It is used rather than `readGraphqlFailure`, which answers only the first field, because the form places every issue at once (a draft's nested path included) through the shared `placeServerIssues`, which sets aside the redirect question's issue for the form to ask. Unplaceable messages join into the root one, each distinct message once. Each placeable issue goes in through `setError`, bar `['endRedirect']`. DESIGN.md §7 leaves a `FORBIDDEN` or `NOT_FOUND` to the page; until a wrapper does more it shows as the root alert with the service's message.
- **Announced from either source**: a failed submit moves focus to the first `aria-invalid` control in page order (`useFocusFirstInvalid`, on `submitCount`, since react-hook-form's last update of a submit carries the new count and every error). The root error is a `.notice--error` with `role="alert"` above the first field, only while there is one.
- **Clearing**: the next submit replaces every error with the resolver's, and editing a field in error revalidates it (`reValidateMode: onChange` after a first submit), clearing a server error as readily as a schema one. A list revalidates on each add and removal once a submit has run, and removing an entry takes its error. The submit is disabled while a save is in flight. The form is `noValidate`.

## Styling

The stylesheet is `src/components/IngredientForm/index.scss`, built on the form primitives in `_primitives.scss` ([`styling.md`](../styling.md), "Form fields"). Binding facts:

- The column is at most `$dialog-column` (32rem), and everything, panels included, sits inside it; the compendium modal is the default width.
- Every button that waits on a request is a `BusyButton` ([`busy-button.md`](busy-button.md)); the alert is an `error` `Notice` ([`notice.md`](notice.md)); Save Ingredient is the view’s one `.btn--solid`. Notices are never a hand-written `notice` class.
- Colour is not the only sign of a held save: the duplicate sentence changes with the state.
- The Toxic switches are start-aligned (`.ingredient-form .switch`).
- A variant card has a 1px muted edge (error red when it holds an error); its icon buttons are 24px, and the pencil’s `$accent` on a 20% tint clears 3:1 (`tests/scss/tokens.test.ts`).
- `hidden` is restated as `display: none` where a display rule would undo it. Lengths come from `space()` and `radius()`; raw ones say why in a comment.
- Chips are the [`Combobox`](combobox.md)’s entries. A long entry is cut off with an ellipsis, never wrapped, the 24px × never shrinks, and the full text stays in the DOM, in the ×’s name and in a `role="tooltip"` that opens only on a cut-off entry, closes on Escape (WCAG 1.4.13), waits 150 ms before closing, and breaks unbroken text. Touch opens it from the emulated hover. List entries have no length cap.
