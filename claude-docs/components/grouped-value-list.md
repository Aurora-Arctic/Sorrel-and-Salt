# GroupedValueList

`src/components/GroupedValueList/` is a curated vocabulary's filter, table and pager. One component serves every such vocabulary, `kind: 'category' | 'form' | 'deity' | 'celestialBody' | 'zodiacSign'`, as [`GroupList`](group-list.md) serves the groups. Categories, forms and deities file each value under a group; celestial bodies and zodiac signs are flat. It is render-only and a server component: the page ([`grouped-value-form.md`](grouped-value-form.md), "On the admin pages") reads one page of the vocabulary under the address's filter and hands it over, each value with its group's name and the address that opens it to edit, with the filter as asked and the groups it can narrow to. Its last column before Edit is Updated: who last edited the value and when ([`updatedColumn`](data-table.md)). Props are in `types.ts`.

## Contracts

- **Everything that tells one kind from another is its entry in `KINDS`** (`kinds.ts`), so a new kind is an entry there and nothing else; the nav's tab and the form's `noun` read it too. It holds `path` (the page's address), `title` (the table's name, "Zodiac Signs"; the heading is the tabbed page's, [`tabbed-page.md`](tabbed-page.md)), `label` (one row in title case, as Add says it), `noun` and `plural` (what a sentence calls one row and several), and, for a grouped kind only, `group`: its `label` (the group column's heading and the filter's label, "Group"), its `plural` (the filter's empty choice, "All Groups") and its `param` (the address parameter naming a group, `group`). The deity kind calls its group a tradition throughout: "Tradition", "All Traditions", `tradition`. A flat kind has no `group`, so its table has no group column and its filter no group select. The list carries `.grouped-value-list--<kind>` for a rule only one kind's rows need.
- **Entry order.** Categories come by group then name. Forms are live forms under live groups, by name, so a form under a deleted group is no longer curated and is not listed. Deities are live deities under live traditions, by tradition name then name. A deity's `otherNames` (alphabetical) show in the Name cell on a muted caption-sized line under the name, "Also called Testrina, Tess"; a deity with none shows its name alone.
- **An entry's group is drawn in its own chip where it has a pair.** `groupColors` is the group's pair from the page's read of the groups, drawn through [`GroupChip`](data-table.md) as the category picker draws it. The categories page passes it; an entry without one, as every deity is, shows the name plain. A form's group leads with its icon, a [`FormIcon`](form-icon.md), through `GroupChip`'s `icon`: `groupIcon`, the generic spoon where the group has none. A category's rows take more room than the table primitive gives and centre their contents, since a chip stands taller than a line of text.
- **The filter is a GET form to the page itself**, as the user list's is ([`user-list.md`](user-list.md)): named by the kind's title ("Filter Categories"), inside a `<search>` landmark, with a search box labelled "Name" (`query`) and its own submit, a magnifier named Search (`SearchField`, [`field.md`](field.md)), and for a grouped kind a group filter labelled by the kind's group label (named by its `param`). There is no Filter button: each field applies as it changes. A filtered page is an address, and filtering starts again from the first page, since the form carries no cursor. `filter.tsx` is the one client file here, holding the fields and what each applies. The shared `FilterForm` holds the form, the navigation and the Clear link at the row's end, drawn while the page shows a name or a group and not drawn while it shows neither, whatever the fields hold ([`filter-form.md`](filter-form.md)).
- **`?query=` is part of the name; `?group=` is a group's slug**, as `?edit=` is a value's and a deity's `?tradition=` a tradition's. The page trims the query, reads a blank one as none, and resolves the slug against the groups it reads for its modal. A slug no group holds is ignored, so the list is every value and the slug leaves every link. The services take `{ query, groupId }`, a deity's `{ query, traditionId }` and a flat kind's `{ query }`, and the count behind the pager reads the same filter as the list.
- **The group filter is typed into once hydrated, and a native `<select>` before.** The server draws the select, so the form submits before hydration: its first option is "All Groups" ("All Traditions"), valued `""`, then each group by slug, alphabetical as read. A native submit sends `query=&group=` (`query=&tradition=`), which the page reads as no filter. Hydration swaps it for the combobox's type-ahead box ([`combobox.md`](combobox.md), "The type-ahead box"), both drawn by `FilterSelectField` with `typeahead` ([`field.md`](field.md)). Typing narrows the groups; the placeholder reads "All Groups" while blank; the clear, "Clear Group" ("Clear Tradition"), is the way back to every group. Both stand at one width, so the swap moves nothing ([`filter-form.md`](filter-form.md#styling), "A choice takes one width"). Text naming no group is no group, so it filters by none. A hidden input carries the same parameter, by slug, so the form's fields are what they were.
- **Each field applies as it changes.** The group applies once a choice settles (a pick, its clear or leaving the box) and only when the settled group differs from the one shown, never while it is typed, carrying the name typed but not yet searched. The name applies on the magnifier or Enter, keeping the group shown. With JavaScript each builds the address with `groupedValuesHref(kind, { query, group })` and `useApplyFilter` pushes it softly. The loading state and the form's keying by the filter shown (so a page showing another filter after Back draws the fields afresh) are the shared form's ([`filter-form.md`](filter-form.md#contracts)). In the workshop `next/navigation` is stubbed ([`workshop.md`](../workshop.md), "`.storybook/`").
- **Every action is an address.** Each row's Edit is its `editHref`. The page's Add Category, Add Celestial Body and the rest are the tab's action beside the heading (`ValueAction` in `src/app/(shell)/curator/value-page.tsx`, from the route group's `@action` slot, built on `AddAction` in `src/app/(shell)/_admin/add-action.tsx`, which takes the dialog's `heading` apart from the button's label), so the page's rather than this component's, and open `?new`. `groupedValuesHref(kind, place, dialog?)` in `href.ts`, on the shared `listHref` (`src/lib/list-href.ts`), builds those, the pager's links and the filter's submit. `place` is `{ query, group, after, before }`, written in that order before the modal, a blank one left out, the group under the kind's group `param`, and none for a flat kind. Every link keeps the page's filter, and every one but the pager's keeps its cursor too, so closing a modal, and a save, lands where it was opened. `new` is a bare flag, read by its presence, as the user list's `awaiting` is.
- **`next/link`, not a plain anchor.** Opening the modal is a soft navigation: the page renders again with the modal open, and the page calls the admin guard on every render.
- **Each Edit is a pencil**, [`EditLink`](icon-tip.md), opening the modal at once under the value's `editHeading` ([`modal.md`](modal.md), "Opening at once"). It is named for its value: "Edit" and the name in `visually-hidden` text, so a screen reader hears "Edit Testcraft" rather than a column of "Edit", and a sighted reader sees the tooltip "Edit" on hover or focus. Two live forms may share a name under different groups, and two deities under different traditions; the group column beside it tells them apart.
- **An empty list says so and what to do, with no table**: "There are no categories yet. Add one with Add Category.", from the kind's `plural` and `label`, which name the tab's Add. A filtered list with no rows names each filter in force and what to do, in the one wording every admin list uses (`noMatchText`, `src/lib/text.ts`): "No categories match “wort” and the group Fixture Healing. Change or clear the filter to see more.", the group by its name and the kind's group `label` ("the tradition …" for a deity).

## Styling

The list is the list primitives ([`styling.md`](../styling.md), "Designing a section"): a [`ListFrame`](list-frame.md), a [`FilterForm`](filter-form.md) and the table [`StackTable`](data-table.md), which turns each row into a card under `$table-stack-width` ("Tables at phone width"). Edit is a `'corner'` action column. A description keeps to `$measure`; the categories' table alone takes `data-table--roomy`, whose cells centre their contents for the chip. At phone width `FilterForm` and `TabbedPage` own the stacking and the Add plus ([`filter-form.md`](filter-form.md), [`tabbed-page.md`](tabbed-page.md)), so the list adds no rule for either.
