# Ingredient Search

`src/components/IngredientSearch/` is the list shell for any page that finds ingredients by name: a search box that offers matches as you type, the page's own filter fields, an action, the results and a pager. The compendium list is its first consumer; the coven Ingredients list and the Grimoire list use it too. Props are in `types.ts` (`IngredientSearchProps` for the server shell, `IngredientSearchFormProps` for the client filter row). `useSearchText()` returns the text in the box now, for a field in the filter slot to carry.

## Contracts

- **The shell renders on the server.** The consumer builds `IngredientSearchForm` (a client component, re-exported from `index.tsx`) because it holds function hrefs, and passes it as `search`.
- **The box asks and the list does not.** The text is debounced (`DEBOUNCE_MS`, `src/lib/debounce.ts`) and feeds the dropdown only. The list changes on Enter, the clear, a pick or the last row. A pick leaves the list as it was and the typed text stays.
- **The clear (x)** empties the box and applies the empty search; the other filters in `searchHref` stay.
- **The magnifier Search button is the one submit**, in Combobox's `leading` slot, with the clear at the end: `[magnifier  Search  x]`. There is no chevron (`toggle={false}`), following the NN/g magnifying-glass advice. Without JavaScript the box is a plain GET form to `action` sending `query`.
- **Names.** The box has no visible label and the placeholder is "Search". The accessible name is "Name" (Combobox draws its own visually hidden label), the clear is "Clear Name" and the status region "Name results". The ranked fields are in `../db/compendium-read.md`.
- **Nothing is asked** until the box is focused or while the text is under `MIN_QUERY_LENGTH` (2), exported by `src/modules/ingredients/validation/compendium-filter.ts` (a zod-only file), counting composed code points. Under the floor the dropdown offers no rows, and once anything is typed it says "Keep typing to search" (announced, sentence case, a message not a label).
- **`source` is a `SearchSource`**: `{kind:'compendium'}` (default), `{kind:'cupboard', workspaceId}` or `{kind:'grimoire', workspaceId, status}`. The box asks one document for its source only. The compendium pages omit `source`, the coven Ingredients page passes the cupboard, and the coven Grimoire page passes the grimoire with its tab's status.
  - A cupboard source asks `workspaceIngredients(workspaceId:, query:, first: 25)` (the `IngredientSearchCupboardMatches` document). Both answers become the same `IngredientSearchMatch`, and the cupboard entry's label (`cupboardEntry(workspaceId:)`) is the row's name.
  - A grimoire source asks `grimoire(workspaceId:, query:, status:, first: 25)` (the `GrimoireSearchMatches` document), so each tab suggests its own status, ranked over title and intent (`../graphql/schema.md`). The hidden label is "Title", the placeholder "Search titles & intents", the clear "Clear Title", and an untitled draft reads "Untitled Spell". A row's `match` has `id` and `slug` equal to the spell id. With `pickHref` a pick opens the Grimoire list's Quick Look; without it a pick applies the row's title (or the typed text) as the search.
- **The dropdown shows at most 25 rows**, the first page, in server order, never a second. If there is another page, a last row "See All Results" (selectable, italic, sentence case with a full stop, not counted in status) applies the debounced text. "No Matches" when nothing matches. Escape closes the dropdown without closing the surrounding modal. These are the combobox's `action` and `empty` (`combobox.md`).
- **A pick opens the match** when `pickHref` is given: through the route modal opener if `pickHeading` is given (the heading shows at once), else `router.push`. Neither goes through the list frame's transition. On every ingredient list with a Quick Look, the list gives `pickHeading={detailsHeading}` and `pickPlace={DETAILS_PLACE}`, and the href is the `?entry=` address (`ingredient-entry.md`, "The details modal").
- **The search row sticks once scrolled to**, with the Filters button, Clear All and the tray. Its layers and spacing are in "The sticky box", "The space under the row", "The sorrel layer", "The phone row" and "Scroll margin". The admin compendium list shares the row; the phone sheet is unchanged.

## The parameter table

A search's whole state is its address, and the address is written and read through one typed table, [`defineSearchParams`](../../src/lib/search-param-table.ts), so a filter is never listed by hand in five places. Each entry is one parameter: the name the address carries, a reader that turns what the address held into a value (a hand-edited value reads as no filter, never an error), a writer that turns a value back, and the GraphQL variable it becomes. The compendium's table is [`CompendiumList/params.ts`](../../src/components/CompendiumList/params.ts); the helpers `textParam`, `choiceParam`, `listParam`, `slugListParam` and `textListParam` cover the usual shapes, and `searchParam` takes any other.

The table gives four functions, and every caller uses only these:

- `read(params)`: the filter an address holds. The page calls it.
- `href(path, filter, extra)`: the address of a filter, in table order, then `extra` for the cursor and the modal. Every link, the pager and the filter form's applies call it, through the list's `compendiumHref`.
- `variables(filter, lookups?)`: the query's variables, a blank as `undefined`. The page keys its cached read by them, so adding a filter changes nothing there. `lookups` is the optional map a slug list needs to become ids.
- `changed(place, change)`: the place with a change applied and the cursor dropped.

**Adding a filter is one new entry** and touches none of those callers; `tests/lib/search-param-table.test.ts` proves it by adding one. The coven's table is the first real one: `COVEN_PARAMS` ([`IngredientSearch/coven-params.ts`](../../src/components/IngredientSearch/coven-params.ts)) spreads the compendium's entries, takes `reviewed` out, and adds `source`, `inStock` and `lowStockOnly`; `tests/components/IngredientSearch/coven-params.test.ts` shows the compendium's table unchanged. The pieces that do change are the filter's own control, the service and the GraphQL argument it reaches.

**A list is a repeated parameter**, `?elements=fire&elements=earth`: `listHref` writes one pair per value and `list` ([`search-params.ts`](../../src/lib/search-params.ts)) reads them back, with `someOf` dropping any value outside the set. An empty list is left out. It is repeated rather than comma-joined because a GET form's checkboxes write repeated names themselves, so a facet filters before hydration and without JavaScript, and because a form's free text may hold a comma. A single-value parameter given twice by hand reads its first.

**The address names a value the way a reader would**, and the table maps it to whatever the query takes: a deity is its slug, `hecate-greek`, while the query takes `deityIds`, since an id would outweigh the rest of the address. A deity's slug is its name with its tradition's, `deitySlug(name, traditionName)`, because two traditions can share a name (`hecate-greek`, `hecate-roman`). A slug follows a keeper's rename of the deity or its tradition, and a category's slug follows its name. A slug that names no live value, such as one in a link saved before a rename, is dropped from its filter, and a filter left with none is not applied, so the list widens rather than failing.

**Free text in a list** (`textListParam`) is a repeated parameter whose values are curated words, not a fixed set: `?forms=Oil&forms=Resin`. Each value is trimmed, a blank is dropped, and a repeat that differs only in case is dropped too (the first spelling stays). It is used for forms, zodiac signs and celestial bodies because those three are keeper-curated vocabularies that offer suggestions rather than a closed list: a form's text is not a foreign key (CLAUDE.md, ingredient identity), so an uncurated value stays writable and the address cannot reject it the way `listParam` rejects a word outside its set.

**A slug list** (`slugListParam`) is a repeated parameter whose values the address spells as slugs and the query takes as ids. `read` drops repeats; `variables` maps each slug through `lookups[lookupKey]` (a `Map` of slug to id the page builds), dropping a slug the map does not hold, and gives `undefined` when none are known. The table holds nothing category-specific. The compendium's `categories` entry is `slugListParam('categories', 'categoryIds', 'categories')`; its page reads the cached `listCategories` (every page, through `allPages`) for the map, and the Categories picker (`CategoryPicker`) after Form in the filter row draws the choice. A pick applies the whole slug list at once. The picker keeps its own chosen state while the address catches up, and the filter row is keyed by the other filters only, so a pick does not remount it: its status region announces the pick once and the list's own status does not. Hidden inputs repeat the slugs so a native GET submit before hydration keeps them. A match is the union of an entry's categories and its forms', by the finder's category arm, ANDed across the categories chosen.

From two categories the filter row also shows a Match radio group, All and Any, which sets `categoryMode`, an enum argument of `compendium` and `workspaceIngredients` defaulting to `all`; `any` matches an entry holding any of the categories, filtered in SQL. The table's `categoryMode` entry writes only `any` (`?categoryMode=any`) and reads anything else as All, so All leaves the address bare. The mode means nothing below two categories, so removing down to one drops it from the address and a second pick starts at All. The form holds the mode as it holds the picks, and the list's key leaves it out, so choosing a radio keeps focus. The mode alone does not make the list count as filtered.

**The compendium's whole table**, in the order the address writes it:

| Address parameter   | Reads as               | GraphQL variable    | Notes                                      |
| ------------------- | ---------------------- | ------------------- | ------------------------------------------ |
| `query`             | text                   | `query`             |                                            |
| `forms`             | text list              | `forms`             | The compendium read folds the case         |
| `withoutReferences` | on or off              | `withoutReferences` | Written `1`                                |
| `withoutForms`      | on or off              | `withoutForms`      | Written `1`                                |
| `elements`          | list of elements       | `elements`          | Dropped when outside `INGREDIENT_ELEMENTS` |
| `categories`        | slug list              | `categoryIds`       | Through the `categories` lookup            |
| `categoryMode`      | `all` or `any`         | `categoryMode`      | Written only for `any`                     |
| `deities`           | slug list              | `deityIds`          | Through the `deities` lookup               |
| `zodiac`            | text list              | `zodiacSigns`       | Sign names                                 |
| `planets`           | text list              | `celestialBodies`   | Celestial body names                       |
| `toxic`             | `toxic` or `not_toxic` | `toxic`             | Absent is any                              |
| `reviewed`          | `1` or `0`             | `reviewed`          | Admin list only; see below                 |

`elements` matches an entry holding any element listed on the entry or on any of its live forms, by array overlap in SQL, ANDed with the other filters.

`reviewed` reads `1` as `'reviewed'` and `0` as `'needs_review'`, and anything else as no filter; the query sends `true` or `false`. Only a curator or a keeper may send it, and the service refuses anyone else. So `COVEN_PARAMS` is the compendium's table with `reviewed` taken out, and the public page strips `?reviewed=` before it reads.

There is no `nomenclature` entry: the compendium search does not filter by classification. The GraphQL query and the service still accept the argument, and a `?nomenclature=` left in an old link is ignored.

**One variables string reads the list and its counts.** The page builds `JSON.stringify(COMPENDIUM_PARAMS.variables(filter, lookups))` once, with `lookups = { categories, deities }` (slug to id), and gives that same string to the cached list read and the cached facet read (`compendiumFacets`). The counts beside each facet value are therefore taken under exactly the filter the list is under. `compendiumFacetCounts` (`CompendiumList/facets.ts`) turns the counts, which are keyed by id for deities and categories and by text for the rest, into the props the filter draws: a value, a label and a count, plus a form's icon, a deity's tradition or a category's group. It drops an id the vocabulary no longer holds, and sorts forms, deities and categories by count, highest first, then label.

**The cursor rule.** A cursor names a place in one filter's results, so it belongs to the filter it was read under. Any change to the filter opens the first page: the filter's controls build their address from `filter` alone, never from the cursor, and `changed` drops `after` and `before`. Only the pager and a modal's way back write a cursor, through `extra`. Reload and Back need nothing built for them: the address is the state, so a reload reads it again and Back steps through the filters one change at a time. The e2e spec in `tests/e2e/admin-compendium.spec.ts` asserts both.

## The search sentence

`sentence.ts` exports `buildSearchSentence({ filter, labels, total, noun, admin })`. It is pure: no React, no component imports. It turns the filter as the address holds it, the display labels of each vocabulary and the total into `{ fragments, hasFilter }`. A fragment is `{ kind: 'text', text }`, `{ kind: 'join', text }` or `{ kind: 'value', text, facet, value }`; the component draws a `value` as a quiet boxed mark and a `join` as a loud word, and draws Clear All while `hasFilter` is true. Types are in `types.ts` (`SearchSentenceFilter`, `SearchSentenceFragment`).

It leads with the count (`No ingredients`, `1 ingredient`, `3 ingredients`; `noun` swaps the pair), then one clause per kind, always in this order whatever order the address holds them: text query, the viewer's covens (the public compendium only), categories, forms, deities, zodiac, celestial bodies, elements, toxic, then a coven list's source, in stock and low stock, then the admin-only nomenclature, No Refs, No Form and Reviewed. Clauses are separated by a comma. An example with every kind:

> 3 ingredients, matching rue, in the protection and healing categories, in the form oil or resin, linked to Isis, under Aries, ruled by the Sun or Mars, of the fire element, that are not toxic, classified as botanical, without references

- **Joining.** Values are joined through `Intl.ListFormat` in `en-US`, which puts the Oxford comma before the last word: "oil, resin, or leaf" (`en-GB` leaves it out). Forms, deities, zodiac, celestial bodies and elements join with "or"; categories join with "and" in all-mode ("in the protection and healing categories") and "or" in any-mode ("in the protection or healing category"). `Intl.ListFormat` is Baseline Widely Available, so the browser-floor guard needs no line for it. The bare word the list format writes ("or", "and") is a `join` fragment, with the spaces round it left as `text`, so the component can set the word apart. A comma stays plain text. A join is never a link and carries no facet.
- **Casing.** A value is shown in lower case (`toLocaleLowerCase('en-GB')`): categories, forms, elements, source and nomenclature. Deities, zodiac signs and celestial bodies keep their capitals ("Hecate", "Scorpio", "the Sun"), since they are proper names. The text query is shown as typed. A value that is already a lower-case phrase ("not toxic", "in stock") is unchanged. The lowering is of the display text only: the fragment's `value` keeps its own spelling.
- **No article before a vocabulary word**, except "the" before Sun and Moon among celestial bodies, which belongs to the linked value ("the Sun").
- **The viewer's covens** read "held in Hearthside or Moonwell", each coven by its name with its capitals kept, joined with "or". Each is plain text, as every value in the sentence is (`SearchSentence` draws values as text, never links), and removes nothing: a coven is removed in the panel. Only an id with a label is named: the page labels the viewer's own covens alone, and the read ignores any other id, so a foreign or malformed id in the address filters nothing and says nothing. The fragments carry the facet `covens` and the coven's id as `value`. Under Not In (`covensNot`) the same list reads "not held in Hearthside or Moonwell". With Not In and no coven in the address at all, for an observer with covens to name, it reads "not held in any of my covens": "not held in " is plain text, as it is with covens picked, and "any of my covens" is the one value, with the facet `covensNot`. If the address names covens and none has a label, it says nothing, under In or Not In, as the read applies nothing.
- **Toxic** takes the address's own choice, `toxic` or `not_toxic`, and says "that are toxic" or "that are not toxic"; `any` or nothing says nothing. The linked fragment's `value` is that same string.
- **Source, In Stock and Low Stock Only** belong to a coven's list and are named whenever the filter holds them. `source` (`local` or `compendium`) reads "from the local source" or "from the compendium source"; `inStock` reads "in stock"; `lowStockOnly` reads "low or out of stock", the two badges it keeps. A false flag or a null source says nothing. Their fragments carry the facets `source`, `inStock` and `lowStockOnly` (`value` `true` for the two flags). The component draws them as plain text, so they remove nothing; a filter is removed in the panel. The coven's list passes `noun` as it likes.
- **Nomenclature, No Refs and No Form** ("without forms") are named only when `admin` is true; otherwise they are ignored and do not count as a chosen filter.
- **Reviewed** is named only when `admin` is true, the same way: `reviewed` says "reviewed by a curator" and `needs_review` says "needing review". Its fragment carries the facet `reviewed` with that setting as its `value`.
- **A value with no label** is named by its raw value, so a stale link still reads. Blank values and empty lists are not chosen.

`tests/components/IngredientSearch/sentence.test.ts` asserts these strings. It is the one named exception to the copy rule, since the strings are what the function makes; the component tests assert only the status region's presence and update.

## The sticky box

The row sticks once scrolled to, with the Filters button, Clear All and the tray, which opens inside the form and so travels with it. The root is `.ingredient-search`; the sticky box is the `<search>`, `position: sticky`, whose parent `.list-frame` spans the results (the form inside would stop at its own end). `--sticky-top` is set by the frame: AppShell uses the bar's bottom, PublicFrame uses 0. The box is opaque through the fill layer and the `sticky-row` layer, so the cards do not show through, and sits above the cards and below the bar, tips and dialogs.

`space(4)` of padding above is the row's own air when stuck, and a negative margin of the same size cancels it at rest, so the page lays out as without it. The search sentence takes back the `space(2)` under the row from the frame's gap.

While the row is stuck it wears `$shadow-floating` faded with `$modal-fade`. `StuckMark` watches a one-pixel sentinel with an IntersectionObserver and sets `data-stuck`. Without the API there is no shadow.

**Forced colours.** While the row is stuck its shadow is dropped, so the row's full-bleed fill takes a 1px `CanvasText` rule along its foot, which runs the width of the page and moves nothing in the row.

## The space under the row

While the tray is shut the row's box ends at the controls, and the `space(2)` between the row and the cards is a margin outside it. Opening the tray rolls that space into the box as padding (the margin shrinks by as much, so the page does not move), under the tray's own slide, and closing rolls it back. The stuck row thus never shows an empty strip under its controls. The tray is anchored to the form inside, not to this box, so none of this moves the tray from the input. Nothing animates under reduced motion.

The 8px follows the tray's edge, not its clock. The tray (`FacetPanel`'s `.facet-panel__clip`; `--slide-ms` is set on the clip inside and so unreadable here) slides 350ms on `ease`, and its edge covers hundreds of px, so 8px rolling over all 350ms looked slow beside it. On `ease` a roughly 400px tray's edge has moved 8px by 12ms (250 to 550px: 10 to 17ms), so the space opens in 12ms. Closing, the edge is within 8px of the row for the last roughly 64ms (55 to 79ms over the same heights), so the space waits 350 - 64 = 286ms and rolls up then, in 64ms on `ease-out`, the shape of that tail. The closed-state rule times the way back to closed and the open rule the way out of it, since a transition takes the timing of the state it ends in. `--open` is on the clip from just after the tray starts to open until it starts to close, the same two moments its rows grow and shrink in (`useSlide`). Before the script the tray is in the flow with the class, so the space is already inside the box.

## The sorrel layer

The fill is `.filter-sorrel`, a decorative `aria-hidden` child that `FilterForm` draws (its `sorrel` prop). It holds a copy of the corner sorrel (`backdrop.md`, "The copy in the search row"), because a sticky box is its own stacking context, so no `z-index` can put the real sorrel between the fill and the controls. The layer is a direct child of the `<search>`, not of the form, whose `container-type` would become the containing block of the fixed copies. `z-index: -1` paints it above the box's own background and beneath the controls. It is hidden under `prefers-contrast: more`.

A solid `mask-image` cuts the fixed copies to the row and makes the layer a stacking context, so they blend with its page colour, as the real one does with the page's. It is a mask, not a `clip-path`, because a clip's edge is anti-aliased at a half pixel (an odd-width window centres the page on one), and there the copies drew a lighter one-pixel line over the real sorrel. The mask's edge matches it. The mask is on this layer and never on the `<search>`, which would cut off the stuck shadow and the tray.

The layer reaches a gutter past the row on either side, so a card under the row (its hover shadow carries 20px) shows no shadow beside it. The page gutter is the same from a phone up and in the shell and the public frame, and no wider, or the page would scroll sideways.

## The phone row

Under `$narrow-column` (the filter row's container width) the row is two lines and both stick: the search box on the first, and the Filters button (filling the second line, all of it when Clear All is not drawn) and Clear All (pushed to the line's end) sharing the second. The `<search>` stays the one sticky box. The primitive's narrow-row rule (`_primitives.scss`, "On a phone's narrow row") gives the first child and each choice a whole line; it is scoped to this row, so the other filter rows are unchanged, and the container query is that rule's own, so the two agree on what narrow means.

## Scroll margin

A focus or a jump that scrolls a control into view lands it below the stuck row, not under it. The root's `scroll-padding-top` is the bar (the shell's and the public frame's alike), the row's own height, and a step of air. The root is the scroll container, which cannot read the frames' `--sticky-top`, set below it. The first `space(2)` is the gap under the row, a margin when the tray is shut and padding when it is open, so a jump lands in the same place either way. Under the narrow column the row is two controls tall plus the row's gap, so the root leaves one more control height plus `space(3)` of room. That query is the container query's width on the window: the column (`$narrow-column`) plus the page's two gutters.
