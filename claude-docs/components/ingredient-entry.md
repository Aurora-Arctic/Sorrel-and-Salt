# IngredientEntry

`src/components/IngredientEntry/` is the body of an ingredient's page, the same on the public compendium route and a coven's: the entry's fields, then one section for each form it comes in. It is a server component (no hook, no `'use client'`). Each route reads an `IngredientDetail` through `ingredientDetailOf` and hands it over. The client parts are `PageNav`, `BackLink`, `edit-pencil.tsx` and `entry-dialog.tsx`. Props are `IngredientEntryProps` in `types.ts`; addresses are typed `Route`, cast once (`as Route`) where typed routes cannot check a built string. The root is `<article class="ingredient-entry">`, inside the route's `<main>`, laid out by its own stylesheet, not `.page-with-nav`.

## Structure

In page order.

1. **The head** (`<header>`):
   - `accessPause`: AppShell's `PausedNotice` (an `aside` named **Site Access**), first, in the text column ([`app-shell.md`](app-shell.md), "The paused notice").
   - `back`: the quiet **Back to Compendium** or **Back to Ingredients** link, with a `LinkHint`; omitted, no link ("The back link"). The same row (`.back-bar ingredient-entry__bar`) ends with **New** or **Updated** (`RecencyMark`) and the one safety badge (`SafetyMark`, [`safety-note.md`](safety-note.md)), flush with the pencil, in flow. The row is drawn for whichever of the three exists.
   - `FormalName` as an eyebrow over the `h1` (`entry.name`), in `.ingredient-entry__naming`, which the icons are placed against. For an entry this coven holds, **In Your Cupboard** is the header's `lead`. From `$shell-tablet-width` up the head keeps to the text column.
   - `replaces` ("The replaced-by block").
   - `EntryMarks` badges ([`entry-marks.md`](entry-marks.md)): **Local** for a coven's own entry; **Compendium** for every compendium entry on a coven's page, held or not (never public); **Annotated** in its place once an override is set; **Retired** (a button opening a tip) when `detail.retired`. A retired entry gets no `replaces` and no `edit`. This row passes `safety={false}`.
   - `movedAway`: a warning `Notice` (status) with a link to the moved entry.
   - On the public page `hiddenFromPublic` shows a notice to a curator or keeper, and `reviewControl` is the head's last row ("The details modal", review mark).
2. **The jump menu** `PageNav` (**On This Page**): **Stock** (`#stock`, where drawn), **Details** (`#details`), a nested list **Forms** (`#form-oil`, labels capitalised, `apart`; [`page-nav.md`](page-nav.md)), and **References** ("References"). Drawn only when there is a form; the skeleton always draws it.
3. **Stock** (`stock-section.tsx`), above Details: `<section id="stock">`, drawn only when the page passes `stock` (`EntryStock`). The coven route passes it for the coven's own entry and for a compendium entry the cupboard holds; never otherwise, never public. Jars are this coven's alone, read by `covenJarsOf` (`src/app/coven-stock.ts`, which the Ingredients list's Quick Look reads too); `stockDialogOf` shapes them for the dialog.
   - The shelf is [`JarShelf`](jar-shelf.md): one jar per form, held or not, forms with no jar after those with one, each group in form order; a jar holding 0 keeps its place; a form with no jar draws a dashed jar reading **No Jar**; a jar whose form is gone is not drawn. The page passes the entry's formal name (`entry.canonicalName`) so form and name pick each vessel. No form: "No stock recorded." The heading, its button and the shelf are one stack with no box (the jars' shine is card-coloured and would fade on a card-coloured panel).
   - A role that permits `inventory: ['update']` (`mayEdit`) gets [`StockDialog`](stock-dialog.md)'s jar button **Edit Stock, <entry name>** at the heading's end (offered with no jar too), and each jar is a button **Edit Stock, <entry name>, <Form>** opening on that form (`openOn`; an empty jar adds the form first). An observer sees the shelf only. A save re-reads the page.
4. **Details**: `<section id="details">`. The description or "No description recorded."; `SafetyNote` with the ingredient's own notes at `level={3}`; the [`DisclaimerNotice`](document-page.md#disclaimer-notice) line linking `/disclaimer`; `NoteMarks`. The side column is a plain `<div>` after the section, not an `<aside>`: a landmark per section would be eight on a page, and each block in it is headed. It holds **Correspondences** (`<dl>`: Elements and Colours, each value capitalised; Celestial Bodies; Zodiac Signs; Deities, a curated deity as "Odin (Norse; also called Woden)"; every row always present, empty ones "No elements recorded."), then **Folk Names**, **Categories** (`.chip`s in `chipColors(group)`), **Substitutes** and **References**, each an `h3` over a `<ul>` named by it; an empty list is a sentence in the same block. Every empty line, and the modal's **No details recorded.**, share `.ingredient-entry__empty` (italic, faded): `$text-placeholder` on the card and modal (4.65:1 light, 6.71:1 dark), `$text-muted` on the page (5.99:1, 9.67:1), because the placeholder is 4.17:1 on the page's darker light ground.
5. **Forms**: `<section id="forms">`, omitted with no form, holding `<section id="form-<slug>">` per form in order, each a region named by the capitalised form name; its `h3` reads `FormIcon`, the name, `ToxicMark`; blocks are `h4`, its caution at level 4. The body is only what the form adds: description, own `SafetyNote`, `DisclaimerNotice` line; non-empty correspondence rows, categories and substitutes in the side column; its reference numbers end its text. A form adding nothing still gets its section and one line saying so, so the anchor and jump link always exist. Lists inside a form are named by form and heading ("Oil Categories"), so the ingredient's own **Categories** and **Substitutes** stay the only lists with exactly those names; a test for the ingredient's own passes `exact: true` or looks inside **Details**.
6. **References** (`references.tsx`): `<section id="references">`, always drawn, the article's last child (v2's notes section is appended after it). `referenceNotes` builds notes and bibliography once from the sorted detail: the ingredient's references first, then each form's in order, one note per link (a source cited twice is two notes; a locator belongs to its note).
   - **Note numbers**: end of Details' and each form's text, a `role="group"` named **References** (an `.eyebrow` label, not a heading, to keep one References heading) of superscript `Note N` links to `#note-N`, each `id="note-ref-N"`.
   - **Notes**: `h3` over `<ol>`; `<li id="note-N">` holds the `renderShortCitation` citation linked to its bibliography entry, the locator, and a backlink "Back to Details" or "Back to <Form>".
   - **Bibliography**: `h3` over `<ul>`; `<li id="ref-<referenceId>">`, each source once, alphabetical by `byCitation`, in `renderCitation`'s full form, an **Open the Source** link (`rel="noopener"`, hidden " (opens in a new tab)") when it has a `url`, and a backlink "Back to Note N" per citing note. It breaks anywhere (`overflow-wrap: anywhere`): a printed url could otherwise set the list's width.
   - No references: "No sources recorded.", no lists. A curator or keeper also gets the Sourcing Score panel last under an `h3` ([`sourcing-score.md`](sourcing-score.md), "On the entry page").
   - The menu's **References** is `apart`: with notes, a group of **Notes** (`#notes`) and **Bibliography** (`#bibliography`), bare ids so no `note-N`, `ref-<id>` or `form-<slug>` can equal them; without, one link to `#references`.
   - Links rest in `$text-primary`, fade to `$accent-hover` on hover and `:focus-visible` (`$accent` is 3.96:1 on the `:target` highlight). Their cue is a faded underline: the `faded-underline` mixin (`_mixins.scss`, a `color-mix` at 55% at rest, 65% on hover and focus, the lowest mixes keeping 3:1 against page and highlight in both themes), one shared rule in `index.scss`.

## Contracts

- **FormalName** (`formal-name.tsx`) is a one-pair `<dl>` (a screen reader announces label and value as the Correspondences list does): the term, `visually-hidden`, names the nomenclature; the definition is the name as an `.eyebrow` with an `InfoTip` (`formal-name-tip`, button "About <term>") saying which naming system. Italics only for a binomial (`BINOMIAL_KINDS`, `src/modules/ingredients/schema/ingredient-enums.ts`) as `<i class="binomial">`, not `<em>`: a taxonomic name is set apart, not stressed. The tip opens beside the ⓘ past `$shell-tablet-width`, below it on a phone (the sticky bar would cover one above), via `--tip-placement` and `useTip`; `tests/e2e/tip-placement.spec.ts` checks it stays inside 390px.

  | Nomenclature                        | Term                                                             | Definition                       |
  | ----------------------------------- | ---------------------------------------------------------------- | -------------------------------- |
  | `botanical`, `fungal`, `zoological` | Botanical / Fungal / Zoological Name                             | `<i class="binomial">`           |
  | `mineral`, `chemical`               | Mineral / Chemical Name                                          | The name, upright                |
  | `unknown` with a name               | Formal Name                                                      | Name, then "(unconfirmed)" muted |
  | `unknown` with none                 | Formal Name                                                      | "Not yet looked up", muted       |
  | `none` with a name                  | Formal Name                                                      | "None", muted; the tip says why  |
  | `none` with none                    | nothing drawn (`FormalName` returns `null`, page and modal head) |                                  |

- **A form's anchor is `form-` plus `slugify`** (DESIGN.md §9); a clash (names unique by trimmed lower case can still slug alike, "oil" and "oil.") takes `-2`.
- **Ids come from the data, not `useId`** (`details-heading`, `form-oil-name`, `form-oil-categories`): one entry per page, and a server component has no hook.
- **A substitute links only to a page the caller names**: with an ingredient, a `Link` to `hrefOf(ingredient)`; a typed name, a deleted ingredient's last name, or a `hrefOf` answer of `undefined` is plain text. A substitute naming a form reads "Name (form)".
- **Every link to another page names the page it draws** (`PendingLink`, `navigationTarget: ingredientLinkTarget(href)`, [`loading.md`](../loading.md)), including the navigation after Make It Ours, and shows a click took: a `LinkHint` dot on text links, `LinkIconHint` on chain-icon links (Similar, In the Compendium). The jump menu and Edit do not ([`link-hint.md`](link-hint.md)). There is no `loading.tsx` or Suspense on purpose: it would turn the public route's 404 and 308 into 200s and break rendering without script.
- **Safety is drawn by `SafetyNote` and `ToxicMark` only**; each is followed by the `DisclaimerNotice` line, drawn even with no notes.
- **Meaning never by colour alone**: Local, Toxic and Retired carry words; a chip carries its name.

## The two routes

- **`/compendium/ingredients/[slug]`** (`src/app/(public)/`) reads `readCompendiumEntry(slug)` (no session). An unknown slug and a coven entry's slug answer 404; a moved slug `permanentRedirect` (308). It asks `viewerIfSignedIn()` to offer a curator Edit and a signed-in person their cupboard choices; a visitor reads the same page with neither. No `<main>` (the layout draws it). It links a compendium ingredient as `/compendium/ingredients/<slug>`, never a coven's own (404 there). Title: name, then formal name in brackets when it differs (`pageTitleOf`, shared).
- **`/coven/[slug]/ingredients/[id]`** (`src/app/(shell)/`) runs `requireCovenMembership(slug)`, `requireSession()`, then `getIngredient(session, id, workspace.id)`; a non-member and an id the coven cannot see answer 404. It draws its own `<main>`. For a compendium entry it passes `replaces` (itself) and, for a curator, `edit`, and sets `alternates.canonical`; the tab title uses the coven's label if its cupboard entry sets one (`cache()`d `getCupboardEntry`, shared with `generateMetadata`). A coven's own entry gets the coven's Edit for a role that may update ingredients. Links go to the public page for compendium ingredients, `/coven/<slug>/ingredients/<id>` for the coven's own.

## Edit

A curator's Edit opens the compendium's edit modal over the entry's page, headed **Edit Compendium Entry** (the coven menu names it the same: it changes the entry for every coven, Annotate only this coven's).

- `edit.href` is the page's address with a bare `?edit`; `closeHref` drops it. The page reads `searchParams` and, for a curator with `?edit` only, reads the form's values with `entryValues` (`src/app/entry-values.ts`, server-only) as `opened`.
- With `edit`, the output is wrapped in `RouteModalProvider` so a press opens the dialog at once over a skeleton ([`modal.md`](modal.md), "Opening at once"). `EditPencil` is IconTip's `EditLink` with `useOpenModalClick` in `.ingredient-entry__cupboard--pencil`; `EntryDialog` is the `RouteModal` and, once `opened`, `IngredientForm`. Only the id, names and nomenclature cross to those client parts.
- A save keeps the modal open: the page replaces its address (public follows a renamed slug; the coven route names the id and passes `savedHref`) and refreshes. No Cancel: Close, Escape and outside click close to `closeHref`, saving unsaved changes first (the admin dialog keeps Cancel). A delete replaces to `deletedHref` (the compendium list, or the coven's Ingredients list). Delete is only inside the modal.
- The dialog is [`CompendiumEntryForm`](ingredient-form.md#compendium-entry-form), shared with the admin compendium's `compendium-dialog.tsx`. `edit.sourcing` carries the Sourcing Score for a curator or keeper.

**A coven's own entry.** `edit.coven` (`{ workspaceId, ingredientsHref, mayPromote }`) makes it the coven's edit, eyebrow **Edit Ingredient** (`editEyebrow`, `edit-heading.ts`): `IngredientForm` with the coven's id; foot Save Ingredient, Cancel, Delete Ingredient (own confirmation, `deleteIngredient(id, workspaceId)`; [`ingredient-form.md`](ingredient-form.md), "The props contract"). A save closes and re-reads. A delete says "{name} deleted" in the status region, replaces to `deletedHref` and focuses the list's heading. Values are read as the member only for a role that may update and only with `?edit`; an observer gets neither. The coven's Ingredients list draws the same dialog under `?edit=<id>` ([`coven-cards.md`](coven-cards.md)).

**`OwnEntryActions`** (`own-actions.tsx`): the pencil **Edit <entry name>** (link to `?edit`, `useOpenModalClick`) and the three dots **More for <entry name>** holding **Edit Stock** first (where `edit.coven.stock` is given, for a role that may update stock) and **Delete Ingredient**, in one Coven section; no bin, since every role that may delete may update stock. Delete asks in `DeleteDialog` (`delete-entry.tsx`, `useDeleteEntry`, `DeleteOwnIngredient`), then replaces to `edit.deletedHref`; a refusal shows in a [`ClickFeedback`](click-feedback.md) callout under the dots. A cancelled Edit gives the focus back to the pencil ([`modal.md`](modal.md), "Giving the focus back").

## Styling

`index.scss` and `summary.scss` use tokens only: `space()`, `stack`, `list-reset`, the shell breakpoints, `$measure`, colour tokens, `$icon-size`, `$glyph-size`, `$inline-mark-size`, `$nav-link-size`, and the optical corrections `$optical-nudge`, `$back-chevron-pull`, `$link-hint-drop`, `$cap-middle` (explained in `_variables.scss`), plus `.badges`, `.badge--*`, `.chip`, `.binomial`, `.btn`. The `local` and `retired` palettes are in `_variables.scss` ([`styling.md`](../styling.md), "Badge palettes"); the look follows its "Designing a section".

- Each correspondence row is a `<div>` (term over value, `space(1)`), rows `space(4)` apart. Running text stops at `$measure` (`dd` and list items `max-width: $measure`); a description keeps typed line breaks (`white-space: pre-line`).
- At 390px the `h1` breaks a word (`overflow-wrap: break-word`) only when it cannot fit a line. Jumps land clear of the sticky bar inside `.app-shell`.
- Forced colours: a `:target` note, mark or source takes a 1px `Highlight` outline (its fill is dropped); the shown switch mirrors `.switch` (`CanvasText` thumb, `Highlight` track and `HighlightText` thumb when on, `GrayText` disabled), no `forced-color-adjust`.

### Layout

The entry takes the frame's wide column (`$wide-column`, allowed by `.page-column` and `.coven-layout`).

- **Article**: a column of parts `space(6)` apart. With a jump menu (`--with-nav`), above `$shell-phone-width` it is a grid: the sticky menu left, head, Stock, Details and forms right; the breakpoint and sticky `top` are `.page-with-nav`'s. The menu column is `minmax(min-content, min(space(8) * 3, 100% - space(8) * 15))`: 12rem at 1152px or wider, below that the content keeps 60rem (20rem side column, 2rem gutter, 38rem text) and the menu gives way, never narrower than its longest label. The menu spans `.ingredient-entry__body` so it sticks for the page's length; its first link is level with the first heading (`$nav-link-size`). On a phone it stands above Details.
- **Body grid** (`entry-body` in `_mixins.scss`), above `$shell-tablet-width`: text column left, side column (`space(8) * 5`, 20rem) right, `space(8)` apart. Row 1 holds Stock (empty and zero height without it), row 2 Details (`1fr`); the side column spans both rows so it starts level with the first section, `margin-block-start: space(1)` (the skeleton's side part takes it through `entry-body`). A long side column grows row 2 and never pushes Stock down. Forms and References span both columns below. Each form is a grid: heading across, text left, lists right. Stock and Details stay in `minmax(0, 1fr)`.
- **Below the tablet width**: one column (Stock, Details, side column, forms), `space(6)` apart; a form's side column runs `space(4)` under its text.
- **Heading rule**: `entry-heading-rule` puts a `$hairline` under the h2 of Stock, Details, Forms and References, the heading text's width plus `space(4)`, `space(1)` under it, never wider than the column. Stock's rule follows its h2, not the head row.
- **Skeleton** uses the same mixins: a Stock part (a heading bar over three jars sized from `$jar-top`, `$jar-drawing-width`, `$jar-drawing-height`, `$jar-plank`, `$jar-cell-min` in `_variables.scss`; always three, since form count and jars are unknown), Details, the side part, then forms. Its heading bars have no rule, so the page adds a few pixels when it loads.

- Entry section rule: hairline as wide as the heading text plus `space(4)`.

- Section grid: heading, text, side column on a phone; past a tablet the side column stands right of the text, the heading across both; not from the menu's breakpoint where text would be a few words wide.

## In Your Cupboard

`held-mark.tsx` draws a shelf of two bottles (a corked one and a round flask) before the name of every entry this coven holds. It says "you hold this": the card's check says In Every Cupboard, the modal's list is In Your Cupboards, its link **See in Your Cupboard**.

- Outside the `h1`, in `PageHeader`'s `lead`, so the heading is the name alone. A `button` named **In Your Cupboard** carrying an `IconTip` (`placement="above"`, opens on hover, focus and press via `opensOnPress`; the press does nothing else; the tip is `aria-hidden`).
- At `heading-size(1)`, icon `$inline-mark-size` (0.72em), `$optical-nudge` gap, `$text-muted`; the cork is the one filled shape, 35% ink, drawn first.
- Beside a jump menu above `$shell-phone-width` it hangs into the menu's column so its right end meets the menu's right edge, keeping the name level with the text beneath. At `$shell-phone-width` and under it stands on its own line under the formal name, at the name's start, 30% larger (the drawing grows, not a transform, so the tap target does); `lead` turns to a column in CSS, markup unchanged.
- On the public page it shows when any coven of the viewer's holds the entry (a view-only coven included): one `covensHoldingEntry` read (`covensHolding` in `cupboard.ts`), passed as `heldInCovens`. Not for a visitor, nor for a compendium entry the coven does not hold.

## Cupboard entries

`detail.cupboardEntry` is the coven's row for a compendium entry it holds (null on the public page). Three kinds are told apart and `isGlobal` is never read: own (`entry.workspaceId !== null`, Local); compendium with a cupboard entry (**Compendium**, or **Annotated** when `isAnnotated(cupboardEntry)`: any of seven overrides set, an empty list counting); compendium without one (drawn as the public page). `applyCupboardEntry(entry, cupboardEntry)` (`src/modules/ingredients/validation/cupboard-merge.ts`, pure, no `server-only`) merges: heading, description, caution and the four correspondence rows read the merged row. The compendium's name is not repeated under the coven's label (In the Compendium links it). Forms, folk names, substitutes, categories, references and the toxic flag are the compendium's. Edit and In the Compendium read the unmerged row. Marks are `output` elements (role status) in the neutral `low-stock` tint: where the row lives is not a warning.

## Cupboard buttons

The optional `cupboard` prop (`{ workspaceId, covenSlug, canAdd, canAnnotate, canRemove, canMakeOurs, removedHref?, plus? }`) comes from the coven route for a compendium entry (and a retired one the coven holds), never from the public page, and is ignored for a coven's own entry. Flags come from `rolePermits` (`ingredient:create`, `update`, `delete`, `MAKE_IT_OURS_PERMISSION`, the set the service checks); the service is the guard. A retired entry has `canAdd` false, so its menu offers Annotate, Make It Ours and Remove, and no curator Edit ([`m12.24-retired-entry-stays-readable.md`](../design-decisions/m12.24-retired-entry-stays-readable.md)). `cupboard-actions.tsx` draws them in the header's action slot as icons ("The icons"). The choices:

- **Edit Compendium Entry** for a curator.
- **Annotate**: a link to `?annotate` (`cupboard.annotate`: `href`, `closeHref`, `opened`), opened at once by `useOpenModalClick`. The page sets `opened` only for a member who may annotate in a coven that holds the entry, from `'annotate' in searchParams`; any other asking is ignored. It shows [`CupboardEntryForm`](cupboard-entry-form.md) in a `RouteModal` "Annotate This Entry"; Cancel, Escape and a save go to `closeHref`. A lone choice is a plain link of the same name.
  - Its foot ends with **More** (`annotate-more.tsx`, `CUPBOARD_MENU_LABEL`), a quiet [`MenuButton`](menu-button.md) flipping above ("Where it opens") offering Make It Ours and Remove on the page menu's flags. Named More because "Edit" would name the dialog. Only when both are allowed; with one, it is a button of its own (Remove `.btn--destructive`, Make It Ours quiet); with neither, nothing. Full width in a stacked foot.
  - Each asks in the form's own confirmation card (`ConfirmQuestion`, same card, scrim and focus handling as Delete and Link to the Compendium; [`modal.md`](modal.md), "Asking over the form"), not a second dialog. Cancel returns the focus to More (or the lone button); Escape is the dialog's own and asks to discard unsaved changes. While it asks, More steps aside (`discardAsking`) and returns on Keep Editing ("Discarding while annotating"). With unsaved changes, Make It Ours adds a `warn` [`Notice`](notice.md) "Changes you have not saved are lost." (`UNSAVED_CHANGES_LOST`, `link-confirm.tsx`; 1.5rem above, 1.75rem below, `confirm-overlay__warning`), since the copy takes saved annotations only; this is the one place Make It Ours runs with a form open. Either write drops unsaved annotations. Remove goes to `removedHref` or else `closeHref`, replacing the history entry; a refusal shows in the form's alert.
- **Make It Ours**: a modal "Make It Ours" naming the entry by its label (Make It Ours, Cancel), then `convertCompendiumEntryToLocal`, both answers disabled and busy while it runs. Success goes to the new own entry `/coven/<covenSlug>/ingredients/<id>`; a refusal closes the modal and shows the sentence in the failure callout.
- **Remove**, destructive colour, filled on hover: a modal "Remove from Cupboard" (Remove, Cancel), then `removeCupboardEntry`. A jar still held refuses; the modal closes and the sentence shows in the callout.

### Discarding while annotating

Confirmations ask in a modal over the page, as Leave Coven does. When cancelled or refused, or the address drops `?annotate`, Modal returns the focus through `returnTo` naming the menu's button (the pressed item is gone with the menu). A successful Remove keeps its confirmation open and busy until the page is read again; `returnTo` then names nowhere (the plus stands in the menu's place) and Modal focuses the page heading. The Annotate and Edit dialogs share one press skeleton, each drawn only for its own head (`annotate-heading.ts`). `removedHref` (set by the route to the coven's Ingredients list, for a retired entry only, whose page is a 404 for the coven once its row is gone) navigates there, replacing history; the confirmation stays busy until the list arrives so focus lands on the list's heading (closed earlier it would focus Edit just before the swap removed it). Every other write calls `router.refresh()`. Make It Ours and Remove, their documents, confirmations and aftermath, are `useCupboardWrites` (`cupboard-writes.tsx`), shared by the page menu and the dialog's More so they cannot drift. An observer sees none.

### What the cupboard actions draw

Up to two icons and the plus, as a list card's foot has them, at the right end of the formal name's line, centred on its first line when it wraps. All come from [`icon-tip.md`](icon-tip.md), each named "<verb> <entry name>" in hidden text, its verb as the tip:

1. **The main icon**, never in the menu, for a role that may write on that page. On a coven's page: **Annotate** (`AnnotateLink`, to `?annotate`; a button asking which coven on the public page) for a held compendium entry, **Edit** for the coven's own. On the compendium's pages (public, admin): **Edit in Compendium** (`CompendiumEditLink`) for a keeper or curator, so it is not taken for a coven's edit; list cards and their Quick Look say plain Edit. Annotate is never main there. Someone who may write nowhere (signed out, observer, practitioner who is no curator) has none. A curator in a coven that holds the entry but may not annotate gets Edit as main, so a menu never holds one choice.
2. **More** (`MoreMenu`, **More for <entry name>**), only when further actions exist: Edit Stock, Make It Ours, Remove, and whichever of Annotate and Edit in Compendium is not main. It always draws labelled sections (`choicesFor`, [`menu-button.md`](menu-button.md), "Sections"): a member sees **Coven**; a curator who is a member sees **Compendium** and **Coven**, the viewer's side first, chosen by the page (`viewing`), never from the address; an empty side is omitted. No bin: every role that may remove may make it ours.

In the markup the icons stay the header's action after the `h1`. The style finds them with `:has()` (`ingredient-entry__cupboard--pencil`, `--icons`, `data-icons` for the count) and places them against `.ingredient-entry__naming` at its end edge; the formal name keeps their width plus a gap free so it wraps short of them. The formal-name line is always drawn, so the icons always have it. A lone Make It Ours stays in the flow. The menu hangs from the button's end edge.

**One failure callout.** Make It Ours and Remove share one [`ClickFeedback`](click-feedback.md) in `CupboardActions`: a floating `role="alert"` box under the focus-keeping button (More), with its badge ("Show the error for Remove <entry name>") and Dismiss. `useCupboardWrites` hands a refusal over via `onRefused`; other callers (the dialog's More, the list card's More) pass their own. Opening a question clears the last failure. It floats so the title's row keeps its height. Success navigates or re-reads, and the heading takes the focus, so says nothing in words.

## On the public page

The public page offers the same cupboard choices through the same `CupboardActions`, passed as `covens` (`PublicCupboardProps`: `{ covens, defaultWorkspaceId, annotate: { closeHref, opened? } }`) instead of `cupboard`. One `CupboardPlace` per coven the viewer may write in, in the switcher's order: whether it holds the entry, the four `rolePermits` flags, and `annotateHref` (`?annotate=<covenSlug>`). `covens` changes none of the page's marks (the public page is the compendium's). It is built per request in `src/app/(public)/compendium/ingredients/[slug]/cupboard.ts` from `covensHoldingEntry` (once, for the shelf too) and `covenRolesIfSignedIn` (the shell's cached memberships read), never from the cached sessionless entry read (CLAUDE.md rule 6). A visitor, someone who may write in no coven, and an observer get none. `cupboard` is never passed, so no Compendium status.

- **The plus** (`AddIcon`, `src/components/AddIcon/`; [`compendium-cards.md`](compendium-cards.md), "The menu") stands just left of the pencil, on the public page and on a coven's page of a compendium entry, while any coven the viewer may add in (`ingredient:create`, not only this page's) lacks the entry. Held covens come from the page's one read: `plusCovensOf(await covensHolding(id), currentWorkspaceId?)` (`src/app/plus-covens.ts`) builds `CupboardPlus` (`{ workspaceId, covens, heldIn }`), per request, uncached, filtered in SQL. The public page derives the shape from `covens` (`plusOfPlaces`); a coven's page passes `cupboard.plus`, for a live compendium entry only (not its own, not retired). One coven: adds there at once; several: a menu by name, a holding coven (this one included) disabled with a green check, named "<coven>, in its cupboard". It animates, announces "Added to <coven>." and a refusal is its own callout. Once every such coven holds it, the card's `HeldMark` (`src/components/CompendiumCards/held-mark.tsx`, In Every Cupboard) takes the plus's place. An observer everywhere and a curator in no coven get neither. Plus and pencil share `.ingredient-entry__cupboard--pencil` with `--pair`. The Quick Look carries the same plus and check, both drawn by `PlusMark` (`plus-mark.tsx`).
- **Edit Stock** is the menu's first choice, on the public page and a coven's page, for a holding coven where the viewer may update stock. Pages that are not a coven's read forms and jars through `readEntryStock` (`src/app/entry-stock.ts`), per viewer outside the cached read, carried as `stock` per place via `stockDialogOf`. One such coven opens the dialog at once; several ask which, in the Coven dropdown. A coven's page of a held compendium entry passes `cupboard.stock` from the Stock section's read. A retired held entry offers it too: stock is per coven, and `readEntryStock` reads a compendium entry's forms per coven with `heldFormsOf` through that coven's proof, so only the coven whose cupboard names it reads it. The item is words only.
- **Other choices** show while any writable coven holds the entry, each where at least one grants the permission. One grantor: acts there directly. Several: Make It Ours and Remove ask which in a Coven dropdown (`coven-choice.tsx`, `SelectField`) listing only grantors, starting on the default where possible; Annotate asks in a picker dialog (`annotate-picker.tsx`: Coven, Continue, Cancel), then opens that `?annotate` address.
- **`?annotate=<covenSlug>`** opens that coven's dialog only when the slug names a coven of the viewer's that holds the entry and lets them annotate; only then is `getCupboardEntry` read. Any other slug is ignored and reads nothing.
- After a Remove the viewer stays on the public page, re-read. Make It Ours leads to the new own entry. Each write is reset (`CupboardWrite.reset`) as its confirmation opens, so a second Remove in another coven is not left busy.

Facts the component rests on: `viewing` orders More's sections and decides the main icon, from page shape, never an address. The Annotate dialog is the address's (`opened`) as the curator's Edit is; other questions are one at a time. The focus-return controls (annotate icon, three dots) are read as the dialog closes, after the render's layout, so refs are the commit's own; once a Remove took the entry they name nowhere.

## The replaced-by block

A coven's own entry lists the compendium entries it replaces; a compendium entry in a coven lists itself once. One `h3` block (not in the jump menu), one [`InfoTip`](info-tip.md) ⓘ after the heading for all links ("About In the Compendium"), each link the entry's own title. At most three, then a **See All N** paragraph (not a list item) to the compendium search; Similar draws the same markup. The list is described by the tip's text (`aria-describedby`).

- The heading is running text with a word joiner before the ⓘ, so a wrapped heading keeps the ⓘ on its last line. The ⓘ takes the heading's face and size and sits half a glyph less half a cap below the baseline, centring it on the capitals (within 0.13px at 1280 and 390; `vertical-align: middle` left it 5px low).
- Each link has the chain icon (`LinkIconHint`, becoming the loading ring while pending, so no dot) and the `icon-link` look: flex, title wrapping and hyphenating, icon at the right end in one column, level with the first line.
- Past `$shell-tablet-width` the block shrinks to its heading (`contain: inline-size`) so the chain icons end where the heading's ⓘ ends, each level with its title's first line, held in by the ⓘ's target inset; a heading that wraps fills the column and ends its icons at the edge (aligning would need JavaScript measurement). Stacked, each icon ends its title's last line with the hint's spacing.
- **See All N** is smaller, underlined in body ink, darker on hover, no icon, flush left, `space(3)` below the last option (options `space(3)` apart in both blocks). Heading to first entry is `$replaces-gap` (`space(5)`). The hairline under the block stands below its last line, midway in the gap to Correspondences.

## The back link

`BackLink` (`back-link.tsx`, client, so `IngredientEntry` stays a server component) writes "Back to" and `label`. The server draws the bare list (`/compendium`). **It returns to the list the entry was opened from.** In the browser it reads the previous page through the Navigation API (`navigation.entries()`); when that page is on this origin at `href`'s path or one of `back.also` (public entry page: `/curator/compendium`, **Curator Compendium**; the spell recipe page: the grimoire's Drafts tab), the link takes its path and query (`listReturnHref`, `back-href.ts`), keeping search, filters and page, and the label follows the path. A plain left press goes `router.back()` so the list is restored; a new-tab press follows the address. Anything else keeps the bare list (entry opened directly, from another page or coven's list, or a crafted address); the list's address never travels in the entry's own (no `?from=`). The Navigation API is past the browser floor, so it is an enhancement behind an `in` check. Proved by `tests/e2e/back-link.spec.ts` and `tests/components/IngredientEntry/back-href.test.ts`.

The link is quiet (small, muted, left chevron, no underline, ink deepens on hover and focus), keeps its own width, and is lifted to the head's top by `top`. The chevron steps back `-20%` of its own 1em box. It carries its own styles (`.back-link`), so the spell recipe page's Back to Grimoire is the same. `BackChevron` is exported alone: the sign-in card's Back button draws it one type step smaller (`caption`; [`sign-in-panel.md`](sign-in-panel.md), "Two views").

## Props in detail

Rules not in `types.ts`:

- **`edit.savedHref`**: a coven's address names the id, so a rename keeps it and a save stays; omitted, a save moves to the public address of the saved slug (rename changes it), `?edit` kept. **`edit.opened`**: the form renders only when asked with `?edit`; absent, the provider shows a skeleton until it arrives. **`edit.coven.stock`**: given only where the role may update stock. **`edit.coven.mayPromote`**: the role's answer to making a folk name the display name; near matches open in the coven.
- **`back.also`**: other paths that are the same list, each with a label.
- **`replaces`**: `tip` is chosen by the page so the component does not branch on tier (own entry: the compendium holds an entry with the same formal name, kept separate, to compare; compendium entry: the link opens its public page, or, once annotated, the original). `entries` are the first three by name, each "Name (Formal Name)" when it differs (`pageTitleOf`), with its public page; `total` how many share the identity; `allHref` is the compendium search for the entry's label via `COMPENDIUM_PARAMS.href('/compendium', { query })`, omitted where nothing matches. The coven route fills it from `compendiumMatchesOf`; omitted for a local with no match. A compendium entry seen from a coven passes itself, `total` 1, no `allHref`.
- **`similar`**: for a coven's own entry with no formal name: entries whose name matches the own entry's, case aside. Display only (linking goes one way in v1, DESIGN.md §13), the same for every role.
- **`cupboard.plus`**: viewer's covens that may add and which hold the entry; omitted (own entry, retired, no coven that may add), neither plus nor check is drawn. `CupboardPlus` is shared with the details modal. **`covens`**, **`heldInCovens`** (any role; false for a visitor) and **`stock`** (omitted public, and for an unheld compendium entry) as above.
- **`IngredientDetailsOpened`**: `editAction` is for a keeper or curator on the admin list, or a steward or practitioner on a coven's list for the coven's own entry (not a held compendium entry); `inCompendium` names it Edit in Compendium. `more` and `actions` mirror the card the window opened from. `plus` as above; omitted for an own entry, a retired one, an observer in no adding coven, a visitor. **`DetailsMarks`**: the safety badge goes on the top line, the rest under the formal name, so `provenance` and `safety` are the dialog's to set. **`ReviewMarkProps`**: the badge saying an entry needs review is the entry's own mark (`EntryMarks`), drawn for everyone.
