# IngredientEntry

`src/components/IngredientEntry/` — the body of an ingredient's page, the same on the public compendium route and a coven's (M8.19): the entry's own fields, then one section for each form it comes in.

Two routes render it: `/compendium/ingredients/[slug]`, which anyone can read, signed out included, and `/coven/[slug]/ingredients/[id]`, which a coven's members read. Each route reads an `IngredientDetail` (`src/modules/ingredients/types.ts`) through `ingredientDetailOf` and hands it over; the component reads nothing itself. It is a server component: no hook and no `'use client'`, so either page renders it directly. `PageNav` inside it is a client component, which a server component may render, and so are Edit's two parts when `edit` is given: `edit-pencil.tsx` and `entry-dialog.tsx` ("Edit", below).

The route gives the page's `<main>`. The component's root is an `<article class="ingredient-entry">`, laid out by its own stylesheet ("Layout", below) rather than by `.page-with-nav`, whose content column is the narrow one.

## Structure

In page order, with the accessible names a test or a story walk finds them by:

1. **The head**, a `<header>` inside the article:
   - `back`, when given: a quiet link at the top left, a left chevron and **Back to Compendium** on the public page or **Back to Ingredients** on a coven's (the owner's call, 2026-10-19). Muted and small, darkening on hover and focus, with a `LinkHint`. Left out, no link shows. **It returns to the list the entry was opened from** (MB.271): `BackLink` (`back-link.tsx`, a client part, so `IngredientEntry` stays a server component) is drawn by the server as the bare list. Once the page is in the browser, it reads the page before this one in the tab's history through the Navigation API (`navigation.entries()`). When that page is on this origin and at exactly `href`'s path, the link takes its path and query (`listReturnHref`, `back-href.ts`), so a searched, filtered or paged list keeps its search, filters and page. A plain left press on such a link goes back through history (`router.back()`), where the list is restored rather than loaded afresh; a press for a new tab or window follows the address. Anything else keeps the bare list: an entry opened directly, from another page, from another coven's list, or from a crafted address, since the list's address never travels in the entry's own (no `?from=`). The Navigation API is past the browser floor (Baseline newly available, 2026-01), so it is an enhancement behind an `in` check: a browser without it gets the bare list. Proved by `tests/e2e/back-link.spec.ts` and `tests/components/IngredientEntry/back-href.test.ts`. The link draws its own chevron and carries its own styles (`back-link.scss`, the `.back-link` class), so the spell recipe page's Back to Grimoire is the same link (M13.21; the owner, 2026-10-29), with `also` naming the grimoire's Drafts tab as the same list. The same row (`.back-bar ingredient-entry__bar`, the shared `.back-bar` the spell recipe page also opens with) holds **New** or **Updated** (`RecencyMark`) at its right end, the top right of the text column, and the entry's one **safety badge** (`SafetyMark`: Toxic over Caution, [`safety-note.md`](safety-note.md)) just right of the recency mark, in reading order and on screen (the owner's calls, 2026-10-20). The two are one pair that ends flush with the pencil at the text column's right edge, the badge last and 8px from the mark, so a badge moves New or Updated left by its width and the gap; with no badge, the mark keeps the row's right end (the owner's call, 2026-10-20). Both stay in the row's flow, so nothing passes the column at any width. With no recency mark the badge takes the mark's place at the row's right end. With no way back and no recency mark the row is drawn for the badge alone, and with none of the three it is left out.
   - The formal name (below), an eyebrow over the heading.
   - `PageHeader`: the formal name and it share one wrapper, `.ingredient-entry__naming`, which the icons are placed against ("The icons", below). The `h1` is `entry.name`, and for an entry this coven's cupboard holds (its own, or a compendium entry it names), the **In Your Cupboard** shelf before it as the header's `lead` (below); `edit` alone puts the pencil, a link named **Edit <entry name>** (`EditPencil`), at the end of the formal name's line, where the icons stand everywhere else ("The icons"). From the tablet width up the head keeps to the text column (the section grid's first column), so the formal name ends where the description's text does.
   - `replaces`: an **In the Compendium** block of links, one ⓘ beside its heading saying why they are shown: for a coven's own entry, the compendium entries of the same formal name, and **See All** past three; for a compendium entry, the entry itself (see the `replaces` row in the props table).
   - The badges, all drawn by the shared `EntryMarks` (M8.14, [`entry-marks.md`](entry-marks.md)), green first and red last (the owner's call, 2026-10-20): **Local** for a coven's own entry, **Compendium** for every compendium entry on a coven's page, held or not (`inCoven`, from `cupboard` being given; never on the public page), **Annotated** in its place once the coven overrides a field (Annotated wins: the two never show together, the owner's call, 2026-10-20), and **Retired** when `detail.retired` (M12.24; "No Longer in the Compendium" until 2026-10-18): a compendium entry the curators retired, read because this coven's cupboard still names it. That last one is a button opening a tip ("No longer in the Compendium; your coven still has it."), found by role and name. The page gives a retired entry no `replaces` and no `edit`, since the compendium no longer holds it. The safety badge is not among them: it is on the back row (above), and this row's `EntryMarks` takes `safety={false}`, so the row is drawn only for Local, Compendium, Annotated or Retired.
   - `movedAway`: a quiet warning `Notice`, a `status`, holding a link named after the moved entry.
2. **The jump menu**: `PageNav`, a `navigation` named **On This Page**, with **Stock** (`#stock`) first where the page has a Stock section (below), then **Details** (`#details`), then the forms grouped under a **Forms** label: a nested `list` named **Forms**, one entry per form, labelled with the form capitalised (`#form-oil`). The Forms group is `apart`, so the same short line stands between Details and Forms as between the forms and References. The grouping is `PageNav`'s `group` ([`page-nav.md`](page-nav.md)), so the ingredient reads apart from its forms. Drawn only when there is a form: with none there is nowhere to jump.
3. **Details**: `<section id="details">`, a `region` named **Details** by its visible `h2`, then its text (`__text`). The side column (`__side`) is a plain `<div>` that stands after the Details section in the body, not inside it (MB.121, so it can stand beside Stock; the Details region does not contain it). It is not an `<aside>`: a `complementary` landmark per section would be eight on a page like the rose's, noise to a screen reader, and each block in it is already headed and labelled. In order:
   - The text: the description, or "No description recorded."
   - Then in the text, `SafetyNote` with the ingredient's own notes only, at `level={3}` (a `region` named **Caution**; nothing when there are none).
   - The side column: **Correspondences**, an `h3` over a `<dl>`: Elements and Colours (each value capitalised, as the form stores them in lower case), Celestial Bodies (`celestialBodies`), Zodiac Signs, Deities (in parentheses after a curated deity, its tradition when known and its other names, "Odin (Norse; also called Woden)", M14.23). Every row is always there; an empty one says "No elements recorded." in its own plural.
   - **Folk Names**, **Categories**, **Substitutes** and **References**: each an `h3` over a `<ul>` named by it, so `getByRole('list', { name: 'Folk Names' })` finds it. Categories are `.chip`s in their group's colours (`chipColors(group)`), the same markup as the category picker's. An empty list is replaced by a sentence in the same block, so the heading never stands over nothing. Every empty line on the page (an empty correspondence row, an empty list, no description, no sources, a form that adds nothing) and the details modal's **No details recorded.** share one style, `.ingredient-entry__empty` in `index.scss`: italics, faded below the body text so it reads as an absence and not a value (the owner's call, 2026-10-20). On the card and in the details modal it is `$text-placeholder`, 4.65:1 light and 6.71:1 dark. On the page, inside `.ingredient-entry`, it is `$text-muted` instead, 5.99:1 light and 9.67:1 dark, because the placeholder fell to 4.17:1 on the page's darker light-theme ground, under AA's 4.5:1. Both stay italic.
   - At the end of the text, `NoteMarks` (MB.155): the numbers of the notes for the ingredient's own references, below.
4. **Stock** (M12.29, `stock-section.tsx`), **the first section, above Details** (MB.121, the owner's call of 2026-10-23, so the page has a rule-headed section the eye meets first): `<section id="stock">`, a `region` named **Stock** by its `h2`, drawn only when the page passes `stock` (`EntryStock`: the coven's id, the forms and jars `StockDialog` takes, and `mayEdit`). The coven route passes it for the coven's own entry and for a compendium entry its cupboard holds, never for one it does not hold and never on the public page, so neither has the section. Its jars are this coven's alone, read by `covenJarsOf` in `src/app/coven-stock.ts`, which the Ingredients list's Quick Look reads through too; `stockDialogOf` there shapes them for the dialog on both pages.
   - **The shelf**: [`JarShelf`](jar-shelf.md), a row of small drawn jars, one per form of the entry, in the forms' order, and whether or not the coven holds a jar of it, except that the forms with no jar go after every form with one (the owner, 2026-10-21), each group keeping the forms' order; a jar holding 0 is still a jar and keeps its place. The Edit Stock dialog's own list of forms is not reordered. A held jar shows its level, the form and its quantity and unit, or **Unmeasured**, and, for a Low or Out jar, the jar drawn in amber or red with its amount as a button opening the Low Stock or Out of Stock tip, as M9.8 sets it ([`jar-shelf.md`](jar-shelf.md)); a form with no jar draws a dashed empty jar reading **No Jar**. The page gives it the entry's formal name (`entry.canonicalName`, or the entry's id with none), which with the form picks each vessel. A jar whose form is no longer among the entry's forms is not drawn. An entry with no form at all says "No stock recorded." in the shared empty style. This replaced the list's own `JarLines` ([`jar-lines.md`](jar-lines.md), which the cards still use).
   - **No box** (MB.121): the heading, its Edit Stock button and the shelf are one stack (`.ingredient-entry__stock-panel`, a `div` inside the section) with no ground of their own, like every other section of the page. M12.29 tried a `.panel` box here; MB.121 removed it, because no other section is boxed and the jars' shine, drawn in the card colour, faded on a card-coloured panel ([`design-decisions/mb.121-workspace-ingredients-review.md`](../design-decisions/mb.121-workspace-ingredients-review.md)).
   - **Edit Stock**: for a role that permits `inventory: ['update']` (`mayEdit`), the heading's row ends with [`StockDialog`](stock-dialog.md)'s jar button, named **Edit Stock, <entry name>**, in the same icon wrapper (`.ingredient-entry__cupboard--icons`) and `.icon-tip__edit` size as the head's pencil, so the page's icons stay one size. It opens the dialog over the page, and a save re-reads the page, so the shelf shows the change. It is offered with no jar too, so a member can record the first. For the same role each jar on the shelf is a button too, named **Edit Stock, <entry name>, <Form>**, that opens the same dialog on that form (`openOn`, [`stock-dialog.md`](stock-dialog.md)); an empty jar's adds the form to the dialog first, so it is how a form's first jar is recorded from the shelf. A viewer sees the shelf and no button. There is no separate Add Stock here.
5. **The forms**: one wrapper `<section id="forms">`, a `region` named **Forms** by its `h2`, left out with no form, holding one `<section id="form-<slug>">` per form, in the order given. Each is a `region` named by the form's capitalised name alone, and its `h3` reads the `FormIcon`, the name, then `ToxicMark` for that form; its blocks are `h4`s and its caution sits at level 4. The body is only what the form adds, split the way Details is: its description and its own `SafetyNote` in the text, the correspondence rows it carries (non-empty ones only), its categories and its substitutes in the side column, which is left out when the form carries none of them. Its own references are not drawn here: the numbers of their notes end its text (`NoteMarks`). A form that adds nothing still gets its section, with one line in its text saying so, so its anchor and jump link always exist.
6. **References** (MB.155, `references.tsx`): `<section id="references">`, a `region` named **References** by its `h2`, the last thing the component renders and always drawn. Notes and the bibliography are built once by `referenceNotes` from the detail, which arrives already sorted: the ingredient's references are numbered first, then each form's in form order, one note per link (a source cited in two sections, or twice in one, is two notes, and a locator belongs to its note).
   - **Note numbers**: at the end of the text of Details and of each form that has references of its own, a `role="group"` named **References** (by a small `.eyebrow` label that is not a heading, so the page keeps its one References heading), holding superscript links `Note N`, each `#N`, separated by spacing only, to `#note-N`. The links carry `id="note-ref-N"`.
   - **Notes**: an `h3` over an `<ol>`. Each `<li id="note-N">` is the short citation from `renderShortCitation` (`<cite>` on italic parts), linked to its bibliography entry, then its locator, then a backlink named "Back to Details" or "Back to <Form>".
   - **Bibliography**: an `h3` over a `<ul>`. Each `<li id="ref-<referenceId>">` is a source once, alphabetically by `byCitation`, in `renderCitation`'s full form (`<cite>` on italic parts), an **Open the Source** link (`rel="noopener"`, with a visually hidden " (opens in a new tab)" so a screen reader hears that it leaves the tab) when it has a `url`, and a backlink "Back to Note N" for each note that cites it.
   - With no references anywhere it says "No sources recorded." and draws neither list.
   - Every link in the section, and the note numbers above rest in `$text-primary` and fade to `$accent-hover` on hover and `:focus-visible` (the owner's call; `$accent` is 3.96:1 on the `:target` highlight, `$accent-hover` above 6:1), with a faded underline, a `color-mix` of the link's own colour at 55% at rest and 65% on hover and focus, the lowest mixes that keep the underline, the only link cue once the colour matches the body ink, at 3:1 (WCAG 1.4.11) against the page and the `:target` highlight in both themes; one shared rule in `index.scss`, its underline the `faded-underline` mixin (`_mixins.scss`), which also holds the argument for the mixes.
   - The jump menu's **References** is `apart` (see [`page-nav.md`](page-nav.md)). With notes it is a group labelled **References**, a nested `list` named by it, holding **Notes** (`#notes`) and **Bibliography** (`#bibliography`), the ids of the two blocks (bare words, so no `note-N`, `ref-<id>` or `form-<slug>` id can equal them). With no sources there is nothing to list, so it stays one link to `#references`.

Inside a form, the lists are named by the form's name and then the heading — "Oil Categories", "Oil Substitutes", "Oil Correspondences" — so the ingredient's own **Categories** and **Substitutes** stay the only lists with exactly those names. Playwright's `name` matches a substring unless `exact: true` is passed, so a walk looking for the ingredient's own list passes `exact: true` or looks inside the **Details** region.

## Contracts

- **The formal name is never blank** (MB.161). It is `FormalName` (`formal-name.tsx`, styled by `formal-name.scss`), drawn by this page and by the details modal's head alike. It is a one-pair `<dl>`: the term says the nomenclature in words, hidden from sight (`visually-hidden`) so a screen reader hears it first, and the definition holds the name as an `.eyebrow` over the heading, with an `InfoTip` beside it (id `formal-name-tip`, its button named "About <term>") saying which naming system the name belongs to, in the words of DESIGN.md §5's nomenclature table (the owner's call: the name alone is seen, and the tip says what it is). The tip opens beside the ⓘ, level with its middle, where there is room (past `$shell-tablet-width`), and below it on a phone, where the shell's sticky bar would cover a tip above. The page asks for the side with `--tip-placement` and `useTip` places it, 4px from the ⓘ like every other tip; the page's own CSS once also moved the bubble, which left it 18px above the ⓘ at 1280 and touching it at 390. `tests/e2e/tip-placement.spec.ts` opens it on both pages of an entry at a 390px phone and checks it stays inside the screen; the gap itself is not tested, being presentation (claude-docs/testing/layer-ownership.md, rule 4: the owner's call, 2026-10-20).

  | Nomenclature                        | Term                                 | Definition                                    |
  | ----------------------------------- | ------------------------------------ | --------------------------------------------- |
  | `botanical`, `fungal`, `zoological` | Botanical / Fungal / Zoological Name | The name in `<i class="binomial">`            |
  | `mineral`, `chemical`               | Mineral / Chemical Name              | The name, upright                             |
  | `unknown` with a name               | Formal Name                          | The name, upright, then "(unconfirmed)" muted |
  | `unknown` with none                 | Formal Name                          | "Not yet looked up", muted                    |
  | `none`                              | Formal Name                          | "None", muted; the tip says why               |

  A `<dl>` rather than a labelled `<p>`: a screen reader announces the label as the term and the name as its value, the same way it reads the Correspondences list beneath, rather than running label and name together as one sentence. Italics only for a binomial, since they follow a settled classification: the kinds are `BINOMIAL_KINDS` in `src/modules/ingredients/schema/ingredient-enums.ts`, shared with the compendium list's edit-dialog heading. `<i>` rather than `<em>`, because a taxonomic name is set apart, not stressed.

- **A form's anchor is `form-` and the form's name through `slugify`** (DESIGN.md §9), so `#form-oil` opens on the oil. Two forms are unique by their trimmed, lower-cased names, which can still slug alike ("oil" and "oil."); the second then takes `-2`.
- **The ids are built from the data, not `useId`**: `details-heading`, `details-folk-names`, `form-oil-name`, `form-oil-categories`, and so on. A page holds one entry, so they cannot collide, and a server component has no hook.
- **A substitute links only to a page the caller names.** One with an ingredient is a `Link` to `hrefOf(ingredient)`; a typed name, a link whose ingredient was deleted (its last name kept, MB.138), and one `hrefOf` answers `undefined` for are plain text. A substitute that names a form reads "Name (form)".
- **Every link to another page names the page it draws** (`PendingLink` with `navigationTarget: ingredientLinkTarget(href)`, [`loading.md`](../loading.md)): a compendium entry or a coven's own entry is a page with its jump menu, the Compendium list the cards under a filter. The same for the navigation after Make It Ours. The skeleton always draws the jump menu, where this page draws it only when the entry has forms.
- **Every link to another page shows a click took** while the server answers: a text link (the substitutes, the moved-away link) with a `LinkHint` dot, a link with the chain icon (the Similar and In the Compendium links) by the icon turning into the loading ring (`LinkIconHint`). The jump menu and the Edit button do not: the first stays on the page, the second opens a modal with its own skeleton. There is no `loading.tsx` and no Suspense boundary on purpose: one would turn the public route's 404 and 308 into 200s and break rendering without script (Next's `loading` file docs, "Status codes"). See [`link-hint.md`](link-hint.md).
- **Safety is drawn by `SafetyNote` and `ToxicMark` only** (M8.13a). The ingredient's note sits in Details; each form's sits in its own section, given that form's notes as `safetyNotes`, since the section's heading already names the form.
- **The notes slot.** The References section is the article's last child, and v2's notes section is appended after it, so adding it moves nothing above.
- **Meaning never by colour alone.** Local, Toxic and Retired carry their words; a category chip carries its name, its colour repeating its group (the full chip level, 2026-10-19).

## Edit

A curator's Edit opens the compendium's edit modal over the entry's own page, not the admin list's (M8.19).

Its dialog is headed **Edit Compendium Entry**, not the admin list's "Edit Ingredient", and the coven menu names the choice the same way: it changes the entry for every coven, while Annotate changes only this coven's version (the owner's call, 2026-10-19).

- `edit.href` is the page's own address with a bare `?edit`; `closeHref` is the address without it. The page reads `searchParams` and, for a curator who has `?edit` (and only then), reads the form's values with `entryValues` (`src/app/entry-values.ts`, server-only) and passes them as `opened`. A visitor, a reader who cannot curate, or a page without `?edit` costs no such read.
- `IngredientEntry` wraps its output in `RouteModalProvider` when `edit` is given, so a press opens the dialog at once over a skeleton while the page loads ([`modal.md`](modal.md), "Opening at once"). `EditPencil` (`edit-pencil.tsx`) is IconTip's `EditLink`, the pencil link with `useOpenModalClick`, in the placed `.ingredient-entry__cupboard--pencil` container; `EntryDialog` is the `RouteModal` and, once `opened` is present, `IngredientForm` in it. Only the entry's id, names and nomenclature cross to those two client parts.
- A save keeps the modal open, as the admin list's does: the page replaces its address (the public route follows a renamed slug; the coven route, which names the id, passes `savedHref`) and refreshes. The dialog has no Cancel button (the owner's call, 2026-10-30): Close, Escape and a click outside close to `closeHref`, saving anything unsaved first. The admin compendium's dialog keeps its Cancel. A delete replaces to `deletedHref` rather than going back to a page that is now gone (the compendium's list, from either route).
- The coven route offers it to a curator for a compendium entry, and to a member whose role may update ingredients for the coven's own entry (M8.17).

**A coven's own entry (M8.17).** `edit.coven` (`{ workspaceId, ingredientsHref, mayPromote }`) turns the same dialog into the coven's edit. Its eyebrow is **Edit Ingredient** (`editEyebrow`, `edit-heading.ts`), since it changes this coven's entry alone. The form is `IngredientForm` with the coven's id, which saves the entry over itself; a near match opens in the coven. Its foot is the form's own: Save Ingredient, Cancel and Delete Ingredient, which asks the form's own confirmation and sends `deleteIngredient(id, workspaceId)` ([`ingredient-form.md`](ingredient-form.md), "The props contract"). A save closes the dialog, back on the page fetched again. A delete replaces the address with `deletedHref`, the coven's Ingredients list, and refreshes, since the entry's page is gone. The page reads the values as the member, with `entryValues`, only for a role that may update and only with `?edit`; a viewer gets no Edit and no read.

- **A coven's own entry's actions.** On the page of a coven's own entry, the actions are two icons (`own-actions.tsx`, `OwnEntryActions`): the pencil, IconTip's `EditLink`, named **Edit <entry name>**, a link to the page's `?edit` opened at once by `useOpenModalClick`; and the three dots, **More for <entry name>**, holding **Edit Stock** first, where the page hands the entry its coven's stock (`edit.coven.stock`, for a role that may update stock; M9.12), and **Delete Ingredient** after it, in the one Coven section. Edit Stock opens this coven's dialog at once, with no coven to choose. There is no bin: every role that may delete may also update stock, so the dots never hold Delete alone, and a page always draws them (the owner's call, MB.123 D37). They stand at the right end of the formal name's line, above the name ("The icons" below). Delete asks in place, in `DeleteDialog` (`delete-entry.tsx`, with `useDeleteEntry` and the `DeleteOwnIngredient` mutation), rather than at an address of its own: a confirmation has nothing to share as an address (option A, the owner's call, 2026-10-20). A delete replaces the address with the coven's Ingredients list (`edit.deletedHref`), and the list's heading takes the focus; a refusal shows in a [`ClickFeedback`](click-feedback.md) callout under the three dots, which floats rather than taking room in the head (M12.31, design F), and gives the dots the focus back. An Edit cancelled gives the focus back to the pencil ([`modal.md`](modal.md), "Giving the focus back").
- **The coven's Ingredients list** draws the same dialog over its cards, under `?edit=<id>` ([`coven-cards.md`](coven-cards.md)).

## Styling

When a long name wraps the header's action onto its own line, `space(4)` stands between the action and the badges (the owner's call, 2026-10-19): the action's bottom margin, with `top` and the header's row gap taking half of it back so the action stays where it was; beside the heading it adds nothing.

`index.scss` and `summary.scss` take tokens only (MB.120): spacing (`space()`, the `stack` and `list-reset` mixins), the shell's breakpoints and offsets, `$measure`, the colour tokens, `$icon-size` and `$glyph-size`, `$inline-mark-size` for the held shelf, `$nav-link-size` for the jump menu's top-level links, and the optical corrections `$optical-nudge`, `$back-chevron-pull`, `$link-hint-drop` and `$cap-middle` (each explained in `_variables.scss`), with and the `.badges`, `.badge--*`, `.chip`, `.binomial` and `.btn` classes. The back link's chevron steps back `-20%`, a fifth of its own 1em box, so the step needs no token. The Show More bar's focus ring is `focus-ring($placement: inset)`, drawn inside the bar where it was the outside ring pulled in by hand. A bibliography entry breaks anywhere (`overflow-wrap: anywhere`), because a citation prints its url as plain text, Chicago's form, and a long url with no hyphen ran past a phone's column; `break-word` would still let the url set the list's narrowest width. The section's look is MB.120's design review ([`styling.md`](../styling.md), "Designing a section"). The `local` and `retired` badge palettes are new here (`retired` takes `low-stock`'s muted inks until the design review), in `_variables.scss` (`styling.md`, "Badge palettes").

**The correspondence rows.** Each row is a `<div>` holding its term and its value, so the list stacks the rows `space(4)` apart and each row stacks its term `space(1)` over its value, on the page and in the details modal alike. Until M12.5 the rules were written for bare `dt` and `dd` siblings, never reached the wrapped rows, and left each label flush on its value.

Running text stops at `$measure`: the description is a `<p>`, which `typography-base` caps, and a `dd` or list item takes `max-width: $measure` itself. A description keeps the line breaks typed into its textarea (`white-space: pre-line`).

### Layout

The owner's, from seeing the page in a browser at M8.19: the entry is read rather than filled in, so it takes the frame's wide column (`$wide-column`, which `.page-column` and `.coven-layout` allow), and lays its lists beside its text.

- **The head.** From above `$shell-tablet-width` it takes the section grid's columns and keeps to the first, so Edit at the end of the heading's line ends where the text column does.
- **The article.** A column of its parts, `space(6)` apart. With a jump menu (`.ingredient-entry--with-nav`, set when there is a form), from above `$shell-phone-width` it is a grid: the menu in a sticky column on the left, the head, Stock, Details and the forms on the right taking the rest. The breakpoint and the sticky `top` are `.page-with-nav`'s, so the two layouts' menus agree. The menu's column is `minmax(min-content, min(space(8) * 3, 100% - space(8) * 15))`: that layout's 12rem while the article is 1152px or wider; below that the content keeps 60rem (the 20rem side column, its 2rem gutter and 38rem for the text) and the menu takes what is left, so on a smaller desktop the menu gives way first rather than holding its width while the text alone narrows (the owner's call); it never goes narrower than its longest label, which it reaches at about 1050px. Measured at 1440, 1150, 1100 and 1000px wide: 192, 158, 108 and 100px; the menu spans the entry's body (`.ingredient-entry__body`, which holds Details, Stock, the forms and References as one grid item), so it sticks for the page's length. The menu's top-level links stand on a stated line (`$nav-link-size`, 1.125rem, at 1.25) and the menu is dropped by half the difference between the Details h2's line and that link's, so the menu's first link (**Stock**, or **Details** with no Stock section) is level with the first section's heading beside it (measured within a pixel at 1280 and 700px). At a phone's width the menu stands above Details.
- **Stock, then Details, with the side column beside them** (the owner's calls, 2026-10-21 and 2026-10-23). From above `$shell-tablet-width` the body (`entry-body` in `_mixins.scss`) is a CSS grid: a text column on the left and the side column (`space(8) * 5`, 20rem) on the right, `space(8)` apart.

The side column is column 2 and spans both rows, so it starts level with the first section, Stock if shown and Details if not. With no Stock, row 1 is empty and has no height. A long side column grows row 2 and never pushes Stock down. Everything else (the forms, References) spans both columns below.
  - **A small drop.** The side column has `margin-block-start: space(1)` (0.25rem, the owner's value, 2026-10-23), and the skeleton's side part takes it through `entry-body`. Measured, the first section's h2 text bottom is 2.0px lower than the side's first heading's text bottom at 1280 and at 1024px, with Stock and without.
  - **The forms.** Each form is a grid: its heading across both columns, then its text on the left and its lists on the right, starting level with the text.
  - **References** come after the forms, full width.
- **The DOM.** The side column moved out of the Details `<section>` to stand right after it, so the grid can place it beside Stock. A screen reader reads Details' text, then the side blocks (each headed), then the forms; the Details region no longer contains the side blocks.
- **Below the tablet width**, on a phone and up to 768px, the page is one column: Stock, Details, the side column, then the forms, each `space(6)` apart. A form's own side column runs under its text, a `space(4)` step below it, as before.
- **Text width.** Stock and Details keep to the text column (`minmax(0, 1fr)`), so nothing in them runs under the side column; the forms are grids, and References runs full width below them.
- **A rule under every section heading** (MB.121, option A of the Stock review): `entry-heading-rule` (`_mixins.scss`) puts a `$hairline` rule under the h2 of Stock, Details, Forms and References. The rule is as wide as the heading's text plus `space(4)` (1rem), starting at the heading's left edge, and sits `space(1)` (0.25rem) under the text; it is never wider than its column, so a long heading wraps. Stock's rule follows the "Stock" h2 and not the head row, so Edit Stock stays put. The skeleton's heading bars have no rule, so the page adds a few pixels under each heading when it loads.
- **The loading skeleton** uses the same mixin, so the page does not jump when it loads: a Stock part first, then Details, then a side part beside them, then the forms as grids. The Stock part is a heading bar over three placeholder jars, each a block the drawing's size on the plank, with a bar for the name and one for the amount. - **Jumps** land clear of the top inset, and of the shell's sticky bar inside `.app-shell`, as `.page-frame__section` does.

## Cupboard entries (M12.16)

`detail.cupboardEntry` is the coven's row for a compendium entry it holds (null on the public page). The component tells three kinds apart and never reads `isGlobal`: a coven's own entry (`entry.workspaceId !== null`) is badged Local; a compendium entry with a cupboard entry (`cupboardEntry != null`) is not, and shows a **Compendium** status, or **Annotated** in its place when `isAnnotated(cupboardEntry)` (any of the seven overrides is set, an empty list counting as set); a compendium entry without one is drawn as before. ## The two routes

- **`/compendium/ingredients/[slug]`** (`src/app/(public)/`) reads `readCompendiumEntry(slug)`, which takes no session. An unknown slug and a coven entry's slug both answer 404 (`notFound()`); a slug the entry has moved off answers `permanentRedirect` to its current address, a 308. The page asks `viewerIfSignedIn()` to offer a curator Edit, which opens the edit modal on this same page (`?edit`, "Edit", below), and to offer a signed-in person their cupboard choices ("On the public page", above). A visitor with no session reads the same page, with neither. It draws no `<main>`, since the `(public)` layout does. A compendium ingredient it links is `/compendium/ingredients/<slug>`; a coven's own is not linked, as the public page would answer 404. Its title is the entry's name, then its formal name in brackets when it has one that differs (`pageTitleOf`, shared with the coven route); the description and canonical link are MB.84's.
- **`/coven/[slug]/ingredients/[id]`** (`src/app/(shell)/`) runs `requireCovenMembership(slug)`, then `requireSession()` (the shell layout skips the email check), then `getIngredient(session, id, workspace.id)`. A non-member, and an id the coven cannot see, answer 404. It draws its own `<main>`. For a compendium entry it passes `replaces` holding the entry itself (its public page's path, relative since the origin varies by deployment, under its own ⓘ sentence) and, for a curator, `edit` (the same modal, at the coven's own address); it also sets `alternates.canonical` in its metadata. The tab title uses the coven's label when its cupboard entry sets one (a `cache()`d `getCupboardEntry` the page and `generateMetadata` share, so one request reads it once; the page reads the detail without the coven and lays that entry in). A coven's own entry gets neither; it gets Edit, the coven's own edit, for a member whose role may update ingredients (M8.17). It links a compendium ingredient to the public page and the coven's own to `/coven/<slug>/ingredients/<id>`.
