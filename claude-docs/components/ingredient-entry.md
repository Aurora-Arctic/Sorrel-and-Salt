# IngredientEntry

`src/components/IngredientEntry/` is the body of an ingredient's page, the same on the public compendium route and a coven's: the entry's fields, then one section for each form it comes in. It is a server component (no hook, no `'use client'`), so ids come from the data (`details-heading`, `form-oil-name`), not `useId`. Each route reads an `IngredientDetail` through `ingredientDetailOf` and hands it over; props are `IngredientEntryProps` in `types.ts`. The client parts are `PageNav`, `BackLink`, `edit-pencil.tsx` and `entry-dialog.tsx`. The root is `<article class="ingredient-entry">` inside the route's `<main>`, laid out by its own stylesheet, not `.page-with-nav`.

## Structure

In page order.

1. **The head** (`<header>`): `accessPause` (AppShell's `PausedNotice`, first; [`app-shell.md`](app-shell.md), "The paused notice"); `back` with a `LinkHint`, omitted for no link, in a row (`.back-bar`) with **New** or **Updated** (`RecencyMark`) and the one safety badge (`SafetyMark`, [`safety-note.md`](safety-note.md)); `FormalName` as an eyebrow over the `h1` in `.ingredient-entry__naming`, which the icons are placed against; `replaces`; `EntryMarks` ([`entry-marks.md`](entry-marks.md)) with `safety={false}`; `movedAway`, a quiet warning `Notice` (a status, never an alert, since it is there from the start). For an entry this coven holds, **In Your Cupboard** is the header's `lead`, so the `h1` is the name alone. A retired entry gets no `replaces` and no `edit`. On the public page `hiddenFromPublic` shows a notice to a curator or keeper, and `reviewControl` is the head's last row.
   - Marks: **Local** for a coven's own entry; **Compendium** for every compendium entry on a coven's page, held or not (never public); **Annotated** in its place once an override is set; **Retired** when `detail.retired`.
2. **The jump menu** `PageNav` ([`page-nav.md`](page-nav.md)), drawn only when there is a form (the skeleton always draws it). References is `apart`: with notes, **Notes** (`#notes`) and **Bibliography** (`#bibliography`), bare ids so no `note-N`, `ref-<id>` or `form-<slug>` can equal them; without, one link to `#references`.
3. **Stock** (`stock-section.tsx`), above Details, only when the page passes `stock` (`EntryStock`): the coven's own entry and a compendium entry the cupboard holds; never public. Jars are this coven's alone, read by `covenJarsOf` (`src/app/coven-stock.ts`, shared with the Ingredients list's Quick Look).
   - [`JarShelf`](jar-shelf.md) draws one jar per form, forms with no jar after those with one; a jar whose form is gone is not drawn. Heading, button and shelf have no box, since the jars' shine is card-coloured and would fade on a card-coloured panel.
   - A role that permits `inventory: ['update']` gets [`StockDialog`](stock-dialog.md)'s button, offered with no jar too, and each jar opens it on its form (`openOn`; an empty jar adds the form first). An observer sees the shelf only.
4. **Details**: description, `SafetyNote` with the ingredient's own notes, the [`DisclaimerNotice`](document-page.md#disclaimer-notice) line, `NoteMarks`. The side column is a plain `<div>`, not an `<aside>`: a landmark per section would be eight on a page. It holds Correspondences, Folk Names, Categories and Substitutes; empty rows stay, as a sentence. Every empty line shares `.ingredient-entry__empty`: `$text-placeholder` on the card and modal (4.65:1 light, 6.71:1 dark), `$text-muted` on the page (5.99:1, 9.67:1), because the placeholder is 4.17:1 on the page's darker light ground.
5. **Forms**: `<section id="forms">`, omitted with no form, and `<section id="form-<slug>">` per form holding only what the form adds (it inherits the ingredient's other fields, DESIGN.md §5). A form adding nothing still gets its section and one line saying so, so the anchor and jump link always exist. Lists inside a form are named by form and heading ("Oil Categories"), so the ingredient's own **Categories** and **Substitutes** stay the only lists with exactly those names; a test for the ingredient's own passes `exact: true` or looks inside **Details**.
6. **References** (`references.tsx`): always drawn, the article's last child (v2's notes section is appended after it). `referenceNotes` builds notes and bibliography once: the ingredient's references first, then each form's in order, one note per link (a source cited twice is two notes; a locator belongs to its note). Note numbers end Details' and each form's text as a `role="group"` named **References** (an `.eyebrow` label, not a heading, to keep one References heading). The bibliography lists each source once, alphabetical by `byCitation`; a printed url breaks anywhere so it cannot set the list's width. A curator or keeper also gets the Sourcing Score panel ([`sourcing-score.md`](sourcing-score.md), "On the entry page").
   - Links rest in `$text-primary` and fade to `$accent-hover` (`$accent` is 3.96:1 on the `:target` highlight). Their cue is the `faded-underline` mixin (`_mixins.scss`), whose lowest mixes keep 3:1 against page and highlight in both themes.

## Contracts

- **FormalName** (`formal-name.tsx`) is a one-pair `<dl>`: the visually hidden term names the nomenclature (a screen reader hears label and value as the Correspondences list does); the definition is the name as an `.eyebrow` with an `InfoTip` saying which naming system. `none` with no name draws nothing, page and modal head alike. Italics only for a binomial (`BINOMIAL_KINDS`) as `<i class="binomial">`, not `<em>`: a taxonomic name is set apart, not stressed. The tip opens beside the ⓘ past `$shell-tablet-width`, below it on a phone (the sticky bar would cover one above), via `--tip-placement` and `useTip`; `tests/e2e/tip-placement.spec.ts` checks it stays inside 390px.
- **A form's anchor is `form-` plus `slugify`** (DESIGN.md §9); names unique by trimmed lower case can still slug alike ("oil", "oil."), and the clash takes `-2`.
- **A substitute links only to a page the caller names** (`hrefOf`); a typed name, a deleted ingredient's last name, or an `undefined` answer is plain text.
- **Every link to another page is a `PendingLink`**, so the destination's own skeleton, chosen by its address, draws while it loads ([`loading.md`](../loading.md)), including the navigation after Make It Ours, and shows a click took (`LinkHint`, `LinkIconHint` on chain icons). The jump menu and Edit do not ([`link-hint.md`](link-hint.md)). There is no `loading.tsx` or Suspense on purpose: it would turn the public route's 404 and 308 into 200s and break rendering without script.
- **Safety is drawn by `SafetyNote` and `ToxicMark` only**, each followed by the `DisclaimerNotice` line, drawn even with no notes. Meaning is never by colour alone: Local, Toxic and Retired carry words; a chip carries its name.

## The two routes

- **`/compendium/ingredients/[slug]`** (`src/app/(public)/`) reads `readCompendiumEntry(slug)` with no session. An unknown slug and a coven entry's slug answer 404; a moved slug `permanentRedirect`s (308). `viewerIfSignedIn()` offers a curator Edit and a signed-in person their cupboard choices; a visitor reads the same page with neither. It links a compendium ingredient as `/compendium/ingredients/<slug>`, never a coven's own (404 there).
- **`/coven/[slug]/ingredients/[id]`** (`src/app/(shell)/`) runs `requireCovenMembership(slug)`, `requireSession()`, then `getIngredient(session, id, workspace.id)`; a non-member and an id the coven cannot see answer 404. For a compendium entry it passes `replaces` (itself) and, for a curator, `edit`, and sets `alternates.canonical`; the tab title uses the coven's label if its cupboard entry sets one (`cache()`d `getCupboardEntry`, shared with `generateMetadata`). A coven's own entry gets the coven's Edit for a role that may update ingredients.

## Edit

A curator's Edit opens the compendium's edit modal over the entry's page, headed **Edit Compendium Entry** (it changes the entry for every coven; Annotate only this coven's).

- `edit.href` is the page's address with a bare `?edit`; `closeHref` drops it. For a curator with `?edit` only, the page reads the form's values with `entryValues` (`src/app/entry-values.ts`, server-only) as `opened`; absent, the provider shows a skeleton until they arrive. With `edit`, the output is wrapped in `RouteModalProvider` so a press opens the dialog at once ([`modal.md`](modal.md), "Opening at once"). Only the id, names and nomenclature cross to the client parts.
- A save keeps the modal open: the page replaces its address and refreshes (the public route follows a renamed slug; the coven route names the id and passes `savedHref`). No Cancel: Close, Escape and outside click close to `closeHref`, saving unsaved changes first. A delete replaces to `deletedHref` and is only inside the modal.
- The dialog is [`CompendiumEntryForm`](ingredient-form.md#compendium-entry-form), shared with the admin compendium's `compendium-dialog.tsx`; `edit.sourcing` carries the Sourcing Score for a curator or keeper.

**A coven's own entry.** `edit.coven` (`{ workspaceId, ingredientsHref, mayPromote }`) makes it the coven's edit, eyebrow **Edit Ingredient**: `IngredientForm` with its own delete confirmation (`deleteIngredient(id, workspaceId)`; [`ingredient-form.md`](ingredient-form.md), "The props contract"). A delete says "{name} deleted" in the status region, replaces to `deletedHref` and focuses the list's heading. Values are read as the member only for a role that may update and only with `?edit`. `edit.coven.stock` is given only where the role may update stock; `mayPromote` is the role's answer to making a folk name the display name. The coven's Ingredients list draws the same dialog under `?edit=<id>` ([`coven-cards.md`](coven-cards.md)).

**`OwnEntryActions`** (`own-actions.tsx`): the pencil and the three dots, holding **Edit Stock** (where `edit.coven.stock` is given) and **Delete Ingredient** in one Coven section; no bin, since every role that may delete may update stock. A refusal shows in a [`ClickFeedback`](click-feedback.md) callout under the dots. A cancelled Edit gives the focus back to the pencil ([`modal.md`](modal.md), "Giving the focus back").

## In Your Cupboard

`held-mark.tsx` draws a shelf of two bottles before the name of every entry this coven holds: "you hold this" (the card's check says In Every Cupboard, the modal's list is In Your Cupboards). It is a `button` carrying an `IconTip` (`opensOnPress`; the press does nothing else). Above `$shell-phone-width` beside a jump menu it hangs into the menu's column so the name stays level with the text; at and under it stands on its own line, 30% larger (the drawing grows, not a transform, so the tap target does).

On the public page it shows when any coven of the viewer's holds the entry (a view-only coven included): one `covensHoldingEntry` read (`covensHolding` in `src/app/plus-covens.ts`), passed as `heldInCovens`. Not for a visitor, nor for a compendium entry the coven does not hold.

## Cupboard entries

`detail.cupboardEntry` is the coven's row for a compendium entry it holds (null on the public page). Three kinds are told apart and `isGlobal` is never read: own (`entry.workspaceId !== null`, Local); compendium with a cupboard entry (**Compendium**, or **Annotated** when `isAnnotated`: any of seven overrides set, an empty list counting); compendium without one (drawn as the public page). `applyCupboardEntry` (`src/modules/ingredients/validation/cupboard-merge.ts`, pure) merges: heading, description, caution and the four correspondence rows read the merged row. The compendium's name is not repeated under the coven's label (In the Compendium links it). Forms, folk names, substitutes, categories, references and the toxic flag are the compendium's. Edit and In the Compendium read the unmerged row. Marks are `output` elements in the neutral `low-stock` tint: where the row lives is not a warning.

## Cupboard buttons

The optional `cupboard` prop (`{ workspaceId, covenSlug, canAdd, canAnnotate, canRemove, canMakeOurs, removedHref?, plus? }`) comes from the coven route for a compendium entry (and a retired one the coven holds), never from the public page, and is ignored for a coven's own entry. Flags come from `rolePermits` (`ingredient:create`, `update`, `delete`, `MAKE_IT_OURS_PERMISSION`, the set the service checks); the service is the guard. A retired entry has `canAdd` false, so its menu offers Annotate, Make It Ours and Remove, and no curator Edit ([`ingredients.md`, "A retired entry stays readable to the covens that use it"](../design-decisions/ingredients.md#a-retired-entry-stays-readable-to-the-covens-that-use-it)). An observer sees none.

- **Annotate** links to `?annotate` (`cupboard.annotate`: `href`, `closeHref`, `opened`), opened at once by `useOpenModalClick`. The page sets `opened` only for a member who may annotate in a coven that holds the entry; any other asking is ignored. It shows [`CupboardEntryForm`](cupboard-entry-form.md) in a `RouteModal`; Cancel, Escape and a save go to `closeHref`.
  - Its foot ends with **More** (`annotate-more.tsx`), a quiet [`MenuButton`](menu-button.md) offering Make It Ours and Remove on the page menu's flags; named More because "Edit" would name the dialog. With one allowed it is a button of its own; with neither, nothing.
  - Each asks in the form's own confirmation card (`ConfirmQuestion`; [`modal.md`](modal.md), "Asking over the form"), not a second dialog. Cancel returns the focus to More; Escape is the dialog's own and asks to discard unsaved changes, and while that asks More steps aside (`discardAsking`). With unsaved changes, Make It Ours adds a `warn` [`Notice`](notice.md) since the copy takes saved annotations only; either write drops unsaved annotations. Remove goes to `removedHref` or else `closeHref`, replacing the history entry; a refusal shows in the form's alert.
- **Make It Ours**: a modal naming the entry by its label, then `convertCompendiumEntryToLocal`. Success goes to the new own entry `/coven/<covenSlug>/ingredients/<id>`; a refusal closes the modal and shows the sentence in the failure callout.
- **Remove**, destructive: a modal, then `removeCupboardEntry`. A jar still held refuses.
- Make It Ours and Remove are `useCupboardWrites` (`cupboard-writes.tsx`), shared by the page menu and the dialog's More so they cannot drift.

### Discarding while annotating

When cancelled or refused, or the address drops `?annotate`, Modal returns the focus through `returnTo` naming the menu's button (the pressed item is gone with the menu). A successful Remove keeps its confirmation open and busy until the page is read again; `returnTo` then names nowhere (the plus stands in the menu's place) and Modal focuses the page heading. `removedHref` (the coven's Ingredients list, for a retired entry only, whose page is a 404 once its row is gone) replaces history, and the confirmation stays busy until the list arrives so focus lands on the list's heading. Every other write calls `router.refresh()`. The focus-return controls are read as the dialog closes, after the render's layout, so refs are the commit's own.

### What the cupboard actions draw

`cupboard-actions.tsx` draws up to two icons and the plus at the right end of the formal name's line, each from [`icon-tip.md`](icon-tip.md) and named "<verb> <entry name>" in hidden text.

1. **The main icon**, never in the menu, for a role that may write on that page. On a coven's page: **Annotate** (`AnnotateLink`; a button asking which coven on the public page) for a held compendium entry, **Edit** for the coven's own. On the compendium's pages: **Edit in Compendium** (`CompendiumEditLink`) for a keeper or curator, so it is not taken for a coven's edit. Annotate is never main there. A curator in a coven that holds the entry but may not annotate gets Edit as main, so a menu never holds one choice.
2. **More** (`MoreMenu`), only when further actions exist: Edit Stock, Make It Ours, Remove, and whichever of Annotate and Edit in Compendium is not main, in labelled sections (`choicesFor`, [`menu-button.md`](menu-button.md), "Sections"): a member sees **Coven**; a curator who is a member sees **Compendium** and **Coven**, the viewer's side first, chosen by the page (`viewing`), never from the address. No bin: every role that may remove may make it ours.

In the markup the icons stay the header's action after the `h1`; the style finds them with `:has()` and places them against `.ingredient-entry__naming`.

**One failure callout.** Make It Ours and Remove share one [`ClickFeedback`](click-feedback.md): a floating `role="alert"` box under the focus-keeping button, so the title's row keeps its height. `useCupboardWrites` hands a refusal over via `onRefused`; other callers pass their own. Opening a question clears the last failure. Success navigates or re-reads and the heading takes the focus.

## On the public page

The same `CupboardActions` receives `covens` (`PublicCupboardProps`: `{ covens, defaultWorkspaceId, annotate: { closeHref, opened? } }`) instead of `cupboard`: one `CupboardPlace` per coven the viewer may write in, in the switcher's order, with whether it holds the entry, the four `rolePermits` flags and `annotateHref` (`?annotate=<covenSlug>`). `covens` changes none of the page's marks. It is built per request in `src/app/(public)/compendium/ingredients/[slug]/cupboard.ts` from `covensHoldingEntry` and `covenRolesIfSignedIn`, never from the cached sessionless read (CLAUDE.md rule 6). A visitor, someone who may write in no coven, and an observer get none.

- **The plus** (`AddIcon`; [`compendium-cards.md`](compendium-cards.md), "The menu") stands left of the pencil while any coven the viewer may add in (`ingredient:create`) lacks the entry. `plusCovensOf(await covensHolding(id), currentWorkspaceId?)` (`src/app/plus-covens.ts`) builds `CupboardPlus` (`{ workspaceId, covens, heldIn }`) per request, uncached, filtered in SQL. A coven's page passes `cupboard.plus` for a live compendium entry only (not its own, not retired). One coven adds there at once; several give a menu by name, a holding coven disabled with a green check. Once every such coven holds it, `HeldMark` (`CompendiumCards/held-mark.tsx`) takes its place. An observer everywhere and a curator in no coven get neither.
- **Edit Stock** is the menu's first choice for a holding coven where the viewer may update stock. Pages that are not a coven's read forms and jars through `readEntryStock` (`src/app/entry-stock.ts`), per viewer outside the cached read, carried as `stock` per place via `stockDialogOf`. Several such covens ask which, in the Coven dropdown. A retired held entry offers it too: `readEntryStock` reads a compendium entry's forms per coven with `heldFormsOf` through that coven's proof, so only the coven whose cupboard names it reads it.
- **Other choices** show while any writable coven holds the entry, each where at least one grants the permission. One grantor acts directly. Several: Make It Ours and Remove ask which in a Coven dropdown (`coven-choice.tsx`) listing only grantors; Annotate asks in a picker dialog (`annotate-picker.tsx`), then opens that `?annotate` address.
- **The coven choice loads apart.** `lazy-coven-choice.tsx` holds the one import of `coven-choice.tsx` (`covenChoiceModule`) and draws nothing until it arrives; a compendium card's More starts it ([`compendium-cards.md`](compendium-cards.md), "The three dots").
- **The three forms load apart.** `lazy-forms.tsx` holds one import each of `IngredientForm`, `CompendiumEntryForm` and `CupboardEntryForm` (`ingredientFormModule`, `compendiumEntryFormModule`, `cupboardEntryFormModule`) and the `Lazy…Form` wrappers the entry, annotate and cupboard dialogs draw; each draws nothing until its code arrives. They bring react-hook-form and zod in, so nothing on a first-load path imports them statically (`tests/guards/first-load-scripts.test.ts`). A coven card's Edit and Annotate links start them ([`coven-cards.md`](coven-cards.md), "Contracts").
- **`?annotate=<covenSlug>`** opens that coven's dialog only when the slug names a coven of the viewer's that holds the entry and lets them annotate; only then is `getCupboardEntry` read. Any other slug is ignored and reads nothing.
- After a Remove the viewer stays on the public page, re-read. Each write is reset (`CupboardWrite.reset`) as its confirmation opens, so a second Remove in another coven is not left busy.

## The replaced-by block

A coven's own entry lists the compendium entries it replaces; a compendium entry in a coven lists itself once. One `h3` block (not in the jump menu), one [`InfoTip`](info-tip.md) for all links, each link the entry's own title, described by the tip (`aria-describedby`). At most three, then a **See All N** paragraph (not a list item) to the compendium search; Similar draws the same markup.

- `replaces.tip` is chosen by the page so the component does not branch on tier. `entries` are the first three by name, "Name (Formal Name)" when it differs (`pageTitleOf`); `total` is how many share the identity; `allHref` is the compendium search for the entry's label via `COMPENDIUM_PARAMS.href('/compendium', { query })`, omitted where nothing matches. The coven route fills it from `compendiumMatchesOf`. A compendium entry seen from a coven passes itself, `total` 1, no `allHref`.
- **`similar`**: for a coven's own entry with no formal name, entries whose name matches its own, case aside. Display only (linking goes one way in v1, DESIGN.md §13), the same for every role.
- The heading is running text with a word joiner before the ⓘ, so a wrapped heading keeps the ⓘ on its last line. Past `$shell-tablet-width` the block shrinks to its heading (`contain: inline-size`) so the chain icons end where the ⓘ ends; a wrapped heading fills the column (aligning would need JavaScript measurement).

## The back link

`BackLink` (`back-link.tsx`, client, so `IngredientEntry` stays a server component) writes "Back to" and `label`; the server draws the bare list (`/compendium`). **It returns to the list the entry was opened from.** In the browser it reads the previous page through the Navigation API (`navigation.entries()`); when that page is on this origin at `href`'s path or one of `back.also` (other paths that are the same list, each with a label), the link takes its path and query (`listReturnHref`, `back-href.ts`), keeping search, filters and page. A plain left press goes `router.back()` so the list's scroll position is restored; a new-tab press follows the address. Anything else keeps the bare list; the list's address never travels in the entry's own (no `?from=`). The Navigation API is past the browser floor, so it is an enhancement behind an `in` check. Proved by `tests/e2e/back-link.spec.ts` and `tests/components/IngredientEntry/back-href.test.ts`.

The link carries its own styles (`.back-link`), so the spell recipe page's Back to Grimoire is the same. `BackChevron` is exported alone: the sign-in card's Back button draws it one type step smaller ([`sign-in-panel.md`](sign-in-panel.md), "Two views").

## The details modal

An entry's details open in a modal over the list. The eye, **Quick Look**, is on the admin Compendium list left of each name and at each card's bottom left on a coven's Ingredients and the public `/compendium` ([`ingredient-card.md`](ingredient-card.md), `startActions`). A name picked from search suggestions opens the same Quick Look, keeping filter and page (`pickHref`, `src/components/CompendiumList/filter.tsx`).

- **Address**: `?entry=` on the list's own address: the slug on the admin list, the id on a coven's list and `/compendium` (also for a visitor). An edit opened from inside keeps `?entry=`, so closing returns to the details.
- **Parts**: `DETAILS_PLACE` and `detailsHeading` (`details.tsx`) are plain values the server page and client link share so a press shows the head the page draws. `DetailsDialog` is a client [`RouteModal`](modal.md) with `readingBody`. Its icons are the card's, from the same components; where the card has no control, the window has none.
- **The head** (`marks` from `detailsMarks`; [`modal.md`](modal.md), "A title with its own end"): New or Updated and the safety badge go on the top line (`topEnd`, so Close has it alone), the provenance badges under the name (`EntryMarks`, `safety={false}`, no recency), so `provenance` and `safety` are the dialog's to set. `FormalName` replaces the "Ingredient" kicker so the dialog is named by the entry's name alone.
  - At the formal name's line end, the card's controls. Admin and compendium lists: the plus (or green `HeldMark` once every coven the viewer may add in holds it; drawn by `PlusMark`, which needs the shell's query client) left of a keeper's or curator's Edit pencil. Coven list: `covenCardActions` (`CovenCards/actions.tsx`, a non-client composer the server page calls and hands down as `actions`): Edit (own entry) or Annotate (held compendium entry), the Edit Stock pencil for a role that may update stock ([`stock-dialog.md`](stock-dialog.md)), and `CardMore` for a held compendium entry (given `leaveHref`, the list without `?entry`, so a remove leaves onto the list). No Delete in the window and no plus on a coven's card. Edit opens over the details; Annotate opens over the list alone (`placed`), since a save changes the details behind. An observer gets no main icon and no More.
  - The plus comes from `plusCovensOf(await covensHolding(id))`, per request, uncached, passed in `IngredientDetailsOpened` as `plus` and `ingredientId`; omitted for an own entry, a retired one, an observer in no adding coven, and a visitor. `editAction` is for a keeper or curator on the admin list, or a steward or practitioner on a coven's list for the coven's own entry; `inCompendium` names it Edit in Compendium.
- **The review mark**, for a curator or keeper on the admin and public compendium. `ReviewMark` (`review-mark.tsx`) shows whether a curator reviewed the entry, which stops the seed rewriting it ([`db/compendium-seed/README.md`](../db/compendium-seed/README.md), "Write-once, and how a correction lands"). The badge reads **Reviewed By Curator** or **Needs Review**; the UTC day it was marked is its tip, day only, never who. The needs-review badge is also the entry's own mark (`EntryMarks`), drawn for everyone.
  - **The switch** is a `SwitchField` labelled **Reviewed** calling `setCompendiumEntryReviewed`. A switch, not a flipping button, so the state is the control's own to a screen reader. It holds the new state while the change is out, carries `aria-busy="true"` until the new `reviewedAt` arrives, with a `Spinner` replacing the thumb after 100ms ([`loading.md`](../loading.md), "Control"); never disabled (a disabled switch draws the dashed look, a different message) and a flip while out is ignored. A refusal shows an error `Notice` and the switch reverts.
  - **Reads**: the admin page reads `readCompendiumReview(session, id)` uncached ([`db/compendium-read.md`](../db/compendium-read.md)). The public pages read it only when the viewer is a curator or keeper, per request outside the cached reads, so every other viewer gets no review data and the page stays indexable. A coven's list never draws it.
  - **`ReviewRow`** (`review-row.tsx`) serves the Quick Look (`IngredientDetailsOpened.reviewLine`, the `under` row), the public entry page (`reviewControl`, the head's last row; the keeper has no entry page) and the edit and add modals. Its words show the SAVED state, never the switch's unsaved value. Where it shows, `EntryMarks` omits its own review badge so it is drawn once. No `order:`, so Tab follows visual order.
  - **In the forms**: `IngredientForm` takes `review` (`reviewed`, and `reviewedAt` when present) and draws the row at the foot before Save, Cancel and Delete. Flipping makes the form dirty; Cancel discards it. It is saved by a second `setCompendiumEntryReviewed` call after create or update returns the id, not in the same transaction; a failure shows "Saved, but the review mark was not". A non-curator's save never sends it.
- **The body** `IngredientSummary` (`summary.tsx`) draws the page's Details with the page's blocks (`blocks.tsx`), stacked at every width; no substitutes, references or Similar. For a held compendium entry it lays the coven's annotations over it.
  - **Description** (`summary-description.tsx`): clipped to six lines by a box whose height the script sets and animates, so without JavaScript the whole text shows. **Show More** is one real `<button>` throughout (`aria-expanded`, `aria-controls`) so focus stays, shown only when the text overflows; `prefers-reduced-motion` skips the animation.
  - **Forms**: given `jars` (from a coven's page only), each form shows quantity and unit, or Unmeasured, with `StockBadge`; a form with no jar shows "Not Stocked" as `.visually-hidden` text, its empty cell keeping its place. A form's own caution stays on the page; a line names the forms that carry one (`SafetyNote`'s `footnote`, [`safety-note.md`](safety-note.md)).
  - **Only what is recorded.** Empty rows and blocks are omitted; with every section empty and no description or caution the body is **No details recorded.** The In Your Cupboards block does not count against that.
  - **In Your Cupboards**: for a compendium entry, a last block links the entry in each of the viewer's own covens that holds it, `/coven/<slug>/ingredients/<id>`, named by the coven, alphabetical; hidden when none, for a visitor, and for a coven's own entry. The read is `covensHoldingEntry` (`cupboard-entries.ts`): covens come from the viewer's own memberships, each under its own `Membership` proof, filtered in SQL, so a coven they are not in never appears and a keeper or curator gets only their own; observers count. It is per viewer, uncached, and runs only while details are open (rule 6): beside `/compendium`'s cached sessionless read, never inside it.
- **The reads.** Admin: `ingredientDetailOf` with the curator's session, uncached, nothing for an entry deleted since. Coven list: `readViewedEntry` (`reads.ts`), uncached, with the coven for a retired entry and its annotations for a held compendium entry. `/compendium`: `readCompendiumDetails` (`src/app/compendium-reads.ts`), the id first with no session, then the public cached read, so an id naming a coven's own entry opens nothing.
- **The foot bar** links to the entry's page: **See in Compendium** (public and admin lists), **See in Your Cupboard** (a coven's list). `DetailsDialog` passes it as Modal's `foot` ([`modal.md`](modal.md), "The foot"), outside the scrolling element, so the body's scrollbar ends above the bar's hairline. `ingredient-details-modal.spec.ts` proves the bar is outside the body, the body scrolls on overflow only, and the bar and last text are both in view at the end of a long entry.

## Loading on first open

The details dialog draws its frame with the entry's heading and a `status` at once; the parts in `details-parts.tsx` load on first open and replace the status. `details-dialog.tsx` holds the frame. The shell's Add Ingredient control loads its form the same way ([`modal.md`](modal.md), "Contents that load on first open").

## Props in detail

Rules not in `types.ts`: with `cupboard.plus` omitted (own entry, retired, no coven that may add) neither plus nor check is drawn; `CupboardPlus` is shared with the details modal. `heldInCovens` is for any role, false for a visitor. `stock` is omitted public and for an unheld compendium entry. `pageTitleOf` titles both routes: the name, then the formal name in brackets when it differs.

## Styling

`index.scss` and `summary.scss` use tokens only, including the optical corrections `$optical-nudge`, `$back-chevron-pull`, `$link-hint-drop`, `$cap-middle` (explained in `_variables.scss`). The `local` and `retired` palettes are in `_variables.scss` ([`styling.md`](../styling.md), "Badge palettes").

- A description keeps typed line breaks (`white-space: pre-line`); running text stops at `$measure`. At 390px the `h1` breaks a word only when it cannot fit a line.
- Forced colours: a `:target` note, mark or source takes a 1px `Highlight` outline (its fill is dropped); the shown switch mirrors `.switch`, with no `forced-color-adjust`.

### Layout

The entry takes the frame's wide column (`$wide-column`).

- **Article**: with a jump menu (`--with-nav`), above `$shell-phone-width` it is a grid with the sticky menu left; the breakpoint and sticky `top` are `.page-with-nav`'s. The menu column is `minmax(min-content, min(space(8) * 3, 100% - space(8) * 15))`: 12rem at 1152px or wider, below that the content keeps 60rem (20rem side column, 2rem gutter, 38rem text) and the menu gives way, never narrower than its longest label. The menu spans `.ingredient-entry__body` so it sticks for the page's length.
- **Body grid** (`entry-body` in `_mixins.scss`), above `$shell-tablet-width`: text column left, side column (20rem) right. Row 1 holds Stock (zero height without it), row 2 Details; the side column spans both rows so it starts level with the first section and a long one never pushes Stock down. The skeleton's side part takes the same mixin.
- **Heading rule**: `entry-heading-rule` puts a `$hairline` under the h2 of Stock, Details, Forms and References, the heading text's width plus `space(4)`.
- **Skeleton** uses the same mixins, with a Stock part of always three jars (form count and jars are unknown). Its heading bars have no rule, so the page adds a few pixels when it loads.
