# AppShell

`src/components/AppShell/` is the frame around every signed-in page: a skip link, the global bar, and the page. Its layout is `src/app/(shell)/layout.tsx`, over `/account`, `/coven`, `/curator` and `/keepers`. It is a server component; only the account menu, the current-page marking and the Add Ingredient button are client code.

## Contracts

- **`(shell)` is a route group** (a folder in parentheses that shares a layout without adding to the URL). The root layout stays free of the session so a public page can choose its own chrome. The shell layout calls `viewerOf()`, which sends a signed-out visitor to sign in but never sends an unverified account to the email page: thrown from a layout, that redirect loops the router, so the page does it ([Route protection](../auth/route-protection.md), "Where the email redirect is thrown"). Pages call their own guards anyway, because a layout does not re-run on a client-side navigation. `forbidden.tsx` sits in the group so a signed-in non-admin's 403 draws inside the shell: a segment's `forbidden` boundary sits inside that segment's layout.
- **`(public)` is the sibling group for the public compendium.** Its layout reads `viewerIfSignedIn()` and never redirects: a signed-out visitor gets [`PublicFrame`](public-frame.md), anyone else this shell. The layout owns the plain `<main>` in both branches, so a public page renders no landmark of its own and one landmark survives the skeleton swap. An unverified account sees the shell's unverified chrome rather than being sent to `/account/email`: the compendium is public and holds no workspace data.
- **`viewerOf()`** (`src/lib/viewer.ts`) is wrapped in React `cache()`, so the shell layout, the coven layout's switcher and the `/coven` landing's notice cost one set of lookups. An unverified account reads an invitation count of 0 and costs no query. `workspaces` is in the switcher's order (alphabetical by name); the shell reads only the first slug.
- **A paused viewer.** An observer whose site access is paused carries `accessPause` (its end `null` when it has none). `viewerOf()` then draws no coven, no curation, no creation and no invitation, reads neither memberships nor the invitation count, and keeps the count of the viewer's own support requests waiting on them (`claude-docs/auth/admin-bootstrap.md`, "Signed in while paused").
  - The shell draws `PausedNotice` above the page in its own `aside`, since the page owns `main`. It is an error `Notice` with `quiet`, so it is a status and not an alert.
  - Over a page that narrows its column the notice takes that column through the page's own grid mixin, so the two cannot drift: `page-with-nav-grid` for Support and the account's tabs, and the same mixin with `$document-menu-column` and the measure for a document page. Each is a `:has()` rule, an enhancement: without it the notice keeps the wide column.
  - An ingredient entry is the exception. Its menu column grows to the menu's longest label, which a grid outside the entry cannot see, so the entry draws its own `PausedNotice` at the top of its text column (`accessPause`, [`ingredient-entry.md`](ingredient-entry.md)) and a `:has(.ingredient-entry__pause)` rule hides the shell's.
- **The bar** holds the brand, the site nav, then Add Ingredient, the account menu and the theme disc at the right. The disc stays in the bar at every width: the account panel holds no theme switch, and the root's corner toggle is hidden on shell pages.
- **The brand** links to `/` for every viewer, an unverified one included: `/` is public, reads the session and offers a signed-in visitor their landing without redirecting. At a narrow phone's width it reads "S&S"; the full name stays for a screen reader (`BrandName`, shared with `PublicFrame`).
- **The site nav** (`nav` named "Site") lists:
  - the Compendium, for every viewer;
  - Your Coven ("Your Covens" for more than one), for a verified account in at least one coven and for a verified curator or keeper in none;
  - Curator and Keepers, for a verified curator or keeper (`canCurate`) alone.
- **Your Coven goes into the coven itself.** `covenHome` (`src/lib/shell-home.ts`) gives `/coven/<slug>` of the first coven the switcher lists that the viewer can open (`firstReachable`: it passes over a coven whose access is paused, or takes the first when every one is), or the `/coven` landing for someone in none, which offers the create page or explains the invitation. `/coven` would only redirect a member there and leave the browser a stop with nothing on it, most visibly from `/keepers`.
- **Under `$shell-tablet-width`** the bar has no room for the links beside the brand, Add Ingredient, the account button and the disc, so the same links are offered in the account panel. `SiteNav` is also the public frame's nav (the Compendium as its one link).
- **Add Ingredient** is the bar's one global action. The places a new ingredient can go are the compendium (for someone who curates) and each coven the viewer may write to; a read-only coven is no destination. One place makes a plain button; two or more add a chevron that opens a menu of them all. The main part opens the default place, which follows the area: the coven a coven page names, the compendium on a curator or keeper page, anywhere else the first writable coven (or the compendium when the viewer has none). The menu's groups put the side the viewer is on first, learned from the address alone (`usePathname()`); it uses the shared `sectionsFor` ([`menu-button.md`](menu-button.md), "Sections"), and the chevron is named "Choose Where to Add" over a menu named "Add Ingredient To".
  - A coven opens a modal over the page at `?new=ingredient-coven-<slug>`, written with the browser's own `pushState`, which Next's router follows: nothing on the server needs re-reading to draw the form. A bare `?new` is the default coven's only off the curator and keeper pages. A slug the viewer cannot write to opens nothing.
  - The compendium navigates to `/curator/compendium?new`, because the route-modal provider that would open it at once sits below the shell (`claude-docs/components/modal.md`, "Add Ingredient").
  - A save that opens the new entry's page sets `leaving` so the dialog's close does not write the address under that navigation. An autosave that creates the ingredient replaces `?new` with the ingredient's own `?edit=` address and keeps the dialog open.
- **`NewSpellElsewhere`** is drawn once in the shell. `?new=spell-<slug>` on a page that is not that coven's grimoire replaces the address with the grimoire's, so Back does not return to the page that only sent the viewer on. New Spell is a dialog over the grimoire, never drawn on another page.
- **An unverified viewer** gets the brand link, the account menu with Sign Out alone, the theme disc, a site nav holding the Compendium alone, and no Add Ingredient.
- **The body during a navigation.** `MainBody` is a client part (the state is the browser's). While a navigation aimed at the `main` region is pending ([loading](../loading.md)), it keeps the page mounted at its full height but hidden (`visibility: hidden`, `inert`, `aria-hidden`), so the scroll position the browser saves for Back is the page's, and lays one `Skeleton` of the target's shape over it inside a `main` pinned under the bar, so the landmark survives the wait.
  - The wait carries a visually hidden `<h1>Loading</h1>`, because the page's heading is hidden with the page and a page without a level-one heading fails the accessibility scan. The overlay that stays over the arrived page while it fades has no heading or landmark of its own ([`SkeletonFade`](skeleton.md), "Skeleton fade").
  - A `coven` or `admin` target is `SectionBody`'s (the page under that section's context row, which stays), and a navigation with no target (a refresh) leaves the page standing.
- **Site targets.** `site-target.ts` works out from the address alone what the destination draws while it is on its way, in the frame the page sits in. The bar's links and the account menu's copies share `siteLinkTarget`. `ingredientLinkTarget` serves a link into the ingredients: a coven's entry belongs to the coven region (`fromCoven`: when the press starts inside a coven only the coven's body changes, from anywhere else the whole main does); any other address gets none.
- **The skip link** ("Skip to Content") targets `#main`, an empty `span` with `tabindex="-1"` just before the page's wrapper, since each page owns its own `main` and no one element could be asked to name. It is not the wrapper itself: a click on plain text focuses the nearest focusable ancestor, so a focusable wrapper took every click on the page's text and the next Tab restarted at the top. [`PublicFrame`](public-frame.md) draws the same span; `tests/e2e/skip-target.spec.ts` walks both.
- **The context row** is the layouts' to render, as only they know the area: the coven layout puts the switcher and `CovenNav` in it, the admin layout "Admin" linking to `/keepers` and `AdminNav` ([`context-row.md`](context-row.md)).
- **Accessibility.** One `banner`, a `nav` named "Site", every link and button 44.5px tall or more, a visible focus ring on each, and `aria-current` on the current link.

## Styling

The bar's inner row, brand, initials and end group are the mixin `frame-bar($block)` in `src/scss/_frame-bar.scss`, shared with [`PublicFrame`](public-frame.md). Measurements are tokens ([`styling.md`](../styling.md), "The application shell and the layers").

- The bar's `margin-bottom` is zeroed (the layout layer gives every `header` one), so a context row meets the bar edge to edge and a page that fits the window does not scroll by it.
- The current site link is told by weight and the `$rule-heavy` accent rule along the bar's foot (`nav-current`), a border and not a box-shadow so forced colours keeps it, with no fill, so a hover's quiet wash still shows.
- `_primitives.scss` takes the bar off `.page-frame`'s height (for the public frame's bar too) and pads `.app-shell__main` for the bottom bar. The root's `scroll-padding-top` and the `scroll-margin-top` of `.page-frame__section` and the ingredient entry's sections are keyed the same way, so a jump or a focus lands below either frame's sticky bar.
