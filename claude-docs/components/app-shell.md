# AppShell

`src/components/AppShell/` is the frame around every signed-in page: a skip link, the global bar, and the page. Its layout is `src/app/(shell)/layout.tsx`, over `/account`, `/coven` and `/keepers`. It is a server component; only the account menu and the current-page marking in the bar's links are client code.

## Contracts

- **`(shell)` is a route group** (a folder in parentheses that shares a layout without adding to the URL). The root layout stays free of the session so a public page can choose its own chrome. Everything that needs a signed-in observer sits under `(shell)`, whose layout calls `viewerOf()`. That sends a signed-out visitor to sign in, but never sends an unverified account to the email page: the page does that ([Route protection](../auth/route-protection.md), "Where the email redirect is thrown"). Pages call their own guards anyway, because a layout does not re-run on a client-side navigation. `src/app/(shell)/forbidden.tsx` sits in the group so a signed-in non-admin's 403 draws inside the shell (a segment's `forbidden` boundary sits inside that segment's layout); it keeps `NotAuthorized` in a `main.page-frame`.
- **`(public)` is the sibling group for the public compendium.** Its layout, `src/app/(public)/layout.tsx`, reads `viewerIfSignedIn()`: null for a signed-out visitor, who gets [`PublicFrame`](public-frame.md); otherwise the viewer and covens, drawn in this shell. It never redirects. Both chromes put the page in a wrapper `div`, so the layout owns the plain `<main>` in both branches (the page in `.page-column` inside it) and a public page renders no landmark of its own. An unverified account sees the shell's unverified chrome rather than being sent to `/account/email`: the compendium is public and holds no workspace data.
- **Props.** `viewer` is a `ShellViewer` (`src/lib/types.ts`): `canCurate` is true for a curator or a keeper, read from the session's role; `canCreate` and `verified` come from the user row; `pendingInvitations` counts coven invitations waiting for the viewer's verified address. `workspaces` is the viewer's covens in the switcher's order (alphabetical by name); the shell reads only the first one's slug, for the brand and Your Coven. `children` is the page with any context row its own layout renders.
- **`viewerOf()`** (`src/lib/viewer.ts`) builds the viewer and covens from `getMe`, `membershipsOf(session, [session.userId])` and, for a verified account only, `countReceivedInvitations(session, undefined)` (an unverified account reads 0 and costs no query). It is wrapped in React `cache()`, so the shell layout, the coven layout's switcher and the `/coven` landing's notice cost one set of lookups. The count goes to the account menu ([`account-menu.md`](account-menu.md)). A refused lookup (impossible for one's own id) throws. The coven layout and the create page read the same list for their switchers.
- **A paused viewer.** An observer whose site access is paused carries `accessPause`, its end `null` when it has none. `viewerOf()` and `viewerIfSignedIn()` read it through `getShellSession()` and then draw no coven, no curation, no creation and no invitation, reading neither the memberships nor the invitation count, and keep the count of the viewer's own support requests waiting on them (`claude-docs/auth/admin-bootstrap.md`, "Signed in while paused"). The shell draws an error `Notice` (red, `quiet`, so a status rather than an alert) above the page, in its own `aside` labelled `Site Access`, since the page owns `main`: "Your site access is paused until …" with the end in `LocalTime`, or "with no end date", then a What This Means link to `/access-paused`. `PausedNotice` (`paused-notice.tsx`) draws it, given the end and a class. `.app-shell__pause` sets it in the wide column's edges. Over a page that narrows its column the notice takes that column through the page's own grid mixin, so the two cannot drift: `page-with-nav-grid` for Support and the account's tabs, and the same mixin with `$document-menu-column` and the measure for a document page. Each is a `:has()` rule, an enhancement: without it the notice keeps the wide column. An ingredient entry is the exception: its menu column grows to the menu's longest label, which a grid outside the entry cannot see, so the entry draws its own `PausedNotice` at the top of its text column (`accessPause`, [`ingredient-entry.md`](ingredient-entry.md)) and a `:has(.ingredient-entry__pause)` rule hides the shell's.
- **The bar** has the brand, the site nav, then at the right Add Ingredient, the account menu and the theme disc. The disc stays in the bar at every width, a phone's included: the account panel holds no theme switch.
- **The brand** is a link to `/` for every viewer, an unverified one included (`/` is public); `/` reads the session and offers a signed-in visitor their landing, without redirecting. At or under `$shell-brand-width` (a narrow phone) it reads "S&S"; the full name stays in the page, visually hidden, for a screen reader. Its two spans are `BrandName` (`brand-name.tsx`).
- **The site nav** (`nav` named "Site") lists the Compendium for every viewer, verified or not; Your Coven ("Your Covens" when the viewer is in more than one) for a verified account in at least one coven, and for a verified curator or keeper in none (that link goes to `/coven`); and Admin for a verified curator or keeper (`canCurate`) alone. `src/lib/shell-home.ts` holds `covenHome`: `/coven/<slug>` of the first coven the switcher lists that the viewer can open (`firstReachable`, passing over a coven whose access is paused, or the first when every one is), or the `/coven` landing for someone in none, which offers the create page or explains the invitation. The link goes into the coven itself because `/coven` would only redirect a member there and leave the browser a stop with nothing on it, most visibly from `/keepers`. At or under `$shell-tablet-width` the bar has no room for the links beside the brand, Add Ingredient, the account button and the disc, so the same links are offered in the account panel. `SiteNav` is also the public frame's nav (the Compendium as its one link).
- **Add Ingredient** is `add-ingredient-button.tsx`, a client part and the bar's one global action. The places a new ingredient can go are the compendium (for someone who curates) and each coven they may write to. One place makes a plain button; two or more make a split button, whose main part opens the default place and whose chevron opens a menu of them all, each "to" its name; none, no button. The default follows the area: a coven page adds to that coven, a keeper page to the compendium, anywhere else to the viewer's only coven or a choice. The menu draws two labelled groups, **Compendium** and **Coven**, when the viewer may add to both, and a plain list when to one kind alone. The side the viewer is on comes first, learned from the address alone (`usePathname()`): a coven's pages (`covenSlugOf`) put the covens first, any other page the compendium. The groups are made by the shared `sectionsFor` ([`menu-button.md`](menu-button.md), "Sections"); the chevron and its menu are a `MenuButton` (`add-ingredient-menu.tsx`), the chevron alone shown as its `icon` and named "Choose Where to Add", its menu named "Add Ingredient To" (`menuLabel`). A coven opens a modal headed by its name over "Add Ingredient", opened by the address `?new=ingredient-coven-<slug>` written with the browser's own `pushState`, which Next's router follows, since nothing on the server needs re-reading to draw the form. The compendium navigates to `/curator/compendium?new` (`claude-docs/components/modal.md`, "Add Ingredient").
- **An unverified viewer** gets the brand link, the account menu with Sign Out alone, the theme disc (the root's corner toggle is hidden on shell pages; without the disc the viewer could not change the theme), a site nav holding the Compendium alone, and no Add Ingredient.
- **The body during a navigation.** `.app-shell__main` is wrapped in `main-body.tsx`, a client part (the state is the browser's), inside a plain block `div` that is the fade's `position: relative` host. While a navigation aimed at the `main` region is pending ([loading](../loading.md)), it hides the page (`visibility: hidden`, `inert`, `aria-hidden`, still mounted at its full height so Back returns to the same place) and lays one `Skeleton` of the target's shape over it inside a `main`, pinned under the bar, so the landmark survives the wait. The wait carries a visually hidden `<h1>Loading</h1>`, because the page's heading is hidden with the page and a page without a level-one heading fails the accessibility scan. A `coven` or `admin` target is `SectionBody`'s (the page under that section's context row, which stays), and a navigation with no target (a refresh) leaves the page standing. The skeleton's frame is the destination's, top-aligned: `wide`, `with-nav` and `entry` in `page-column` (the last two with the side menu drawn, `entry` in the ingredient page's wide grid), `narrow` in `page-frame--narrow`, with a `panel` under a form; the standard centred `.page-frame` stays for a target that names none. When the wait ends, the skeleton stays over the arrived page for 200ms and fades out ([`SkeletonFade`](skeleton.md#skeleton-fade)); the overlay carries no heading or landmark of its own.
- **Site targets.** `site-target.ts` works out from the address alone what the destination draws while it is on its way, in the frame the page sits in; `siteLinkTarget(base, href)` gives the site links theirs. A link into the ingredients: a compendium entry is a wide page with its jump menu; a coven's entry sits under the coven's context row, so it belongs to the coven region (`fromCoven`: when the press starts inside a coven only the coven's body changes, from anywhere else the whole main does); the Compendium search a See All opens is the Compendium's list; any other address gets none. A site link: the Compendium opens on its cards under a heading and a filter in the wide column; the coven index is in the forms' column; a coven's own home (a lone coven's link goes straight to it) is a page with its contents menu; the admin index is wide sections of links. The bar's links and the account menu's copies share this.
- **The skip link** ("Skip to Content") is the first element and targets `#main`, an empty `span` with `tabindex="-1"` just before the page's wrapper (`.app-shell__main`), since each page owns its own `main` and no one element could be asked to name. The link moves focus to the span, and the next Tab reaches the page's first control; `.skip-target:focus` draws no ring, as the span has no box. It is not the wrapper itself: a click on plain text focuses the nearest focusable ancestor, so a `tabindex="-1"` wrapper took every click on the page's text and the next Tab restarted at the top. [`PublicFrame`](public-frame.md) draws the same span before its page wrapper. `tests/e2e/skip-target.spec.ts` walks both.
- **The context row** is the layouts' to render: the coven layout puts the switcher and `CovenNav` in it, the admin layout "Admin" linking to `/keepers` and `AdminNav` ([`context-row.md`](context-row.md)).
- **Accessibility.** A skip link, one `banner`, a `nav` named "Site", every link and button 44.5px tall or more, a visible focus ring on each, and `aria-current` on the current link.

## Styling

The bar's inner row, brand, initials, end group and their narrow-window rules are the mixin `frame-bar($block)` in `src/scss/_frame-bar.scss`, shared with [`PublicFrame`](public-frame.md); this stylesheet keeps the shell's own (the sticky pin, the brand's right padding, hiding the nav under `$shell-tablet-width`, the theme and saved-message wrappers). The site nav is `.app-shell__nav`; the public frame overrides the hiding in its own sheet. Measurements are tokens ([`styling.md`](../styling.md), "The application shell and the layers"). The bar is `position: sticky; top: 0` at `layer('shell')`, exactly `$shell-bar-height` tall, with `margin-bottom: 0` (the layout layer gives every `header` a bottom margin; zeroed, so a context row meets the bar edge to edge and a page that fits the window does not scroll by it), on `$surface-card` with a `$hairline` bottom edge, its inner column `$wide-column` wide, centred. The site links fill the bar's height, square, and the current one is told by weight and the `$rule-heavy` accent rule along the bar's foot (the `nav-current` mixin, a border and not a box-shadow, so forced colours keeps it), with `aria-current="page"` and no fill, so a hover's quiet wash still shows. Controls are `$control-height` tall. At or under `$shell-tablet-width` the site nav leaves the bar and the account button is an avatar alone. `_primitives.scss` takes the bar off `.page-frame`'s height (for the public frame's bar too, `:is(.app-shell, .public-frame)`) and pads `.app-shell__main` for the bottom bar. The root's `scroll-padding-top` and the `scroll-margin-top` of `.page-frame__section` and the ingredient entry's sections are keyed the same way, so a jump or a focus lands below either frame's sticky bar.

## Tests and stories

`tests/components/AppShell/index.test.tsx` covers who sees Admin and Your Coven, the brand's target, the Your Coven label, Add Ingredient's target, the unverified bar, the skip link's target and the invitation count reaching the account menu. `tests/lib/shell-home.test.ts` and `tests/lib/viewer.test.ts` cover the helpers (the count is read for a verified viewer, never queried for an unverified one). `tests/e2e/menu-button-edge.spec.ts` scans for accessibility with the Add Ingredient menu open at a desktop width. Stories: `src/components/AppShell/index.stories.tsx`, "Shell / App Shell", `States`, each inside `ShellFrame` (`.storybook/shell-frame.tsx`); the body swap has `Feedback / Main Body` (`.storybook/main-body.stories.tsx`, [loading](../loading.md), "Stories").
