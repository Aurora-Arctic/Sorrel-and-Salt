# GroupedValueForm

`src/components/GroupedValueForm/` is the admin's form for a curated value, grouped or flat. Grouped kinds file the value under a group: a category, a curated ingredient form, or a deity (whose group is its tradition). Flat kinds are filed under nothing: a celestial body or a zodiac sign. One component serves them all through `kind: 'category' | 'form' | 'deity' | 'celestialBody' | 'zodiacSign'`, as [`GroupForm`](group-form.md) serves the groups, so a new vocabulary is a kind and not another copy. It holds no modal: the page puts it in one.

The form kind is named for the GraphQL type `IngredientFormValue`, because `IngredientForm` is the ingredient entry form (DESIGN.md §7). The copy still calls a row a "form" (Add Form, Save Form).

## Kinds

Everything that tells one kind from another is its entry in `KINDS` (`index.tsx`), declared through `defineKind`. A new kind is an entry there plus its three mutation documents. `defineKind` holds the mutations to the kind's input and hides the input type from the record, so kinds whose inputs differ sit in one `KINDS`.

- **Copy** (`GroupedValueCopy`, `types.ts`). `group.hint` is set only where it gives a rule the label does not (a deity's Tradition: a god several peoples honour is filed under one). `descriptionHint` is set only on the kinds whose suggestions match the description as well as the name (form, deity, celestial body, zodiac sign), since that flow is not in the label ([`info-tip.md`](info-tip.md), "When a field gets a tip"). `renameNote` is set on every kind but the category.
- **Values and schema.** The form's values are always `{ name, description, groupId, folkNames, drafts }`, the last two a deity's other names and the box they are typed in. The category and form kinds use the shared server schema itself (`CategoryInput`, `IngredientFormValueInput`, `src/modules/vocabulary/validation/`).
  - A kind whose input names the group otherwise supplies its schema with that key renamed to `groupId`, a `toInput` that renames it back, and `inputKeys`, which says where the server paths it, so a refusal still lands beside the group field. `DeityInput` calls the group `traditionId`, so the deity's `inputKeys` is `{ groupId: 'traditionId' }`, and its `otherNames` is swapped for `folkNames`, the `{ value }` entries the field keeps.
  - A flat kind has no `group`, so no group field is drawn. Its values still carry `groupId`, always `''`, so every kind has one shape; its schema (`CelestialBodyInput`, `ZodiacSignInput`, `astrology-value.ts`) parses the name and description alone and `toInput` leaves the group out.

## Contracts

- **The shared schema runs first.** The Zod resolver runs the kind's schema before any mutation is sent, so a blank name, a blank description or an unchosen group never reaches the server. The service runs the same schema again (DESIGN.md §7).
- **A server field error lands beside its field.** A `VALIDATION` error's `fieldErrors` go to `setError` by path: `name`, `description`, the group's input key, and an other name's `['otherNames', i]` on that entry. Anything else renders above the fields in a `Notice` alert ([`notice.md`](notice.md)). The slug collision is pathed to `name`, since the slug is derived from the name. The shared `readGraphqlIssues` (`src/lib/graphql-failure.ts`) gives every field error at once where `readGraphqlFailure` answers only the first; `placeServerIssues` places each under its field and joins the rest into the alert. A refusal that is not `VALIDATION` is one issue with the server's sentence, or `GENERIC_FAILURE` when there is none.
- **The group is a closed set typed into**: the combobox's type-ahead box (`SelectField`'s `typeahead`). Typing narrows the list to the groups whose name holds the text, the first highlighted so Enter takes it. Only a listed group is ever the value: text naming none leaves the group blank, so Save shows the schema's error beside the field, as for a group never chosen. For a form, each group's row and the chosen value draw its [`FormIcon`](form-icon.md) before the name (the generic spoon for a group with no icon), decoration outside the option's accessible name. Category groups and traditions carry none.
- **A deity's Other Names** is the ingredient form's [`ListField`](ingredient-form.md). A save sends the whole list and the service brings the stored names to it (DESIGN.md §5, `deity_other_names`). The field keeps its entries under the ingredient form's keys, `folkNames` and `drafts.folkNames`, because `ListField`'s paths are that form's; so the box refuses, as a folk name's does, a name already listed in any case and the deity's own name. The service refuses a name another deity of the tradition holds, naming that deity, and the refusal lands on the entry. Every other kind draws no list and sends none.
- **Every field but Other Names is required.** The asterisk is hidden from the field's name: a screen reader hears "Name" and `aria-required`.
- **Save is offered only when there is something to save**: disabled on a new value until something is typed, and on an existing one until something changes (`isDirty`); putting a value back disables it again. The confirmation's Delete is busy the same way.
- **A rename of any kind but a category carries onto the compendium.** Renaming a form rewrites every live compendium variant that picked it ([`mb.162-compendium-holds-curated-values.md`](../design-decisions/mb.162-compendium-holds-curated-values.md)); a deity's rename rewrites the name on every live `ingredient_deities` row that picked it ([`mb.132-admin-deities.md`](../design-decisions/mb.132-admin-deities.md)); a celestial body's or zodiac sign's reaches every entry listing it the same way. None is part of an entry's identity or address, so no address moves and no redirect is asked for (the compendium's admin form asks, of an entry's own save: [`db/ingredient-slugs.md`](../db/ingredient-slugs.md)). While an existing value's trimmed name differs from the saved one, a `.field__hint` sits above the actions and Save's `aria-describedby` points at it; putting the name back removes it. A new value never shows it, nor does a change of group, which moves no entry.
- **A delete asks first, and says what it does.** `Delete "<name>"?` and the kind's `deleteNote` appear on a card over the form, which is held until it is answered, the focus on Cancel and back on the delete button when Cancel puts it away ([`modal.md`](modal.md), "Asking over the form").
  - A category's delete removes nothing of a coven's: an entry filed under it keeps its link and stops reading the category ([`deleteCategory`](../../src/modules/vocabulary/services/categories.ts)). Every other kind's delete is refused while a compendium entry uses it; covens' ingredients keep what they wrote, as their own value.
  - A refusal comes back as a `FORBIDDEN` naming the compendium entries filed under the category ([`db/categories.md`](../db/categories.md), "Category writes"), or as a plain message naming the entries that pick the form or the deity. It shows in the alert notice, the form stays open and the confirmation is withdrawn. A refusal that names its remedy is not a bad value in a box, so it gets no field (DESIGN.md §7).
- **Unsaved changes are asked about.** `formState.isDirty` goes to the shared guard ([`modal.md`](modal.md#unsaved-changes)); Discard Changes calls `onDone`.
- **Undo and redo** ([`field.md`](field.md#undo-and-redo)). `useFormHistory` is off while the unsaved-changes or the delete question is up. A save closes the form rather than resetting it, so nothing calls `clear()`.

## On the admin pages

`/curator/categories`, `/curator/forms`, `/curator/deities`, `/curator/celestial-bodies` and `/curator/zodiac-signs` are one page, `ValuePage` (`src/app/(shell)/curator/value-page.tsx`). Each route's `page.tsx` keeps its tab title and hands over its kind and address. `value-kinds.ts` holds each kind's readers from `@/modules/vocabulary`, each mapped onto the page's own names, so the deities' `traditionId` and the astrology services' leading vocabulary argument stop there.

- **The modal.** The form opens in a `RouteModal` ([`modal.md`](modal.md)) from the address, or at once from a press on an Edit or Add ("Opening at once" in `modal.md`). `?new` opens an empty form; `?edit=<slug>` opens the value at that slug, under an eyebrow with the saved name as title and a deity's tradition after it ([`modal.md`](modal.md), "An edit dialog's head"). `value-dialog.tsx` is the client edge, since a server component cannot hand `RouteModal` the function its contents take. The page always renders it, with `opened` set only when the address opens a modal, so a press's skeleton and the form that replaces it are one dialog; the form is keyed by the value's id.
- **Leaving.** Closing, saving or deleting fades the modal out, then `router.replace`s the page it opened over, filter and cursor kept (`closeHref`, from `groupedValuesHref`), so Back does not reopen it, and `router.refresh()`es so the list re-reads.
- **Slugs move.** A form's slug is its name and its group's (`wax-substance`), a deity's its name and its tradition's (`hecate-greek`, from `deitySlug`), and a celestial body's or zodiac sign's its name, so a save can move the address; closing after every save means the modal never sits on a stale one. A deity's address also moves when its tradition is renamed, or deleted and its deities moved ([`group-form.md`](group-form.md); [`mb.132-admin-deities.md`](../design-decisions/mb.132-admin-deities.md)), so an old `?edit=` link can go stale without the deity changing. An `?edit=` naming no live value opens nothing and says so above the list in `MissingNotice`.
- Why a modal on a URL rather than separate pages or intercepted routes: [`design-decisions/m5.6-admin-categories.md`](../design-decisions/m5.6-admin-categories.md).

## Styling, stories and tests

The form is the shared pieces ([`styling.md`](../styling.md), "Form fields"). Its one rule of its own, `.grouped-value-form__note`, sets the rename note a step above the actions, under the form's class because the primitives are emitted under `body` and would otherwise win on specificity. The workshop has no API, so a story's save answers with the generic error.

Tests: `tests/components/GroupedValueForm/`, with the nine tests every kind shares run once, on the category, as rows of `tests/support/grouped-value-form.tsx` (a kind shares that code path, so another kind's run would prove nothing more); `tests/app/(shell)/curator/value-page.test.tsx` for the pages ([`grouped-value-list.md`](grouped-value-list.md#testing)); and `tests/e2e/admin.spec.ts` through the real server.
