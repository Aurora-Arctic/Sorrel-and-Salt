# CompendiumList

`src/components/CompendiumList/` is `/curator/compendium`'s filter, table and pager, built as the category list's is ([`grouped-value-list.md`](grouped-value-list.md)). It is render-only and a server component: the page reads one page under the address's filter through `listCompendium` and hands it over. Props and the filter shape are in `types.ts`. The formal name sits beside the label because it is the entry's identity. The page reads each page's forms in one batch through `variantsOf(null, refs)`, the read `Ingredient.variants` resolves through, not one read per row.

## Contracts

- **The filter has three audiences.** `CompendiumListFilter` takes `audience`: `'admin'` (the default), `'public'` or `'coven'`.
  - Public filters at `/compendium`, draws no No Refs control and no Classification facet, and words its empty sentence through the exported `emptyText(..., whenEmpty)`. Its cards are [`compendium-cards.md`](compendium-cards.md).
  - Coven takes `covenSlug` and `workspaceId`, filters at `/coven/<slug>/ingredients` (`covenIngredientsHref`), is the same row on `COVEN_PARAMS`, and also carries `source`, `inStock` and `lowStockOnly`, so the panel draws Source, In Stock and Low Stock Only. Its name search suggests from the coven's cupboard and a pick opens `/coven/<slug>/ingredients/<id>`. Its live counts ask `workspaceIngredientFacets` (the `CovenFacetCounts` document). Its cards are [`coven-cards.md`](coven-cards.md).
  - The admin search has no Classification filter (the column stays in the table).
- **In My Covens, on the public page alone.** `covens` is the viewer's covens as `{ id, name, paused }`, every membership an observer's included (a paused one is listed disabled), handed to [`FacetPanel`](facet-panel.md), which draws the combobox with an In / Not In choice and no counts. Picked, the list holds only the entries a cupboard of any one of them holds (a live `workspace_compendium_entries` row); none picked filters nothing. The ids are a repeated `covens` parameter, which counts as a filter, so the page is `noindex`. Not In is `covensNot=1`, absent for In: with covens picked the list holds the entries none of them holds, with none picked the entries none of the viewer's covens holds. Removing the last picked coven resets the choice to In, so `covensNot` leaves the address with it. The live counts ask `compendiumFacets` with `covensNot` too. The sentence wording is in [`ingredient-search.md`](ingredient-search.md), "The search sentence". The page passes no `covens` for a visitor or an account in no coven, and the admin and coven lists pass none, so the field is not drawn there. How the page reads the narrowed list is under "The compendium page".
- **The filter is a GET form** to `/curator/compendium` (`COMPENDIUM_PATH`), inside a `<search>` landmark, `position: relative` because the panel opens just under it. It is the name type-ahead ([`ingredient-search.md`](ingredient-search.md)), then [`FacetPanel`](facet-panel.md) with `admin` on, with [`SearchSentence`](search-sentence.md) above the results outside the form. `FilterForm`'s own Clear link is off (`clear={false}`) since the panel carries Clear All ([`filter-form.md`](filter-form.md)). Filtering starts again from the first page, since the form carries no cursor. `filter.tsx` is the one client file.
- **Every address carries the whole filter.** Apply Filters, a panel close or the Search submit builds the address from the filter shown with the name typed (trimmed) and every facet set over it (`hrefFor`, through `COMPENDIUM_PARAMS.changed`, which drops the cursor). `categoryMode` is written only from two categories up. Picking a name in the dropdown instead opens that entry's Quick Look (`?entry=`) over the list as shown, the filter and page (`cursor`) kept and the typed text not applied, on all three lists: by slug on the keeper's, by id on the public and coven lists, as each list's eye opens it. Closing it goes back to the same page.
- **Before hydration** the dialog is drawn open inside the form, each facet a native control under the name the parameter table reads ([`ingredient-search.md`](ingredient-search.md#the-parameter-table)): Apply Filters or Enter in the search box submits them all. Once hydrated, a change in the panel is held, since the panel covers the results; Apply Filters, Escape or any other close applies every held change in one soft navigation. Back steps through those and a reload restores the last. A close with nothing changed pushes nothing. Clear All beside the Filters button applies at once; the one at the panel's foot clears what is held, then applies and closes. The typed name applies only through Apply Filters or Enter.
- **The panel is held ahead of the page.** `CompendiumListFilterRow` takes the page's filter again whenever it changes (Back, Clear All). The row is keyed by the name searched only, so a facet change keeps the open panel and its focus, and a new text search redraws it, closing the panel. While a list is on its way, `FilterForm` marks the controls `aria-disabled` and refuses presses, so a second change goes nowhere.
- **The sentence** is `buildSearchSentence` over the filter, the total (`resolveNumberedPage`'s `totalCount`) and the labels the facets give: a deity by its name with its tradition added when another deity shares the name. It takes `searching` from the list's navigation, so it types itself out while a new search loads and stays still when a pager end changes the page.
- **Every action is an address.** Each row's Edit is its `editHref`, the page's Add Ingredient is `?new`, and `compendiumHref(place, dialog)` builds both, the pager's links and the filter's submit, on the shared `listHref` (`src/lib/list-href.ts`). Links are `next/link`, not plain anchors: opening the modal is a soft navigation, and the page calls the admin guard on every render.
- **Forms.** The Form column joins forms with the card's dot (`dotted-row`, [`styling.md`](../styling.md), "Dotted lists") and a spoken comma. The forms' gap belongs to the row, not to each form, so a wrapped form starts at the cell's edge. The row is `vertical-align: top` because an inline-flex box takes its baseline from its first item and the icon's svg has none, which left the names 4px above the row's other text. The dot is centred on the form's own box, which is why the form wrapper is a flex box. The page reads the Form box's choices as `facets.forms` from `compendiumFacets` and each form's icon from `listIngredientFormValues`, every page of it through `allPages` (`src/lib/pagination.ts`), not one page of the maximum: 84 forms are seeded against `MAX_PAGE_SIZE`'s 100, and more are added as the compendium grows. Two live forms may share a name in different groups, so the page offers each name once, whatever its case.
- **Each name links to its entry's own page**, `/compendium/ingredients/<slug>`, the public route, which offers a curator Edit over the page. The link is a `LinkIconHint` ([`link-hint.md`](link-hint.md)), so while it is pending the chain turns into the loading ring in the same space and this link has no dot. The chain icon keeps it from resting on colour alone. Pointed at or focused, the icon alone grows by a transform from its inline start, so nothing reflows. The Quick Look eye to the name's left opens the entry's details over the list at `?entry=<slug>`. The link is in the Name cell, so the wide table and the stacked card draw it alike.
- **None is an em dash.** A null formal name, or an entry with no form, shows "—", since the Unknown list tells an entry with an unconfirmed formal name from one with none by this column. An entry with no form is flagged on the keeper's to-do list.
- **Each Edit is a pencil, [`EditLink`](icon-tip.md),** opening the modal at once under the entry's `editHeading` ([`modal.md`](modal.md), "Opening at once"). Its name carries the formal name in `visually-hidden` text because two rows can share a label, never a formal name.
- **An empty list says why, with no table.** With no filter the compendium is empty and the sentence says how to begin; a filtered list names each filter in use and says to change or clear it. The sentence is a node built from `noMatchLead` and `NO_MATCH_ADVICE` (`src/lib/text.ts`), the same pieces as the string `noMatchText` other admin lists use, so each value can be bold. The public cards share it.
- **Facet choices and their order.** `types.ts` carries every filter's choices with counts, read for the filter shown. Forms, deities and categories go most entries first, then by label, and hold only values some entry carries plus the chosen ones, which sit at zero. Signs, celestial bodies and elements list all values, zeros included, in the vocabulary's order. Toxic comes as toxic, then not toxic.

## The Categories column

The column draws the shared `CategoryChips` ([`category-chips.md`](category-chips.md)) at `compact`. The page reads them in one batch (`readCardCategories`), so a category only a form carries shows here as on the card. The +N panel is fixed-position, so the table frame's scrolling neither clips it nor grows the row; `tests/e2e/admin-compendium.spec.ts` measures both, on a desktop table and a phone card.

## The Categories column floor

At a frame of 75rem or more the column is at least 16.75rem of content (plus the cell inset on each side). That is the widest row of chips any of the 313 seeded entries shows with the final compact, dot-less chips, measured in Chromium at a 16px root: Aspen's Ancestor Work and Communication with its +8 button and the row's 4px gaps, 266px (16.625rem), rounded up to the next 0.25rem. Narrower, the floor does not apply and the table scrolls instead of wrapping the chips; as a card the rule never applies and the chips wrap.

## The pinned Edit column

- **The Edit column stays at the table's right edge** while the others scroll beneath it, in the neutral `sticky-action-column` mixin ([`styling.md`](../styling.md)); as a card it is static again. The column is `$sticky-column-layer` (1, `_layers.scss`) and the +N panel is `layer('floating')`, so it passes over the pinned pencils beneath. The pencil's tip opens inside the cell's stacking context, to its left, so no later pinned cell reaches it.
- **A row stays on one line while the table is a table.** `data-table--nowrap` alone does not hold the two flex rows, so `.compendium-list__forms` and the Categories cell's chip row are set to `flex-wrap: nowrap` too (the chip rule is scoped to the Categories cell, so cards elsewhere still wrap). As a card they wrap again.

## The Reviewed filter and the shown switch

- **Reviewed.** The admin Reviewed chip ([`facet-panel.md`](facet-panel.md)) writes `?reviewed=1` for reviewed entries and `?reviewed=0` for those needing review. The admin page passes the curator's session to `listCompendium`, `countCompendium` and `compendiumFacets`, since the service refuses the filter, and leaves out the counts, for anyone who does not curate ([`../db/compendium-read.md`](../db/compendium-read.md)). The public list and a coven's list carry no `reviewed` and no `hidden`.
- **Hidden.** A Hidden chip writes `?hidden=1`, which the service reads as `listing: hidden`; the admin page asks for `listing: all` by default so a curator sees every entry.
- **The shown switch** (`ShownToggle`, `src/components/IngredientEntry/shown-toggle.tsx`) sets whether an entry is in the public compendium. Its thumb holds the Quick Look eye, whose upper lid comes down when hidden. The lid moves by a CSS transition on the path's `d` inside `@supports (d: path('M0 0'))`; Safari cannot, so there the shapes change at once from the markup's own `d`. While a save runs the thumb cross-fades to a loading ring only after 100ms, so a faster save shows no ring ([`../loading.md`](../loading.md), "Control").
- **Where it appears.** The admin entry's details carry it after Reviewed with the name "Shown in Compendium" and no visible label, saving on flip as the details have no Save. The public compendium's details have none. The entry page (`/compendium/ingredients/[slug]`) carries it after Reviewed for a curator or keeper, saving on flip with the normal refresh. A curator or keeper still reaches that page when the entry is hidden, through the uncached `readCompendiumEntryAsCurator` (the public read finds nothing first); the page is `noindex` with a Notice under the heading, and everyone else gets the 404 ([`../design-decisions/m14.35-curators-see-hidden-entry-pages.md`](../design-decisions/m14.35-curators-see-hidden-entry-pages.md)). The admin edit and add modals and the public compendium's edit modal carry it as a form field after Reviewed: a flip changes the form and writes nothing, Save sends it in the entry's own create or update, and Cancel drops it. An edit starts from the entry's `shown`; an add starts hidden when neither the entry nor any of its forms has a category, shown otherwise, and the curator's flip then wins. The input's `shown` is optional: left out, a create is shown (the column's default) and an update leaves the flag as it is, so the list row's and the details' flips are not undone by any other save. The entry's own mark and the switch that sets it are in its details ([`ingredient-entry.md`](ingredient-entry.md), "The details modal").

## The sort

The admin list sorts from the Name and Sourcing Score headings ([`data-table.md`](data-table.md), "Sortable columns"). The first click sorts Name A to Z and Sourcing Score lowest first, so the worst-sourced entries come first, ties broken by name. With no search the list is by name, A to Z, with the Name heading marked. Under a search the default is Best Match and no heading is marked; Best Match comes back by clearing the search, or from the phone select.

| URL                               | Order                         |
| --------------------------------- | ----------------------------- |
| no `sort`, no search              | Name, A to Z                  |
| no `sort`, a search               | Best Match                    |
| `?sort=name`                      | Name, A to Z                  |
| `?sort=name&order=desc`           | Name, Z to A                  |
| `?sort=sourcing_score`            | Sourcing Score, lowest first  |
| `?sort=sourcing_score&order=desc` | Sourcing Score, highest first |

`order` reverses whatever `sort` names, so a link to the first direction needs one parameter and an old `?sort=sourcing_score` link keeps meaning lowest first. An unknown value of either reads as absent. Each link keeps the filter and drops the page cursor and any open modal, so a change of order starts at page one.

The score is read in the same SQL query as the rows (`withSourcingScore`). At phone width, where headings are hidden, a Sort By select above the cards offers each column in each direction, with Best Match first under a search; it is drawn only once JavaScript runs, so without it the headings still sort on a wide screen. The score sort and the score are a curator's: the service refuses either from anyone else, and the public and coven lists carry no `sort` and no `order` (`publicParams` and `COVEN_PARAMS` leave them out). The score is computed in SQL ([`../db/compendium-read.md`](../db/compendium-read.md), "The sourcing sort"), and an entry's own score and its facts show in its edit dialog ([`sourcing-score.md`](sourcing-score.md)).

## The filter row

Its rules are the contracts above: a change in the panel is held and applies in one soft navigation on close; before hydration the panel is a native GET form; picking a name opens that entry's Quick Look over the list as shown; Clear All applies at once. While the panel is open its counts follow the held filter and the list and sentence do not move.

## The panel's counts

While something is held, the options, segments and chips show what the filter as held would list, not what the page drew. `useLiveFacets` (`live-facets.ts`) asks the public `compendiumFacets` query through `/api/graphql` (no session), with the held filter built through `COMPENDIUM_PARAMS.variables` from the `categories` and `vocabulary.deities` slug-to-id maps. The ask waits for the clicking to settle (`DEBOUNCE_MS`), is keyed by the variables so an answer for a filter since replaced is never shown, and keeps the previous answer on screen while the next comes. The chips show their placeholder while the ask is out. With covens held, the variables carry `covenIds`, and the service proves each id against the session the request carries, so the counts are of the entries those covens hold; with none, the answer is the cached, public one. The ask is off while the held filter equals the applied one, so the page's own counts show then. A failed ask leaves the page's counts in place. No resolver needed a DataLoader: the query is one request per ask.

## The compendium page

`src/app/(public)/compendium/page.tsx` draws the list per request over the cached reads (`readCompendium` and the rest take no session), so every card and link is in the server HTML. The viewer is asked only for the foot of each card, and never redirects.

- **Curator Edit.** A curator (`canCurate`) gets Edit on each card, which opens the compendium's edit dialog over the results from `?edit=<slug>` and closes back to the same search. `?edit=` is read only once the viewer is known to curate; for anyone else it opens nothing and reads nothing. The list's reads stay the cached, sessionless ones, keyed by the address alone.
- **Filters the page drops.** No Refs, No Form and Reviewed are the curators' to-do lists, so `?withoutReferences=1`, `?withoutForms=1`, `?reviewed=` and `?hidden=` are dropped before the table reads them. The services refuse a review filter from anyone who does not curate, so dropping it keeps the page from failing on one.
- **In My Covens and Not In.** In My Covens narrows the list to the entries the viewer's picked covens hold, any role. Not In (`?covensNot=1`) narrows it to the entries none of them holds, or with none picked, none of the viewer's covens. Only then, and only with a session, the list and its counts are read through the uncached held-in reads, which prove each coven and drop the rest (reading the cached ones when every coven is dropped). Otherwise, and for a visitor whatever the address says, the reads are the cached ones. Each card's plus or check counts and names every coven of the viewer's that holds the entry, including the ones they only view.
- **Quick Look.** Each card's Quick Look, for anyone, opens the entry's details over the results from `?entry=<id>`, read by id with no session through the public entry page's cached read: the compendium as the compendium has it, with no coven's label, annotations or held state. An id naming no compendium entry (a coven's own included) opens nothing and says nothing. A curator's Edit in the details opens the edit dialog over them and closes back to them.

## Styling

The table is [`StackTable`](data-table.md) and the pager `Pager` ([`pager.md`](pager.md)), soft. The formal name is plain, not italic: a binomial is italicised, a mineral's or chemical's name is not, and the row does not carry its kind.
