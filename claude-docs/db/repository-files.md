## The repository's files

`src/db/repository/` is one file per concern, and callers import only its `index.ts` (`@/db/repository` resolves to it). The folder lists itself; these are the placements that are not obvious from a name.

- **`index.ts`** holds named re-exports only, never a declaration and never `export *`, so what it names _is_ the surface `soft-delete-finder-guard.test.ts` reads its finders from.
- **`types.ts`** holds the table shapes a finder or writer admits, the options `selectFrom` reads, the `AuditWriter`, and what a finder takes and returns.
- **`predicates.ts`** holds `scopedTo`, `inCompendium`, `notSoftDeleted` (each decided by the table's shape), `inTiers` and `readableInTiers` (the two tiers read together), and the text matches `containsText`, `fold`, `caseFoldedEq` (two values equal under `lower`, with no trim), `trigramMatch` and `foldedWordMatch`.
- **`select.ts`** holds `selectFrom` and `existsIn`, the two places a read query is built, plus `existsByKey` (the live parent whose key column equals an outer column, which every finder with a parent-scoped EXISTS uses), `whenIds` and `forIds` (the one empty-id early return; `tests/guards/repository-shared-pieces.test.ts` refuses a bare one), `existsInIncludingSoftDeleted` (for `inUseIngredientParent` alone), `selectOne`, the keyset bounds, the similarity thresholds and `readUnder`, the transaction a read sets them in.
- **`write.ts`** holds `withAudit` and the writer it builds, spreading in the named writes of each table marked `namedWrites` from the file beside its finders (`writerFor`).
- **`unit-of-work.ts`** holds `currentWriteTransaction` and `runInWriteTransaction`, the store `withAudit` publishes its transaction in, so `selectFrom` reads on it.
- **`ingredient-parent.ts`** holds `readableIngredientParent` (a child row's parent ingredient read in its tier), `inUseIngredientParent` (the same read, also admitting a retired compendium entry the reading coven's cupboard names) and `inUseVariantParent` (a variant's row read through the variant to that ingredient).
- **`tokens.ts`** holds `hashToken`, the one place a link's token is hashed, so a caller that needs a view token's hash (the support view link, the seed) takes it from the index.
- **`finders.ts`** holds the generic finders and the page-and-count pairs every list is cut and counted by: `findPageInTiers`, `findPageInScope`, and `findPageInScopeIncludingSoftDeleted` (the same without the tombstone filter, for the coven Ingredients list alone).

### Why some repository files are apart

Each split keeps imports one-way. `ingredient-parent.ts` builds on `select.ts`'s `existsIn`, so it cannot sit in `predicates.ts`, which `select.ts` imports; `select.ts` builds queries for any table and names none. `grimoire.ts` is apart from `spells.ts` because `finders.ts` imports `readableSpells` from it and `grimoire.ts` pages through `finders.ts`. The `sorrel/module-boundaries` lint rule holds the one-way edges.

**The rest of the folder is internal, and that is enforced.** `selectFrom` and `existsIn` are exported from `select.ts` because the finders beside them build on them. What keeps them inside the folder is a `no-restricted-imports` group banning `@/db/repository/*` and `**/db/repository/*` everywhere (restated in each override, which replaces rather than merges), and the `sorrel/module-boundaries` lint rule (`lint/sorrel-lint.js`), which resolves every relative import in `src/` and fails any edge into the folder that is not its index. Import order is not load-bearing (["The seed module"](seed-module.md)).

### Why the ORM stays on its stable line

`drizzle-orm` follows the `0.45` line and `drizzle-kit` the `0.31` line (the stable dist-tags), and neither moves to a `1.0` release candidate. The `package.json` ranges are not exact pins, and Dependabot moves the patch. The stable line is effectively frozen and `1.0` is not GA, so moving would trade a stable-but-frozen dependency for a prerelease one.

- `npm audit` carries a standing moderate advisory (GHSA-67mh-4wv8-2f99), reached only through `drizzle-kit` → `@esbuild-kit/esm-loader` → a nested `esbuild ~0.18.20`. **It has no runtime exposure**: it concerns esbuild's _dev server_ accepting cross-origin requests, `drizzle-kit` is a build-time devDependency that never ships to Vercel, and nothing runs `esbuild serve`. `checks.yml`'s `audit` leg is non-blocking at every severity and only comments on the PR.
- Staying put is sustainable because `@pothos/plugin-drizzle`, which tracked the ORM's version, is gone. `drizzle-orm` is reachable only from the database layer and banned by lint everywhere else (["Where queries may be built"](repository-files.md)), so it is a query builder behind a choke point, not an architectural commitment.

**Revisit when any of these fires**, not before:

- `drizzle-orm` / `drizzle-kit` `1.0` goes GA on the `latest` dist-tag.
- `drizzle-kit generate` cannot express DDL a task needs. Partial unique indexes with predicates and a `lower(name)` expression, and multicolumn `gin_trgm_ops` indexes from `index().using('gin', …)`, are expressed without hand-editing; the only hand-edit a generated migration carries is an idempotency keyword (["Hand-written migrations"](migrations-and-scripts.md)).
- The advisory gains a runtime path, or escalates past moderate.

### Debugging a query

`make db-psql` (`docker compose exec postgres psql -U sorrel sorrel`) opens a prompt against the compose `postgres` service. `DEBUG_SQL=1` in the environment makes `connection.ts`'s Drizzle logger print every statement the repository emits, `withAudit`'s `set_config('app.current_user_id', …)` included; it is off by default. Full setup: `claude-docs/testing/debugging.md`.

### Where queries may be built

CLAUDE.md rule 4's other half, a SELECT built anywhere but the repository, is enforced by a second `no-restricted-imports` group in the same config entry, banning `drizzle-orm` and `drizzle-orm/*`. A Drizzle query cannot be built without importing the query builder at runtime, so banning the import bans the capability. `src/modules/*/services`, `src/graphql`, `src/app`, `src/components`, `src/lib` and every part of `tests/` outside `tests/db` (`tests/e2e/` included) fail `npm run lint` on a runtime import, whatever the finder is named. `allowTypeImports` keeps `import type` legal everywhere: a type import is erased at compile time and builds nothing.

The database layer is exempted by an `overrides` block matching `src/db/**/*.ts`, `src/modules/*/schema/**/*.ts`, `tests/db/**/*.ts`, `tests/modules/**/*.ts`, `tests/support/db/**/*.ts`, `scripts/**/*.ts` and `drizzle.config.ts`. Two oxlint behaviours shape it, and both are load-bearing:

- A rule set to `"off"` or `"allow"` inside `overrides` is **ignored**, so the exemption cannot be written as a disable. It is a narrower copy of the rule: the client group alone, without the query-builder group.
- An `overrides` block **replaces** the top-level rule config for the files it matches rather than merging. That is why the copy restates the client group verbatim: drop it and the whole database layer silently loses rule 2.

A green test suite would otherwise hide that second failure mode. `lint-db-client-boundary.test.ts` keeps one probe per rule and the exemption pin below. Its probes live in throwaway `__lint-probe__/` directories inside the repo (gitignored, removed once linted), not in `tmpdir`, because both rules are scoped by path and a file outside the tree matches no `overrides` block.

**What each rule makes impossible, rather than merely absent:**

| Rule                    | Impossible                                                                                                    |
| ----------------------- | ------------------------------------------------------------------------------------------------------------- |
| Client ban              | Reaching `db` — and so a transaction, or an unaudited write — outside the repository and the exempt files.    |
| Query-builder ban       | Building any query at all outside the database layer, including one that would skip `deleted_at IS NULL`.     |
| `selectFrom` unexported | Reaching an unfiltered read from inside the repository.                                                       |
| Access boundary         | A resolver, page or component reaching the repository, or anything under `src/db`, without passing a service. |

The access boundary is described in [`graphql/protections.md`](../graphql/protections.md), "The access boundary". Its second half, `server-only` on every service, stops a client component from importing a service at all.

### What a `sql` fragment is for

Inside the repository a Drizzle builder is used wherever one exists (`eq`, `isNull`, `gt`, `lt`, `ne`, `inArray`, `exists`), and a `sql` fragment means either that no builder says it or that a rule keeps it raw. Drizzle ships builders for every comparison, for set operators (`unionAll`, `.as()`), for joins and for the plain aggregates (`count`, `max`, …), and none for a function call, an expression, a cast or a row value. A reviewer should be able to place a fragment in this list, and one that is not obviously one of these carries a one-clause comment saying which it is:

| Fragment                                                                                                                                                                                                                                                                                               | Why it is raw                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| pg_trgm's `%`, `<%` and `similarity()`                                                                                                                                                                                                                                                                 | No builder; the operators are what the trigram index answers (["Fuzzy matching"](fuzzy-matching.md))                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| A function or expression: `lower(btrim(…))`, `unaccent_immutable(…)`, `greatest(…)`, `mode() within group (…)`, `json_agg(…) filter (…)`, `row_number() over (…)`, `now() - make_interval(…)`, `a \|\| ' ' \|\| b`, a `case`, a bare literal in a select list (`select 1`, the union's `0` and `null`) | No builder. The comparison _around_ one is still the builder's — ``ne(sql`btrim(…)`, '')``, ``lt(users.updatedAt, sql`now() - …`)`` — so a fragment holds the expression and nothing else                                                                                                                                                                                                                                                                                                                                                                                                                 |
| A row value and its casts: `(sort, id)` against `(cast(… as <the column's type>), …)`, `(…)::int`                                                                                                                                                                                                      | No builder for a row value, and the cast must be the column's own type (["Keyset pages"](keyset-pages.md)); the `>` and `<` are `gt`'s and `lt`'s                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `set_config(…, true)`                                                                                                                                                                                                                                                                                  | `SET LOCAL` with a bind parameter, which no builder issues (rule 3; ["Fuzzy matching"](fuzzy-matching.md))                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| A whole statement: the `union all` arms of a suggestion list, of `findSimilarIngredients`'s match or of `findCompendiumPage`'s search, a `Derived` source, the scalar subquery ranking a folk name, and the `not in (select …)` and `left join (select …)` inside them                                 | **Raw by rule, not for want of a builder.** Drizzle has `unionAll`, `.as()`, `.leftJoin()` and `notInArray(…, subquery)`, but each arm is a `.select(`, and the guard confines those to `select.ts`'s two builders. The arms' fields are the expressions above anyway, so building the frame would leave most of the tags where they are. The cost is the one `existsIn` closed for the four `EXISTS`: an arm's `notSoftDeleted` is by convention, inside a string the guard cannot read. Closing it means a third builder in `select.ts` that hands a union arm out filtered, argued for in its own task |

**A fragment that recurs is written once**, in `predicates.ts`: `fold` is `lower(btrim(…))`, the fold a suggestion, a list entry and a form compare under; `trigramMatch` is an autofill's `(text % query or query <% text)`; `foldedWordMatch` is a search's accent-folded `<%` and `word_similarity`, the spelling the `*_unaccent_trgm` expression indexes answer, with the `strpos` test of whether a field holds the query verbatim. `set_config` is written once per purpose too: the trigram thresholds in `select.ts`'s `readUnder`, which a similarity read and a keyset read both run under, and the actor's four settings in `src/db/audit.ts`'s `publishActor`, which `withAudit` and the seed share. A finder calls the helper, so a change to how a value is folded or matched is one edit.

**Not on the list** (use the builder or helper): `… is null` where `isNull()` serves; the compendium-tier predicate (`inCompendium`, and `inTiers` and `readableInTiers` for the proofs' covens); a correlated `exists (select 1 …)` (`existsIn`, ["Soft-delete filtering"](soft-delete.md)); and a comparison written into a string (`a > b`, `x <> ''`, `id in (…)`), where `gt`, `ne` and `inArray` take a fragment on either side. The schema files under `src/modules/*/schema/` are the other place the `sql` tag appears (index predicates, `CHECK` expressions, column defaults); they are DDL, `drizzle-kit`'s input, and this list does not govern them.

### Who may import the client

CLAUDE.md rule 2, only `src/db/repository/` may import `db`, is enforced by a `no-restricted-imports` entry in `.oxlintrc.json`. It bans every relative shape `connection.ts` can be reached by (`./connection`, `../connection`, `**/db/connection`, with or without `.ts`), type-only imports included, so a new importer fails `npm run lint` and the pr-gate lint job.

Exemptions are `// oxlint-disable-next-line no-restricted-imports` comments on the import itself, not config, because oxlint **ignores** a rule set to `"off"` or `"allow"` inside an `overrides` block, so a per-file exemption there would look like it worked and do nothing. Eight files carry one:

| File                                       | Why it needs a client, not a writer                                                                                                                                                                                                                                             |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/db/repository/write.ts`               | The choke point itself: `withAudit` opens the transaction every write runs in.                                                                                                                                                                                                  |
| `src/db/repository/select.ts`              | The choke point again: `selectFrom`, the one read query builder.                                                                                                                                                                                                                |
| `src/db/repository/provisional-users.ts`   | The one `users` hard delete, which runs outside `withAudit` (["The provisional-account delete"](identity-model.md)).                                                                                                                                                            |
| `src/db/repository/sign-in-failures.ts`    | The per-account counter of failed password sign-ins, outside `withAudit` because a failed sign-in has no session to take audit ids from.                                                                                                                                        |
| `src/db/repository/passkeys.ts`            | Removing a passkey unless it is the account's last way to sign in, one transaction under a lock, outside `withAudit` as the passkey plugin's own writes are, since `passkeys` has no audit columns.                                                                             |
| `src/lib/auth.ts`                          | Better Auth's `drizzleAdapter(db, …)` takes the Drizzle client. It runs its own inserts through its adapter and database hooks (`claude-docs/auth/admin-bootstrap.md`), so there is no session to hand `withAudit`; the user-create hook stamps `createdBy`/`updatedBy` itself. |
| `scripts/db-seed.ts`                       | The seed CLI constructs the handle it passes to `seed(db, …)`, which writes as the bootstrap user rather than through a session.                                                                                                                                                |
| `tests/db/test-database-isolation.test.ts` | The connection _is_ the subject: it asserts `db` points at this worker's `sorrel_test_<n>` clone.                                                                                                                                                                               |

`tests/guards/lint-db-client-boundary.test.ts` pins that set as exactly those eight and lints one deliberate violation per rule. A ninth turns the test red, so it has to be argued for in the diff. The violations are written at test time rather than committed as fixtures because oxlint skips anything matching the config's `ignorePatterns` even when the path is passed explicitly (`--no-ignore` does not override it), so a committed fixture would have to be lintable by `npm run lint` and would fail the very check it proves.

### Connection URL parameters

postgres.js's `parseOptions` deletes `sslmode`, reads the keys in its own defaults, and sends every other query parameter to the server verbatim as a startup parameter, which the server rejects with `42704`. `CLIENT_ONLY_PARAMS` lists the libpq keys it does not consume; it is listed, not derived, because deriving would read `node_modules` at runtime. Deliberately not listed: `sslmode` (consumed, mapped to `ssl`), `channel_binding` (the driver reads it, enforces `require`, defaults to `prefer`), `application_name` and `options` (real server parameters), and the keys postgres.js names itself: `connect_timeout`, `target_session_attrs`, `sslnegotiation`, `prepare`, `max`, `fetch_types`.

`withoutClientOnlyParams` strips rather than rejects because a hotfix's URL is written by Neon's Vercel integration, which rewrites the variable itself, so nobody can delete a parameter by hand. `channel_binding` is kept (the driver enforces it) and `sslmode=require` requests TLS. It imports nothing because scripts run directly under Node load it as well as Next. A URL with nothing to remove, or one `new URL` cannot parse, comes back unchanged so postgres.js reports its own error.
