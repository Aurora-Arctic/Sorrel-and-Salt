**N7.1 — Deploy a Hotfix Preview on a Database the Workflow Owns** · 6h

_Story:_ As the person shipping a hotfix, I want a hotfix preview that deploys on a database the workflow creates and removes itself, so that a fix can be checked on a live preview before it reaches production.

No dependency. The only hotfix preview run among the last 40 deploy runs (PR #1688, 2026-11-11) failed at the `migrate` job, so the `deploy` job was skipped and no preview address was posted. Two mechanisms choose the preview's database today: `migrate.yml` migrates whatever `POSTGRES_URL` the Vercel pull returns, and the running preview reads `DATABASE_URL` from Vercel. Neither workflow creates the Neon branch, waits for it, or checks it exists; both rely on the Neon and Vercel integration, and `design-decisions/data.md` records that this was never verified. Nothing deletes the Neon branch when the hotfix PR closes; the `teardown` job removes only the domain alias.

The task starts with diagnosis: push a throwaway `hotfix/*` branch and read the real migration error. The issue for MB.299 is closed, so the reason should now print; its entry in `claude-docs/tasks/v1/mb.md` may still read as open, and is corrected if so. Then `deploy.yml` creates the Neon branch itself with Neon's `create-branch-action`, which returns the existing branch on a second push, and sets an expiry as a backstop. The branch's direct address goes to `migrate`, and its pooled address is set as a branch-scoped `DATABASE_URL` in Vercel, the way staging's is pinned today, so one mechanism names the database for both the migration and the running preview. `teardown` deletes the branch with Neon's delete-branch action and removes the branch-scoped variable. The parent branch is production, because a hotfix branches off `main` and needs production's schema; the alternative, a schema-only branch with no real data, is in beta on Neon and is not used.

_Acceptance criteria:_

- The throwaway `hotfix/*` branch's migration error is read from the log and recorded in the PR body, and the cause is fixed or named
- A throwaway `hotfix/*` PR deploys a preview and posts its address
- A second push to the same PR reuses the same Neon branch and creates no second one
- One password sign-in completes on the live preview address
- Closing the PR removes the domain alias, the Neon branch, and the branch-scoped `DATABASE_URL` variable
- The branch-creation step sets an expiry, and `migrate` and the preview both read their database address from that step's output
- The Neon branch's parent is the production branch
- MB.78 is retired with `task-board retire` after the sign-in check passes, and not before
- `claude-docs/ci/deploy.md`, `claude-docs/design-decisions/data.md`, and `claude-docs/secrets.md` describe the new mechanism and no longer say the integration creates hotfix branches
- The docs that say a hotfix preview cannot complete a real sign-in are corrected: `claude-docs/auth/config.md`, `claude-docs/secrets.md`, `claude-docs/auth/plugins.md`, `claude-docs/auth/impersonation.md`, and MB.53's entry
