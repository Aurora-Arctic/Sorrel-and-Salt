**M17.1 — Scope Subscription Billing: The Stripe Spike and Its Task Breakdown** · 4h

_Story:_ As the owner, I want the plugin-or-SDK question settled by a spike against Stripe's test mode and the billing work broken into tasks, so that subscription billing can be scheduled as fast-follow work with its design decided rather than re-derived.

MB.79 wrote the five billing requirements and the Stripe plugin's fit against each into DESIGN.md §13, and left one question open until the work was scheduled: Better Auth's Stripe plugin, `@better-auth/stripe`, or a thin service over the Stripe SDK with audited tables of its own. This task closes that question the way MB.30 closed the organization-plugin question: by running both against Stripe's test mode in a throwaway branch, not by reading documentation. It then decides the billing data model within this schema (a billing reference on `workspaces`, the admin exemption flag, and where the entitlement check runs, all through `withAudit`), defines the multi-coven discount (whose invoice a member's other memberships reduce), and mints the billing tasks on Wave 17 — Fast follow. No billing code lands in this task: the spike branch is not merged, and the diff touches only Markdown and the board.

_Acceptance criteria:_

- A decision record at `claude-docs/design-decisions/m17.1-billing-plugin-or-sdk.md` names the choice between the Stripe plugin and a thin service over the Stripe SDK, states what the test-mode spike showed for each of the five requirements, and names the throwaway branch the spike ran on
- The record decides the billing data model: the column or table that ties a workspace to its Stripe customer and subscription, the admin exemption flag on `workspaces`, and the service where entitlement is checked, each written through `withAudit` with audit columns
- The record defines the multi-coven discount: which workspace's invoice a member's other memberships reduce, and how the discount is computed and applied
- Each piece of billing work is minted as its own `M17.n` task on Wave 17 — Fast follow with an estimate, a table task before every behaviour task that depends on it, and the tasks are named in the record
- DESIGN.md §13's Subscription billing subsection, its §14 row and §15 bullet say the decision is made and point at the record and the tasks; `claude-docs/backlog.md`'s V2 item moves to V Fast Follow and names the tasks
- `claude-docs/tasks/m17.md` and `claude-docs/waves/wave-17.md` carry the tasks and their order
- The diff touches only Markdown, `scripts/tasks-md.mjs` and the board; no dependency is added and no code under `src/` changes
