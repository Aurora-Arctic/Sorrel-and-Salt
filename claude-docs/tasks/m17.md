**M17.19 — Keep Only the Latest Drizzle Snapshot** · 2h

_Story:_ As a developer, I want the migration folder to hold only the files a migration needs, so that `src/` is not 80% generated schema snapshots that nothing reads.

`src/db/migrations/meta/` holds one Drizzle snapshot per migration, 137 files and about 740,000 lines — 80% of every line under `src/`. `drizzle-kit generate` reads the folder, checks each file's format and that no two share a parent, then diffs the schema against the newest one only; `drizzle-kit migrate` reads `_journal.json` and the `.sql` files and never opens a snapshot. Nothing else in the repo reads them: `scripts/check-migration-order.ts` and the PR gate read `_journal.json`. The only thing the old snapshots give is a historical diff, which git history gives anyway.

Two parts, in one PR: the one-off drop, and the mechanism that keeps the folder at one snapshot from then on. `npm run db:generate` becomes a wrapper (`scripts/db-generate.ts`) that runs `drizzle-kit generate` and then deletes every `meta/*_snapshot.json` except the one the newest `_journal.json` entry names.
