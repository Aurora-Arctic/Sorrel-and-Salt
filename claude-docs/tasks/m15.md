### Support

This task is numbered M15 because it was minted for Wave 15, on the owner's call (2026-10-13, during the Wave 11 review), and its subject belongs with no one milestone: how a person using the site reaches whoever runs it. [Wave 15](../waves/wave-15.md) runs it first.

**M15.1 — Scope a support form reviewed by admins** · 1h

_Story: As a person using the site, I want to send a question or a problem to whoever runs it from inside the site, so that I am not left searching for an address; and as an admin, I want those messages in one list I can work through, so that nothing is lost in a mailbox._

A scoping task, in the shape of MB.175's: it decides, records and mints, and builds nothing itself. The site has no way to be contacted today. The shape the owner asked for is a form whose submissions are rows in a database table, reviewed by admins on the admin section rather than mailed to them. The record it produces is `claude-docs/design-decisions/m15.1-support-form.md`, and each decision below is answered there, with its reason, before the build tasks are minted.

The decisions to make:

- **Who can submit.** The compendium is the one public surface (MB.80), so a signed-out reader may have a question too. Decide whether the form takes submissions from a signed-out visitor, with the spam exposure that brings, or only from a signed-in account, which is what every other write here requires.
- **The table.** Its name, and its columns: the sender (an account, or an address when signed out), a subject, the message, the page it was sent from, a status (open or resolved), who resolved it and when, and the audit columns every table spreads. Soft-deleted or hard-deleted, and whether a resolved row is kept. A support row is written by the person sending it, so decide how it goes through `withAudit` (rule 3) when the sender holds no session.
- **The form.** Where it lives — a route of its own, reached from the account menu and the public shell's footer — and what it asks for; the length limits; and whether it says anything back beyond "received".
- **The admin list.** A page under `/admin`, paged through the M3.6 helper (rule 8), newest first, open requests ahead of resolved ones, with the one action an admin needs: mark resolved. Whether an admin can reply from here at all, or only read, is a decision; v1 mails nothing back unless the record says so.
- **Abuse.** A limit on how many submissions one account or address may make in a period, and whether a signed-out submission is held for a check before it is listed.
- **What it is not.** Not the help and FAQ articles MB.175 scopes, and not a notes or moderation system (§13).

Then mint the build, each task its own PR, in the order the rules fix: the table task first (`CREATE TABLE` and its migration, nothing else), then the service and mutation under rule 1 and rule 3, then the form page, then the admin page, with the component docs and stories each page needs. Place them in Wave 15's row before M11.8, whose axe sweep scans every page, and before MB.124, the last design review, so that both cover them. Update `DESIGN.md` in the same PR: the table in §5, the mutation in §8's SDL, the routes in §9.
