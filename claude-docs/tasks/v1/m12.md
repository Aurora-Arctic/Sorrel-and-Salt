### Share cards

**M12.34 — Generate a share card for each public page** · 3h

_Story:_ As someone sharing a compendium entry in a chat or a post, I want the link to show a card naming the entry, so that whoever sees it knows what it is before opening it.

Today the public pages (`/`, `/compendium` and each `/compendium/ingredients/[slug]`) send Open Graph and Twitter text tags but no image (MB.84, `src/lib/page-metadata.ts`). The Open Graph protocol (ogp.me) lists `og:image` among its four required properties, and without it a shared link shows a plain text card. This task gives each public page an image.

The cards are generated, not drawn. Each is a Next `opengraph-image.tsx` file that builds a PNG with `ImageResponse` (read `node_modules/next/dist/docs/01-app/03-api-reference/04-functions/image-response.md` and the `opengraph-image` file-convention doc beside it, and cite them in the code comment). An entry's card shows its name, its formal name when it has one, and the site name, set in the site's two typefaces on a theme colour. `/` and `/compendium` get one site card. There is no photograph, so nothing needs licensing beyond the fonts. The card reads only the cached, sessionless compendium read, as the page does, so a coven entry's slug or an unknown slug gets no card (404), as the page does.

**Fonts.** The site's typefaces are Cormorant Unicase and Lexend, both under the SIL Open Font License 1.1 (OFL; `src/app/fonts.ts`, `claude-docs/styling.md`, "Type"). The licence allows graphics made with them, commercial use included: the OFL FAQ (openfontlicense.org/ofl-faq) 1.1.1 and 1.13 say a graphic made with an OFL font is not itself subject to the OFL, and 1.4 allows bundling in commercial software. Committing the font files to the public repo is distribution, so FAQ 1.20 applies: the copyright statement, the licence notice and the licence text sit beside the files, as `public/email/fonts/` already does for the email templates. `ImageResponse` takes only ttf, otf and woff (the same doc), so the email templates' `.woff2` copies cannot be reused. Download TTF copies of the weights the card uses from the typefaces' official sources and commit them with their OFL texts somewhere the server code reads and not under `public/`, since they are not served. Cormorant Unicase Bold comes from the `google/fonts` repository. Lexend comes from the static instances in its upstream repository, `googlefonts/lexend`: `google/fonts` ships it only as a variable font, and `ImageResponse`'s renderer, satori, throws reading a variable font's axes (`parseFvarAxis`). No font is fetched from Google at runtime. Where each file came from, and how the 500 KB limit on an image route's bundle is met, is in [`../../seo/share-card.md`](../../seo/share-card.md), "Fonts".

**Caching.** A card is drawn once per entry and served from cache after that, never drawn per request (the owner's call, 2026-10-19). What the Next docs say, read for this mint: the `opengraph-image` convention page says generated images are "statically optimized (generated at build time and cached) unless they use Request-time APIs or uncached data", that the file is "a special Route Handler that is cached by default unless it uses a Request-time API or dynamic config option", and that the `fetch` options and route segment options (such as `revalidate`) change this; `ImageResponse`'s page says the image can be made at build time or at request time. The docs read say nothing about cache tags, `Cache-Control` headers or `generateStaticParams` for these files, so the build does not assume them: it reads the card through the cached compendium read, which carries the `compendium` tag, so a keeper edit's `revalidateTag('compendium')` (`CLAUDE.md` rule 6) refreshes a renamed entry's card on that edit and not on a timer. If a tag does not reach an image route, the task finds from the docs and by trying what does, and records it. The response carries cache headers that let a browser and the CDN keep it. No workspace data is involved, so rule 6 allows this.

**The tags.** Once there is an image, `twitter:card` becomes `summary_large_image`, and `og:image` carries its width, height and alt text (the entry's name; the site name for the site card). `og:locale` stays at its default, on the owner's call (2026-10-19).

**Rule 1.** `CLAUDE.md` rule 1 names `robots.ts`, `sitemap.ts` and the public-file route handlers as routes that take no session. This task adds the image routes to that sentence, with the same condition: no session, and only what the public compendium already shows.

**The design**, approved by the owner: both cards are 1200 by 630 on the dark theme. The site card sets the site name in Cormorant Unicase above the tagline's first sentence in Lexend, over a shelf of seven jars drawn like the ingredient page's. The entry card sets the site name and a Compendium eyebrow at the top, the entry's name and its formal name in the middle, up to four of the entry's own categories as chips in their group's colour with a +N chip for the rest, and a band along the foot with one segment per group. It uses the ingredient's own categories only, not its forms'. The measurements are in [`../../seo/share-card.md`](../../seo/share-card.md), "The design".

**The owner signs off the card's look before the PR**, as a design-review task does: the task stops once the card renders, in both the entry and the site form, and the owner looks at them at the size a chat app shows them. The PR waits for that.

M11.16 no longer makes a share image. It sources the favicon, the app icons and the front-door mark, and records the fonts and this task's output in its ledger. This task lands first.

_Acceptance criteria:_

- `/`, `/compendium` and every compendium entry page declare `og:image` and `twitter:image` at an absolute URL, with width, height and alt, and `twitter:card` is `summary_large_image`
- An entry's card route answers 200 with a PNG for a compendium entry, and 404 for a coven entry's slug and for an unknown slug, asserted in e2e
- The card leaves out a hidden compendium entry (the `shown` column) in SQL, so a hidden entry has no public share card, asserted by a direct-slug test
- The card is drawn only from the cached sessionless compendium read
- Requesting the same entry's card twice draws it once, shown by state (a cache header or a build-time file, whichever the docs support), and a keeper edit to the entry's name refreshes it; the response carries cache headers a browser and the CDN can keep
- The font files are committed as TTF (or OTF), each with its OFL licence text and copyright beside it, and no font is fetched from Google at runtime
- `CLAUDE.md` rule 1 names the image routes
- `npm run lighthouse:seo` still scores 100 on the pages it audits
- The owner has signed off the card's look (signed off 2026-10-31)
