**M11.9 — Audit Every Wait Against the Loading Standard and Fix the Gaps** · 16h

_Story:_ As a user returning after a quiet week, I want every wait on the site to answer the moment I act, so that Neon's resume looks like a wait and never like a broken page.

Audit every data-backed route, and every client action that waits on the network, against the loading standard M12.33 set ([`loading.md`](../../loading.md); the record is [`ui.md`, "One Loading Standard for the Site"](../../design-decisions/ui.md#one-loading-standard-for-the-site)), then fix each gap found, in this task. The standard has three parts for a wait: the control answers at once, the changing region shows a skeleton, and the page bar shows after 100ms. It deliberately has no route-level `loading.tsx` and no route-level `<Suspense>`, because either would turn the guards' 404, 403 and redirect answers into a 200, and would break a page rendering without JavaScript ([`loading.md`](../../loading.md), "Why there is no `loading.tsx` and no route-level Suspense"). So this task adds neither: a first paint on a cold database is a server render, and the audit checks what the person sees after that, on each press.

The audit includes the `/admin/users` filter (folded in during MB.53, re-estimated from 2h). Since MB.53 the filter is a client component: Filter is disabled until the form differs from the filter shown, and a submit opens the filtered address as a full load, whose only feedback is the browser's own spinner. It gains a pending state: the button shows it is working from the submit until the filtered list arrives, whether that stays a full load or becomes a client-side navigation. (The page's address changes if M15.77 lands first.)

The estimate is 3h, up from 2.5h. The 2.5h priced writing skeletons for each route; M12.33 has since built the pieces and adopted them widely, so the fixes should be small, but the audit now covers every route and every client action, not only first paint, and the number of gaps is not known until it is done.

_Acceptance criteria:_

- A written audit lists every data-backed route and every client action that waits on the network, and for each says which of the three parts it has and which it lacks; it is kept in `claude-docs/` beside `loading.md`
- Every gap the audit finds is fixed in this task with the pieces `loading.md` names ("How to adopt it"), or is recorded in the audit with the owner's decision to leave it
- The `/admin/users` filter shows a pending state on its button while the filtered list loads, and a filtered page is still its own address (MB.52)
- No `loading.tsx` and no route-level `<Suspense>` is added, and the guards still answer with their own status codes
- Each fix is tested with an artificially delayed query, and respects prefers-reduced-motion
