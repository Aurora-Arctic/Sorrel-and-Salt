**M12.3 — Facet Counts for the Ingredient Search** · 3h

_Story:_ As a coven member or a visitor, I want to see beside each filter value how many results choosing it would give, so that I never filter my way to an empty list.

A facets read beside each list read, `compendiumFacets` and `workspaceIngredientFacets`, each taking the same filter as its list and returning `IngredientFacets`: per kind, a list of `{ value, count }`, the value being what that kind's filter argument takes (a category or deity id, a form, sign or planet name, an element or a toxic setting). OR kinds are counted with their own selection removed, so choosing Oil leaves Resin's count standing. Categories in All mode are counted with every selection applied, and in M8.12's Any mode like the OR kinds. Each kind is one grouped query over the filtered set, in SQL, and never a query per value. Fixed vocabularies, zodiac, planets, elements (M8.13) and toxic, come back whole with zero counts included; forms, deities and categories return the values with a count above zero plus any chosen value. The Compendium read takes no session and is cached under the `compendium` tag keyed by the filter; the workspace read runs under the Membership proof and is never cached (CLAUDE.md rule 6). The Compendium read returns `CompendiumFacets`, the seven kinds plus No Refs as one number, `withoutReferences: Int!`: the entries citing no live reference (MB.153) under every other part of the filter. The switch's off state is the list total, so it needs no count; the coven read does not take the switch and keeps `IngredientFacets`. Classification is counted nowhere, since it is leaving the search (owner, 2026-10-17).

_Acceptance criteria:_

- Choosing a form leaves the other forms' counts unchanged; choosing a category in All mode changes the other categories' counts, and in Any mode does not
- Workspace facets count local rows and no other workspace's: user D's call over W's filter returns no W value (The hiding rule described here is retired by M12.28; see `claude-docs/design-decisions/m12.13-cupboard-names-the-compendium-plan.md`.)

- Workspace facets pass through no `unstable_cache`
- The query count for one facets read is bounded by the number of kinds, asserted
- Soft-deleted rows and retired forms count for nothing
- `compendiumFacets.withoutReferences` equals the total the list read returns with No Refs on, asserted by running both
- Docs corrected: the GraphQL summary in `claude-docs/`
