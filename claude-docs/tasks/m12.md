### Folk names

This task is numbered M12 because it was minted for Wave 12, on the owner's call (2026-10-13), by the Wave 11 review, which found that no task owned the control that calls M8.3a's `promoteFolkName`. Its subject belongs with no one milestone: it extends a component M8 builds.

**M12.1 — Promote a folk name from the ingredient form** · 1h

_Story:_ As a workspace member, I want to promote a common name to an ingredient's display name, so that the label I see matches what I actually call it.

A promote control on each row of the folk-name list in `IngredientForm` (`src/components/IngredientForm/`). It calls M8.3a's `promoteFolkName` mutation, then refreshes the form with the swapped values: the server does the swap, and the form never juggles the list itself. On a compendium row the control's confirmation says the swap is global, because every coven sees it. The component's story and doc are updated under `.claude/rules/components.md`.

_Acceptance criteria:_

- The control promotes in one round trip, with no client-side list juggling
- A compendium row's control states the swap is global before it runs
- Viewers do not see the control
- It is keyboard operable
- Axe reports nothing at 375px
- M8.3a's story acceptance test passes

**M12.2 — Publish llms.txt and ai-catalog.json for the Compendium** · 1.5h

_Story:_ As an AI agent or search crawler, I want a plain description of the site and a machine-readable list of what it offers publicly, so that I can find and cite the Compendium without guessing at its structure.

Two static, public, read-only files describing the one public surface (MB.80). `/llms.txt` answers with Markdown in the llms.txt shape: an H1 with the site name, a one-line summary in a blockquote, and a link list to `/compendium` and one page per current Compendium entry. `/.well-known/ai-catalog.json` is a JSON file in the shape of the AI Catalog draft, listing the Compendium as one entry. Both read the entry list through the same cached Compendium read as MB.84's sitemap, with no session, and both are in `PUBLIC_ROUTES` in `src/proxy.ts`. They are route handlers that serve public files and carry no application data, as `/robots.txt` and `/sitemap.xml` do, so they are not a third access path. Off production, the proxy's `noindex` header (MB.84) covers both.

The AI Catalog spec is a draft, and one secondary source says a later version renamed the path to `/.well-known/ard.json`. The build reads the current spec first and records the path and fields it follows in a comment and in `claude-docs/`.

_Acceptance criteria:_

- A signed-out request to `/llms.txt` and to `/.well-known/ai-catalog.json` returns 200, and the proxy passes both through
- `/llms.txt` begins with an H1 and links `/compendium` and one `/compendium/ingredients/<slug>` per current entry; a soft-deleted entry and a workspace entry are absent, asserted with a seeded workspace ingredient that must not appear
- Neither file contains `/coven`, `/admin`, `/api` or any workspace-scoped name or slug
- `ai-catalog.json` parses as JSON and carries the draft's required fields
- The Compendium read takes no session and is cached under the `compendium` tag, so an admin mutation refreshes it
- Off production, both responses carry `X-Robots-Tag: noindex`
- `/robots.txt` does not disallow either file
- Docs corrected: the public-surface notes in `claude-docs/`, the `PUBLIC_ROUTES` list, and `claude-docs/backlog.md` line 14 ticked

### Search facets

Two tasks minted 2026-10-15 from the owner's backlog, numbered M12 because they were minted for Wave 12 on the owner's call. **M12.3 — Facet Counts for the Ingredient Search** · 3h

_Story:_ As a coven member or a visitor, I want to see beside each filter value how many results choosing it would give, so that I never filter my way to an empty list.

A facets read beside each list read, `compendiumFacets` and `workspaceIngredientFacets`, each taking the same filter as its list and returning, per kind, the values with their count under the filter plus that value. OR kinds are counted with their own selection removed, so choosing Oil leaves Resin's count standing. Categories in All mode are counted with every selection applied, and in M8.12's Any mode like the OR kinds. Each kind is one grouped query over the filtered set, in SQL, and never a query per value. Fixed vocabularies, zodiac, planets and toxic, come back whole with zero counts included; forms, deities and categories return the values with a count above zero plus any chosen value. The Compendium read takes no session and is cached under the `compendium` tag keyed by the filter; the workspace read runs under the Membership proof and is never cached (CLAUDE.md rule 6).

_Acceptance criteria:_

- For every kind, a value's count equals the total the list read returns with that value added, asserted by running both
- Choosing a form leaves the other forms' counts unchanged; choosing a category in All mode changes the other categories' counts, and in Any mode does not
- Workspace facets count local rows and no other workspace's: user D's call over W's filter returns no W value
- Compendium facets take no session and refresh after an admin mutation, through `revalidateTag`
- Workspace facets pass through no `unstable_cache`
- The query count for one facets read is bounded by the number of kinds, asserted
- Soft-deleted rows and retired forms count for nothing
- Docs corrected: the GraphQL summary in `claude-docs/`

**M12.4 — Facet Chips, Counts and the Search Sentence** · 5h

_Story:_ As a coven member or a visitor, I want to pick several forms, deities, signs and planets, set Toxic, see what each choice does to the count, and read one plain sentence saying exactly what is being searched for, so that filtering is predictable and never a guess.

On `IngredientSearch`, plugging into M8.13's URL state: a Forms multi-select typeahead with the chosen values as chips inside the control, a Deities multi-select grouped by tradition, Zodiac and Planets as chip rows, and Toxic as a three-way segmented control. Each value shows M12.3's count; a zero in a fixed vocabulary stays in place disabled, and a typeahead sorts zeros last. Above the results, one sentence built by a pure function from the filter, the vocabulary labels and the total, returned as typed fragments: it leads with the count, takes one clause per kind in a fixed order, joins values with "or" for OR kinds and "and" for all-mode categories through `Intl.ListFormat` in `en-GB`, uses templates that need no article before a vocabulary word, names categories as "in the Protection category", puts "the" before Sun and Moon only, and says "matching" for the text query. Each value in it is a link to the same filter without that value, Clear All ends it, and the sentence is the `role="status"` region. Admin-only clauses name Classification and No Refs. The public and coven lists lose Classification; the admin list keeps it. Server rendered, so the GET form still filters before hydration. The sentence function's test asserts its strings, the one named exception to the copy rule, while the component tests assert the status region's presence and update only.

_Acceptance criteria:_

- Two chosen forms list an entry holding either; a form and a deity together list only entries holding both, each proven by the rows shown
- Toxic has three states and the URL carries the chosen one
- Each value's count equals the total shown after choosing it
- Zero-count Zodiac and Planets values remain, disabled; the typeaheads list them last
- A status region sits above the results and updates on each change; each chosen value in it is a link that removes it; Clear All resets every facet
- The sentence function is unit-tested on its strings: lists of two and three with no serial comma, "the" before Sun and Moon, counts of zero, one and many
- Every facet is in the URL; reload restores the view; Back steps through changes
- Every facet still applies before hydration through the GET form
- Public and coven lists carry no Classification; the admin list keeps Classification and No Refs
- Axe clean at 375px; the Ladle story and `claude-docs/components/` doc updated
- Docs corrected: the search line under Feature Additions in `claude-docs/backlog.md` ticked

### Ingredient detail modal

Minted 2026-10-16 from the owner's backlog, numbered M12 because it was minted for Wave 12 on the owner's call. It sits after M9.12 and before M12.1, so the modal opens the finished ingredient form, and after M8.17, M8.19 and M9.6, whose edit modal, page content and list it composes.

**M12.5 — Open an Ingredient's Details in a Modal from Its Name** · 1.5h

_Story:_ As a coven member or a site admin, I want to click an ingredient's name in a list and read its details in a modal, with an Edit button where I am allowed to change it, so that I can look something up or fix it without leaving the list.

On the coven's Ingredients page (M9.6) and the admin's Compendium list, an ingredient's name opens a modal showing the content of the detail page (M8.19), built as one shared component so the page and the modal cannot drift. The name stays a real link to the detail page, so a new tab, no JavaScript and keyboard "open link" still work. The public `/compendium` page (M8.18) is unchanged: its names are plain links to the entry's page and open no modal, which keeps it static and crawlable (MB.80). The modal shows an Edit button to a site admin on a compendium entry and to a coven owner or member on their coven's own entry. Edit opens M8.17's `EditIngredientModal`, and a save refreshes the list and the details. The button is a convenience: the service still refuses everyone else (`CLAUDE.md`, rule 1).

_Acceptance criteria:_

- Clicking a name in the coven Ingredients list or the admin Compendium list opens a modal with the entry's details, and the name is still a link to its detail page (middle-click and no-JavaScript reach the page)
- The public `/compendium` page opens no modal: a name there is a plain link to the entry's page, and the page stays static with its list in the initial HTML
- The modal and the detail page render the same shared component, and nothing from M8.19 is duplicated
- Edit is shown to a site admin on a compendium entry, and to a coven owner or member on a coven entry; it is absent for a viewer, for a member looking at a compendium entry, and for a site admin looking at a coven entry
- Edit opens `EditIngredientModal`; saving updates the list row and the details in the modal, and closing with unsaved edits prompts as M8.17 does
- Direct-id test: a viewer, a non-member and a site admin are each refused by the service when they send the edit for a coven entry, and a member is refused for a compendium entry, with the preconditions asserted (the actor could see the entry), so the test fails without the guard
- Escape and the close button dismiss the modal and return focus to the name; axe clean, usable at 375px
- Docs corrected: the Feature Additions line in `claude-docs/backlog.md` ticked, the modal's Ladle story and `claude-docs/components/` doc added
