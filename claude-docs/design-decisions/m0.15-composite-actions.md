# M0.15 — port shared composite actions

**Status:** decided · **Date:** 2026-09-09

The task: copy resume-2026's five shared composite actions
(`checkout-to-app`, `job-summary`, `pr-comment`, `timer-elapsed`,
`timer-start`) unchanged, adjust any hardcoded repo name, and prove they
resolve and run from at least one workflow — while the workflows that will
actually depend on them for real (lint/format/typecheck in M0.16,
build/audit in M0.17, …) are explicitly later tasks.

## Decided

- **All five `action.yml` files are copied byte-for-byte.** `diff` against
  the fetched resume-2026 originals is empty. None of the five reference
  `resume-2026`, `mjoynes-wombat-web`, or any other repo name internally —
  they're generic (checkout-and-copy, timers, a step-summary writer, a
  github-script PR commenter parameterized entirely by its inputs).
- **The "hardcoded repo name" the task description warns about lives in the
  callers, not the actions.** `checkout-to-app` does the checkout itself, so
  it can't be referenced as a local `./.github/actions/checkout-to-app` path
  the way the other four are — `./...` resolves against
  `$GITHUB_WORKSPACE`, which doesn't have the repo in it yet at that point.
  resume-2026's own workflows work around this by referencing it via its
  full `owner/repo` path instead:
  `mjoynes-wombat-web/resume-2026/.github/actions/checkout-to-app@main`.
  Every workflow in this repo that calls `checkout-to-app` must use
  `Aurora-Arctic/Sorrel-and-Salt/.github/actions/checkout-to-app@main`
  instead — confirmed against `gh api repos/Aurora-Arctic/Sorrel-and-Salt`
  (`default_branch: main`, matching the `@main` ref resume-2026 used).
- **A new `.github/workflows/composite-actions-check.yml` is the "at least
  one workflow" the acceptance criteria ask for**, rather than reaching
  ahead into M0.16 (lint/format/typecheck) or M0.17 (build/audit). Those
  three-plus workflows are each their own task with their own acceptance
  criteria (e.g. M0.16: "fails when its check is deliberately broken",
  "runs inside the container"); porting one here to satisfy M0.15 would mean
  M0.16 either re-does it or inherits a workflow it didn't write against its
  own criteria. A small standalone workflow that only exercises the five
  actions keeps M0.15's surface to exactly what it's scoped to, and doubles
  as a permanent regression check for `.github/actions/**` independent of
  which specific checks currently consume it.
- **Triggers:** `pull_request` on paths `.github/actions/**` and the
  workflow's own file, plus `workflow_dispatch` for a manual run. Mirrors
  the `shared: &shared` path-filter anchor resume-2026's `pr-gate.yml` uses
  for the same purpose (rerun a check when the composite action it depends
  on changes) — scoped down to just this one workflow since the others
  don't exist yet.
- **Runs on bare `ubuntu-latest`, not a container.** resume-2026's real check
  workflows run `checkout-to-app` inside a `container: image: <testing
image>` job, whose Dockerfile `WORKDIR /app` gives it a pre-made,
  correctly-owned `/app` for `checkout-to-app`'s unconditional
  `cp -a "$GITHUB_WORKSPACE"/. /app/` to write into (plus `options: --user
root`, needed for `actions/checkout` to write the runner's `_temp` dir
  inside a container). That "testing" image is `build-image.yml`'s output,
  which isn't ported until M0.24. Rather than pull that dependency forward,
  the smoke workflow adds one extra step, "Prepare /app"
  (`sudo mkdir -p /app && sudo chown "$(id -u):$(id -g)" /app`), ahead of
  `checkout-to-app` — the hosted runner's default user has passwordless
  `sudo` but no write access to `/` otherwise. `checkout-to-app` itself is
  untouched; the workaround lives entirely in the calling workflow.
- **The verification step asserts the checkout side-effect, not just
  "the step didn't error."** It `test -f`s each of the five ported
  `action.yml` files under `/app/.github/actions/`, which only exist there
  if `checkout-to-app`'s copy actually ran — a stronger proof than trusting
  the composite action's own exit code.
- **PR comment only fires on `pull_request` events**
  (`if: always() && github.event_name == 'pull_request'`) since
  `workflow_dispatch` has no `github.event.pull_request.number` to comment
  on.

## Verified

- `npx js-yaml <file>` parses all five `action.yml` files and the new
  workflow with no errors.
- `diff` between each new `action.yml` and the file fetched from
  `repos/Aurora-Arctic/resume-2026` via `gh api` is empty.
- `grep -rn 'resume-2026\|mjoynes-wombat-web' .github/` finds nothing.
- **Not verifiable pre-push:** the workflow's actual run. Committing/pushing
  is `/create-pr`'s job, not this task's — the workflow is `pull_request`-
  triggered on `.github/actions/**`, so opening the PR for this same diff
  runs it for real and is the end-to-end demonstration. Confirm the
  `Composite Actions Check` run is green on that PR before merging.

## Rules this sets

- Any future workflow that needs `checkout-to-app` must reference it as
  `Aurora-Arctic/Sorrel-and-Salt/.github/actions/checkout-to-app@main`, never
  `./.github/actions/checkout-to-app` — the latter fails because the
  checkout it performs hasn't happened yet at that point in the job.
- `.github/workflows/composite-actions-check.yml` stays even after M0.16+
  land real consumers — it's a direct test of the shared actions themselves,
  not a stand-in for the checks that will also exercise them indirectly.
