# M9.17 — E2E specs tag the stories they walk, and the checklist shows them

> **Superseded by M9.1 (2026-10-16):** stories are proved by browser flows in `tests/e2e/stories/`, so the ` · browser` column this plan adds is gone. See `m9.1-stories-are-browser-flows.md`.

## Context

The owner asked whether the user stories should have Playwright tests too. They
do not, by design: DESIGN.md §11 makes the service-layer acceptance suite in
`tests/acceptance/` the definition of done, and layer-ownership rule 9 (MB.224,
2026-10-11) keeps Playwright to what only a real server can prove, with seven
named flows (M11.1 to M11.7) plus the axe sweep (M11.8) in Wave 15. MB.230 then
deleted the Playwright duplicates of Vitest flows, and MB.235 measured Playwright
as the gate's critical path.

What is missing is traceability, not a coverage rule. All seven M11 entries cite
stories, but no spec under `tests/e2e/` names one, and the stories checklist
(`npm run test:stories`) cannot say which stories have any browser proof. The
owner chose "trace, don't duplicate" (2026-10-12): keep rule 9 and the seven
flows, have each spec declare the stories it walks, and give the checklist a
browser-flow column so Wave 15 can aim the flows at the gaps.

**Standard tool:** Playwright test tags (`test('…', { tag: '@story-6' }, …)`),
supported since 1.42 and installed at 1.63. Tags appear in the JSON report
(`JSONReportSpec.tags`), in the HTML report, and filter a run
(`npx playwright test --grep @story-6`). No bespoke marker.

The implementation runs **in a worktree** (owner's instruction, 2026-10-12):
`/home/node/worktrees/m9.17-e2e-story-tags`, branch
`feature/m9.17-e2e-story-tags`, off a fast-forwarded local `staging`. `/app`
holds M6.7's uncommitted work and is not touched.

### 2. The checklist's browser-flow column

- **New** `tests/support/browser-flows.ts`: reads every `tests/e2e/**/*.spec.ts`
  from disk through `tests/support/paths.ts` (`fromRoot`), matches
  `/@story-(\d+)/g`, and returns `{ byStory: Map<number, string[]>, unknown: UnknownTag[] }`
  where the file paths are repo-relative. A text scan, not a Playwright
  `--list` subprocess: the stories config already reads DESIGN.md from disk the
  same way, and the scan needs no server config. A tag in a comment would
  count; review holds that, as it holds the describe names (MB.224).
- `tests/support/story-checklist.ts`: `buildChecklist` takes the browser map
  (default: the scan), adds `browser: string[]` to each story entry and a
  `browser` count; `unknown` gains the stray tags with their file.
  `formatChecklist` appends ` · browser` to a story with a flow, and the tally
  gains `N with a browser flow`. Stray tags print under "Not a v1 story" with
  the spec path.
- `tests/support/types.ts`: `StoryEntry.browser`, `Checklist.counts.browser`
  (or a sibling field), `UnknownSuite` widened or a sibling `UnknownTag`.
- `.github/scripts/summarize-stories.mjs`: mirrors the suffix and tally in the
  markdown checklist.
- `.github/scripts/summarize-playwright.mjs`: a second collapsible block,
  "Stories walked", built from `specs[].tags` of the JSON report: one line per
  tagged story in id order, folded as the checklist folds (any failing spec →
  failing). The one-line stat is unchanged.

No tests for the harness itself: MB.224 retired them, and a broken checklist is
seen by whoever runs it. No new Vitest guard for stray tags: the checklist's
"Not a v1 story" list is the report, held by review (rule 8).
