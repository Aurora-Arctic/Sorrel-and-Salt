# M8.5 — compendium and ingredient GraphQL queries

**Status:** decided and built. Only the decisions, the reasons and what they rule out are kept here.

## Decision

- **Rule 8** caps every list at 100 rows a page, so the client never holds the whole compendium (or a coven's ingredients), and a client-side filter cannot be _the_ search for either list.
- **MB.80** made `/compendium` a static ISR page with no request-time API, so a filtered view has to come from the browser through GraphQL — MB.80's own plan says so (C9, D10). MB.80 exposed the contradiction; M8.4/M8.10 vs rule 8 caused it. The public/admin split only shows up as M5.5 wanting a `nomenclature` filter the query lacks.

2. **Install `unaccent` now.** Extension + `IMMUTABLE` SQL wrapper + expression trigram indexes, inside this task. Neon supports `unaccent` (its dictionary is not editable there, which is exactly what keeps the wrapper honest).
   Also decided while planning: M8.5 runs **before** M5.2 in the execution order, so the compendium _read_ services are built here and M5.2 keeps the writes. The page sorts `(name, id)` — M8.14's `(lower(name), canonical_key, id)` needs a compound keyset the helper does not have yet. Superseded in part while building: MB.104, minted on the owner's question, adds that keyset to rank a search by its score, and M8.14 declares its parts on it. The task is bigger than its 2h: the entry will say so (~5h).

- `tests/modules/ingredients/schema/ingredients-indexes.test.ts` pins the exact index list ("exactly, not at least") — add `ingredients_unaccent_trgm`; `ingredient-folk-names-schema.test.ts` likewise if it pins the list.
  `CREATE EXTENSION IF NOT EXISTS unaccent;` then `CREATE OR REPLACE FUNCTION unaccent_immutable(text) RETURNS text LANGUAGE sql IMMUTABLE PARALLEL SAFE STRICT AS $$ SELECT public.unaccent('public.unaccent'::regdictionary, $1) $$;` — the dictionary named explicitly so `search_path` cannot change what the function means, which is what makes `IMMUTABLE` honest; a SQL-language function because `LANGUAGE c` needs superuser and `sorrel` is not one. `unaccent` is a trusted extension (PG13+), so the database owner may create it on Neon and in every test clone.
