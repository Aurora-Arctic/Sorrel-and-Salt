# M12.9 and M12.10 — undo and redo in the forms: the approved plan

**Status:** decided and built. Only the decisions, the reasons and what they rule out are kept here.

## Decision

1. **One stack per saved thing, newest first.** Ctrl+Z and the Undo button both undo the most recent change in the form, wherever focus is: the model every editor uses, one rule to learn. A reference panel saves itself, so it keeps its own stack. Focused-field-first undo and per-variant stacks were considered and set aside as unpredictable: the user cannot see the stacks, so could not tell which of three answers a press would give.
2. The form owns Ctrl+Z everywhere, including inside text boxes. Typing in one field is grouped into one step per pause of about half a second, or until focus leaves the field. The browser's own per-keystroke undo is suppressed inside the form so the two never fight.
3. Redo is Ctrl+Shift+Z and Ctrl+Y; on a Mac, Cmd+Z and Cmd+Shift+Z. Cmd+Y is not bound: it opens Chrome's history.
   Good UX and accessibility are requirements, not extras.
   Several diffs in one step happen when a change triggers a `setValue` in the same tick (picking the `none` nomenclature empties `canonicalName`, `IngredientForm/index.tsx:419`): one Ctrl+Z undoes the whole pick. Diffs rather than whole-form snapshots because the diff names tell the hook where to send focus, and because applying them with `setValue(name, before, { shouldDirty: true, shouldValidate: isSubmitted })` leaves errors, `submitCount` and field registration alone, where `reset` would clear or redo them. Newest-first application is what makes per-field writes safe: a step is only ever applied on top of the state it was recorded from. `setValue` on a field-array name notifies `useFieldArray` through `_subjects.array` (react-hook-form `_setValue`, `index.esm.mjs:2785`), so a removed or reordered row comes back. `shouldDirty` recomputes `isDirty` against the defaults, so undoing to the start disables Save and releases `useDiscardGuard`.
   `onKeyDown` on the `<form>`: return when `!enabled`, `defaultPrevented`, `nativeEvent.isComposing`, `altKey`, the target is inside an open combobox (`[aria-expanded="true"]`, downshift owns its keys), or `ignore(target)`. Then: `z` with Ctrl or Cmd → Shift ? redo : undo; `y` with Ctrl and not Cmd → redo. **Always `preventDefault`** for these chords inside the form, even with nothing to undo, so the browser's stale native stack never reverts a text box behind the form's back (after Save & Add Another, say); with nothing to do, announce that. Either modifier is accepted on every platform (no `navigator.platform`); Ctrl+Z is not native undo on a Mac, so nothing is lost.
   After applying a step: call `onRestored(names)` first so a closed section or card opens, then focus the `[name]` element of the step's first diff; for an array diff (a removed row, a reorder) focus the first control inside the fieldset that holds the array, else the array's legend's fieldset (`tabIndex={-1}`); if nothing is found, or the focused element went away, focus the Undo button, never `body`. Then announce: "Undid change to Name", "Redid change to Light Theme Colour", "Undid change to Folk Names", "Nothing to undo". The live region is labelled so it is told from the list fields' own regions.
   Forms are `mode: onSubmit`, `reValidateMode: onChange`. `shouldValidate: formState.isSubmitted` keeps that: no errors before the first submit, errors follow a restore after it. `submitCount` is untouched, so `useOnEachSubmit` and `useFocusFirstInvalid` do not re-fire. Server errors set by `setError` stay until the next submit, as they do after any edit.
   TDD, red first. Tests assert state (values, Save enabled, a status region present, a button disabled, where focus is), by role and label, never copy (layer-ownership rules 2 and 4).
4. **Reducer tests** `tests/components/Field/form-history.test.ts`: record, undo, redo, cleared; a new step after an undo empties the future; cap of 100; same-tick diffs join one step; typing extends within the pause and not past it or past a blur; a select pick never merges with typing.
5. **Docs**: `claude-docs/components/field.md` gets an "Undo and redo" section (steps, newest-first, keys, focus follows the undo, what is skipped, reset clears, `enabled`, `ignore` and `onRestored`, the always-preventDefault decision) and rows in its file table; `group-form.md` and `grouped-value-form.md` a line each; `modal.md` a note beside "Unsaved changes" and "A control in the header". No story: a hook is not a standalone component, and the forms' stories already render the buttons.
6. The reference panel (`reference-panel.tsx`, its own `useForm`) runs its own `useFormHistory` with its own `FormHistoryButtons` beside its Close control (`:376`); its handler stops propagation so the outer form never sees its chords.
