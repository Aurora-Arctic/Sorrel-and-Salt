# Plan: cut per-turn cost, write token-efficiency rules, make test output useful

## Context

Usage is burning faster than one session explains. `/context` showed ~42k tokens of fixed overhead per turn, and memory has since been pruned (~6.6k → ~3k). An Opus review of the first draft found that the two biggest levers are settings, not prose:

- The project's `.claude/settings.json:22-23` sets Opus and Fable to `high` effort. That overrides the owner's own `~/.claude/settings.json`, which sets them to `medium`, because project settings take precedence. Thinking tokens bill as output.
- The auto-compaction windows (Opus 200k, Fable 250k, everything else 500k) keep long, expensive contexts alive. Estimate: a long Fable session costs ~40% less per turn late on with a 150k window.
- The `CLAUDE.md` trim saves ~2.6k tokens per turn (`/context` units), which is 1–3% of a long turn. It's still worth doing, because `CLAUDE.md` is 22.8 KB, over its own 20 KB limit (`claude-docs/agent-skills.md:77`, `:108`).

Owner decisions: remove the effort overrides; lower the compaction windows moderately; split the rules between the project `CLAUDE.md` and `~/.claude/CLAUDE.md`; keep all 13 domain invariants and cut only detail.

## Part 3 — Token-efficiency rules (Task B, branches after A merges)

Each rule states a concrete default with its exception. Rules Claude cannot carry out itself (`/clear`, `/compact`, `/usage` are commands only the owner can type) become "suggest it to the owner".

**Project `CLAUDE.md`, a new "Spending tokens" section of about 6 lines.** It applies to any contributor's session and to subagents:

1. **Cap tool output.** A pass prints only its verdict. On a failure, read the failing part with `tail`, `grep` or `jq`. Read a file over ~300 lines by section, using `offset`/`limit`.
2. **Never mask an exit code.** Log to `.reports/<name>.log`, `echo "exit $?"`, then tail the log. Never pipe a build straight into `tail`.
3. **Verify once.** Run a single spec while iterating, and the full coverage, stories and e2e suites once at task end. Exception: the owner asks for more.
4. **Suggest `/clear` at a task boundary**, and `/compact` at a phase change.
5. **Flexibility clause.** Every rule here yields when the owner asks for the opposite, or when following it would thin a test (tests are the guardrails).

The long form goes in a new `claude-docs/token-efficiency.md`: why a long session costs more per turn, why agents start cold (~35–40k tokens of startup context each, an estimate), and the build-log recipe. Cite `claude-docs/testing/where-tests-live.md:423` for `env -u CLAUDECODE` rather than restating it.

**`~/.claude/CLAUDE.md` (personal, not in the repo)**, about 5 lines:

1. **Few agents.** Brief once, with paths and what is already ruled out. Send each follow-on step to the same agent with `SendMessage`. Split into lanes only when the work is genuinely parallel.
2. **Sonnet by default.** Use Opus only with a stated reason, or for test-writing lanes. This matches the memory note `feedback_agents_on_opus`.
3. **Don't poll** anything that notifies on its own, and don't loop on GitHub.
4. **Suggest `/usage`** when spend looks high.
5. The same flexibility clause.

Memory follow-up, outside any PR: once both files land, shorten the memory notes `feedback_agents_on_opus` and `feedback_test_quality_over_token_savings` to the owner's dated quotes plus a pointer.

Docs to update in Task B: `claude-docs/agent-skills.md:74-87` if the `CLAUDE.md` section list changes, and `claude-docs/commands.md`, where the Tests table gets the build-log recipe.

## Part 4 — Make Playwright output useful (Task C, independent)

Today the local e2e run uses the html reporter only, which prints nearly nothing, not even the text of a failure. This change makes failures visible as much as it makes output small.

- **`playwright.config.ts:101`:** when `CLAUDECODE` is set and `CI` is not, add `['dot']` to the reporters and keep `html`. This mirrors `vitest.config.mts:154`, and leaves the host developer and CI unchanged. Change the config, not the command line: a CLI `--reporter` drops the html folder (see the comment at `:61`).
- **`playwright.stories.config.ts:22`:** under `CLAUDECODE` only, use `dot` instead of `list`, and keep the custom checklist reporter. This config has no `CI` branch, so the condition is new.
  - `list` is still needed for the timing procedure at `claude-docs/testing/e2e.md:539-540`, which reads per-file `(2.6s)` suffixes. Either let `PW_REPORTER=list` override it, or point that procedure at `STORIES_JSON`.
- Use `dot`, not `line`: in a non-terminal shell, Playwright 1.64's `line` reporter prints one line per test.

  - Task C's Playwright check runs from its worktree on a free port (8200+), never on 8000.
  - **What can't go in a worktree:** `~/.claude/CLAUDE.md` and the memory notes live outside the repo, so they are edited in place, after Task B's wording is settled.
- **One Sonnet agent** does the edits. Each follow-on task goes to the same agent with `SendMessage`. The main session reviews and commits.
- No PR opens unless you ask.
