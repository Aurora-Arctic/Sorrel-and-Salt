# M0.12 — port `Docker/docker-compose.yaml`, drop the Gatsby LMDB volume

**Status:** decided · **Date:** 2026-09-08

`resume-2026/Docker/docker-compose.yaml` is two services — `development` and
`devcontainer` — on the three-stage Debian `Dockerfile.node`, with six named
volumes: a `node_modules`, a Gatsby `.cache` (LMDB), and a `/gatsby-public`
volume for each service. The task asked for a port that keeps `node_modules`
and drops the Gatsby LMDB cache volume. The Asana task added one item beyond
the milestone breakdown — a container for the Ladle workshop — which the
project owner confirmed should ship in this PR.

## Decided

- **Two services, `app` and `workshop`.** `app` builds
  `Docker/Dockerfile.node` `target: development` and serves `next dev` on 8000;
  `workshop` builds the same stage and runs `ladle serve` on 61000.
- **`workshop` is behind the `workshop` compose profile.** A bare
  `make docker-up` starts only `app` (and, from M0.13, Postgres); the workshop
  is opt-in via `make docker-workshop` (`docker compose --profile workshop
up`). It is the same-image companion you do not always want running — the
  common case is the app alone. `docker-build` / `docker-down` /
  `docker-rebuild` pass `--profile workshop` so they still build and tear it
  down.
- **No `devcontainer` service.** `Docker/Dockerfile.node` (M0.11) has only
  `development` and `testing` stages — its decision record explicitly rules a
  `devcontainer` compose service out of M0.12. `.devcontainer/` (M0.14) points
  at the `development` stage directly. With no devcontainer there is no Claude
  or GitHub token to inject, so the `docker-up` make target drops
  resume-2026's `update-token` prerequisite.
- **The Gatsby LMDB cache volume is gone, with nothing in its place.**
  `gatsby_cache_*` mounted at `/app/.cache` backed Gatsby's LMDB data store,
  which does not exist here. `next dev` writes `.next/` into the bind-mounted
  tree; that is fine — `.next` is git- and docker-ignored. A dedicated `.next`
  named volume was tried and reverted: a fresh named volume mounts root-owned,
  and `next dev` runs as `node`, so it needs the mount point pre-created and
  chowned in the Dockerfile the way resume-2026 did for `/app/.cache`. That is
  a change to M0.11's file; it waits for a task that actually needs `.next`
  container-side.
- **The `/gatsby-public` volume and `link-public.js` symlink workaround are
  gone.** Gatsby-only.
- **One `node_modules` volume per service** (`node_modules_app`,
  `node_modules_workshop`), mirroring resume-2026's separate
  `node_modules_development` / `node_modules_devcontainer`. A fresh named
  volume is populated from the mounting image on first use; two services
  sharing one fresh volume race to write the same files and one of them dies
  with `mkdir ... file exists`. Observed, then fixed by splitting.
- **`name: sorrel-and-salt` pinned in the file.** Compose otherwise derives
  the project name from the parent directory — `docker` — which
  `resume-2026/Docker/docker-compose.yaml` already claims on the same machine.
  Without the pin the two repos share `docker_node_modules` and clobber each
  other; this was observed (an M0.11-era stale volume shadowed the image's
  baked `node_modules`, and both containers exited `next: not found`).
- **No `command:` override on `app`.** `package.json`'s `dev` script is already
  `next dev --hostname 0.0.0.0 --port 8000`, and it is the Dockerfile `CMD`, so
  the container is reachable through the port map with nothing added.
  `workshop` does need `-- --host 0.0.0.0` — `ladle serve` binds `localhost`
  otherwise.
- **`workshop` publishes 61000 and 61002.** 61000 serves; 61002 is the pinned
  Ladle HMR socket (`.ladle/config.mjs`). 61001 (`ladle preview`) is a
  build-time port and is not mapped.

## Verified

- `make docker-up` on a clean machine starts `app` only; `curl` returns 200 on
  `http://localhost:8000`. `make docker-workshop` then adds `workshop`; `curl`
  returns 200 on `http://localhost:61000`. `make docker-down` removes both.
- `docker compose restart` leaves `node_modules_app` intact — 359 entries
  before and after, `node_modules/.bin/next` still executable.
- `docker volume ls` for the project shows only `node_modules_app` and
  `node_modules_workshop`: no LMDB / `.cache` / `gatsby_*` volume.
- `docker compose config` validates.

## Rules this sets

- **M0.13** adds the `postgres` service and volume to this file, wired to the
  `sorrel-node` image tag CI publishes (M0.18), and sets `DATABASE_URL` on
  `app`.
- **M0.14** builds `Docker/Dockerfile.node` `target: development` for
  `.devcontainer/`; there is no `devcontainer` service or stage to point at.
- A `.next` (or other root-owned) named volume added later must come with the
  matching `mkdir`/`chown` in `Docker/Dockerfile.node`.
