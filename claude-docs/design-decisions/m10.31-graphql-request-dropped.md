# M10.31: graphql-request dropped for a fetch wrapper

## What §7 chose

`DESIGN.md` §7 chose `graphql-request` as the browser's way to send a GraphQL
document, with TanStack Query caching the answer. It was picked as the small,
well-known client: it posts the query and throws when the response carries
`errors`.

## Why it was dropped

- **It is the old name of a project that moved on.** `graphql-request` is now the
  "old version" of Graffle, kept on a branch with occasional releases. Its last
  release, 7.4.0 (December 2025), accepts `graphql` 14 to 16 only, and a range
  that takes 17 is unlikely to come.
- **It held `graphql` at 16.** One copy of `graphql` in the tree avoids the
  "Cannot use GraphQLSchema from another module or realm" failure, so a single
  package that stops at 16 keeps all of them there.
- **The repo used two things from it:** `request()` and the `ClientError` class.
  It never used batching, `gql`, `rawRequest` or a custom `fetch`.

## What replaced it

`src/lib/graphql-client.ts` now holds the whole client. `send()` calls the global
`fetch` with a POST of `{ query: print(document), variables }`, `content-type:
application/json` and `accept: application/graphql-response+json,
application/json`, the same `accept` value `graphql-request` sent, so Yoga's
status codes are unchanged. It throws `GraphQLClientError` (`status` and the
response's `errors`) when the status is not OK, the body carries `errors`, or
there is no `data`; a partial answer still never resolves. `fetch` is looked up on
every request, so a story or test can stand in for `window.fetch`.
The class sits in `src/lib/graphql-client-error.ts`, apart from the client, so a component test that stubs the client does not take it away. `graphql-failure.ts` reads that class instead of `ClientError`; the rules for
retrying and for placing errors on a form are unchanged.

`DESIGN.md` §7 (the **Client** line) and the §14 row on `userErrors` now name the
wrapper; the rest of each argument stands.

## What this leaves

The `graphql` pin now waits on `@escape.tech/graphql-armor` alone (`^16.10.0`,
issue #885). See [`graphql/graphql-pin.md`](../graphql/graphql-pin.md).
