# M3.8 — React cache() wrapper and the server read path

**Status:** decided and built. Only the decisions, the reasons and what they rule out are kept here.

## Decision

1. **`cache()` keys object arguments by identity** (`react.react-server.production.js`: objects go in a `WeakMap`, primitives in a `Map`). A wrapper taking `(session, workspaceId)` dedupes only if both callers pass the _same_ `Session` object — true via `getSession()`, false for `asUser()` and for any caller that rebuilds the session. So the cache key must be **primitives**: the cache goes around the role lookup _inside_ `assertMembership`, keyed on `(userId, workspaceId)`, not around a new `(session, workspaceId)` export. Every current and future caller of `assertMembership` then gets the dedupe with no per-task adoption, whatever permission it asks for.
2. **Route Handlers have no React cache dispatcher.** Nothing under `next/dist/server` calls `getCacheForType`; only the Flight renderer does. Without `ReactSharedInternals.A`, React's `cache()` is `fn.apply` — a pass-through. On the GraphQL path `cache()` is therefore inert and DataLoader (rule 9) is the dedupe. The doc must say this rather than claim memoisation on both transports.
3. **Dedupe is only observable inside a Flight render**, and loading the Flight server needs the `react-server` export condition. A probe (since deleted) proved it works under Vitest with `ssr.resolve.conditions/externalConditions: ['react-server']`: one render → one call, second render → second call, and fails without the condition ("The `react-server` condition must be enabled"). The `db` project cannot take the condition globally: `react-dom/server` resolves to a file that throws under it, and `tests/db/email-verification.test.ts`, `tests/services/admin-role.test.ts`, `tests/services/provisional-accounts.test.ts` import `@/lib/auth` → react-email → `react-dom/server`. So a small third project, `rsc`, carries the render test.

- Comment (conclusion only, argument in the doc): keyed by the two ids because `cache()` compares objects by identity; scoped to one server render, a pass-through in the GraphQL route handler where DataLoader batches instead.
  "Mutations never take the server read path" has one mechanical hole lint cannot see: a `'use server'` directive is not an import, so M3.9's `no-restricted-imports` rules will never catch a server action. This guard scans `src/**` (tracked and untracked, `slug-rule.test.ts` style since it reads contents) and fails on `'use server'` / `"use server"`. Precondition assertion: the scan found `src/app/api/graphql/route.ts` (so an empty scan cannot pass).
- Why the count is of `findWorkspaceRole` calls, not of Postgres statements: `src/db/repository.ts` is the only importer of the client (rule 2), so a repository call _is_ a Postgres round trip; the render test can therefore mock the repository and stay off Postgres.
