# M0.10 — porting Claude skills from resume-2026

**Status:** decided · **Date:** 2026-09-08

The task said "port the ones that apply — testing conventions, component
documentation, commit and PR conventions, CI debugging". Taken literally that
list does not exist: `resume-2026/.claude/skills/` holds six skills and every one
is Gitflow branch/PR workflow. This note records what "applies" was read to mean.

## Decided

- **Port all six Gitflow skills as-is** (`create-feature`, `create-hotfix`,
  `create-main-sync`, `create-pr` + `reference-hotfix.md`, `create-release`,
  `prune-branches`). They cover the "commit and PR conventions" item and match
  this repo's Gitflow lane exactly.
- **Do not create skills for the other three items.** "Testing conventions",
  "component documentation" and "CI debugging" are `claude-docs/` prose in
  `resume-2026` (`CI-SETUP.md`, `ACCESSIBILITY.md`, `components/`), not skills.
  This repo already carries the equivalents — the Testing section of `CLAUDE.md`
  and `claude-docs/`. A skill shell with no ported content would be indirection
  pointing at documentation the repo already has.
- **Create `.claude/settings.json`** with the `permissions.ask` block. The skills
  tell the reader to expect a confirmation prompt on `git push origin *` and the
  `gh pr` calls; without the file that instruction described nothing. Scoped to
  exactly those entries — no `permissions.allow`, no MCP config (that stays in
  the personal `settings.local.json`).
- **Name `CLAUDE.md` as the Gitflow source of truth, not `gitflow.yml`.** The
  enforcing CI workflow does not exist until M0.17/M0.20. The skills say "until
  then, `CLAUDE.md`; after, the workflow" so they are accurate today and point
  the right way once the workflow lands.

## Rules this rules out

- A later task adding `.github/workflows/gitflow.yml` (M0.17/M0.20) **must**
  revisit `create-pr`, `create-release`, `create-main-sync` and
  `reference-hotfix.md` to tighten the "until then" hedges — see the closing
  note in [`../agent-skills.md`](../agent-skills.md).
- If a genuine testing/CI/component skill is later written (ported or new), it
  goes in `.claude/skills/` and gets a row in `CLAUDE.md`'s Skills table and an
  entry in [`../transcripts/agent-skills.md`](../transcripts/agent-skills.md).
- `.claude/settings.json` is shared config. Personal permission grants stay in
  `.claude/settings.local.json`.
