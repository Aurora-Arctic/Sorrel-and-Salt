# M0.32 — Stories for every component already in the tree

**Status:** decided · **Date:** 2026-09-08 · **Builds on:**
[m0.31-workshop-theme-decorator.md](./m0.31-workshop-theme-decorator.md),
[m0.30-ladle-component-workshop.md](./m0.30-ladle-component-workshop.md)

Every `src/components/<Name>/` directory gets an `index.stories.tsx` covering its
meaningful states. When this task ran, the tree held exactly one component —
`ThemeToggle` (M0.29) — so the core of the task is that one file, enriched from
M0.30's single-render smoke test.

Alongside it, this task also brought `_typography.scss` into the workshop
(scoped, reversing an M0.30/M0.31 call) and added a **design-language reference
page** in `.ladle/` — a single place that renders the type scale, colour tokens,
category-group colours, chips, badges, the raised panel and the focus ring from
the real partials. Both are covered below.

---

## Per-story theme is pinned through `.meta`, read by the M0.31 decorator

`ThemeToggle`'s meaningful states include "light selected" and "dark selected".
The M0.31 decorator already drives the theme for the whole story frame from
Ladle's toolbar control and remounts the story on a change — but a reviewer
opening the `Light` story shouldn't have to also flip the toolbar, and a story
can't set `globalState.theme` itself.

Ladle passes a story's `.meta` object to the `Provider` as `storyMeta`. M0.31's
decision doc had already named "an opt-in per-story parameter" as the extension
point for exactly this. So M0.32 adds ~3 lines to `.ladle/components.tsx`: if
`storyMeta?.theme` is `'light'` or `'dark'`, the decorator uses it instead of
`globalState.theme` — for both the `applyTheme()` call and the remount `key`.

- A story pins with `Light.meta = { theme: 'light' }`. Ladle requires `.meta` to
  be an object literal and JSON-serializable; a bare `{ theme: '…' }` is both.
- A pinned story ignores the toolbar (the toolbar does nothing while it's open).
  That's intended: the story _is_ that theme.
- `Default` and `ReducedMotion` set no `.meta`, so they follow the toolbar
  exactly as before.

This is the only change outside the story file, and it's infrastructure M0.32's
acceptance criteria require rather than an adjacent task.

## `ReducedMotion` renders no prose, and is a plain component render

`prefers-reduced-motion: reduce` is a media feature — a story can't force it
(no class, no attribute, activates only from the OS or DevTools rendering
emulation). So `ReducedMotion` renders exactly like `Default`; its reason for
existing as a separate, linkable story is carried in the source comment, visible
through Ladle's source addon.

It renders no explanatory `<p>` of its own — the reason it exists is in the
source comment, not the DOM — but prose in a story is no longer a problem to
avoid: the "keep `_typography.scss` out of the workshop" call is reversed below.

## `_typography.scss` is in the workshop now, scoped to the story frame

M0.30 and M0.31 kept `_typography.scss` out. Imported globally it dropped bare
element rules — `h1`/`p`/`a`, `section`/`header` margins, `ul { list-style: none;
li::before { content: '◆' } }` — onto Ladle's own `<ul>`/`<li>`/`<a>` sidebar
and toolbar chrome. Both tasks noted the fix was "scope it to the story frame"
and left it.

M0.32 does that. `_typography.scss`'s rules became a `typography-base` mixin
that emits nothing on its own; the caller decides what selector they hang off:

- `src/app/globals.scss` — `body { @include typography-base; … }`. Same rules
  the app always had, one `body` ancestor deeper (`h1` → `body h1`, so
  specificity 0,0,1 → 0,0,2). Component class styles are ≥ 0,1,0 and still win;
  nothing in the app leans on beating a bare element selector with another.
- `.ladle/typography.scss` — `.ladle-story-frame { @include typography-base; }`.
  Every story now renders headings, body copy and lists exactly as a page does,
  and Ladle's chrome (outside `.ladle-story-frame`) is untouched.

The rules live in one place; only the selector differs. This is the change the
user asked for on seeing M0.31's decision — prose belongs in the workshop.

Two things about headings changed while it was open, both app-wide via
`globals.scss`, both at the user's direction:

- **Weight** — all four levels now run at `font-weight: 700` (was 600).
  Cormorant Unicase is a high-contrast display face with delicate hairlines that
  thin out the smaller it's set and the darker the ground — 600 read light on
  dark. A size-ramp (h1/h2 at 600, h3/h4 at 700) was tried first and wasn't
  enough; flattened to 700, the face's heaviest (no variable axis;
  `src/app/fonts.ts` loads 500/600/700). Nothing above 700 exists for this face
  — if headings still read light, the display face is the lever, which is an
  M0.6 decision.
- **Scale** — anchored at `h4 = 1.5rem` and stepped up ~1.2: h3 `1.8rem`, h2
  `2.15rem`, h1 `clamp(2.5rem, 5vw, 3.75rem)`. The old scale bottomed out at
  `1.125rem`, which set the smallest headings too close to 1rem body copy.

Also in the shared partials, same PR, same direction:

- `badge()`'s `font-size` 0.75rem → **0.8125rem** (matches `chip()`).
- **Safety badge fill desaturated** — `$saturation` on the `$wax` adjust dropped
  36% → 22% (dark) and 35% → 22% (light) so it reads as sealing-wax rather than
  fluorescent. Only saturation moved; lightness is untouched because the
  near-black label has ~0.2 of contrast headroom on the fill. New fills
  `#df4e37` / `#a02c1a`; all four pairings still clear AA (4.71 / 4.28 dark,
  6.02 / 6.69 light). The M0.7 decision doc carries an "Amended M0.32" note with
  the updated table.
- **`$font-mono`** added to `_variables.scss` and a `code` / `kbd` / `samp` rule
  to `typography-base`. The reference page was hand-rolling monospace on its
  token-name / hex / slug spans; those are now `<code>` elements styled by the
  app partial. The app will want incidental `<code>` (token references, error
  detail) too — a platform UI-monospace stack, no webfont. This is the
  principle "styling lives in the app `.scss`, not the workshop file" applied:
  everything the app _could_ own now does. What stays local to
  `design-language.scss` is layout lengths (no spacing/radius token exists) and
  the `.dl-eyebrow` overline / `.dl-btn` button / `.dl-binomial` — treatments
  the app has no primitive for and that M0.6–M0.8 deliberately didn't build.

### Fonts

The app self-hosts Cormorant Unicase + Lexend through `next/font`, which defines
`--font-display` / `--font-body` on `<html>`. The workshop has no `next/font`, so
those custom properties were undefined — and `$font-heading` / `$font-body`
_start_ with a bare `var(--font-display)` / `var(--font-body)` with no fallback
inside the `var()`. An undefined `var()` with no fallback is invalid at
computed-value time: it doesn't fall through to the quoted `'Cormorant Unicase'`
/ `'Lexend'` next in the stack, it discards the whole `font-family` declaration.
So every element rendered in Ladle's default font.

Two parts to the fix, both in `.ladle/`:

- `.ladle/head.html` (a file Ladle injects into `<head>`) loads both faces by
  name from Google Fonts, weights matched to `src/app/fonts.ts`.
- `.ladle/typography.scss` defines `:root { --font-body: 'Lexend';
--font-display: 'Cormorant Unicase'; }` — the workshop's stand-in for what
  `next/font` does on `<html>` — so the `var()` resolves and the loaded faces
  are actually used.

Dev-workshop only; the app never contacts `fonts.googleapis.com`, and
`workshop:build` output is gitignored and CI-only. (The `var(--font-*)` with no
fallback is a latent app bug too — any component rendered outside the root
layout hits it — but hardening `_variables.scss` is out of scope here.)

## The design-language reference page — and why it lives in `.ladle/`

A single page rendering every shared primitive at shipping size: the raw palette
(the eight hand-picked hues, fixed hex, each with its purpose) and the runtime
`var(--token)` layer (each with its purpose) it's `color.adjust()`ed into, the
type scale, the eight `--group-*` colours as `chip()`'s two states, both
`badge()` palettes, `modal-surface()`, `focus-ring()`, and an "everything at
once" ingredient-card specimen. It reads the real `_variables.scss` /
`_mixins.scss` / `_typography.scss` — no value is re-typed (the raw hexes are
hardcoded on purpose: they're compile-time constants, not `var()`s). It's the
in-repo successor to the throwaway M0.6 / M0.7 exploration artifacts.

It is **not** a component and the app never imports it, so it lives at
`.ladle/design-language.{tsx,scss,stories.tsx}`, not `src/components/`. Putting
it under `src/components/` would have needed no config change (the `stories`
glob already covers that path) but would have added a non-component to the
directory that the M0.33 gate polices and that every "what components exist"
read has to special-case. Instead the `stories` glob became an array —
`['src/components/**/index.stories.tsx', '.ladle/*.stories.tsx']` — which
**reverses M0.30's acceptance criterion** "stories are discovered only at
`src/components/**/index.stories.tsx`". M0.33's gate is still "a component
directory with `index.tsx` needs a sibling `index.stories.tsx`"; the `.ladle/`
location is the one known exception, called out in `config.mjs`.

`design-language.scss` holds nothing the app needs — reference-page chrome plus
a hand-rolled `.dl-btn` (buttons are a deliberate future redesign, not
prototyped here). Everything shared is `@include`d from `src/scss/`, never
redefined. The whole file nests under `.dl`: because `.ladle/typography.scss`
scopes `_typography.scss` to `.ladle-story-frame`, a bare `p` on the page is
`.ladle-story-frame p` at (0,1,1), which outweighs a plain `.dl-eyebrow`
(0,1,0) — the eyebrows, captions and the binomial were silently losing their
size/weight until every rule was lifted to (0,2,x). No `index.test.tsx`: it's a
static page with no behaviour, and `workshop:build` in CI (M0.33) is the smoke
test — a throw fails the build.

Three stories — `Default` (follows the toolbar), `Light` / `Dark` (pin a theme
via `.meta`, reusing M0.32's per-story pin). Render-only, no test ids, no
snapshots.

## No test ids, no snapshots, no assertions

The stories only render. `ThemeToggle`'s behaviour — click-to-light/dark,
`aria-pressed`, the facet swap, listener cleanup — is already covered by
`index.test.tsx` with role and label queries. A story that re-asserted it would
duplicate that suite and, per [`CLAUDE.md`](../../CLAUDE.md), stories carry no
test ids and no snapshots.

## Verified

- `npm run workshop:build` exits 0; `build/meta.json` lists `themetoggle--*`
  (default/light/dark/reduced-motion) **and** `design-language--*`
  (default/light/dark). The story bundles carry `theme:"light"` / `theme:"dark"`
  — the pins reach the decorator. Built CSS shows `.ladle-story-frame h1 { … }`
  and the `◆` list marker scoped to `.ladle-story-frame` (not leaking to Ladle
  chrome), and `.dl-badge--safety` / `.dl-chip--protection` resolved through the
  M0.8 mixins.
- `npm run lint`, `npm run format:check`, `npm run typecheck` pass. (`tsconfig`
  doesn't reach `.ladle/`, so `tsc` skips `design-language.tsx` — Vite/esbuild
  compiles it in the build; oxlint lints it and is clean.)
- `src/app/globals.scss` compiles; the app's prose rules are unchanged apart
  from the `body` prefix.

## What this commits later tasks to

- **M0.33** adds the gate that fails a component directory with `index.tsx` and
  no `index.stories.tsx`. `ThemeToggle` is covered, so the tree is clean for it.
  The gate stays scoped to `src/components/`; `.ladle/*.stories.tsx` is a known
  non-component location and doesn't feed the "needs a story" check.
  `workshop:build` goes into the CI build job and the PR gate.
- A component whose meaningful states need something the frame can't express
  per-story yet (a forced viewport width, an RTL flip, a mocked date) extends
  the `storyMeta` read in `.ladle/components.tsx` the same way `theme` was added
  here — or uses Ladle's own built-in addons where they cover it.
- `typography-base` is the one definition of the document prose rules. A change
  to headings or body copy is one edit; the app and the workshop both follow.
- The design-language page is the place a new token or mixin gets a specimen —
  M0.7's group colours, M0.8's chip/badge/modal-surface already have one; a
  future spacing scale or elevation set adds a section rather than a new page.
