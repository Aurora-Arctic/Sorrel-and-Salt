# M0.23 — `.actrc` and `make act-*` (local CI via act)

**Status:** decided · **Date:** 2026-09-08

The task: port `resume-2026`'s `.actrc` and `make act-*` targets so the real
reusable check workflows run locally through [`act`](https://github.com/nektos/act),
"adjusting image references if needed", so CI debugging doesn't require pushing.

## Decided

- **`.actrc` is `resume-2026`'s two directives, verbatim.** Its whole content
  there is `-P ubuntu-latest=catthehacker/ubuntu:act-latest` and
  `--pull=false`; this repo's copy adds only a comment header.
  `catthehacker/ubuntu:act-latest` is the closest public match to GitHub's
  `ubuntu-latest` runner and is multi-arch (amd64 + arm64), so it also runs
  on Apple Silicon. `--pull=false` leaves the first-use image pull to Docker
  and skips a registry round-trip on every later `make act-*`.

- **`make act-*` ported for lint, format, typecheck** — plus `act-image`,
  `act-cache-checkout`, and an `act-test` aggregate. `act-vitest` /
  `act-playwright` from `resume-2026` arrive with `vitest.yml` /
  `playwright.yml` (later milestones); `audit` and the published
  `build-image` are deliberately left out, matching `resume-2026`'s own note.

- **`act-build` deferred despite `build.yml` existing.** Its
  `actions/cache@v6` step isn't gated by `should-run` and isn't in act's
  action cache, so an offline run tries to clone it and fails; it needs an
  `act-cache-*` target pre-cloning `actions/cache` the same way
  `act-cache-checkout` handles `checkout-to-app` (and the way
  `resume-2026`'s `act-cache-artifact` handles `upload-artifact` for
  `act-vitest`/`act-playwright`). That belongs with a task that verifies the
  build locally, not this one — M0.23's criteria are met by lint/format/
  typecheck.

- **`act-image` builds `Docker/Dockerfile.node`'s `testing` target locally
  under the tag the job asks for** (`sorrel-and-salt-testing:local`), passed
  in as `--input image=…`. The per-check workflows are `workflow_call`-only
  with a required `image` input normally produced by `build-image.yml` (M0.24,
  not yet ported) and consumed from GHCR. Because the image is present locally
  under exactly that tag, `docker run` never reaches GHCR, so the workflows'
  `container: credentials:` block is a no-op — hence `-s
GITHUB_TOKEN=dummy-token` is enough. Same local-build-instead-of-reach-ahead
  deferral `lint-format-typecheck-check.yml` (M0.16) already made.

- **`act-cache-checkout` clones this repo's `main` into act's action cache.**
  Every job's first step is `Aurora-Arctic/Sorrel-and-Salt/.github/actions/checkout-to-app@main`
  — a remote `owner/repo/path@ref`, not a local `./` path (M0.15: it runs
  before the checkout that would make `./` resolvable). act expects that ref
  pre-cloned at
  `~/.cache/act/Aurora-Arctic-Sorrel-and-Salt-.github-actions-checkout-to-app@main`;
  `--action-offline-mode` on each target then stops act re-fetching it. The
  clone is guarded by a `[ -d ]` test, so it runs once per machine.

- **`--input should-run=true` on `act-lint` / `act-typecheck`.** Both gate
  every real step behind `if: inputs.should-run`, whose `default: true`
  GitHub applies for a `workflow_call` but `act` (0.2.89, invoked with `-W`
  on the file directly) does not — without the explicit input the job
  reports success having executed nothing. `format.yml` has no such input,
  so `act-format` passes none. This is the "adjusting if needed" the task
  calls for; `resume-2026`'s targets predate needing it.

- **Incidental fix — `bash` and `git` added to `Dockerfile.node`'s `testing`
  stage.** `resume-2026`'s testing image is the full Debian `node` image;
  M0.11 slimmed this repo's to `node:26.6.0-alpine`, which ships neither.
  The check workflows (byte-for-byte ports, M0.16) force `shell: bash` +
  `set -o pipefail`, and `checkout-to-app`'s second step is `shell: bash`, so
  in a bash-less image every step exits `127`; `actions/checkout` needs `git`
  or it falls back to a tarball download that `--action-offline-mode` blocks.
  Both are test/CI-only and land in `testing`, not `development`. This was not
  visible before: real CI's `lint-format-typecheck-check.yml` has been red on
  every run for an unrelated reason (`checkout-to-app@main` doesn't resolve
  until these actions reach the default branch), so it never got as far as
  running a step in the container. `make act-*` is the first thing to. Kept in
  this PR because no `act-*` target meets its acceptance criteria without it;
  flagged in the PR body, precedent being M0.16's own "incidental fix required
  for runs-green" (Prettier) and M0.19's healthcheck correction.

- **Also Prettier-formatted, content unchanged:**
  `claude-docs/design-decisions/m0.22-gitflow-rulesets.md` and
  `claude-docs/transcripts/ci.md` — pre-existing drift (same recurring
  doc-format lag M0.16 hit) that made `make act-format` red out of the box.

## Verified

Host has Docker 29.6.2 + act 0.2.89.

- `make act-lint` → `oxlint .` runs in-container, `Found 0 warnings and 0
errors`, **Job succeeded**.
- `make act-typecheck` → `tsc --noEmit` runs, **Job succeeded**.
- `make act-format` → `prettier --check .` runs, **Job succeeded** (after the
  two-file format fix above).
- Image resolves with no manual pull: `act-image` builds
  `sorrel-and-salt-testing:local`; act logs `docker pull
image=sorrel-and-salt-testing:local … forcePull=false` and proceeds — no
  GHCR auth, no `docker pull` by hand.
- `.actrc` diff against `resume-2026/.actrc` is the two directives plus
  comments.

## Rules this sets

- A new reusable check workflow (`vitest.yml`, `playwright.yml`, …) ships its
  `act-<name>` target in the same PR, following the pattern here
  (`act-cache-artifact` too, for anything that uploads an artifact).
- `Dockerfile.node`'s `testing` stage is the place to add CI-only OS packages;
  `development` stays minimal.
