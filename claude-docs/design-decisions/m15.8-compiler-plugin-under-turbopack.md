# M15.8 — The codegen compiler plugin does not shrink the Turbopack build

Status: the gate failed and the plugin was not built. On 2026-11-07 the owner chose `documentMode: 'string'`, which M15.8 builds. The task was then widened, and the per-page split is now built without the plugin, by sending each document as its caller's own text. The schema builder and the GraphQL engine are also cut from the browser ("The split, built" below).

## What the task assumed

Codegen's client preset ships a Babel plugin that rewrites each `graphql(...)` call into an import of that one document. The task assumed that, under Turbopack, a page would then ship only the documents it calls.

## What was tried

1. The plugin cannot be named from the preset package: its `exports` map hides the `babel` subpath. A local copy of it, loaded by absolute path, was used instead. The copy aliases the import, because many modules export a constant named after their own document (`export const XDocument = graphql(...)`), which the unaliased import would clash with.
2. Turbopack runs it through `babel-loader` set in `turbopack.rules` (needs `babel-loader` and `@babel/core` 7 as dev dependencies), with the TypeScript and JSX syntax plugins only, so Next's own compiler still compiles the file. `experimental.turbopackUseBuiltinBabel: false` silences the "manual babel-loader" warning.
3. `withWorkflow` owns the plain `*.ts` and `*.tsx` rule keys and adds its own content test to them, so a rule on those keys never ran on ordinary files. Brace keys (`*.{ts,cts}`, `*.{tsx,jsx}`) reach every file.
4. The plugin was also made to delete the `graphql` import once every call was replaced, so `src/gql/gql.ts` (the map of all documents) is unreachable. A `sideEffects: false` `package.json` in `src/gql/` was tried as well.

Result: the loader works. The `gql.ts` map text is gone from the chunks. But `/compendium` and the two coven ingredients pages still hold all 130 generated documents, in one 194 KB chunk, because Turbopack keeps every export of `src/gql/graphql.ts` live. No error occurs; the exports are simply not dropped.

## Figures (client chunks, gzip)

| Page                     | Before   | After the plugin | Documents held |
| ------------------------ | -------- | ---------------- | -------------- |
| `/compendium`            | 487.3 KB | 481.5 KB         | 130 of 130     |
| Coven ingredients detail | 425.4 KB | 420.5 KB         | 130 of 130     |
| Coven ingredients list   | 494.7 KB | 488.8 KB         | 130 of 130     |

About 1 percent. The acceptance criterion (a page ships no other document's text) is not met.

## Proposal: `documentMode: 'string'`

Set codegen's `documentMode: 'string'` so each generated document is a plain string, not a parsed syntax tree. Callers would parse nothing at load.

- It would shrink: the generated file, since a string is far smaller than the equivalent node tree; this is where nearly all of the 194 KB goes.
- It would not shrink: the number of documents a page holds. All 130 would still ship, as strings, until a per-document split also exists.
- Cost: every consumer that expects a `DocumentNode` (the fetch helper, the document-depth guard, tests) must change, and the cost needs measuring first.

Not built, as the brief said.

## Alternative

Make codegen emit one module per document, so unused documents are never imported. That needs a custom codegen plugin and is a larger task. It was not needed: the split below reaches the same result.

## The split, built

Two cuts. Neither changes what the browser sends: a request still carries the query text.

1. **No server packages in the browser.** The cursor codec lived in `src/lib/pagination.ts`, which imports `@pothos/core`, and the compendium list's URL parsing imported the codec, so every page shipped the schema builder and, through it, `graphql`. The codec moved to `src/lib/cursor.ts`, which imports neither. It encodes with `btoa` and `atob` instead of `Buffer`, so Next's `Buffer` polyfill left too. `tests/guards/browser-server-packages.test.ts` walks every file a `'use client'` file imports and fails on a runtime import of either package, or of `src/gql/`. It failed before the cut.
2. **Each page carries only its own documents.** Callers import `graphql` from `src/lib/graphql-document.ts`, which returns the text it is given, typed as codegen's generated function. Codegen still finds and types every call, but nothing in the browser imports `src/gql/gql.ts`, the map of every document. The one shared fragment, `ReferenceRow`, is written out in its three callers, because a caller's text must be its whole document. `tests/lib/graphql-document.test.ts` asserts that each call's text is the document codegen generated for it.

- Load the date field and the sortable field only when a dialog that holds one opens (about 34 KB).

- Give the account menu and the banner an auth client without the passkey and two-factor plugins (about 5 KB). This touches sign-in, so it is the owner's decision.
