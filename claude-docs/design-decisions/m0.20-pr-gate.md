# M0.20 — port pr-gate.yml

**Status:** decided · **Date:** 2026-09-09

The task: copy resume-2026's `pr-gate.yml` and wire it to the reusable
per-check workflows ported so far (`lint`, `format`, `typecheck`, `build`,
`audit`), leaving `vitest` and `playwright` — both M1 — stubbed.

## Decided

- **`gitflow` (M0.22) and the real `build-image.yml` (M0.24) are also not
  ported yet, even though the task notes only call out `vitest`/`playwright`
  by name.** Neither exists in this repo, so upstream's `needs: gitflow` on
  every job and `uses: ./.github/workflows/build-image.yml` for the image
  can't be copied as-is:
  - `gitflow` — dropped entirely for now. Every `needs: [...]` list that
    included it upstream has it removed; M0.22 adds it back to each job when
    it ports the real workflow. Nothing in this task's acceptance criteria
    depends on Gitflow validation, so there's no stand-in to build.
  - `build-image` — replaced with the same ad hoc, run-scoped image build
    `lint-format-typecheck-check.yml`/`build-audit-check.yml` already use
    (M0.16/M0.17's own "Rules this sets": _"Any workflow needing the testing
    container image before build-image.yml (M0.24) exists builds its own ad
    hoc, run-scoped copy rather than porting build-image.yml early"_). Tagged
    `ghcr.io/.../testing:pr-gate-<run id>` — scoped to this workflow's own
    run id, distinct from the two smoke workflows' `smoke-<run id>` tags, so
    a PR that touches both never collides on a GHCR tag. `cancel-in-progress:
false` on this job only, matching upstream's own reasoning: it pushes to
    a shared `type=gha` layer cache, and a cancelled push can freeze a
    half-written layer into that cache for every later run to reuse.
- **`vitest` and `playwright` are stub jobs**, not omitted entirely: each is
  a bare `runs-on: ubuntu-latest` job with one no-op `run: echo` step, kept
  under their real, eventual job names. The reasoning upstream's own
  `should-run` comments give for why a _skipped_ job must still complete
  under its real name (a job-level `if:` reports a bare, unqualified check
  name that a "job / job" required-status-check can never match) applies
  just as much to a job that doesn't exist yet — M1 swaps the stub step for
  `uses: ./.github/workflows/vitest.yml`/`playwright.yml` without ever
  needing branch protection's required-check names touched.
- **The `changes` path-filter job drops the `vitest`/`playwright`/`gitflow`
  categories and their `audit` category too** (upstream filters `audit` on
  `changes` but never actually uses the output — `audit`'s job below has no
  `should-run` input, matching `audit.yml`'s own lack of one). Outputs are
  exactly `lint`, `typecheck`, `build` — the three checks that both exist
  and take a `should-run` input.
- **`build`'s filter swaps Gatsby's file globs for Next.js's**: drops
  `gatsby-config.ts`/`gatsby-node.ts`/`gatsby-ssr.ts`/`gatsby-browser.ts`/
  `static/**`, adds `next.config.ts`/`public/**` (the repo has no `public/`
  directory yet, but the build filter should already cover it once one
  exists — same reasoning `.oxlintrc.json`'s node-globals override already
  anticipates `src/app/**/route.ts` ahead of any routes existing). `lint`
  and `typecheck`'s globs needed no Gatsby-specific changes — they were
  already generic over `**/*.ts`/`**/*.tsx` etc.
- **`audit`'s job is gated `if: github.event_name == 'pull_request'`**, even
  though `pr-gate.yml`'s only trigger is `pull_request` (unlike the two
  smoke workflows, which also run on `workflow_dispatch`). Kept for the same
  rule M0.17 recorded — a reusable workflow whose required input
  (`audit.yml`'s `pr-number`) is used unguarded downstream must not be
  reachable from a trigger where that input could be empty — as a guard
  against this workflow's own triggers ever widening later, not because it
  does anything today.

## Verified

- `npx js-yaml pr-gate.yml` parses with no errors.
- `grep -rn 'resume-2026\|mjoynes-wombat-web' .github/` finds nothing (the
  one `resume-2026` match is this file's own prose, not a workflow).
- `npm run lint` / `format:check` / `typecheck` all exit 0, unaffected by
  this task's YAML-only change.
- **Not verifiable pre-push:** the real gate run. Opening the PR triggers
  `pr-gate.yml` for the first time (paths this diff touches trivially
  qualify — it's the file itself), confirming `lint / lint`, `format /
format`, `typecheck / typecheck`, `build / build` all go green, `audit /
audit` posts its PR comment, and `vitest`/`playwright` complete as
  no-ops. A throwaway commit breaking one real check (e.g. an oxlint
  violation) should turn the overall run red without the stub jobs
  affecting that outcome, before reverting.

## Rules this sets

- A job stubbed ahead of the workflow it will eventually call keeps its real
  job name and runs unconditionally as a no-op, the same way a
  path-filtered-out job keeps its name via `should-run` — never a
  job-level `if:` that changes what GitHub reports the check as.
- `pr-gate.yml`'s `changes` job only outputs a category for checks that both
  exist and actually consume a `should-run` input; a filter nothing reads is
  dead configuration, not documentation.
