# M12.9 and M12.10 — undo and redo in the forms: the approved plan

The plan the owner approved on 2026-10-16, copied as approved. The task entries in [`tasks/m12.md`](../tasks/m12.md) are what the work is held to; this records how the design was reached and the models set aside along the way.

## Context

The owner asked how hard Ctrl+Z in the forms would be. Today the browser undoes typing inside one text box and nothing else: a select pick, a removed chip, a toggled switch, a colour, a removed or reordered variant, reference or list row has no way back except Cancel, which discards everything. There is no undo code, no shortcut handling and no form history anywhere in `src/`.

The three forms that matter all run on react-hook-form 7.90 (`IngredientForm`, `GroupForm`, `GroupedValueForm`). The five small `useState` forms (name, email, create coven, the two invite forms) are one or two text fields whose undo is already native; they stay out.

**The owner's decisions (2026-10-16):**

1. **One stack per saved thing, newest first.** Ctrl+Z and the Undo button both undo the most recent change in the form, wherever focus is: the model every editor uses, one rule to learn. A reference panel saves itself, so it keeps its own stack. Focused-field-first undo and per-variant stacks were considered and set aside as unpredictable: the user cannot see the stacks, so could not tell which of three answers a press would give.
2. **Undo takes you to what it changed.** Focus moves to the undone field, its folded section opens, and a live region names it. This is what makes an undo in a long form legible.
3. The form owns Ctrl+Z everywhere, including inside text boxes. Typing in one field is grouped into one step per pause of about half a second, or until focus leaves the field. The browser's own per-keystroke undo is suppressed inside the form so the two never fight.
4. Redo is Ctrl+Shift+Z and Ctrl+Y; on a Mac, Cmd+Z and Cmd+Shift+Z. Cmd+Y is not bound: it opens Chrome's history.
5. Visible **Undo** and **Redo** buttons, small and quiet, disabled when there is nothing to do, so the feature is discoverable and reachable on touch and without chords.
6. A save resets history: the saved values are the new starting point.
7. Two tasks: **M12.9** the mechanism, buttons, tests and docs, wired into the two admin forms; **M12.10** `IngredientForm` adopts it.
8. The store is React's `useReducer` plus a context. react-hook-form stays the one store of values; no new dependency.

Good UX and accessibility are requirements, not extras.

## Design

### A step is the fields one action changed

```ts
{
  diffs: {
    name: string;
    before: unknown;
    after: unknown;
  }
  [];
  at: number;
  typing: boolean;
}
```

Several diffs in one step happen when a change triggers a `setValue` in the same tick (picking the `none` nomenclature empties `canonicalName`, `IngredientForm/index.tsx:419`): one Ctrl+Z undoes the whole pick. Diffs rather than whole-form snapshots because the diff names tell the hook where to send focus, and because applying them with `setValue(name, before, { shouldDirty: true, shouldValidate: isSubmitted })` leaves errors, `submitCount` and field registration alone, where `reset` would clear or redo them. Newest-first application is what makes per-field writes safe: a step is only ever applied on top of the state it was recorded from. `setValue` on a field-array name notifies `useFieldArray` through `_subjects.array` (react-hook-form `_setValue`, `index.esm.mjs:2785`), so a removed or reordered row comes back. `shouldDirty` recomputes `isDirty` against the defaults, so undoing to the start disables Save and releases `useDiscardGuard`.

### Recording

Subscribe once with `methods.subscribe({ formState: { values: true }, callback })`. Per callback:

- `restoring` set → ignore (our own `setValue`s).
- `defaultValues` identity changed, or `name` undefined with changed values → the form reset itself: dispatch `cleared`, take `present`. (`reset` emits `{ name: undefined, type: undefined }` at `index.esm.mjs:3539`; the callback receives `defaultValues`, `:3167`.)
- values deep-equal `present` → ignore (field-array effects re-emit).
- else diff at `name` (`get(present, name)` vs `get(values, name)`); if the newest step is still open (same tick), append the diff; else if typing on the same name within `pauseMs` (500) with no `focusout` since and both values strings, extend its `after`; else push a new step and empty the future. Cap at 100.

### The pieces, all in `src/components/Field/`

Beside `use-field.ts` and `form-actions.tsx`, where every form already imports from.

- `form-history.ts` — the pure reducer: state `{ past: Step[]; future: Step[] }`; actions `recorded`, `extended`, `undone`, `redone`, `cleared`. Tested directly.
- `use-form-history.ts` — `useFormHistory(methods, { root, enabled?, ignore?, onRestored?, pauseMs?, limit? })` returns `{ undo, redo, canUndo, canRedo, clear, onKeyDown, announcement }`. Owns the subscription, the `restoring` flag, applying a step, focus and the announcement. `onRestored(names)` lets a form open whatever holds those fields (the ingredient form's folded sections and variant cards). Labels come from the DOM at undo time: the `[name]` element's `labels[0]`, trailing `*` dropped as `tests/support/interact.tsx:byLabel` does, else `aria-label`, else the enclosing fieldset's legend (list fields), else a generic fallback.
- `form-history-context.ts` — `FormHistoryContext` carrying the hook's return, so the buttons and the live region reach it without props.
- `form-history-buttons.tsx` — `FormHistoryButtons`: two icon buttons each inside `IconTip` (`tip="Undo"` / `"Redo"`, `aria-label="Undo"` / `"Redo"`), `.btn .btn--small .btn--quiet`, `disabled` when `!canUndo` / `!canRedo`, markup after `IngredientForm/references.tsx:383`; plus the live region `<output className="visually-hidden" aria-label="Edit History">`, the shape of `fields.tsx:401`, alternating a trailing ` ` so two identical announcements both read (as `Modal/discard.tsx:86`). Portals into the modal header slot when `useModalHeaderSlot()` gives one (every form here opens in a `RouteModal`), else renders inline at the top of the form, the slot's own documented fallback (`Modal/header-slot.ts`).

### Keys

`onKeyDown` on the `<form>`: return when `!enabled`, `defaultPrevented`, `nativeEvent.isComposing`, `altKey`, the target is inside an open combobox (`[aria-expanded="true"]`, downshift owns its keys), or `ignore(target)`. Then: `z` with Ctrl or Cmd → Shift ? redo : undo; `y` with Ctrl and not Cmd → redo. **Always `preventDefault`** for these chords inside the form, even with nothing to undo, so the browser's stale native stack never reverts a text box behind the form's back (after Save & Add Another, say); with nothing to do, announce that. Either modifier is accepted on every platform (no `navigator.platform`); Ctrl+Z is not native undo on a Mac, so nothing is lost.

`enabled` is false while a question is up: `!discard.asking && !confirming` (plus `!deleting && question === null` in the ingredient form). The questions render inside the `<form>` and the rest goes `inert`, so this is belt and braces.

### Focus and announcements

After applying a step: call `onRestored(names)` first so a closed section or card opens, then focus the `[name]` element of the step's first diff; for an array diff (a removed row, a reorder) focus the first control inside the fieldset that holds the array, else the array's legend's fieldset (`tabIndex={-1}`); if nothing is found, or the focused element went away, focus the Undo button, never `body`. Then announce: "Undid change to Name", "Redid change to Light Theme Colour", "Undid change to Folk Names", "Nothing to undo". The live region is labelled so it is told from the list fields' own regions.

### Validation and errors

Forms are `mode: onSubmit`, `reValidateMode: onChange`. `shouldValidate: formState.isSubmitted` keeps that: no errors before the first submit, errors follow a restore after it. `submitCount` is untouched, so `useOnEachSubmit` and `useFocusFirstInvalid` do not re-fire. Server errors set by `setError` stay until the next submit, as they do after any edit.

## Risks

- `setValue` on an array name versus `useFieldArray`'s internal `ids`: confirmed in source, proved by the probe test first.
- `useDuplicateWarning` debounces on the watched name, so an undo re-runs it after its delay; harmless.
- Focus moving on undo can surprise a screen-reader user mid-sentence; the announcement names the field, and the move is what every editor does. Confirm in the owner's walk.
- The reference panel's edits count for the discard guard but not for the outer history; its own history is its own. Say so in the doc.
