# M8.5 — compendium and ingredient GraphQL queries

Branch `feature/m8.5-compendium-and-ingredient-graphql-queries`, stacked on M8.2's branch (in review). Issue #337, `In Progress`.

## Context

M8.5 adds the `compendium` list, the `ingredient` detail and the `ingredientFormValues` queries. Reading its consumers turned up a contradiction the task inherits:

- **M8.4/M8.10** say the search box matches through `filterIngredients()`, a pure client-side function over rows already loaded.
- **Rule 8** caps every list at 100 rows a page, so the client never holds the whole compendium (or a coven's ingredients), and a client-side filter cannot be _the_ search for either list.
- **MB.80** made `/compendium` a static ISR page with no request-time API, so a filtered view has to come from the browser through GraphQL — MB.80's own plan says so (C9, D10). MB.80 exposed the contradiction; M8.4/M8.10 vs rule 8 caused it. The public/admin split only shows up as M5.5 wanting a `nomenclature` filter the query lacks.

**Decided with the user (2026-09-28):**

1. **The `compendium` query is the search.** Filtering is SQL: `query` is case- and accent-insensitive word similarity (`<%`, threshold 0.5 — changed from `ILIKE` substring during the build, at the user's request) over the display name, the formal name and live folk names; `categoryIds` is AND; `form` is a folded equality. **M8.4 is retired**; its criteria move to M8.5 (matching, AND default, empty = all) and M8.12 (OR). M8.10 is rewritten: the debounced input refetches the query with `query`.
2. **Install `unaccent` now.** Extension + `IMMUTABLE` SQL wrapper + expression trigram indexes, inside this task. Neon supports `unaccent` (its dictionary is not editable there, which is exactly what keeps the wrapper honest).
3. **`ingredient(id: ID!, workspaceId: ID): Ingredient!`** — non-null; a miss, a workspace entry asked for without its coven, and another coven's id all answer `NOT_FOUND`, as `me` and `getWorkspaceIngredient` do. Without `workspaceId` the read is the compendium alone; with it, the compendium or that coven under `assertMembership`.
4. **Extra filter args land in their own tasks**: `categoryMode` (M8.12), `element` (M8.13), `nomenclature` (M5.5). Their entries get a line saying so.

Also decided while planning: M8.5 runs **before** M5.2 in the execution order, so the compendium _read_ services are built here and M5.2 keeps the writes. The page sorts `(name, id)` — M8.14's `(lower(name), canonical_key, id)` needs a compound keyset the helper does not have yet. Superseded in part while building: MB.104, minted on the owner's question, adds that keyset to rank a search by its score, and M8.14 declares its parts on it. The task is bigger than its 2h: the entry will say so (~5h).

## Out of scope

M8.3's anti-join, M9.4's `workspaceIngredients`, MB.9's `ingredientsById`, MB.11's duplicate field, admin writes (M5.2), and making the _fuzzy_ paths (`findSimilarIngredients`, the suggestion finders) accent-insensitive — they keep the raw-column trigram indexes; the new expression indexes sit alongside, so nothing is dropped and no ack sidecar is needed.

### 2. Repository finders

**Tests first** — new `tests/db/repository/ingredients.test.ts` (bare `postgres()`, `truncate ingredients cascade`, rows via `insertIngredient(sql, makeIngredient({...}), A.id)` from `tests/support/db/insert-ingredient.ts`, categories by seeded name). Expected order always from SQL (`order by name, id`) — the DB collates `en_US.utf8`, never JS `sort`.

- `findCompendiumPage({}, page)`: compendium rows only; **precondition** a W row exists and is absent.
- `query`: case-insensitive on `name`, on `canonicalName`, on a _live_ folk name, not a soft-deleted one; **accent-insensitive both ways** (`una` finds `Uña de Gato`, `Uña` finds `Una`); `%`, `_` and `\` are literal (rows `Fixture 100% Pure`, `Fixture_Under`); blank = no filter.
- `categoryIds` AND: Protection+Cleansing matches `[p, c]`, Protection alone does not; `[]` = no filter.
- `form`: `' HERB '` matches `herb`, not `root`; combined with `query`.
- Walk 30 rows through `resolvePage` at `first: 7`: each once, SQL order, `hasNextPage` flips on the last page; a soft-deleted row never appears.
- `findOneIngredient([], id)`: compendium row found; W row `undefined` — precondition `findOneIngredient([proofW], id)` finds it (proof via `assertMembership(asUser(B), WORKSPACE_W_ID, { ingredient: ['read'] })`); D's proof for X does not; soft-deleted → `undefined`.
- New `tests/db/repository/vocabularies.test.ts`: `findIngredientFormValues(page)` walks the 78 seeded forms once in `(name, id)` order; a soft-deleted form is absent; soft-deleting the Curio group hides its 13 forms (precondition: count before).
- Pinned lists: `tests/db/repository/index.test.ts` and `tests/guards/soft-delete-finder-guard.test.ts` `EXPORTED_FUNCTIONS` gain `findCompendiumPage`, `findOneIngredient`, `findIngredientFormValues`; `SCOPED_FINDERS` gains `findOneIngredient` only (it calls `scopedTo`; the compendium page does not). `tests/guards/module-boundaries.test.ts` `TIER_SEAM` gains `findCompendiumPage` and `findOneIngredient`, each with a one-line reason.

**Then** — `src/db/repository/ingredients.ts`:

- `export interface IngredientFilter { query?: string; categoryIds?: readonly string[]; form?: string }` — a _named_ interface: the finder guard brace-matches a function body from the first `{`, so an inline object type in a signature breaks it.
- `findCompendiumPage(filter, page)`: `selectFrom(ingredients, and(inCompendium(ingredients), notSoftDeleted(ingredients), …arms, pageBounds(keyset)), keyset)` with `keyset = { sort: ingredients.name, id: ingredients.id, request: page }`. Inline `inCompendium(` in the exported function (the boundary guard attributes a non-exported helper's call to the preceding export).
  - Search arm, the shape of `findSimilarIngredients` (`alias(ingredients, 'candidate')`, `UNION ALL` inside ``inArray(ingredients.id, sql`(…)`)``, not an `OR` around a subquery — db.md "Fuzzy matching"): `unaccent_immutable(candidate.name) ILIKE unaccent_immutable($pattern) OR … canonical_name …` ∪ folk names under `notSoftDeleted(ingredientFolkNames)`. Pattern built here: `` `%${query.replace(/[\\%_]/g, '\\$&')}%` `` (LIKE's default escape is `\`; a bound parameter). The function call is a `sql` fragment (what fragments are for); verify in `node_modules/drizzle-orm` whether `ilike` takes an `SQL` left operand, else write the comparison as one fragment. pg_trgm's GIN answers `ILIKE` on the expression index.
  - Category arms: one `existsIn(ingredientCategories, and(eq(ingredientCategories.ingredientId, ingredients.id), eq(ingredientCategories.categoryId, id)))` per id (`notSoftDeleted` is `undefined` for a join table — fine).
  - Form arm: ``eq(sql`lower(btrim(${ingredients.form}))`, sql`lower(btrim(${form}))`)``, the fold `CANONICAL_KEY` uses.
- `findOneIngredient(memberships, id)`: `selectFrom(ingredients, and(or(inCompendium(ingredients), ...memberships.map((m) => scopedTo(m, ingredients))), notSoftDeleted(ingredients), eq(ingredients.id, id)))`, mirroring `findManyOfIngredients`.
- `src/db/repository/vocabularies.ts`: `findIngredientFormValues(page)` — `findPage`'s four-line body (the guard needs `notSoftDeleted(` in the body, so `findPage` cannot be called) with `existsIn(ingredientFormGroups, eq(ingredientFormGroups.id, ingredientForms.groupId))`, parity with `findVocabularySuggestions`'s "curated only while its group is live".
- `src/db/repository/index.ts` re-exports the three and `type IngredientFilter`.
