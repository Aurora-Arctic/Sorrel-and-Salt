# M0.8 — modal-surface, chip and badge mixins

**Status:** decided · **Date:** 2026-09-07 · **Builds on:**
[m0.7-category-and-safety-tokens.md](./m0.7-category-and-safety-tokens.md)

M0.7 settled the _shapes_ — a pill for a chip, a square corner for a badge, a solid fill
for the loud treatments — against the real colours, because a shape that cannot hold 4.5:1
is not a styling decision to discover later. This task writes them into `_mixins.scss` and
records the handful of calls that were left open.

No colour is chosen here and no ratio changes. Every value the three mixins emit comes
through `category-group()`, `badge-token()`, `$text-on-color` or an M0.6 alias, so the
contrast tables in the M0.7 doc remain the record for all of it.

---

## The API

```scss
@include modal-surface; // or modal-surface($shadow-floating)
@include chip('mind'); // unselected
@include chip('mind', selected);
@include badge('safety'); // or badge('low-stock')
```

| Mixin             | Argument                 | Rejects                                      |
| ----------------- | ------------------------ | -------------------------------------------- |
| `modal-surface()` | a shadow token, optional | —                                            |
| `chip()`          | group slug, state        | an unknown slug; a state that is not the two |
| `badge()`         | a `$badge-palettes` key  | an unknown palette                           |

All three set colour, edge and geometry and **nothing else** — no width, no margin, no
cursor, no layout. The design will change (CLAUDE.md); what these hold is the part that is
contrast-checked and must not be re-picked per component.

### `modal-surface($shadow: $shadow-elevated)`

The raised panel: `$surface-card`, `$text-primary`, a `0.5rem` radius and the elevated
shadow. Elevation is an argument because a nested surface — a confirm over an already-open
modal — wants the floating shadow rather than a second full-strength one. Most call sites
pass nothing.

**Not here: padding, width, position, and the backdrop.** A modal is centred, sized and
dimmed by the component that owns it (M3.x). A mixin that positioned its caller could only
ever fit one modal, and the backdrop is not a surface.

### `chip($group, $state: unselected)`

A pill, always edged in its group's colour. `unselected` leaves the ground transparent and
lets the label wear the colour; `selected` fills solid with it and inverts the label onto
`$text-on-color`.

The states are named for what the UI does — the category chips are multi-select (story 22)
— and map onto M0.7's quiet and loud treatments respectively. Both carry the same 1px edge
and the same padding, so a row can mix them without the selected ones jumping half a pixel
out of rhythm.

Solid is not decoration, and the reason is worth keeping to hand: M0.7 tried the obvious
loud treatment — the group colour as a low-opacity wash behind a coloured label — and it
cannot hold 4.5:1. The eight were tuned to land _just_ above the floor, so washing the
ground with the same colour closes exactly the gap they were tuned for. Solid sidesteps it
and introduces no new arithmetic, because the inverted label _is_ the page surface: a
selected chip's label ratio is the `vs page` column already tabulated. Worst pairing in the
set is `wellbeing` at 4.74.

### `badge($palette)`

Takes a `$badge-palettes` key — `'safety'` or `'low-stock'` — rather than a colour, so the
two badges cannot be drawn in each other's ink. Square-cornered, which is what keeps a
badge from reading as a chip now that chips are pills.

**There is no variant argument, deliberately.** The palette's own declared treatment
decides the drawing: `safety` is `solid` because its ink only works solid, and asking for
it tinted is already a compile error from `badge-token()`. A variant argument would offer a
choice that M0.7 established does not exist, and a caller passing the wrong half of it
would land on tokens measuring 3.85 and 2.78.

A solid badge draws no border — a solid fill is its own boundary, clearing 3:1 against both
surfaces on its own account (4.43 dark, 6.38 light). It does carry a **1px transparent**
one. That is geometry rather than an edge: without it a solid badge stands 2px shorter than
the tinted badge beside it on the same `IngredientCard`, which is the one place both appear.

## Motion

Each mixin rides `theme-transition()` over exactly the properties it sets that can change
with the theme — `background-color`, `color`, and `border-color` for the two that draw an
edge — and each drops to `transition: none` inside `reduced-motion`. That is per mixin
rather than once globally: a component including one of these gets the whole convention
without having to remember the second half of it.

## Verified

Compiled with `sass --load-path=src/scss` against a fixture per mixin:

- **Each mixin compiles in isolation**, from a file that `@use`s only `mixins` — no
  warnings, and the tokens it emits (`--group-mind`, `--badge-safety-fill`,
  `--badge-low-stock-fg/bg/border`) are name-for-name the ones `globals.scss` assigns.
- **Both chip states** render at identical geometry, differing only in ground and label.
- **Both badge palettes** render their own treatment's parts and no others.
- **All three** emit the `prefers-reduced-motion` block.
- Four error paths exercised: an unknown group slug, an unknown chip state, an unknown
  palette, and `'low_stock'` for `'low-stock'` — each naming the valid set in the message.

## What this commits later tasks to

- A component styles a chip or a badge by including the mixin and adding **layout only**.
  A component that re-states a colour these mixins already set is a bug, not a variation.
- **The modal backdrop belongs to the modal component** (M3.x), along with sizing, focus
  trap and dismissal. If a second modal needs the same backdrop, that is a shared component
  or a fourth mixin — not a growth of `modal-surface()`.
- **A ninth category group** needs nothing here; `chip()` reads the map.
- **A ninth badge palette** picks its treatment first (M0.7's rule) and needs nothing here
  either, as long as the treatment is one of the two.
