# M0.30 — Ladle as the component workshop

**Status:** decided · **Date:** 2026-09-08 · **Builds on:**
[m0.6-typography-and-palette.md](./m0.6-typography-and-palette.md)

Every standalone component renders in isolation so it can be built and reviewed against
the tokens without routing a page to it. This task stands up that workshop. It is a
greenfield tooling choice, not a port — `resume-2026` has no workshop of any kind.

---

## The choice: Ladle, not Storybook or Histoire

**Ladle.** It is Vite + React only. That is the whole reason:

- **It never couples the workshop to a Next.js major.** This repo lands mid-Next-16.
  Storybook's Next framework (`@storybook/nextjs`) tracks Next's build internals and has
  historically trailed each major; a workshop that imports it inherits that lag. Ladle
  renders components through plain Vite, so a Next upgrade cannot break it.
- **It installs an order of magnitude lighter.** One `@ladle/react` dependency (plus the
  `vite` it builds on) against Storybook's dozen-plus `@storybook/*` packages and their
  builder chain.
- **Its config is one file.** `.ladle/config.mjs` for the workshop, `.ladle/vite.config.ts`
  for the Vite side. No `main.ts` + `preview.ts` + framework preset + addons registry.

**Not Storybook.** Its one real advantage here would be running stories through the planned
Vitest projects as a test surface. That advantage is thin in this repo: component testing
is fixed on role and label queries (see [`CLAUDE.md`](../../CLAUDE.md), Testing) and
accessibility on Playwright + `@axe-core/playwright`. Neither wants a story runner, so the
reason to pay Storybook's weight and its Next coupling never arrives.

**Not Histoire.** Its React plugin trails its Vue one and is not a safe bet on React 19,
which this repo is already on.

## What landed

| File                                           | Holds                                                                                     |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `.ladle/config.mjs`                            | `stories` glob, `port` 61000, `outDir` `build`, dark default theme, pinned HMR port       |
| `.ladle/vite.config.ts`                        | Sass API pinned to `modern-compiler`; the seam for staying aligned with Next              |
| `.ladle/theme.scss`                            | the token layer of `globals.scss` — theme blocks + body surface, no typography            |
| `.ladle/components.tsx`                        | imports `./theme.scss` so the theme token custom properties exist; passthrough `Provider` |
| `package.json` → `workshop`, `workshop:build`  | `ladle serve` / `ladle build` — the placeholders are gone                                 |
| `makefile` → `workshop`, `workshop-build`      | wrap the npm scripts; both show in `make help`                                            |
| `src/components/ThemeToggle/index.stories.tsx` | one `Default` render — the pipeline's smoke test (see below)                              |

### Stories are discovered at exactly one path

`stories: 'src/components/**/index.stories.tsx'` — one file per component directory, beside
`index.tsx` and `index.test.tsx`, imported the same way. Nothing outside a component
directory is a story. The M0.33 gate ("no standalone component without a story") is written
against this exact shape.

### Sass must resolve the way `next dev` resolves it

A component's `index.scss` opens with `@use '../../scss/variables' as *;`. The workshop and
the app must not disagree about what that resolves to.

Next 16 runs dart-sass through `sass-loader` with no `sassOptions` set, which lands on the
**modern API with empty load paths** — resolution is purely relative to the importing file
(confirmed in `node_modules/next/dist/compiled/sass-loader`). Vite 6's Sass default is the
same modern compiler with the same empty load paths. So parity needs no option: not
`loadPaths`, not `includePaths`, not an `additionalData` prelude.

`.ladle/vite.config.ts` therefore sets only `css.preprocessorOptions.scss.api =
'modern-compiler'` — pinned so a future Vite default flip can't move the workshop off that
shared pipeline — and stands as the one place to add a matching option if Next ever gains a
`sassOptions`.

### The token custom properties have to exist in the workshop — but not `_typography.scss`

`_variables.scss` maps every theme token to a `var(--…)` — `$accent` is `var(--accent)`,
`$text-primary` is `var(--text-primary)`, and so on. The `--accent: …` assignments
themselves live only in `src/app/globals.scss` (`:root { @include theme-dark }`, the
`prefers-color-scheme: light` block, and `html[data-theme='light']`). Nothing under
`src/components/` imports `globals.scss` — the app pulls it once in the root layout. So the
workshop has to pull those assignments in too, or every `var(--token)` a component emits
resolves to nothing and "render it against the tokens" isn't true.

The workshop can't import `globals.scss` **itself**, though: it also `@use`s
`_typography.scss`, whose document-wide element rules (`li::before { content: '◆' }`, the
`ul` padding reset, the `a` recolour, `section`/`header` margins) then land on Ladle's own
sidebar and list controls — which are `<ul>`/`<li>`/`<a>`. Components style themselves from
tokens and mixins ([`CLAUDE.md`](../../CLAUDE.md), Conventions), so those global prose
rules aren't what a story needs anyway.

`.ladle/theme.scss` is therefore a trimmed copy of `globals.scss` — the three theme blocks
and the `body` surface, verbatim, minus the `@use './typography'`. `.ladle/components.tsx`
imports it and exports a passthrough `Provider`. The three blocks are duplicated, not
shared, so they carry a comment to keep them in step; M0.31 decides whether
`_typography.scss` belongs in the workshop at all, scoped to the story frame.

### Dark by default

`addons.theme.defaultState: 'dark'` in `.ladle/config.mjs`. The app is dark-first
(`globals.scss`: `:root { @include theme-dark }`; a `prefers-color-scheme: light` system
gets light, an explicit `[data-theme]` beats both), so the workshop opens dark to match.
Ladle's theme control writes `html[data-theme]`, which `.ladle/theme.scss` reads the same
way `globals.scss` does — so the token `var(--…)` values do follow the toolbar. What
doesn't follow yet is `ThemeToggle`'s own JS state (its sun/moon facet, `aria-pressed`),
which reads `data-theme` only on mount; M0.31's control fixes that with a remount.

### Hot reload

Already on. `ladle serve` runs Vite with HMR and React Fast Refresh, so editing a story, a
component or its SCSS updates the open workshop with no refresh. The exception is the
`.ladle/` files themselves — Vite can't hot-swap them, so a change there needs the dev
server restarted. `hmrPort` is pinned to `61002` (`61000` serves, `61001` is `ladle
preview`) so the HMR socket doesn't take a random port that a non-localhost client can't
reach.

### Why a story ships in this task at all

The per-component stories are M0.32's job. But one of M0.30's own acceptance criteria is
that _a story using `@use '../../scss/...' as *` compiles with the same resolution as
`next dev`_ — which cannot be shown without a story to compile. So `ThemeToggle` (the only
component in the tree) gets a single `Default` render now, scoped as the pipeline's smoke
test. M0.32 enriches it with the states that matter — light selected, dark selected,
reduced-motion — and sweeps in any component merged in the meantime.

### `tsc` steps back from story files

`*.stories.tsx` is added to `tsconfig.json`'s `exclude`, mirroring the existing
`*.test.tsx` exclusion. `@ladle/react`'s published types pull its bundled app sources
(`typings-for-build/**/*.tsx`), which don't pass this repo's `strict` on their own and
aren't reached by `skipLibCheck` because they ship as `.tsx`, not `.d.ts`. The workshop
compiles stories through Vite/esbuild — types stripped, not checked — so `ladle build`
still exercises them end to end. M0.32 revisits when it adds the first real stories.

## Verified

- `npm run workshop` and `make workshop` both serve on `http://localhost:61000/`.
- `npm run workshop:build` exits 0 and writes `./build` (gitignored via the existing
  `build` entry); `git check-ignore build` confirms.
- The built CSS carries `ThemeToggle`'s rules with `var(--accent)`, `var(--accent-hover)`
  and `var(--surface-page)` — i.e. `@use '../../scss/variables'` **and**
  `@use '../../scss/mixins'` resolved, same as under `next dev`.
- The same CSS carries the token definitions from `.ladle/theme.scss` — the `:root` dark
  block (`--accent: rgb(53% 71% 41%)` from `$sorrel-bright`), the
  `prefers-color-scheme: light` block and the `[data-theme='light']` block
  (`--accent: #4a6b34` from `$sorrel`) — so those `var(--…)` references have real values in
  the workshop, and they differ per theme.
- The built CSS carries **no** `_typography.scss` output — no `◆` marker, no `list-style`
  reset — so Ladle's own list controls are untouched.
- `make help` lists `workshop` and `workshop-build`; no `workshop*` npm script is still a
  placeholder.
- `npm run lint`, `npm run format:check`, `npm run typecheck` all pass.

## What this commits later tasks to

- **M0.31** grows `.ladle/components.tsx` from the passthrough left here into the real
  decorator, keeping the `./theme.scss` import (and deciding whether to fold
  `_typography.scss` back in, scoped to the story frame). Three things it owns, all
  observed while standing this up:
  - the app-surface frame around each story (background, `$text-primary`);
  - a **containing block** on that frame (and cancelling `.ladle-main`'s padding) so a
    `position: fixed` component — `ThemeToggle` — sits in the story frame's corner instead
    of escaping to the viewport and floating over Ladle's own chrome;
  - a light/dark toolbar control that stamps `html[data-theme]` through the M0.29 helper
    (no second copy of that code) **and remounts the story**, because Ladle's native theme
    control already flips `html[data-theme]` — the token `var(--…)` values do follow it —
    but `ThemeToggle` reads `data-theme` only on mount, so its sun/moon facet and
    `aria-pressed` don't switch without a remount.
- **M0.32** owns story _content_: every `src/components/*` directory gets an
  `index.stories.tsx` covering its meaningful states.
- **M0.33** adds the gate (Oxlint rule or `scripts/` check) that fails a component
  directory with `index.tsx` and no `index.stories.tsx`, and puts `workshop:build` in the
  CI build job (M0.17) and the PR gate (M0.20). It also lifts the `*.stories.tsx` `tsc`
  exclusion's rationale into a permanent home if the type friction is still live.
- A new component is added to the workshop by dropping `index.stories.tsx` in its
  directory — no config change, because the glob already covers it.
