# Backend DRY review — plan (MB.206–MB.214)

**Status:** for approval · **Date:** 2026-10-10 · stored as `claude-docs/design-decisions/mb.206-plan.md` in MB.206's PR

## Context

The owner asked for a review of the backend for repeated code that forces one change to be made in several places, and for the same review of the frontend to be folded into the three remaining design reviews (MB.115, MB.116, MB.117) rather than done now.

Three explorations read every file under `src/modules/*/{services,schema,validation,graphql,loaders}`, `src/db/**`, `src/graphql/**`, `src/lib/**` and `src/emails/**`. Tests are out of scope: MB.180–MB.189 consolidated them and all are merged. `src/app/**` and `src/components/**` are the design reviews'.

**What was found, by cost.** The vocabulary layer is the heaviest: seven services (`category-groups`, `ingredient-form-groups`, `deity-traditions`, `deities`, `categories`, `astrology`, `ingredient-form-values`) repeat one create/update/delete/get-by-slug skeleton, seven copies of the slug-collision refusal, four of the page walk, three of the move-target refusal, and their six GraphQL files repeat the same object type, input type and 18 mutation fields. The repository writes the two-tier read scope `or(inCompendium, ...scopedTo)` out twelve times and the page/count pair six times beside `findPage`, which already does it. Each schema file spells the id column, the slug and seed-key partial uniques and the description CHECK by hand (8 tables; `categories` and `category_groups` lack the CHECK the other six have). `reference_links` lists its five sourced entities in about eight places across schema, seed and repository. The seed writes its own key reader around every `insertMissing`. Three vocabulary schemas use `z.uuid()` where every service uses `RowId = z.guid()`, which refuses a hand-written fixture id the service would accept. `lib/auth.ts` has four near-identical provider blocks and no exhaustiveness check, so a fifth provider would compile and silently not register. Smaller: 48 copies of `if (!session) throw new Forbidden()` across GraphQL files, the ingredient's 16 input fields declared four times, the five child-loader clears twice, the 17 reference fields listed six times, the quantity precision hard-coded in `spell_ingredients` beside `quantities.ts`.

**Decisions taken by the owner (this session):** shared helpers for the services, not a descriptor factory — each service keeps its exported functions and JSDoc, and the expiry guard (`tests/guards/compendium-expiry.test.ts`, which greps each exported admin write for `assertSiteAdmin(` and `expireCompendium()`) keeps working · a factory for the curated-vocabulary GraphQL writes, beside the small helpers, with the SDL snapshot as the proof · the tasks sit at Wave 8's tail, after MB.117 · all minted now in one pass.

## Rules every task follows

- **Pure refactor unless the entry says otherwise.** The service, repository and validation tests are the proof: they stay as they are and stay green. A test that has to change is a behaviour change and is named in the PR body. The three behaviour changes are named below (MB.209's `RowId`, MB.208's seed GUCs, MB.214's CHECK).
- **Constraints kept:** authorization in services with the `Membership`/`SiteAdmin` proof taken first; only `src/db/repository/` imports the client and only `select.ts`/`write.ts` build queries; no `drizzle-orm` at runtime above the repository; every list through `t.pagedConnection` + `findPage`; loaders through `define-loader.ts`; types in type-only files (`tests/guards/types-in-type-files.test.ts`); modules reach each other through `@/modules/<name>` only (vocabulary may not import ingredients); every service opens with `import 'server-only'`; migrations forward-only, so no column or index is renamed to tidy a schema.
- **A new helper file inside a module is not re-exported from the module's index** (`group-moves.ts` and `held-entries.ts` are the precedent), unless another module needs it.
- **Mechanism + guard where a guard is cheap** (the sweep-task rule): the soft-delete finder guard's regex widens for each new predicate name in the same PR; a lint `no-restricted-syntax` entry keeps the session narrowing out of resolvers once `sessionOf` exists.
- **Coverage must not drop per touched `src/` directory**, compared in `.reports/coverage/coverage-summary.json` before and after.
- **Docs in the same PR** (MB.31): a `claude-docs/` section that describes a shape that moved is corrected in that task; a comment keeps saying why a thing is not the obvious alternative (MB.50).
- **Verification for every task:** `npm run test:coverage`, `npm run pre-commit`, the e2e specs of the touched area, then `node scripts/task-board.mjs sync <ID>` after the entry is edited. No commit, push or PR unless the owner asks in their own message.
