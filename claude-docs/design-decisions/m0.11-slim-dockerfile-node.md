# M0.11 — slim two-stage `Docker/Dockerfile.node`

**Status:** decided · **Date:** 2026-09-08

`resume-2026/Docker/Dockerfile.node` is three stages on the full Debian `node`
image: `builder` (deps) → `testing` (+ Playwright system libs + a bundled
Chromium) → `devcontainer` (+ `nano`, `zsh`, `socat`, `bubblewrap`, `gh`,
oh-my-zsh). The task asked for a slim port with just `development` and
`testing`, the devcontainer consuming `development` directly.

## Decided

- **Alpine base, pinned to the same Node tag.** `FROM node:26.6.0-alpine`.
  Same version string as `resume-2026` so the size comparison below is
  like-for-like; the musl base is where most of the reduction comes from
  (~184 MB vs ~1.1 GB for Debian `node:26.6.0`).
- **Two stages, `testing` built `FROM development`.** `development` is
  deps + source + `CMD ["npm","run","dev"]`. `testing` adds only
  `NODE_ENV=test` and a vitest default command — no third stage, no
  `devcontainer` target. M0.14 points `.devcontainer/` at `development`.
- **No Playwright anything.** No `apt`/`apk` browser libraries, no
  `npx playwright install`. E2e is not run from this image (CI runs it via its
  own job / the Playwright container); leaving it out saves ~500 MB+. If a
  future task needs Playwright in an image, it adds a stage here — it is not
  retrofitted into `testing`.
- **Dependencies in their own layer, before source.** `COPY package.json
package-lock.json` → `npm ci` → then `COPY . .`. Editing a source file
  leaves the `npm ci` layer `CACHED` (verified).
- **`npm ci`, not `npm i`.** There is a committed lockfile; `ci` is
  reproducible and fails on drift. (`resume-2026` used `npm i` because its
  flow predated a stable lock.)
- **New `.dockerignore` at the repo root.** `resume-2026` has none — it never
  `COPY`s source into the image, relying entirely on the compose bind mount.
  This file does copy source (so the `testing` image is self-contained for
  CI), which makes an ignore file mandatory: without excluding `node_modules`
  the host's macOS/arm build would overwrite the container's `npm ci` output.
  It also keeps `.next`, `.git`, `build`, coverage and local env/state out.
- **`libc6-compat` only.** One ~1 MB `apk` package as a shim for prebuilt
  glibc-assuming native addons. Nothing else is installed.
- **No `tini` in the image.** PID-1 signal handling is left to compose
  (`init: true`, M0.12) / `docker run --init`, matching `resume-2026`.

## Image size — recorded

Sum of layer sizes, single platform (arm64), uncompressed, via
`docker history`:

| Image                                          | Size     |
| ---------------------------------------------- | -------- |
| `sorrel-node:development` (this file)          | 862 MB   |
| `sorrel-node:testing` (this file, final)       | 862 MB   |
| `resume-2026` `testing` stage                  | 3,945 MB |
| `resume-2026` `devcontainer` stage (its final) | 4,035 MB |

The final image drops from **~4,035 MB to 862 MB — ~79% smaller** (~4.7×).
The remaining 862 MB is ~184 MB Node/alpine + ~677 MB `npm ci`; the install
layer is large because the lockfile already carries the full dev/test stack
(`@swc/core`, `esbuild`, `msw`, `@parcel/watcher`, …) and is a property of the
project's dependencies, not this Dockerfile.

## Verified

- `docker build --target development` and `--target testing` both succeed.
- After appending a line to `src/app/layout.tsx` and rebuilding, `RUN npm ci`
  reports `CACHED`; only `COPY . .` re-runs.
- `docker run --rm --entrypoint sh sorrel-node:testing` running
  `npx vitest run` on a one-line smoke test: **1 passed**. vitest is pulled
  by `npx` today; once M0.9 adds it to `package.json` it lands in the cached
  deps layer and the `CMD ["npx","vitest","run"]` resolves locally.

## Rules this rules out

- **M0.12 (`docker-compose.yaml`)** must build `target: development` for the
  app service and must not reference a `devcontainer` or `builder` target —
  those stage names do not exist here.
- **M0.14 (`.devcontainer/`)** builds the `development` stage; there is no
  dedicated devcontainer image stage to point at (an explicit M0.14
  acceptance criterion).
- **M0.13 / M0.18** wire the published image tag; the `testing` stage is the
  one CI builds to run vitest, against a Postgres service it supplies.
- Adding Playwright/browser tooling is a new stage in this file, never an
  addition to `testing`.
