# M12.2: three public files are route handlers

_Decided by the owner on 2026-10-19, with M12.2. The file formats and the specs they follow are in [`../seo/ai-discovery.md`](../seo/ai-discovery.md)._

## Decision

Three files are served by route handlers (`route.ts` files, the Next.js way to answer a URL with a hand-built response): `/llms.txt`, `/.well-known/ai-catalog.json` and `/.well-known/ard.json`. They list the public Compendium for search crawlers and AI agents. `CLAUDE.md` rule 1 says "no bespoke route handlers", so rule 1 now names these three as outside its two transports, in the way the OAuth handshake at `/api/auth/*` already is.

## Why route handlers

- **No metadata file convention covers them.** Next.js builds `robots.txt` and `sitemap.xml` from `robots.ts` and `sitemap.ts`. It has no such file for `llms.txt` or for a catalog in JSON.
- **A static file in `public/` cannot follow the cache tag.** The files list every live Compendium entry. The entries are held in the data cache under the `compendium` tag, and every admin change expires that tag (rule 6, `claude-docs/db/compendium-cache.md`). A file written at build time would stay as it was until the next deploy, so a new entry would be missing from it and a removed one would still be named.

Each handler reads `listCompendiumSlugs()`, the same cached read the sitemap uses. It takes no session, because the Compendium is the one public surface (MB.80).

## Why this is not a third access path

Rule 1 forbids a third way to reach application data, because two ways ending at the same service function keep one set of authorization rules. The files do list entry names and descriptions, which is data, but only what the public Compendium already shows to anyone. They reach no workspace-scoped data and carry none:

- They take no session and call no service that checks one.
- The one read they make is the public Compendium read. Soft-deleted entries and every coven's own ingredients are left out in SQL, and a test proves both are absent.
- Every URL in them is built from `SITE_ORIGIN`, never from the request.

`robots.ts` and `sitemap.ts` already stand in the same place, as does the OAuth handshake. The rule's purpose, that no data skips the service checks, is kept.

## What holds it

The lint rule `sorrel/route-allowlist` in `lint/sorrel-lint.js` refuses a route handler anywhere except `/api/graphql` and `/api/auth/*`. It now has a second, named exemption for exactly these three files. A fourth public file is a deliberate edit to that list, which is how a new exception gets seen in review. The proxy already lets `/llms.txt` and `/.well-known/*` through without a session (`claude-docs/auth/route-protection.md`).
