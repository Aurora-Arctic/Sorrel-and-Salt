## The two entries (as they go into `tasks/m12.md`)

### M12.6 — Form Groups Carry an Icon (schema) · 3.5h

_Story:_ As a site admin, I want each form group to record which icon stands for it, so that every form filed under the group shows that icon wherever forms are listed.

A nullable `icon` column on `ingredient_form_groups`, typed as a Postgres enum `form_group_icon` over the six names `botanical`, `animal`, `mineral`, `substance`, `fluid`, `curio` — an enum rather than a CHECK because adding an icon is then `ALTER TYPE … ADD VALUE`, expand-only and clear of the destructive-DDL guard, where a CHECK would need a DROP and an ack sidecar. The list lives once, in a new `src/modules/vocabulary/schema/form-group-icons.ts` that imports nothing, the way `ingredient-enums.ts` holds the nomenclature kinds, and feeds the enum, the zod input, the seed and M12.7's component. `src/db/seed/forms.ts`'s six groups each name their icon, and a second, hand-written migration backfills a database that already holds them, keyed on `seed_key` and writing only where `icon IS NULL`, on `0052_retune-category-group-colours.sql`'s pattern. `IngredientFormGroupInput` gains `icon` as nullable and optional, so an admin can clear one; `CategoryGroupInput` stops extending it and builds its own `curatedValueInput('group')`, since a category group takes no icon. The GraphQL type exposes `icon` as an enum field the way `nomenclature` is, the input takes it, and the SDL snapshot and `src/gql/` are regenerated. NULL means "the generic", which M12.7 draws. The decision record `design-decisions/m12.6-form-icons.md` holds the choice of group over form, the generic as a structural necessity, the spoon's provenance and what was rejected (per-form icons, no icons, a CHECK), and corrects DESIGN.md §5's `ingredient_form_groups` entry and its "No colour — form groups section an autofill dropdown" sentence, the SDL in §9, `db/form-vocabulary-seed.md`, `db/categories.md` and the schema file's comment.

_Acceptance criteria:_

- `ingredient_form_groups.icon` exists, nullable, of enum type `form_group_icon` with exactly the six values; `tests/modules/vocabulary/schema/vocabularies.test.ts` lists it as the form groups' own column and category groups still carry none
- `npm run check:destructive-ddl` passes with no ack sidecar
- A fresh seed gives every seeded group its icon; the backfill migration fills a database that already held the six and leaves an admin-set or admin-cleared icon alone, each proven on the row
- `createIngredientFormGroup` and `updateIngredientFormGroup` accept each of the six names and `null`, refuse any other string with a validation error, and expire the compendium tag; `createCategoryGroup` takes no `icon`
- `IngredientFormGroup.icon` and `IngredientFormGroupInput.icon` are in the committed SDL; `npm run codegen` output committed
- DESIGN.md §5 and §9, the seed doc, `db/categories.md` and the schema comment say the new shape; `design-decisions/m12.6-form-icons.md` and `m12.6-plan.md` exist
- `npm run test:coverage` green

### M12.7 — Forms Show Their Icon, and the Admin Picks a Group's · 12h

_Story:_ As anyone reading a list of forms, I want a small mark beside each form saying what kind of thing it is, one mark for a form the vocabulary does not know, and the same mark on the Forms tab, so that a list scans before it is read; and as a site admin I want to choose a group's icon when I add or edit the group, so that a new group is never left on the generic by accident.

Three parts in one PR, in this order. **The icons.** A new `src/components/FormIcon/` — directory, story, doc — holding seven stroke icons in an `icons.tsx` on the nav's conventions (24-unit square, `currentColor`, no fill, `aria-hidden`): one per `FORM_GROUP_ICONS` name and the generic salt spoon, drawn on the Backdrop's `salt-spoon.webp` and signed off by the owner on 2026-10-16 (its path is in `design-decisions/m12.6-plan.md`). `<FormIcon name={icon ?? null} />` renders the named icon, and the spoon for `null` or a name it does not know. The six group icons are drawn here, and **the task stops for the owner's review of them in the Ladle story before anything else is built**, as a design-review task does. `SectionNav/icons.tsx`'s `forms` entry imports the spoon from `../FormIcon` and the flask goes; its "used here and nowhere else" comment and `components/section-nav.md`'s Icons bullet are corrected. **The admin pick.** `GroupForm` gains, for `kind === 'form'` only, a labelled radio group of the six icons plus None (the generic), each option showing its icon and name, placed where a category group's two colour fields sit; its create and update documents select and send `icon`, `null` clearing it, and `GroupValues` carries it as it carries the colours (empty for the other kinds, dropped by their schemas). `GroupList` and `GroupedValueList` show the icon before a form group's name through `GroupChip`, which takes an optional icon as it takes optional colours, and the admin readers and `GroupRow`/`ValueGroupRow` pass `icon` through. **The built surfaces.** `Combobox` gains an optional `icon` on an option, rendered before the label and outside the accessible name; the form suggestion carries its group's icon — `FormSuggestion` gains `icon` through the group join in `src/db/repository/vocabularies.ts`, its type and its GraphQL field — and `FormField` passes it to each option, the "use what you typed" row and the picked box's qualifier taking the spoon. `FormLink` gains `icon`, read from `formChoice { group { icon } }`, so a variant card's head and the substitute summary's Form line lead with the icon. The admin compendium page's read gives `CompendiumList` each form's icon beside its name and the Form column renders them. Resolution is one rule in one place: the curated form's group's icon, else the spoon. The unbuilt surfaces — M8.13, M8.14, M8.18, M8.19, M9.6, M10.15 and M12.4 — carry an amend line from the mint and adopt `FormIcon` when built.

_Acceptance criteria:_

- `FormIcon` renders an SVG hidden from assistive technology for each of the six names, and the spoon for `null` and for a name it does not know, asserted on what is rendered
- The owner has signed the six group icons off in the Ladle story, which shows all seven at 1rem, 1.25rem and 1.5rem on both themes, before the rest of the task is built
- The admin nav's Forms tab shows the spoon; the flask path exists nowhere in `src/`
- The radio group appears for a form group and not for a category group or a tradition, reachable by role and label; saving with an icon chosen stores it and editing to None stores NULL, both asserted on the row through the service
- The form groups list and the forms list show an icon beside each group that has one and the spoon beside one that has none
- A Combobox option with an icon renders it and its accessible name is unchanged
- `formSuggestions` returns each curated form's group icon and NULL for an in-use uncurated value, asserted on the rows
- In the ingredient form a curated variant shows its group's icon and an uncurated one the spoon; the compendium list's Form column shows an icon per form
- Axe clean at 375px; stories and `claude-docs/components/` docs for `FormIcon` (new), `SectionNav`, `GroupForm`, `GroupList`, `GroupedValueList`, `Combobox`, `IngredientForm` and `CompendiumList` updated
