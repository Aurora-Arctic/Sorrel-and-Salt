# M13.17: A shared draft can go back to private

Decision (owner, 2026-10-28): "I still can't turn off share on a draft that is visible to the coven."
Asked to choose, the owner picked: while a spell's status is `draft`, Share With the Coven can be
switched off (`workspace → private`). Once the spell is `complete`, visibility widens only, as before.

This amends [`m13.17-new-spell-private.md`](m13.17-new-spell-private.md), which kept the one-way rule
for every spell and so left a draft already stored as `workspace` stuck shared. The fix landed in
PR #1308.

## The rule now

- A stored `draft` may go `workspace → private`, including in a save that keeps it a draft.
- A stored `complete` spell may not. The refusal is the same explaining error as before.
- A write that sets `status: complete` and `visibility: private` together on a shared spell is refused:
  completing is the write that locks it, so it may not also narrow it.
- Both checks read the status the **stored row** has, and the second also reads the status the write
  names (`assertWidens(current, next, nextStatus)` in `visibility-rule.ts`). Reopening a complete
  spell as a draft and narrowing in one write is refused, because the stored status is `complete`.
- The check stays in the service (`setSpellVisibility` and `updateSpell`). The builder only mirrors it.

## Builder

The Share With the Coven switch is locked only on a saved, complete spell that is shared. On a shared
draft it is enabled and switching it off is an ordinary pending change that Save Spell saves.
A person who switches it off and presses Mark Complete in one go gets the service's refusal in the
notice; the lock note on a complete spell reads as before.

## Not taken

Treating "nobody has read the draft yet" as the test. The service has no way to know it. The status is
the owner's line: a draft is a working in progress, and a complete spell is one others may build on.
