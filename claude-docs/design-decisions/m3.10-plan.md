# M3.10 — `me` query, `User` type and field-level auth scope

Branch `feature/m3.10-me-query-user-type-and-field-level`, stacked on `origin/feature/mb.86-modular-monolith`.

## Context

The shell needs the signed-in user's identity and their covens. Today the schema has only `ok: Boolean!` and `AuditInfo`, and no loader exists. M3.10 adds three things:

- the first real query field;
- the first module-owned GraphQL types, in `src/modules/<name>/graphql/`;
- the first loader.

Acceptance criteria:

- `me` returns the signed-in user.
- An unauthenticated `me` is rejected.
- Another user's email is not exposed.
- Memberships resolve through a loader.

Three facts shaped the plan:

- **A service cannot build a `where`.** MB.33 bans a runtime `drizzle-orm` import in services, so every read needs a named repository finder. Today there is no by-id read and no way to list one user's memberships across workspaces.
- **Module `graphql/` and `loaders/` directories are outside every access-boundary lint override.** `.oxlintrc.json`'s rule-1 override covers `src/graphql/**`, `src/app/**` and `src/components/**`. A resolver in `src/modules/identity/graphql/` could import the repository at runtime and lint would pass. This PR adds the first files there, so it adopts the override.
- **`src/graphql/schema/index.ts`'s comment is wrong.** It says to register a module as `import '@/modules/<name>/graphql'`. That is a deep import, which both the lint and `module-boundaries.test.ts` refuse. Registration goes through the module index instead.

Your decisions:

- **Minimal Workspace:** add `Workspace { id, name, slug, audit }`, which M6 extends.
- **Wider scope:** `email`, `role` and `canCreateWorkspace` all sit behind the self-or-admin scope.

The estimate grows from 2h to about 3–4h, and the TASKS.md landed note says so.

## Schema added

```graphql
type Query {
  me: User!
} # replaces `ok`
enum UserRole {
  user
  admin
}
enum WorkspaceRole {
  viewer
  member
  owner
}
type User {
  id: ID!
  name: String!
  image: String
  email: String! # scope: self or admin
  role: UserRole! # scope: self or admin
  canCreateWorkspace: Boolean! # scope: self or admin
  memberships: [WorkspaceMember!]! # through the membershipsByUser loader
  audit: AuditInfo!
}
type WorkspaceMember {
  role: WorkspaceRole!
  joinedAt: DateTime!
  workspace: Workspace!
  audit: AuditInfo!
}
type Workspace {
  id: ID!
  name: String!
  slug: String!
  audit: AuditInfo!
}
```

- **Scoped fields stay non-null.** A refused field throws `Forbidden`, as every scope refusal does (`builder.ts`'s `unauthorizedError`). A query for another user's email therefore fails loudly rather than returning the user without it. `graphql.md` documents that.
- **`memberships` is a bare list.** It is bounded by its parent, per §7's rule for nested lists.

## Implementation

### 1. Repository: three finders (`src/db/repository.ts`)

- **`findOneById(table, id)`** is general, the read-side twin of `write.updateById`. It uses the same `Unscoped & NotSpellScoped & Identified` constraint and filters soft-deleted rows.
- **`findManyByIds(table, ids)`** is the same, batched. An empty `ids` returns `[]` without a query.
- **`findMembershipsOfUsers(userIds)`** is the second read that takes no proof, beside `findWorkspaceRole`. It is justified the same way: the rows it reads are the user's own memberships across workspaces, so there is no workspace to hold a proof for. It returns live `workspace_members` rows for those users. A correlated `EXISTS` excludes a soft-deleted workspace; it is written as `sql`, like `findManyInSpell`, because the repository keeps one select builder.

Both export pins are updated with a line of argument each:

- `tests/db/repository.test.ts`: `repository public API`
- `tests/guards/soft-delete-finder-guard.test.ts`: `EXPORTED_FUNCTIONS`

### 2. `identity` module

- **`services/profile.ts`: `getMe(session)`.** It reads `findOneById(users, session.userId)` through `cache()`, keyed by the user id (the `membership.ts` pattern). It throws `NotFound` when the row is gone or soft-deleted. It takes `Session`, not `Session | null`, so a signed-out call cannot compile.
- **`graphql/user.ts`.** Defines the `UserRole` enum, the `User` objectRef (exported as `UserRef`), and `me`:
  - `me` carries `authScopes: { signedIn: true }`, and the resolver narrows the session as `two-transports.test.ts` does.
  - The three private fields use `authScopes: (user) => ({ self: user.id, admin: true })`, which passes if either scope holds.
- **`index.ts`** re-exports `profile` and `graphql/user`.

### 3. `coven` module

- **`services/memberships.ts`: `membershipsOf(session, userIds)`.** It returns one result per key, in key order:
  - a key other than `session.userId` gets a `Forbidden`, admin included, because an admin reaches no workspace;
  - otherwise `findMembershipsOfUsers` plus `findManyByIds(workspaces, …)`, two queries per batch whatever the key count;
  - the result is composed as `{ ...memberRow, workspace }`.
- **`loaders/memberships-by-user.ts`: `membershipsByUser`**, built with `defineLoader`. A null session maps every key to `Forbidden`.
- **`graphql/workspace.ts`.** Defines the `WorkspaceRole` enum, `Workspace`, `WorkspaceMember`, and `builder.objectField(UserRef, 'memberships', …)`, which reads `ctx.loaders.membershipsByUser.load(user.id)`. That makes it a `coven → identity` edge, which `ALLOWED` already permits.
- **`index.ts`** re-exports the service, the loader and the GraphQL file.

### 4. GraphQL host

- **`builder.ts`** gains the scope `self: string`, holding when `session?.userId === userId`. Its comment is updated.
- **`loaders/index.ts`**: `LOADERS = { membershipsByUser }`, imported from `@/modules/coven`.
- **`schema/index.ts`**:
  - imports `'@/modules/identity'` and `'@/modules/coven'` for their registrations;
  - drops `ok`, per its own comment ("stands until the first real query field"), after checking that nothing else reads it (grep of e2e, Altair doc and `src/gql`) — **not done:** the grep found the route's tests, the e2e spec and the codegen guard all probing with `ok`, which answers without a session or the database, so it stays;
  - gets a corrected comment.
- **Regenerated files:**
  - `src/graphql/schema.graphql`, via the snapshot `-u`;
  - `src/gql/`, via `npm run codegen`.

### 5. Lint adoption

- **`.oxlintrc.json`**: the access-boundary override's `files` gains `src/modules/*/graphql/**/*.ts` and `src/modules/*/loaders/**/*.ts`.
- **`tests/guards/lint-access-boundary.test.ts`** gains a probe in each new directory.
