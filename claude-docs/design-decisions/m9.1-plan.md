# M9.1 — Stories are browser flows: the story suite moves to Playwright, in its own CI workflow

## Context

The owner's call, 2026-10-16, while starting M9.1: **a user story is proved by a browser flow a user could walk, never by a service call or a GraphQL response.** "Stories should be testing user flows not data transactions." A story test with no live page to walk is rewritten as a browser flow or discarded.

This reverses what the record holds. DESIGN.md §11 "Acceptance tests — story traceability" made `tests/acceptance/*.test.ts` (Vitest, against services) the definition of done; its example is a service call, and the reason was never argued, only assumed. The choice was then locked in by the red-scaffold TDD pattern (a service test can land before its page exists) and by CI cost: MB.224's layer-ownership rule 9 confined Playwright to what only a real server can prove, MB.230 deleted Playwright duplicates of Vitest flows, MB.235 measured Playwright as the gate's slowest job. On 2026-10-12 the owner was asked this question and chose "trace, don't duplicate" (M9.17: `@story-N` tags and a ` · browser` column). Today's call supersedes M9.17.

Further decisions from the owner today:

- **The story suite runs in its own CI workflow**, never on the gate — a red scaffold is never on the merge path, and the gate's time falls rather than rises.
- **No separate task: everything lands in M9.1**, including rewriting the 45 existing Node acceptance tests (stories 1–18, 58–62) as browser flows. M9.1's entry is amended and re-estimated.
- **A gate e2e test that a story flow now proves is deleted.** The story suite becomes the browser suite; `tests/e2e/*.spec.ts` keeps only what no story walks.
- **Tests are the guardrails**: token efficiency never thins a flow. Role/label locators, state assertions, no copy assertions (CLAUDE.md Testing; `claude-docs/testing/layer-ownership.md`).
- **Opus for the lanes that write flows**; Sonnet elsewhere.
- **A flaky story is a failing story.** Retries run so the suite completes, but a test that passed only on retry is reported failing — flakes get fixed, not tolerated.

What the exploration found that shapes the plan:

- Pages missing today: `/coven/[slug]/ingredients` (M9.6), `/coven/[slug]/grimoire` (M10.11), `/compendium` and `/compendium/ingredients/[slug]` (M8.18, M8.19, MB.83). So **stories 12–16 cannot be walked yet** and become fixme scaffolds like 20–27. Stories 1–11, 17–19, 58–62 have their pages.
- Gate specs already walk most of those: `coven-create`, `shell`, `coven`, `workspace-invitation`, `invite`, `admin`, `admin-compendium`, `admin/modal-loading`, `admin-invitations`, `admin/privilege-changes`, `account` (`tests/e2e/`). These become the story flows and leave the gate.
- `signInAs` (`tests/e2e/session.ts:70`) always inserts a fresh user; the seeded A–E are unverified in the e2e database and unusable. Covens are set up by raw SQL in specs (`coven.spec.ts:29-54`). Story specs keep both patterns: SQL and `signInAs` for setup (MB.101), the UI for the step the story is about.
- Playwright 1.64: `TestCase.tags` carries `@story-N` in the reporter API; `test.fixme(title, { tag, annotation }, body)` compiles and reports skipped; `onEnd` may return `{ status }`.

## Mechanism (lane 0, Sonnet — lands first, every other lane branches from its commit)

**Specs and config**

- Story specs live in `tests/e2e/stories/<NN>-<group>.spec.ts` (still under `tests/e2e/`, so `tests/guards/test-location.test.ts` holds). A story is named by Playwright's tag only: `test('…', { tag: '@story-12' }, …)` or an array for several.
- `playwright.config.ts` exports `baseConfig` (outputDir, fullyParallel, workers, globalSetup/teardown, use, forbidOnly) and `slotServers` beside its default export; the default export spreads `baseConfig`. `chromium` and `auditProject` add `/[\\/]stories[\\/]/` to their `testIgnore` arrays (a top-level `testIgnore` is overridden by a project's own), so `npm run e2e` never runs a story.
- New `playwright.stories.config.ts`: `defineConfig({ ...baseConfig, testDir: './tests/e2e/stories', webServer: slotServers, retries: CI ? 1 : 0, passWithNoTests: true, reporter: [['list'], ['./tests/support/story-playwright-reporter.ts', { outputFile: process.env.STORIES_JSON }], ...(CI ? [['json'], ['html', …]] : [])], projects: [{ name: 'stories', use: devices['Desktop Chrome'] }] })`. Only the slot servers — not 8100/8101.
- `package.json`: `"test:stories": "flock /tmp/sorrel-e2e.lock playwright test --config playwright.stories.config.ts"` (shares ports 8001+ with `e2e`). `Makefile` target follows. Delete `vitest.stories.config.mts`; remove `tests/acceptance/**` from `NOT_UNIT` in `vitest.config.mts` and from `NOT_A_PROJECTS` in `tests/guards/test-location.test.ts`; check `tests/support/db-project.mts` comments.

**Checklist**

- New reporter `tests/support/story-playwright-reporter.ts` (types from `@playwright/test/reporter`): collect `TestCase`s in `onTestEnd`, decide in `onEnd` from `test.outcome()` — `unexpected` → failed, **`flaky` → failed** (owner: a story that needed a retry is a story with a bug to fix; retries stay on so the run completes, the checklist line reads ` — FAILING (flaky)` so the cause is visible), `skipped` → skipped, `expected` → passed; a test with no result when `result.status === 'interrupted'` → failed (Vitest's `pending` equivalent). A test under `stories/` with no `@story-N` tag is listed under "No story tag" and makes `onEnd` return `{ status: 'failed' }` — the mechanical guard that replaces review of `describe` names. Writes JSON when `outputFile` is set; prints `formatChecklist`; `printsToStdio() { return true }`.
- `tests/support/story-checklist.ts`: `buildChecklist(observations: {storyId, state, file}[], stories = V1_STORIES)`; keep `statusOf`, `summarizeChecklist`, `formatChecklist`; drop `browser`, `browserFlows`, `unknownTags` (unknown tags become `unknown: {id, file}[]`, still printed "Not a v1 story"). Delete `tests/support/browser-flows.ts`, `tests/support/story-reporter.ts`, `parseStoryHeading` (unused after), and the Vitest-only types in `tests/support/types.ts`. `tests/support/stories.ts` (DESIGN §10 parser) stays.
- `.github/scripts/summarize-stories.mjs`: drop `browser`/`browserFlows`/`unknownTags`. `.github/scripts/summarize-playwright.mjs`: delete "Stories walked".

**CI**

- `playwright.yml` gains input `suite` (`e2e` default | `stories`): switches the run command (`STORIES_JSON=/app/stories.json npm run test:stories`), `continue-on-error: true` on the run step for stories (a reusable-workflow call job cannot carry it), the summariser (`summarize-stories.mjs`), log file, `check-name` `Stories` / `marker-slug` `stories`, and skips the coverage artifact. Cache restore unchanged; `build-only` stays false so a stories run never saves.
- _Superseded before merge by a `stories` job in `pr-gate.yml` (`m9.1-stories-are-browser-flows.md`, "The two suites")._ New top-level `.github/workflows/stories.yml`: `on: pull_request` (staging, main; paths `src/**`, `tests/e2e/**`, `playwright*.config.ts`, the two workflows, `.github/scripts/summarize-stories.mjs`, `.github/actions/**`), `push` to `staging` (job summary only), `workflow_dispatch`. Jobs `e2e-image` and `db-image` call the existing builders as `e2e-cache.yml` does; `stories` calls `playwright.yml` with `suite: stories` and `pr-number`. Concurrency `stories-${{ github.event.pull_request.number || github.ref }}`, cancel-in-progress. **Never a required check** — the ruleset keeps it optional, and the step's `continue-on-error` keeps the job green while the comment shows the red checklist from `steps.run.outcome`.
- `vitest.yml`: remove the "Run acceptance stories", "Summarize stories", "Write stories job summary" and "Comment stories on PR" steps and the header comment.

**Red scaffolds**

`test.fixme('<flow>', { tag: '@story-20', annotation: { type: 'fixme', description: 'M9.6 builds /coven/[slug]/ingredients' } }, async ({ page }) => { …the intended steps… })`. The body typechecks and never runs; going green is `fixme` → `test` and dropping the annotation. The task that builds the page unskips its story in its own PR.

## Flow lanes (Opus, worktrees under `/home/node/worktrees/m9.1-<lane>`, branched from lane 0's head)

Each lane **adds** story specs only; it deletes nothing under `tests/e2e/` and edits no doc. It reports back, per story spec, the gate tests (file + exact title) it makes obsolete — the audit step deletes them in `/app`, so two lanes never edit one gate file. Setup follows the existing specs: `signInAs` for users, raw `postgres` for covens and rows, `recreateE2eDatabase()` in `beforeAll`, Mailpit for mail (`latestMessageTo`), `assertNoAccessibilityViolations` after a waiting assertion. Every story the lane owns is walked end to end in the browser as a user would — each `it` of the old Node test that is a user-visible behaviour becomes a step or an assertion; a refusal is proved by the control being absent **and** the direct URL/action being refused (404/403 page), since "no rows" alone proves nothing.
