# M15.84 — The Compendium Page Sends Each Thing Once

M15.7's measurement of `/compendium` (PR #1610) found two kinds of data that reached the browser twice. This record says what changed for each, why that form was chosen, and what it cost.

## The vocabularies

**Before.** The page sent every category and every deity in full for the search field's suggestions (`categories`, `vocabulary.deities`), and sent them again inside the filter's choices, which the server had already labelled (`facets`: a value, a label and a count for each).

**Now.** The page sends the service's counts as they come (`counts`, keyed by id for a category or a deity and by text for the rest). The filter labels them in the browser with `facetChoices(counts, vocabulariesOf(categories, vocabulary))` in `src/components/CompendiumList/facets.ts`. That is the code the open panel already ran to label a live answer from `/api/graphql`, so the browser downloads no new mapping code. The coven ingredients page and the curator compendium take the same props.

**Why this form.** The other way round, sending only the labelled choices and dropping the full lists, would leave the suggestions without the categories and deities no entry under the current filter carries. The suggestions offer every one.

**What is left.** Each deity's name is in the page's data once. Each category's name is in the vocabulary once, and again on each card that wears it, as `{ id, name }` for the card's chips.

## The cards

A card has to reach the browser twice: once as the HTML the server draws, and once in React's data (the `self.__next_f.push` payload), so that React can take the page over. The second copy cannot be removed, but it can be made smaller.

**Before.** `IngredientCard` was a server component, so its second copy was its drawn element tree: every class name, the recency and form-icon SVGs, and every wrapper element.

**Now.** `IngredientCard` (`index.tsx`) is a server wrapper that renders `CardFace` (`face.tsx`), a client component holding the same markup. The second copy is the card's props, and the browser draws the markup from them. Before handing them on, the wrapper reduces the props to what the face shows:

- Safety notes, the entry's and each form's, become a one-character stand-in (`'*'`), or `null` for none. The card shows only a Caution badge, never the text.
- Each variant keeps only its form, its group's icon, and whether it is toxic or has notes.

**Why this form.** The other form considered was to keep the card a server component and trim its markup. That would shrink both copies a little, but every class name and icon would still be sent twice. Sending the card's data removes the second copy of the markup entirely, and the card's code then has to be downloaded once, which the figures below show is the smaller cost.

**What is left.** Whatever a page passes in `actions`, `startActions` and the jar slot is still sent as a drawn element tree, because those are server-drawn elements. The heading's details link, with its formal name, is sent the same way.

## The cost and the figures

These were measured as M15.7 measured them: a production build (`next build`, then `next start`) of the commit before the change (`cdbc4007c`) and of the change, each against the same database seeded with the `standard` scenario (758 compendium entries, 101 categories, 290 deities). The HTML was fetched signed out and signed in (as the seed's user A, a member of the Whitethorn coven), and the first-load scripts were read in a browser. Compressed means gzip. A KB here is 1,000 bytes.

| Page                                  | HTML before (raw / gzip) | HTML after (raw / gzip) | Change (raw / gzip) |
| ------------------------------------- | ------------------------ | ----------------------- | ------------------- |
| `/compendium`, signed out             | 451.3 KB / 60.3 KB       | 356.1 KB / 56.8 KB      | −95.2 KB / −3.6 KB  |
| `/compendium`, signed in              | 473.6 KB / 61.9 KB       | 377.2 KB / 58.3 KB      | −96.5 KB / −3.6 KB  |
| `/coven/whitethorn-coven/ingredients` | 306.6 KB / 51.3 KB       | 286.7 KB / 50.1 KB      | −19.9 KB / −1.2 KB  |

| Page                                  | First-load scripts before (raw / gzip) | After (raw / gzip)    | Change (raw / gzip) |
| ------------------------------------- | -------------------------------------- | --------------------- | ------------------- |
| `/compendium`, both                   | 1,412.7 KB / 425.3 KB                  | 1,418.9 KB / 427.0 KB | +6.2 KB / +1.7 KB   |
| `/coven/whitethorn-coven/ingredients` | 1,512.9 KB / 459.0 KB                  | 1,519.1 KB / 461.4 KB | +6.2 KB / +2.4 KB   |

On `/compendium`, React's data shrank from 244.2 KB to 162.6 KB signed out (36.5 KB to 33.5 KB compressed). One card's share of it, measured as the distance from one card's link to the next, went from about 5.0 KB to about 2.0 KB.

On `/compendium` the first-load scripts grow by 1.7 KB compressed while the HTML shrinks by 3.6 KB, so the first visit downloads less. On the coven ingredients page the scripts grow by 2.4 KB while the HTML shrinks by 1.2 KB, so a first visit that starts there downloads about 1.2 KB more. The scripts are cached after the first visit, and the HTML saving recurs on every visit, so the change was kept for that page too rather than giving the two pages different cards. A coven card's own share shrinks less (about 4.4 KB to 3.3 KB), because its jar lines and actions are still drawn on the server.
