  - Approved: browser checks use their own database, seeded with `a` and `e` marked as agreed. The shared dev database is never changed.
  - Approved: stop measuring the old skeletons.
  - An Opus agent verifies every layout at the end.

## Part 1 — Skeletons beside each page (replaces M12.33's link targets)

**Mechanism** (`src/lib/navigation/`):

1. `NavigationProvider` stores the destination `href` in the active navigation, next to `owner`. `useNavigationState()` returns `{ busy, href }`. The `target` option, the `NavigationTarget` type and the `navigationTarget` prop are deleted. Deleting the type makes a link-named skeleton impossible to write, so no lint guard is needed.
2. `route-match.ts` matches a pathname against the app's route patterns. It ignores route groups `(…)` and `@action` slots, drops the query string, and handles the dynamic segments `[slug]`, `[id]`, `[number]`, `[token]` and `[key]`. There are no intercepting routes. Next has no client-side matcher.
3. `src/app/skeletons.ts` is the registry: route pattern → `{ host: 'main' | 'coven' | 'admin', Skeleton }`.
   - A host draws only when the destination's entry names it and the host is mounted for that address. The coven host draws only for the same coven slug.
   - Otherwise `MainBody` draws the whole frame, as today.
   - A pathname equal to the current one draws nothing at host level: a pager or filter in `ListFrame` keeps its own skeleton.
   - Guard test `tests/guards/skeletons.test.ts` scans `src/app/**/page.tsx` and fails if a data-backed page has no registry entry or if an entry names no page. Pages exempted on purpose (auth forms with no data, `@action` slots) are listed by name in the test. This follows the sweep-task rule's "mechanism plus mechanical guard".

**Skeleton files.** `skeleton.tsx` sits beside each `page.tsx`, or beside a layout where a layout stays up during the wait: `TabbedPage` layouts, the coven layout and the curator and keepers layouts. Each draws the page's real components with placeholder content:

- **`PageHeader`:**
  - Static titles show the real text ("Compendium", "Users").
  - Dynamic titles get one new prop, `pendingTitle`, which draws a `Skeleton line` inside the same `h1` box.
  - `eyebrow`, `lede` and `action` take Skeleton blocks.
- **`TabbedPage`** renders with its real `tabs` array, imported from the same module the layout uses. The tab panel draws the destination tab's own skeleton, which replaces `tab-switch.tsx`'s shape and filtered props.
- **`PageNav`** takes static placeholder entries. Its count and section labels come from the page module where they are static, so the 140px against 288.5px drift goes.
- **Lists and tables:**
  - `ListFrame` and `FilterForm` render with their real controls disabled and `aria-hidden`, so field count and widths match.
  - `DataTable` gets skeleton rows from the page's own `columns` definition.
- **`IngredientCard` and `SpellCard`.** Each gets its frame extracted (`CardFrame`, the parts with no data), and the card and its skeleton both draw that frame.
- **`.page-column`, `.page-frame` and `.page-with-nav`** are written as class markup, which repeats on every page. They become small layout components (`PageColumn`, `PageFrame`, `PageWithNav`) that the page and its skeleton both use. The existing pages adopt them in this PR.
- **Route modals:** `loadingBody` stays, with the modal skeleton beside the modal (`SupportRequests` today).

**`Skeleton`** shrinks to its blocks (`line`, `block`, `row`, `card`). The page shapes (`table`, `cards`, `form`, `page`, `contents`, `recipe`, `detail`, `requests`) are removed, together with `site-target.ts`, `AdminNav/target.ts`, `covenTarget` and their tests.

**Representative files:**

- `src/lib/navigation/{provider.tsx,use-navigation.ts,types.ts,pending-link.tsx}`
- `src/components/AppShell/main-body.tsx`, `src/components/SectionBody/index.tsx`, `src/components/Skeleton/index.tsx`
- `src/components/PageHeader/`, `src/components/TabbedPage/tab-switch.tsx`
- `src/app/(public)/compendium/skeleton.tsx`, `src/app/(shell)/keepers/(people)/users/skeleton.tsx`, `src/app/(shell)/coven/[slug]/skeleton.tsx`

## Part 3 — MB.124 design review (run as MB.123 was: `design-decisions/mb.123-plan.md`)

1. **Audit, read-only, in parallel with Part 1:**
   - **Camera lane:** both themes, 375px and 1280px, on its own database as decided. It covers the 403, 404 and 500 pages (`ErrorScreens`, `NotAuthorized`, `global-error.tsx`), every empty state, and a whole-site walk.
   - **Research lane:** Chicago-form sources (NN/g, GOV.UK Design System, WAI-ARIA APG, Baymard) on error pages, skeletons, empty states and floating panels.
   - Each lane writes numbered findings with file:line.
2. **Sign-off:** a mocks lane draws one option per open question. A private claude.ai artifact shows them with radios, a notes box and a light/dark toggle. You pick there, and the picks are recorded as a comment on #581.
3. **Build lanes:** each in its own worktree branch, merged into the task branch by the main session. Items known now:
   - **Error pages share one design.** `global-error.tsx` uses `ErrorPage`'s frame and `ReportThis`, and the 403 gets a `<title>`. The thrown and the server-drawn 404 look the same.
   - **One `EmptyState` component** replaces the 12 hand-drawn `*__empty` classes and wraps `emptyList()`.
   - **`ConfirmedAction` moves to its own directory**, with its own CSS, story and doc. One shared confirm row serves `Answers`, `ConfirmQuestion` and `DiscardQuestion`. A new `ConfirmDialog` replaces the five hand-written confirms (4 files).
   - **Floating panels get one width token**, which replaces `$switcher-min-width`, `$switcher-list-min-width` and AccountMenu's raw 13rem, subject to your pick.
   - **`StackTable`'s first cell becomes `th scope="row"`**, and the cell-counting tests are updated.
   - **The QR code is drawn dark-on-light with a quiet zone in both themes.** Today it is `$chalk-muted` on `$soot` in both. You check it scans in Google Authenticator, Microsoft Authenticator and 1Password on your phone, because no agent can do that.
   - **`$layers` already exists** (`_variables.scss:955`). The leftover in the issue is stale. The 28 single-digit local `z-index` values are allowed by `styling.md`, and that is recorded, not changed.
   - Every finding of the whole-site read is fixed if under an hour, and minted as a task if not.
4. **Storybook and `/design-sync`:** a separate agent updates every affected story ("States" first) and runs `/design-sync` until every changed story grades `match` or `close`. `/design-sync` is not a skill in this repo (`.design-sync/` holds only config). See question 2.
5. **Accessibility:** `scanBothThemes` moves from `tests/e2e/axe.spec.ts` into `tests/e2e/axe.ts`. The error pages, skeletons, empty states and the whole-site read are axe-checked in both themes, plus a keyboard-only pass and a screen-reader pass against WCAG 2.2 AA. Each failure is fixed or minted.
