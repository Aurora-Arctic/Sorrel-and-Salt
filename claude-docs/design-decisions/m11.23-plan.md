# Pre-commit on changed files only

## Context

Today the git hook (the `pre-commit` npm package, configured by the `"pre-commit": ["lint", "format:check", "typecheck"]` array in `package.json`) and the `npm run pre-commit` script both run over the **whole repo**: `oxlint .`, stylelint on every `.scss`, `prettier --check .`, and `tsc --noEmit`. Every commit pays for the whole repo, even a one-line doc fix. The owner wants pre-commit to check only the files that changed. CI's `checks.yml` keeps the whole-repo gate, so narrowing the local check gives up no protection.

Decisions taken with the owner:

- **The hook checks staged files.** Unstaged edits are stashed aside while it runs, so it checks exactly what is being committed.
- **`npm run pre-commit` run by hand checks every tracked file changed since HEAD**, staged or not, so a run before `git add` still checks something. An untracked file needs `git add` first.
- **Typecheck stays whole-project but only runs when TypeScript changed**: a staged `.ts`/`.tsx`/`.mts`/`.cts` file, `tsconfig.json`, `package.json` or `package-lock.json`. `tsc` can't be scoped to files, because changing an exported type can break files nobody touched. It is already incremental (`tsBuildInfoFile` in `tsconfig.json`).
- **It gets its own task and branch**, not the M9.1 branch.

## Approach: lint-staged

Use **lint-staged**, the standard tool for this (memory: prefer the standard package over a bespoke script). It works out the file list, stashes and restores unstaged changes, and passes the files to each command. Its `--diff=HEAD` flag gives the by-hand behaviour (and turns off stashing on its own). Keep the existing `pre-commit` npm package as the hook installer. It just runs a different script.

**Recommendation: lint-staged.** It is the one option that checks the copy being committed, the hiding is the part most likely to go wrong in a script we write ourselves, and its real cost is one small extra package (memory: prefer the standard tool). The `pre-commit` package stays as the hook installer, so nothing changes in how hooks get set up.

### Files

1. **`package.json`**
   - Add the devDependency `lint-staged` (current major, exact-pinned like the rest of the lockfile).
   - `"pre-commit"` script → `lint-staged --diff=HEAD`. This is the by-hand run: tracked changes since HEAD.
   - New `"pre-commit:staged"` script → `lint-staged`. This is the hook's run: staged files only.
   - The `"pre-commit"` array (the hook's config) → `["pre-commit:staged"]`.
   - `lint`, `lint:css`, `format:check` and `typecheck` stay unchanged as the whole-repo commands CI and anyone else can run.

2. **New `lint-staged.config.mjs`.** It's `.mjs` because the typecheck and config-change entries need functions, which JSON can't hold. Each entry has a comment saying why:
   - `*.{js,mjs,cjs,jsx,ts,mts,cts,tsx}` → `oxlint`, run on the listed files.
   - `{src,.ladle}/**/*.scss` → `stylelint --allow-empty-input`, the same scope as `lint:css`.
   - `*` → `prettier --check --ignore-unknown`. Prettier still honours `.prettierignore` for paths passed explicitly.
   - `{**/*.{ts,tsx,mts,cts},tsconfig.json,package.json,package-lock.json}` → `() => 'tsc --noEmit'`. Returning the command from a function means it gets no file arguments, runs once, and checks the whole project.
   - **When a check's own config changes, that check reruns over the whole repo**, because a narrowed check would miss what the new rule now flags:
     - `{.oxlintrc.json,lint/**}` → `() => 'oxlint .'`
     - `{.prettierrc*,.prettierignore}` → `() => 'prettier --check .'`
     - `{.stylelintrc*,package.json}` → `() => 'npm run lint:css'`. `package.json` is on this list because it carries `browserslist`.

3. **Docs, corrected in the same PR (MB.31)**

## Verification

In the worktree, after `npm install`:

1. **Whole-repo sanity**: run `npm run lint`, `npm run format:check` and `npm run typecheck` once, so the new config file itself passes.
2. **Hook narrows to staged files**: stage a `.ts` file with a lint error and run `git commit`. It should be refused, with oxlint naming only that file.
3. **Unstaged edits are ignored by the hook**: stage a clean file and leave a bad unstaged edit in another file. The commit should pass, and the unstaged edit should be restored afterwards.
4. **The by-hand run sees unstaged edits**: `npm run pre-commit` with that same unstaged bad edit should fail.
5. **Typecheck is skipped for non-TS changes**: a staged `.md`-only change runs prettier only, with no `tsc` in lint-staged's output. A staged `.ts` change runs `tsc`.
6. **Config changes rerun the whole repo**: touch `.prettierrc` and confirm `prettier --check .` runs.
7. **Ignore files hold**: a staged file under `src/gql/` or `src/graphql/schema.graphql` is not flagged by prettier.

Discard all the probe edits afterwards (`git restore` / `git reset`, in the worktree only).
