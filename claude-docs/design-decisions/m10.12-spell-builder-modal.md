# M10.12 — The spell builder is a modal

**Decided (2026-10-27, the owner):** the spell builder is a wide modal over the grimoire's list, not a page of its own. The working summary is [`../components/spell-builder.md`](../components/spell-builder.md); the modal it sits in is [`../components/modal.md`](../components/modal.md).

## Why

- **The owner's call**, made on 2026-10-27 while M10.12 was being built as the page `/coven/[slug]/grimoire/new`.
- **Consistency with Add Ingredient.** A coven's other "make a new thing" form, Add Ingredient (M8.16), is a modal opened by the address over the page it was opened from. A spell made the same way reads the same way, and Close returns the person to the list they came from.
- **Ingredient forms will autosave too** (M13.24). Once both forms save as they go, both are drafts that are kept rather than thrown away, so both can share one way in and one way out.

## The four decisions

1. **A modal, opened by the address.** `?new=spell` over the grimoire opens the builder empty, and `?edit=<id>` opens a saved spell. The modal is `size="wide"`. The page `/coven/[slug]/grimoire/new` and its test are removed.
2. **The first save swaps the address.** A create replaces `?new=spell` with `?edit=<id>`, with `router.replace`, so Back goes to the grimoire rather than to an empty New Spell, and a reload opens the saved draft. The builder reports a create through `onCreated` whichever way the save was made, so M13.17's autosave moves the address the same way as Save does. The dialog keeps the same builder under the new address, so nothing typed is lost. A create made by Close skips the swap, since the dialog is closing.
3. **Edit uses the same modal.** A spell card's pencil and Quick Look's Edit open `?edit=<id>` (M13.10). The planned page `/grimoire/[id]/edit` is dropped. The recipe page hosts its own copy of the dialog at `?edit=<id>`, with the recipe page as the address Close returns to.
4. **Close saves, then closes, and asks nothing.** Close, Escape and a click outside save anything unsaved, then close (`useSaveOnClose`). This is the builder's exception to M13.14's Discard Changes question: a spell's draft is kept, never thrown away. A refused save keeps the dialog open with the refusal shown. Closing the tab or reloading still asks the browser's own question, which no page can answer by saving.

## The `?new` values

The owner chose on 2026-10-27 that `?new` takes a value naming what it opens:

| Address           | Opens                                                                                                       |
| ----------------- | ----------------------------------------------------------------------------------------------------------- |
| `?new=spell`      | New Spell on the grimoire; nothing on a coven's other pages (an admin page reads any `?new` as its own add) |
| `?new=ingredient` | Add Ingredient for the default coven                                                                        |
| `?new` (no value) | The same as `?new=ingredient`, so older links keep working                                                  |
| `?new=<slug>`     | Add Ingredient for the coven with that slug, as before                                                      |

**Why `spell` and `ingredient` are reserved coven slugs.** `?new=<slug>` already names a coven, so a coven whose slug was `spell` or `ingredient` would make `?new=spell` or `?new=ingredient` mean two things. `isReservedCovenSlug` (`src/lib/coven-path.ts`) refuses both, as it already refused `new`, and the creation service gives a coven named Spell the slug `spell-2`. No coven in the seeds used either slug when the rule was added.

## Opening with no skeleton

New Spell's press writes `?new=spell` with the browser's `history.pushState`, as Add Ingredient's does, and the dialog reads the address itself (`useSearchParams`) and draws the empty builder at once. Opened the other way, through the server, the modal first showed its loading skeleton, 518px tall, and then the form at 720px; the dialog is centred, so its top jumped up the screen as the form arrived. That was the owner's report of a dialog that "does a weird scrolling thing and jumps size". Opening a saved spell still goes through the server, since only the server can read the spell.
