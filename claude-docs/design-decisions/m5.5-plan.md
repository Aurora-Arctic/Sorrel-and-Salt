# M5.5 — Admin compendium CRUD: the approved plan

**Status:** approved · **Date:** 2026-10-07

The owner's calls are recorded in [`m5.5-admin-compendium.md`](m5.5-admin-compendium.md).

Worktree `/home/node/worktrees/m5.5`, branch `feature/m5.5-admin-compendium-crud`, stacked on MB.178 (PR #700).

## Context

Story 18: a site admin adds, edits and soft-deletes compendium entries at `/admin/compendium`, through GraphQL, reusing `IngredientForm`. The surveys found the write services built and tested (M5.2: `createCompendiumEntry`, `updateCompendiumEntry`, `deleteCompendiumEntry` in `src/modules/ingredients/services/compendium.ts`, with collisions, MB.82's `endRedirect` refusal, MB.162's curated-only rule, substitutes and references held to the compendium). Everything above them is missing:

- no compendium mutations in the schema;
- no `nomenclature` filter on `compendium`, at any layer;
- every lookup the form uses, and `possibleDuplicates`, requires `workspaceId: ID!`;
- `IngredientForm` is create-only and coven-only: no edit values, no update, no delete, no compendium mode, no `endRedirect` confirmation;
- no page mounts the form, and the nav's Compendium entry is a plain `<a>` to a page that doesn't exist.

**The owner's calls, made at scoping:**

1. **One PR, as M5.5.** The 2h estimate is corrected; nothing is minted.
2. **M5.6's page shape, with a large modal.** `?new` / `?edit=<slug>` open the form in `Modal`, given a wide size. M8.16 already puts this form in a modal, and the References panel was nested inline for exactly that reason.
3. **Nullable `workspaceId` on the lookups.** Null reads the compendium tier alone, the convention `ingredient(id, workspaceId)` and `createReference` already use.
4. **Save Ingredient opens the entry's admin modal,** `?edit=<slug>`. There is no public entry route yet.

**One refinement to call 3, for review:** the lookups keep their `signedIn` scope rather than becoming public. MB.80 draws the public line field by field (`tests/db/graphql-query-scopes.test.ts`), and only a signed-in admin's form calls these. The `null` arm is open to any signed-in user, which is safe because it reads only public compendium data.

**The categories criterion lands with MB.126.** An update replaces the whole entry, `categoryIds` included, so until the picker exists the form carries an entry's category ids through an edit untouched. MB.126 adds the picker to `IngredientForm` itself and reads the public `categories` query, so after MB.126 merges and staging is merged in, the compendium form gets it without M5.5 code. M5.5 then adds the test, and its PR opens with `Closes #300`.

## 1. Backend (GraphQL, services, repository)

**`nomenclature` filter.**

- `CompendiumFilter` (`src/modules/ingredients/validation/compendium-filter.ts`) gains `nomenclature: z.enum(NOMENCLATURE).optional()`.
- `IngredientFilter` (`src/db/repository/types.ts:401`) gains the field too.
- `compendiumList` (`src/db/repository/ingredients.ts:316`) gets an `eq(ingredients.nomenclature, …)` arm. The page and the count share `compendiumList`, so `totalCount` follows.
- The Pothos arg goes in `src/modules/ingredients/graphql/compendium.ts`, as `t.arg({ type: Nomenclature })`.

**Compendium mutations**, in a new `src/modules/ingredients/graphql/compendium-entries.ts`:

- `createCompendiumIngredient(input: CompendiumIngredientInput!, endRedirect: Boolean): Ingredient!`
- `updateCompendiumIngredient(id: ID!, input: CompendiumIngredientInput!, endRedirect: Boolean): Ingredient!`
- `deleteCompendiumIngredient(id: ID!): ID!`

How they're built:

- Each carries `authScopes: { admin: true }` and `if (!session) throw new Forbidden()`, M5.6's pattern (`vocabulary/graphql/categories.ts:72`).
- `CompendiumIngredientInput` mirrors `IngredientInput` (`workspace-ingredients.ts:42`), with `nomenclature` required. The Zod parse stays the real check.
- An update clears the five child loaders, as `updateIngredient` does (`workspace-ingredients.ts:126`).

**Lookups with `workspaceId: ID` (nullable), null meaning the compendium alone.**

- **Queries:** `formSuggestions`, `planetSuggestions`, `zodiacSuggestions`, `deitySuggestions`, `commonNameSuggestions`, `referenceSuggestions` and `possibleDuplicates`.
- **Services** (`vocabulary/services/suggestions.ts`, `ingredients/services/{common-names,references,duplicates}.ts`): build `memberships: Membership[]`, which is empty for null and holds `[await assertMembership(…)]` otherwise. This is `getIngredient`'s pattern (`compendium.ts:108`).
- **Finders** switch from `membership: Membership` to `memberships: readonly Membership[]`, with `or(inCompendium(t), ...memberships.map(m => scopedTo(m, t)))`. That is the house idiom ("No proofs reads the compendium alone", `ingredients.ts:31`). The finders: `findVocabularySuggestions`, `findCommonNameSuggestions`, `findReferenceSuggestions` and `findSimilarIngredients`.
- `ingredientSuggestions` stays coven-only, since a compendium substitute reads `compendium(query)` (the task's criterion).

Then run `npm run codegen` and commit the SDL snapshot and `src/gql/`.

## 2. `IngredientForm`: compendium and edit modes

Props (`src/components/IngredientForm/types.ts`). The coven-edit combination can't be expressed, so coven edit stays M8.16's:

```ts
type IngredientFormProps = { onSaved?: …; onDeleted?: () => void } &
  ({ workspaceId: string } | { workspaceId: null; entry?: { id: string; values: IngredientFormValues } });
```

**Save and delete**

- **Save:** create calls `createWorkspaceIngredient` for a coven and `createCompendiumIngredient` for the compendium. An edit calls `updateCompendiumIngredient`, with `defaultValues = entry.values`.
- **`SavedIngredient`** gains `slug`, so the page can address the saved entry.
- **Edit mode buttons:** Save Ingredient is the only save button, disabled until the form is dirty, with its spinner. Delete Ingredient (`.btn--destructive`) uses CategoryForm's inline confirmation, Delete / Keep It, and then calls `onDeleted`.

**Compendium mode** (`workspaceId === null`)

- The classification is marked required.
- The form, planet, sign and deity boxes are choose-only: their options are filtered to `curated`, with `offerTyped` false (`fields.tsx:489`).
- The substitutes box queries `compendium(query)`, maps nodes to `SubstituteLink { isGlobal: true }` and leaves out the entry itself.
- Folk names and references query with `workspaceId: null`. The reference panel calls `createReference` with null, which is already supported.
- The duplicate warning queries `possibleDuplicates(workspaceId: null)` and drops the entry's own id.

**`categoryIds`**

- `categoryIds: string[]` is added to `IngredientFormValues`: `[]` when empty, the entry's ids when editing, and always sent by `toInput`.
- It has no field until MB.126.

**`endRedirect` confirmation**

- `fieldNameOf` maps a `['endRedirect']` issue to a confirmation state, not to `root`.
- The form shows the message, with **End Redirect & Save** and **Keep It**. Confirming resends the same values with `endRedirect: true`.

## 4. The page: `/admin/compendium`

**Files.** Mirror `src/app/admin/categories/`: `page.tsx`, `types.ts`, `compendium-dialog.tsx`, plus a `CompendiumList` component directory with `index.tsx`, `filter.tsx`, `href.ts`, `types.ts`, `index.scss`, a story and a doc.

**Reads.**

- `requireAdminSession()` gates the page.
- A `cache()`'d reader runs `resolvePage` → `listCompendium(filter, req)` and `countCompendium(filter, start)`.
- The address is read with `single()` / `readableCursor()` (`src/lib/search-params.ts`).

**The filter**, MB.178's native GET form:

- `?query=`
- `?nomenclature=<kind>`: a native `<select>` over the classifications, reusing the form's labels. Unknown is the to-do list.
- `?withoutReferences=1`: a checkbox, the second to-do list.
- An unknown kind is ignored.

**The list**

- Columns: Name · Formal Name (an em dash when there is none, which is how the criterion tells the two kinds of unknown apart) · Form · an Edit link.
- A soft `Pager` follows the list.
- A filtered list with no rows says that no entry matches.

**The modal**

- `?new` opens an empty form.
- `?edit=<slug>` runs `resolveCompendiumSlug(slug)`:
  - `entry`: the server builds the edit values from `getIngredient`'s row with `folkNamesOf`, `categoriesOf`, `substitutesOf`, `deitiesOf` + `deityTraditionsOf`, `referencesOf` + `citationText`, and `formChoicesOf` + `formGroupsOf` (compendium refs, null session). The mapper lives in `src/app/admin/compendium/entry-values.ts` and is `server-only`.
  - `moved`: `redirect()` to the current `?edit=`.
  - `NotFound`: an alert reading "No compendium entry has that address".

**After a save or delete**

- Save Ingredient: `router.replace(href(here, { edit: saved.slug }))` + `refresh`.
- Save & Add Another: stay on `?new`, and the form clears itself.
- Delete or close: replace with the list's address, filter and cursor kept, + `refresh`.

**Nav.** AdminNav's Compendium entry becomes a `<Link>` now that the route exists.
