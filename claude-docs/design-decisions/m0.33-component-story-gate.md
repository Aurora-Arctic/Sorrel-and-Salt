# M0.33 — Gate: no standalone component without a story

**Status:** decided · **Date:** 2026-09-08 · **Builds on:**
[m0.32-component-stories.md](./m0.32-component-stories.md),
[m0.30-ladle-component-workshop.md](./m0.30-ladle-component-workshop.md)

M0.32 gave every component in the tree an `index.stories.tsx`. This task keeps
it that way: a check that fails when a component ships without one, so "every
future component is in the workshop" is enforced rather than remembered.

---

## A script, not an Oxlint rule

The task named an Oxlint rule as the first choice "if it can express
'directory has `index.tsx` ⇒ directory has `index.stories.tsx`'". It can't:

- Oxlint (v1) has no custom-rule / plugin API — the rule set is the built-in
  Rust one. There is nowhere to add a repo-specific assertion.
- The check is inherently cross-file and filesystem-shaped: "this file's
  existence implies that sibling's existence". A single-file linter has the
  wrong unit of work for it even in principle.

So it's `scripts/check-component-stories.ts` — Node's native TypeScript
(`node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON scripts/…`, matching
`resume-2026`'s `scripts/`), with `scripts/package.json` = `{ "type": "module" }`.
`tsconfig` doesn't reach `scripts/`, so `tsc` doesn't typecheck it; oxlint does
(the `.oxlintrc.json` `scripts/**/*.ts` override already exists — node env,
`no-console` off).

## What it checks

Walks `src/components/` recursively. Every directory that contains an
`index.tsx` must contain an `index.stories.tsx`. Recursion (not a single
`src/components/*/` level) so a nested component — `src/components/Forms/Input/`
— is covered; the M0.32 `config.mjs` comment already anticipates
`forms--input--default` story ids.

- Clean tree → prints a one-line count, exits 0.
- One or more missing → prints each missing path (`src/components/Foo/index.stories.tsx`),
  a pointer to the CLAUDE.md convention, exits 1.
- No `src/components/` at all → exits 0 (nothing to police); the directory
  currently holds only `ThemeToggle`, which M0.32 already covered, so the gate
  is green on landing.

## Scope is `src/components/` only

`.ladle/*.stories.tsx` — the M0.32 design-language reference page and any future
workshop-only page the app never imports — is deliberately outside the walk.
M0.32's decision doc calls this the "one known exception": the `stories` glob in
`config.mjs` is an array whose second entry picks those up for the workshop, but
they are not components and nothing requires them to sit next to an `index.tsx`.
The gate polices the `src/components/` shape and nothing else.

## Where it runs

- **pre-commit** — added to the `pre-commit` array in `package.json` (the
  `pre-commit` package runs those npm scripts) and to the chained `pre-commit`
  script. `make check-stories` / `make pre-commit` wrap it, per the makefile's
  "same muscle memory" rule.
- **CI** — `npm run check:stories` and `npm run workshop:build` are both plain
  npm scripts. The CI build job (M0.17) and the PR gate (M0.20) **do not exist
  yet** (`.github/` is not in the tree; M0.14–M0.21 are unstarted). When they
  land they add these two script calls — `check:stories` for the missing-file
  gate, `workshop:build` so a story that _throws_ fails the run. Leaving the
  checks as npm scripts is the whole handoff; there is no workflow file to edit
  in this PR, and editing one that doesn't exist would be an adjacent task.

## M0.10 component checklist

The task's last criterion — "if the M0.10 component-documentation skill has
landed, its checklist names the story file" — is N/A. M0.10 ported only the six
Gitflow skills from `resume-2026`; there is no component-documentation skill
(see [m0.10-porting-claude-skills.md](./m0.10-porting-claude-skills.md) and
CLAUDE.md's Skills section). The equivalent guidance lives in
`claude-docs/components/README.md`, which already lists the story file as part
of a complete component, and CLAUDE.md's Conventions section, updated here.

## Verified

- `node scripts/check-component-stories.ts` on the real tree: `1 component,
every one with a story.`, exit 0.
- With a seeded `src/components/_GateFixture/index.tsx` and no story: prints
  `src/components/_GateFixture/index.stories.tsx`, exit 1. Fixture removed →
  back to exit 0.
- `npm run pre-commit` runs `check:stories` as its last step and passes.
- `npm run lint`, `npm run format:check`, `npm run typecheck` pass.
- `npm run workshop:build` still exits 0 (unchanged; named here because CI runs
  it beside the gate).

## What this commits later tasks to

- **M0.17 / M0.20** add `npm run check:stories` and `npm run workshop:build` to
  the build job and the PR gate when the workflows are ported. No code change to
  the gate itself — the scripts are the contract.
- A new component's PR is incomplete until `index.stories.tsx` exists; pre-commit
  now says so locally before CI does.
- If a component ever legitimately can't have a story, that's a change to this
  script's scope (an ignore list, or a marker file) and a note here — not a
  silent carve-out.
