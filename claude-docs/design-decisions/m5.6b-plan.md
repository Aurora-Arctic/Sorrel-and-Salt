## Context

M5.6b (#303) puts the two group vocabularies, `category_groups` and `ingredient_form_groups`, on the admin page shape M5.6 set up and M5.6a reused: one route each, with a modal opened from the URL (`?new`, `?edit=<slug>`). The core of the task is the write-time contrast floor: `colorDark` against the dark card (`$soot-raised` `#1f1c16`) and `colorLight` against the light page (`$parchment` `#efe9da`), each at 4.5:1. A refusal names the column and the ratio and is pathed to that column (MB.36, MB.43).

Work happens in the worktree `/home/node/worktrees/m5.6b` on `feature/m5.6b-admin-group-crud-with-colour-contrast`, off `origin/staging`. `/app` still holds M5.5's uncommitted work.

## The owner's calls (recorded in `claude-docs/design-decisions/m5.6b-admin-groups.md`)

1. **Deleting a category group that still has live categories moves them to a group the admin picks, after a confirmation.** In the modal, Delete Group first shows a group picker ("Move its N categories to"). After a group is picked, a second step asks to confirm: "Move N categories to _Wellbeing_ and delete _X_?" Confirming runs one transaction that moves the categories and soft-deletes the group. A category's slug is its name alone, so nothing else moves, and compendium and coven links stay.
2. **Deleting a form group moves its forms to a group the admin picks, with the same two steps.** Each moved form re-slugs, since `formSlug(name, group)`. If a form of the same name already sits in the target group, the delete is refused on `moveTo`, naming it. **This amends the criterion:** the forms stay curated, so a compendium entry's pick is never orphaned, and the "refused while a live compendium entry picks a form under it" rule no longer applies to form groups. DESIGN.md §5 (the MB.162 paragraph and the deities paragraph's "like a form group"), `db/member-autofill.md`, `db/compendium-writes.md` and M5.6b's entry get corrected to match. MB.132's traditions still decide for themselves.
3. A group with no live rows under it deletes plainly. A group that has rows but no other live group to move them to is refused on `moveTo` ("Add another group first").

## Implementation

### Contrast: `src/lib/contrast.ts` (new)

- `relativeLuminance(hex)` and `contrastRatio(a, b)` (WCAG 2.1, the formula `tests/db/seed/categories.test.ts` already uses), `CHIP_GROUNDS = { dark: '#1f1c16', light: '#efe9da' }`, and `MIN_CHIP_CONTRAST = 4.5`.
- Test `tests/lib/contrast.test.ts`: known ratios, plus the grounds pinned to `_variables.scss`'s `$soot-raised` and `$parchment`, the way the seed test pins its grounds.

### Validation: `src/modules/vocabulary/validation/`

- `category-group.ts` — `CategoryGroupInput`: trimmed non-blank `name` and `description`; `colorDark` and `colorLight` matching `#rrggbb`, lower-cased, each with a `superRefine` against its own ground. The message names the column and the ratio, e.g. "The dark-theme colour reads 3.92:1 on the dark card; it needs at least 4.5:1", pathed to `colorDark` or `colorLight`. Because the schema is shared, the form refuses before the request and the service refuses again.
- `ingredient-form-group.ts` — `IngredientFormGroupInput`: name and description.
- Tests cover each column's refusal, a hex that would pass the _other_ theme's ground, a dark hex that clears the dark page (`#14120e`) but not the card, and **every seeded pair in `CATEGORY_GROUPS` parsing clean**.

### Repository (`src/db/repository/write.ts` and types)

- New writer `regroupCategories(_admin, fromGroupId, toGroupId)`, which moves every live category off a group in one UPDATE. Services may not build the `where` themselves (rule 4: no drizzle at runtime outside db). The admin proof follows the `carryFormRename` precedent.
- Forms re-slug one row at a time through the existing `write.updateById(ingredientForms, …)`, the way M5.6a's form update does. No new writer is needed.

### Services: `src/modules/vocabulary/services/`

- `category-groups.ts`: `getCategoryGroupBySlug`, `createCategoryGroup`, `updateCategoryGroup` (slug = `slugify(name)`; touches no category; refuses a collision on `category_groups_slug_unique` pathed to `name`), and `deleteCategoryGroup(session, id, moveTo?)`. The delete counts live categories through the existing `countCategories({ groupId })`. If there are any, `moveTo` is required, must not be `id`, and must name a live group; otherwise a `ValidationError` on `moveTo`. Then, inside `withAudit`, `regroupCategories` followed by `softDeleteByIds`. `listCategoryGroups` already exists and moves here from `categories.ts`.
- `ingredient-form-groups.ts`: the same four, plus the following.
  - **Rename re-slugs every live form under the group** (M5.6a's record). The forms are walked through `findIngredientFormValues({ groupId })`, each new `formSlug` is checked against `findOneBySlug` excluding itself, and a collision is refused on `name`, naming the form that holds it. Then `updateById` runs per form in the same transaction, as does a race caught on `ingredient_forms_slug_unique`.
  - **Delete moves the forms:** the same walk, `formSlug(name, target.name)`, a collision refused on `moveTo` naming the target's same-named form, then per-form `updateById({ groupId, slug })` and the group's soft delete, all in one transaction.
  - The re-slug walk and its collision check are shared by rename and delete in one private helper.
  - `listIngredientFormGroups` moves here from `ingredient-form-values.ts`.
- Both open with `import 'server-only'` and `assertSiteAdmin` before the input is read. `index.ts` exports them.

### GraphQL: `src/modules/vocabulary/graphql/`

- `category-groups.ts`: `CategoryGroupInput` (name, description, colorDark, colorLight), plus `createCategoryGroup`, `updateCategoryGroup` and `deleteCategoryGroup(id: ID!, moveTo: ID): ID!`, all `authScopes: { admin: true }`. Each clears `loaders.categoryGroupsById` and `categoriesByIngredient`.
- `ingredient-form-groups.ts`: the same three for form groups. Each clears `ingredientFormGroupsById` and `ingredientFormsById`.
- `CategoryGroupRef` and `IngredientFormGroupRef` stay where they are. No new list query: the pages read services (rule 1), and `ingredientFormGroups` already exists. No `revalidateTag` call, since nothing is cached under `compendium` yet; that is M8.6's job, matching the M5.6 and M5.6a mutations.
- Then `npm run codegen` and the SDL snapshot.

### Components (each with a directory, story and doc in `claude-docs/components/`)

- **`GroupForm`** — one form for both vocabularies, since MB.132's traditions will reuse it. It has name and description, and with `colors` set (category groups) two **`ChipColorField`**s. On an existing group it offers Delete Group. That button opens the move step when `memberCount > 0`: a `ComboboxSelect` of the _other_ groups and then the confirmation. When the group has no rows, it opens a plain confirmation. Copy, mutations and the `moveTo` refusal are per vocabulary, set through a `kind: 'category' | 'form'` prop. The owner's form-save rules apply: Save is disabled until dirty, a spinner shows while saving, Cancel is quiet, and the destructive button is `.btn--destructive`. Button labels are title case.
- **`ChipColorField`** — a native `<input type="color">` bound to a hex text input, and a sample chip previewed on its own ground (dark card or light page) with the live ratio shown beneath it. Layout and tokens only until the design review (MB.115).
- **`GroupList`** — a Name and Description table (plus two swatches for category groups) with Edit links and the `Pager`. It has no filter: there are eight and six rows.
- Each list gets an href helper in the shape of `formsHref`.
