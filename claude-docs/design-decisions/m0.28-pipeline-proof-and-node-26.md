# M0.28 — end-to-end pipeline proof; deploy.yml on Node 26

**Status:** in progress · **Date:** 2026-09-09

M0.28 exists to run the whole deploy pipeline once while the app is a trivial
page, so deploy problems surface before any feature work. The first run did
exactly that.

## What M0.28 found

M0.26's `deploy.yml` merged to `staging` (PR #40) and its first real run
([run 34388520913](https://github.com/Aurora-Arctic/Sorrel-and-Salt/actions/runs/34388520913))
**failed at `npm ci`**, before Vercel was ever contacted:

```
npm error `npm ci` can only install packages when your package.json and
package-lock.json … are in sync.
npm error Missing: typescript@5.9.3 from lock file
```

### Root cause

`deploy.yml` ran `actions/setup-node@v4` with `node-version: 22` — the only
place in the repo not on Node 26 (`Docker/Dockerfile.node` pins `26.6.0`;
local dev is 26.x; `@types/node` is `^26.1.2`). It was a carry-over default
from the port, not a considered choice.

- Node 22 bundles **npm 10.9.8**; Node 26 bundles **npm 11.19.0**, which is
  what generated the committed `package-lock.json`.
- `typescript@^7.0.2` (the new Go-based compiler) ships ~20 per-platform
  optional dependencies (`@typescript/typescript-darwin-arm64`, …) plus a
  `typescript@5.9.3` JS fallback. npm 11 records that tree in a shape npm 10
  reads as incomplete, so npm 10's `npm ci` sync check rejects the lockfile.
- Reproduced in Docker: `npm ci` fails on `node:22-slim`, passes clean on
  `node:26-slim` against the same committed `package.json` + lockfile.

### Fix

Both `Set up Node` steps in `deploy.yml` (the `deploy` job and the `teardown`
job) pinned to `node-version: 26.6.0`, matching `Docker/Dockerfile.node` and
local dev. No lockfile change — the lockfile is correct; the runner was wrong.

This supersedes the "Node 22, npm cache" detail in
[`m0.26-disable-previews-and-alias-staging.md`](m0.26-disable-previews-and-alias-staging.md)
("Bare runner" bullet).

baseline". Three numbers, one machine-local and two from CI's `job-summary`

| Staging preview deploy | `deploy.yml` on push to `staging` (`vercel pull`+`build`+`deploy --prebuilt`) | _to record from the first green run_                             | —                       |
| Production deploy      | `deploy.yml` on push to `main` (`--prod`)                                     | _to record from the first green run_                             | —                       |

The two CI rows are filled in once this branch reaches `staging` (the merge
triggers the preview deploy) and `main` (via `release/0.0.x`), from the
`Deploy (…)` job summary each run writes.
