**Guards.** Each page runs its own guard, since a layout does not re-run on a navigation inside it. A signed-in page calls `requireSession()`; a coven page `requireCovenMembership(slug)`, which gives a stranger the 404; `/curator` and the `/keepers` index and Support `requireCuratorSession()`; the other `/keepers` pages `requireAdminSession()`. The services behind each page are the authorization (§3). The public pages (`/`, `/compendium`, `/support`, the document pages) call none.

**The help pages sit on the public frame**: `/help` and its sub pages use the public frame with its signed-in island, are listed in `PUBLIC_ROUTES` and the sitemap as the compendium's routes are, and are linked from `Welcome`, the public frame's footer, `AppShell` and the 404 page. They ship after launch, so none of those links exists until they do.

**The admin pages are grouped into tabbed pages**: a list shares a page with the groups that organise it, a tab each — Categories (Categories, Groups), Forms (Forms, Groups), Deities (Deities, Traditions), Astrology (Celestial Bodies, Zodiac Signs) and People (Users, Invitations, Privilege Changes). Each tab keeps its own address above, so a link or a reload lands on it. A page's heading and tabs stay put while the open tab's content and its action beside the heading change: each page is a route group under `src/app/(shell)/curator/` with one shared layout, and the action is an `@action` slot. `src/components/AdminNav/sections.ts` lists every page and its tabs, which the nav, the `/curator` and `/keepers` indexes and each layout all read (`claude-docs/components/tabbed-page.md`).

Workspace ingredients and stock are **one page**, not two. A filter chip distinguishes local entries from compendium entries; a separate page would be a distinction without a difference.

**Button labels are title case** — "Sign In", "Send Confirmation", "Continue with Google" (a short preposition stays lower, as title case has it). A label that reads as a sentence is a hint the control is doing too much. **Headings are title case too** — a page heading, a dialog title and a table's column heading: "Sign In", "Add Category", "Category Groups", "Sign-In Methods", "Coven Creation" — so a button and the dialog it opens read alike. **So are field labels** — "Email Address", "Name or Email".

## Components

Component folders are `src/components/<Name>/` with `index.tsx` and `index.scss`, imported `from '../components/<Name>'`. The test lives at `tests/components/<Name>/index.test.tsx`, never beside the component.

**`AppShell`** is the application-wide navigation frame, not a route. It wraps every signed-in page and carries the primary nav, the `WorkspaceSwitcher`, and one global Add Ingredient button. The button's target follows the area: a coven page adds to that coven's ingredients, an admin page to the compendium, and elsewhere to the viewer's only coven or a choice. Editing is on the ingredient wherever it is shown, never inside a relational field, and never in the shell. An account menu offers Your Account and Sign Out, and, while coven invitations wait for the viewer's verified address, a dot on its button and a count that links to the account page's Invitations section; on shell pages the theme toggle sits in the bar at every width instead of the fixed corner, and the menu holds none. The section nav is one component for the coven and admin areas: icon tabs in a context row under the bar, and a bottom bar on a phone. It is a layout component rather than a route because the nav must persist across navigation between workspace-scoped and global pages; the coven layout nests inside it and adds only workspace-scoped chrome. The two public compendium pages are dynamic over the cached compendium reads, the layout reading the session when present: the public layout renders the signed-in or signed-out chrome on the server.

**`IngredientSearch`** is shared by compendium, ingredients, and spell builder (`claude-docs/components/ingredient-search.md`). Each consumer supplies the action slot — Compendium passes "Add ingredient," Ingredients passes Edit/Delete, Spell Builder passes "Add to jar." Filter state lives in the URL query string. The text match covers `name`, the folk names, `canonicalName` — searching the formal name is how someone who knows the binomial finds the right one of four rows labelled "Cat's Claw" — and each variant's form and description, still one row per ingredient however many of its forms match. Category chips group by the category's `groupId`, groups alphabetical by name, AND by default with an OR toggle, an entry matching a category filed on it or on any of its forms. The form filter takes a list and matches an entry holding a live variant of any form chosen; its options come from the curated vocabulary plus the variant forms in use outside it (§5), not a fixed set. The toxic setting keeps entries flagged toxic on the entry or any live form, or neither (`claude-docs/design-decisions/ingredients.md`, "Search facets take lists and a toxic setting"). The element filter, the five, matches an ingredient whose `elements` holds the one chosen, among others or alone.

**`IngredientCard`** renders the formal name and the entry's forms as a secondary line beneath the display label — "_Salvia rosmarinus_ · Herb, Oil" — read from its variants, since two entries can share a label and the forms are what a reader holds. Lists sort on `(lower(name), identity_key, id)`, so identically labelled entries keep a stable order told apart by their formal names.

**The ingredient detail page is the ingredient, then its forms.** The ingredient's own description, correspondences, folk names, deities, categories, substitutes and references come first, each section that cites sources ending with its note numbers; then one section per live variant, in form-name order, anchored `#form-<slug>` with the form's name through `slugify`, so a link can open on Rosemary's oil: `/compendium/ingredients/rosemary-salvia-rosmarinus#form-oil`. Each section shows only what that form adds — its description, its safety notes, its correspondences, categories and substitutes, and, at its end, the numbers of the notes for its own references — since a form inherits the ingredient's by the union rule (§5). Under the ingredient's safety notes and under each form's, with notes or without, one line says the notes are not complete and links the disclaimer at `/disclaimer`, on a compendium entry and on a coven's entry alike. The public slug carries no form, so every form of an entry shares one address.

## Componentized Sass

Every component folder carries its own `index.scss`, imported by its `index.tsx`. One global stylesheet, `src/app/globals.scss`, is imported once by the root layout, with nothing component-specific in it. It exists because two things must be emitted exactly once: `_typography.scss`'s global element rules, and the theme token assignments. Each component's `index.scss` is its own compilation unit, so a shared partial that emitted CSS would duplicate it into every compiled stylesheet — which is why `_variables.scss` and `_mixins.scss` stay declaration-only.

Shared partials live in `src/scss/` (`_variables`, `_mixins`, `_typography`, `_buttons`, `_print`) and are `@use`'d directly by whichever component needs them, never routed through a parent: `@use '../../scss/variables' as *;`. Never the deprecated `@import`.

**Not CSS Modules.** Scoping comes from BEM names (`block__element--modifier`), which stylelint's `selector-class-pattern` enforces, rather than from hashed class names. The reason is the class layer `_primitives.scss` emits once from `globals.scss` — `.btn`, `.field`, `.page-frame`, `.data-table`, `.chip` — which components use by name from JSX and style inside their own rules (`.user-list .data-table td`). Under CSS Modules each of those becomes a `:global()` wrapper or an import from a shared module, a tax paid in nearly every component for a collision guarantee the linter already provides. Nor is per-route CSS what Modules buy: Next chunks CSS from the import graph (`experimental.cssChunking`, on by default), so a component's `index.scss` reaches only the routes that render the component either way (`claude-docs/design-decisions/ui.md`, "Component styling is global Sass with BEM names, not CSS Modules").
