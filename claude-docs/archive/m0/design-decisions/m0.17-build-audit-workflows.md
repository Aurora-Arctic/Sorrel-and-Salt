# M0.17 — port build and audit workflows

**Status:** decided · **Date:** 2026-09-09

The task: copy resume-2026's two remaining un-ported reusable per-check
workflows (`build`, `audit`), pointing `build` at the Next.js output instead
of Gatsby's, while `pr-gate.yml` (M0.20) and `build-image.yml` (M0.24) are
still both later tasks — the same situation M0.16 documented for
`lint`/`format`/`typecheck`.

## Decided

- **`audit.yml` is copied unchanged except the same `checkout-to-app`
  repo-path fix M0.15/M0.16 made.** `diff` against the fetched resume-2026
  original (`mjoynes-wombat-web/resume-2026/...` →
  `Aurora-Arctic/Sorrel-and-Salt/...`) is empty. Its raw `actions/github-script`
  comment-rendering (severity table, per-package breakdown, marker-based
  upsert) is generic over the audited repo and doesn't reuse the ported
  `pr-comment` composite action — confirmed against the live resume-2026
  `lint.yml`, which _does_ use `job-summary`/`pr-comment` natively, so
  `audit.yml`'s different shape is upstream's own design, not something to
  "fix" during the port.
- **`build.yml` is copied with the same repo-path fix, one comment update
  ("Gatsby build" → "Next.js build"), and one addition: a `.next/cache`
  caching step**, per `npm run build` (`next build`) needing it and
  resume-2026 having nothing to carry over here — Gatsby's build has no
  equivalent CI-cache guidance and resume-2026's `build.yml` caches nothing.
  Follows Next's own `node_modules/next/dist/docs/01-app/02-guides/ci-build-caching.md`
  GitHub Actions recipe (`actions/cache`, keyed on `package-lock.json` +
  source file hashes, with a lockfile-only `restore-keys` fallback). The
  cache `path` is the absolute `/app/.next/cache` — `checkout-to-app`
  populates both `$GITHUB_WORKSPACE` (what `hashFiles()` reads) and `/app`
  (where `npm run build` actually writes, since the job's working directory
  is `/app`) — same reasoning `lint.yml`/`format.yml`/`typecheck.yml` already
  use for the absolute `log-file` paths they pass to `job-summary`/`pr-comment`.
  `actions/cache@v6` is the current major at time of writing; nothing else in
  `.github/` pins that action yet.
- **`package.json`'s `build` script now forces `NODE_ENV=production`**
  (`"build": "NODE_ENV=production next build"`). `Docker/Dockerfile.node`'s
  `testing` stage — the exact image `build.yml`'s `container: image:` job
  runs against — bakes in `ENV NODE_ENV=test` (M0.11, so vitest picks the
  right project). Turbopack's production build crashes prerendering
  `/_global-error` (`TypeError: Cannot read properties of null (reading
'useContext')`) under any `NODE_ENV` other than `production` or unset —
  confirmed by reproducing it locally with `NODE_ENV=test npm run build`
  before the fix, and confirming a clean run after. Without this, every real
  `build / build` CI run would fail, unconditionally, the first time this
  workflow actually executes — this isn't a local-shell quirk, it's the
  container image this exact task wires up to run the build.
- **A new `.github/workflows/build-audit-check.yml`** calls both, mirroring
  `lint-format-typecheck-check.yml`'s ad hoc smoke-test pattern exactly: same
  scoped-tag `testing` image build (`ghcr.io/.../testing:smoke-<run id>`),
  same reasoning for not porting `build-image.yml` early.
- **The `audit` job is gated `if: github.event_name == 'pull_request'`**,
  unlike every job in `lint-format-typecheck-check.yml`. `audit.yml` declares
  `pr-number` as a _required_ input and interpolates it unguarded into the
  PR-comment script (`const prNumber = ${{ inputs.pr-number }};`) — with no
  `if: inputs.pr-number` step guard the way `lint.yml`/`format.yml`/
  `typecheck.yml` have for their optional `pr-number`. On `workflow_dispatch`
  (no PR), `github.event.pull_request.number` is empty, which would render as
  `const prNumber = ;` — a syntax error, not merely a silent no-op. `build`
  has no such dependency and runs on both triggers unconditionally, same as
  `lint-format-typecheck-check.yml`'s three jobs.
- **The acceptance criterion "audit workflow fails on a seeded high-severity
  advisory" is read as the report surfacing the finding (a ⚠️ WARNING PR
  comment), not the job or PR gate turning red.** resume-2026's `audit.yml`
  is deliberately, doubly non-blocking — `continue-on-error: true` _and_
  `run: npm audit --json > audit-results.json || true` on the one step that
  can fail — and its own `pr-gate.yml` documents this explicitly ("audit is
  deliberately not among them; it's PR-only and never gates a merge").
  `DESIGN.md` §12 lists `audit` among the workflows "ported verbatim," and
  per `CLAUDE.md` the design doc wins over `TASKS.md`'s wording where they'd
  otherwise conflict. Verified by extracting the comment-rendering script and
  running it against a seeded `audit-results.json` with one `high`-severity
  finding (see Verified below) — confirms the ⚠️ WARNING callout, severity
  table, and package/fix-available row render correctly; the real container
  run happens once the PR is open, same as every other check in this port.

## Verified

- `npx js-yaml <file>` parses `build.yml`, `audit.yml`, and
  `build-audit-check.yml` with no errors.
- `diff` against `audit.yml`/`build.yml` fetched from
  `repos/Aurora-Arctic/resume-2026` via `gh api` (repo-path substituted, plus
  the one comment line and the cache step for `build.yml`) shows only the
  intended changes.
- `grep -rn 'resume-2026\|mjoynes-wombat-web' .github/` finds nothing.
- `npm run build` (`next build`) succeeds and populates `.next/cache` — first
  confirmed run of this script in the repo's history, since no CI workflow
  has called it before this task. First run (before the `package.json` fix)
  failed under a shell with `NODE_ENV=development` pre-set, with the same
  `/_global-error` prerendering crash the `testing` image's baked-in
  `NODE_ENV=test` would trigger in real CI; `NODE_ENV=test npm run build`
  reproduced it directly, and passes now that `build` pins
  `NODE_ENV=production` itself.
- `npm run lint` / `format:check` / `typecheck` all exit 0, unaffected by
  this task's YAML-only changes.
- Audit's comment-rendering logic, extracted and run standalone against a
  seeded `{ metadata: { vulnerabilities: { high: 1, total: 1 } }, ... }`
  fixture, renders the expected ⚠️ WARNING callout with a correct severity
  table and package row (`seeded-vuln-pkg | high | Yes (seeded-vuln-pkg@2.0.0, major)`).
- **Not verifiable pre-push:** the two workflows' actual container runs.
  Opening the PR triggers `build-audit-check.yml` (paths this diff touches),
  confirming `build / build` goes green and `audit / audit` posts its
  real PR comment; a throwaway commit with a deliberately vulnerable
  dependency added would additionally confirm the live, non-fixture path.

## Rules this sets

- `.github/workflows/build-audit-check.yml` stays even after `pr-gate.yml`
  (M0.20) lands a real caller — a direct regression check for
  `build.yml`/`audit.yml`, not a stand-in for the gate (same rule M0.16 set
  for `lint-format-typecheck-check.yml`).
- A reusable check whose `workflow_call` inputs are used unguarded (no
  `if: inputs.foo` step gate) must not be called from a trigger where that
  input can be empty — gate the _calling job_, not just hope the input is
  always populated.
