# M0.16 — port lint, format and typecheck workflows

**Status:** decided · **Date:** 2026-09-09

The task: copy resume-2026's three reusable per-check workflows
(`lint`, `format`, `typecheck`) and confirm each runs its npm script inside
the testing container image — while `pr-gate.yml` (M0.20), the workflow that
will call them for real, and `build-image.yml` (M0.24), whose output is the
`image` input they require, are both explicitly later tasks.

## Decided

- **All three workflow files are copied unchanged except the same
  `checkout-to-app` repo-path fix M0.15 made.** `diff` against the fetched
  resume-2026 originals, with `mjoynes-wombat-web/resume-2026/...` replaced
  by `Aurora-Arctic/Sorrel-and-Salt/...`, is empty for all three. Nothing
  else about the container job, the `should-run` skip pattern, or the
  output-summarizing steps needed to change — they're generic over the repo
  they run in.
- **A new `.github/workflows/lint-format-typecheck-check.yml` is what
  actually calls the three `workflow_call` workflows**, since neither caller
  named in their own descriptions (`pr-gate.yml`, `merge-queue.yml`) exists
  yet. Same reasoning M0.15 recorded for `composite-actions-check.yml`:
  reaching ahead into M0.20 to port `pr-gate.yml` early would mean that task
  either redoes this workflow or inherits one it didn't write against its
  own acceptance criteria (path-filtering via `dorny/paths-filter`, the
  `gitflow` dependency, wiring `vitest`/`build`/`playwright`/`audit` too).
  A small standalone caller keeps M0.16's surface to exactly the three
  workflows it's scoped to, and — like `composite-actions-check.yml` — stays
  on afterward as a direct regression check for `lint.yml`/`format.yml`/
  `typecheck.yml` themselves, independent of whichever real gate currently
  consumes them.
- **The `image` input is satisfied by building `Docker/Dockerfile.node`'s
  `testing` target ad hoc, not by porting `build-image.yml` early.** The
  ported workflows require a real `container: image:` to run their
  `container:` job against; nothing in the repo yet publishes one for them.
  `build-image.yml` (M0.24) is the correct long-term source — it
  content-addresses the tag by hashing `Docker/Dockerfile.node` and
  `package-lock.json` so unrelated pushes reuse a prior build instead of
  rebuilding — but porting it now would be the exact same "task redoes a
  later task's work" problem as `pr-gate.yml` above, just one layer deeper.
  Instead `lint-format-typecheck-check.yml` builds and pushes the same
  `testing` target itself, tagged `ghcr.io/.../testing:smoke-<run id>` —
  scoped to the run, never reused, and never intended to be. This is real
  waste (a full rebuild every time this workflow triggers) that M0.24
  removes once it exists; it's accepted here because the alternative is
  porting M0.24's actual logic under M0.16's acceptance criteria instead of
  its own.
- **`format.yml` keeps no `should-run` input; `lint.yml`/`typecheck.yml`
  keep theirs untouched even though nothing calls it with `false` yet.**
  Both are inert until `pr-gate.yml`'s path-filter job exists to drive them
  — carried over unchanged now so M0.20 doesn't need to touch these files
  again, matching "copy the three reusable per-check workflows" literally.
- **The smoke caller's own triggers mirror `composite-actions-check.yml`'s
  pattern**: `pull_request` on the paths that could invalidate any of the
  three checks (the checks' own workflow files, this file, the composite
  actions, `Docker/Dockerfile.node`, and each tool's config/manifest —
  `.oxlintrc.json`, `.prettierrc`/`.prettierignore`, `tsconfig.json`,
  `package.json`, `package-lock.json`) plus `workflow_dispatch`. Unlike
  `pr-gate.yml`'s real `changes` job, there's no per-check path filtering
  here — all three always run together, since this workflow's only job is
  proving the three resolve and behave, not gating a real PR efficiently.
- **`pr-number: ${{ github.event.pull_request.number }}` is passed
  unconditionally**, same as every job in resume-2026's own `pr-gate.yml`.
  On a `workflow_dispatch` run that expression is empty, which each called
  workflow's own `if: ... && inputs.pr-number` steps already treat as falsy
  — no extra conditional needed in the caller.

## Verified

- `npx js-yaml <file>` parses all four new/changed workflow files with no
  errors.
- `diff` between each of `lint.yml`/`format.yml`/`typecheck.yml` and the
  file fetched from `repos/Aurora-Arctic/resume-2026` via `gh api` (with the
  `checkout-to-app` repo path substituted) is empty.
- `grep -rn 'resume-2026\|mjoynes-wombat-web' .github/` finds nothing.
- **Incidental fix required for "runs green":** `npm run format:check`
  failed on three pre-existing `claude-docs/*.md` files (drifted from
  Prettier's style, left over from M0.15's own doc-writing) before any
  change in this task. Since the new `format.yml`/`lint-format-typecheck-check.yml`
  couldn't demonstrably run green with that drift in place, `npx prettier
--write` was run on exactly those three files (`ci.md`,
  `design-decisions/m0.15-composite-actions.md`, `transcripts/ci.md`) —
  content unchanged, only Prettier's own formatting. `npm run lint`,
  `format:check`, and `typecheck` all now exit 0 on the host; the container
  run is the real proof (next bullet).
- **Not verifiable pre-push:** the three workflows' actual container runs,
  and the deliberately-broken-check failure case. Committing/pushing is
  `/create-pr`'s job, not this task's — `lint-format-typecheck-check.yml`
  triggers on `pull_request` for paths this diff touches, so opening the PR
  runs all three for real. Confirm `lint / lint`, `format / format`, and
  `typecheck / typecheck` are green on that PR, then push one throwaway
  commit that breaks each check in turn (an oxlint violation, an
  unformatted file, a type error) to see its job go red and its PR comment
  flip to a failure callout, before reverting and merging.

## Rules this sets

- Any workflow needing the testing container image before `build-image.yml`
  (M0.24) exists builds its own ad hoc, run-scoped copy rather than porting
  `build-image.yml` early — the same deferral this task made.
- `.github/workflows/lint-format-typecheck-check.yml` stays even after
  `pr-gate.yml` (M0.20) lands a real caller — a direct regression check for
  `lint.yml`/`format.yml`/`typecheck.yml`, not a stand-in for the gate.
