# M0.31 — Theme and token decorator for the workshop

**Status:** decided · **Date:** 2026-09-08 · **Builds on:**
[m0.30-ladle-component-workshop.md](./m0.30-ladle-component-workshop.md),
[m0.6-typography-and-palette.md](./m0.6-typography-and-palette.md)

M0.30 left `.ladle/components.tsx` as a passthrough `Provider` and named three things for
this task: an app-surface frame around each story, a containing block on that frame so a
`position: fixed` component sits in the story instead of Ladle's chrome, and a light/dark
toolbar control that drives `html[data-theme]` through the M0.29 helper and remounts the
story. This task lands all three.

---

## The toolbar control is Ladle's own, read by the decorator

Ladle already ships a theme control in the toolbar (`addons.theme`, enabled since M0.30).
It writes `html[data-theme]` itself and its state — `light` / `dark` / `auto` — arrives in
the user `Provider` as `globalState.theme`. Rather than build a second control, the
decorator **reads that state** and re-applies it through the one function the app uses.

- `light` / `dark` → `applyTheme(theme)` from `src/components/ThemeToggle` (M0.29). That is
  the whole write: the `data-theme` attribute **and** the persisted `localStorage['theme']`
  choice, in a `try`/`catch`. No second copy of it lives in the workshop.
- `auto` → the control's **unset position**. The decorator writes nothing and clears both
  the attribute and the storage key, so `.ladle/theme.scss` resolves the theme through
  `prefers-color-scheme` exactly as `globals.scss` does in the app for a viewer who has
  never touched the toggle. This is M0.29's rule — an absent attribute is a valid state —
  holding in the workshop.

`.ladle/config.mjs` `addons.theme.defaultState` moves from `'dark'` to `'auto'` so the
workshop **opens** in that unset state. The app is still dark-first; that lives in
`globals.scss` (`:root { @include theme-dark }`), not in the workshop config. One click on
the toolbar control pins light or dark from there. Ladle's own init side effect
(`init-side-effects.ts`) stamps a `prefers-color-scheme`-resolved `light`/`dark` on load
even for `auto`; the decorator's `auto` branch clears it. Because that resolution matches
what the CSS media query would pick, clearing it changes nothing visible — it only takes
`data-theme` back out of the DOM and lets the media query stay live.

## The story remounts on every theme change

`ThemeToggle` reads `data-theme` **once, on mount** — its sun/moon facet and `aria-pressed`
are set in mount effects, not from a subscription. So flipping the attribute alone leaves
its JS state frozen even though the token `var(--…)` values follow. The decorator wraps the
story in `<div className="ladle-story-frame" key={theme}>`; changing `key` unmounts and
remounts the subtree, so `ThemeToggle` re-reads on the fresh mount and its facet tracks the
control.

Ordering: a parent's effect runs _after_ its children's, so the decorator's `useLayoutEffect`
can't set `data-theme` before the remounted `ThemeToggle`'s mount effect reads it. It
doesn't need to — Ladle's toolbar handler sets `data-theme` **synchronously, before it
dispatches**, so by the time the decorator re-renders with the new `globalState.theme` the
attribute is already current for the light/dark case. `useLayoutEffect` (not `useEffect`)
keeps the persisted write and the `auto` clear ahead of paint.

## The frame: surface + containing block, and it clips like a viewport

`.ladle/story-frame.scss` is a new partial (kept out of `.ladle/theme.scss`, whose three
theme blocks are a verbatim copy of `globals.scss` and shouldn't grow layout rules):

- **Surface.** `background-color: $surface-page; color: $text-primary` — the same M0.6
  tokens `globals.scss` puts on `<body>` — so a component renders on the ground it ships
  on with no per-story setup.
- **Containing block.** `transform: translateZ(0)`. Any non-`none` transform makes the
  frame the containing block for a descendant `position: fixed`, so `ThemeToggle` pins to
  the frame's corner rather than floating over Ladle's toolbar and sidebar.
- **Clip.** `overflow: hidden`. The frame stands in for the app viewport, so it trims like
  one: `ThemeToggle` parks a rotated facet past the top and right edges, and against the
  new `transform` containing block that overflow was adding a **page scrollbar in Ladle**
  (the app doesn't show it — there the facet overflows the initial containing block, which
  doesn't extend the scroll region the same way). Clipping to the frame contains it; a
  taller-than-frame story scrolls within the frame, never sideways.
- **Gutter.** `.ladle-main { padding: 0 }` drops Ladle's 3em gutter so the surface reaches
  the chrome; the frame supplies its own `padding: 3rem`. That padding is the one plain
  length in the file — M0.6–M0.8 are colour and type, there is no spacing scale to name,
  and a workshop gutter is chrome, not component design.

Colour and motion otherwise come only from M0.6/M0.8: `$surface-page`, `$text-primary`,
`theme-transition()`, `reduced-motion`.

## `_typography.scss` stays out of the workshop

M0.30 left this open: whether the document-wide element rules belong in the workshop,
scoped to the story frame. They don't, for now. `_typography.scss` emits **bare element
selectors** — `li::before { content: '◆' }`, the `ul`/`a` resets, `section`/`header`
margins — and a `@use` can't scope another stylesheet's output under a selector. Pulling it
in either bleeds onto Ladle's own `<ul>`/`<li>`/`<a>` chrome (the reason M0.30 dropped it)
or needs `_typography.scss` restructured to nest under `.ladle-story-frame`, which is out
of proportion to this task and would fork the app's one global prose stylesheet.
Components style from tokens and mixins, not prose ([`CLAUDE.md`](../../CLAUDE.md)), so no
story needs it yet. M0.32 revisits if one that renders prose arrives.

## Verified

- `npm run workshop:build` exits 0; the built CSS carries `.ladle-story-frame` with
  `var(--surface-page)` / `var(--text-primary)`, the `transform`, `overflow: hidden` and
  the `.ladle-main { padding: 0 }` reset.
- `npm run lint`, `npm run format:check`, `npm run typecheck` pass. (`tsconfig.json` does
  not include `.ladle/`, so `tsc` does not check `components.tsx`; the `@ladle/react` value
  import it now carries is bundled by Vite/esbuild, which the build exercises.)
- In `npm run workshop`: the `ThemeToggle` `Default` story renders on the page surface;
  the toolbar theme control switches the frame light↔dark and the toggle's own facet and
  `aria-pressed` follow (the remount); on first load with no click, `<html>` carries no
  `data-theme` and the OS `prefers-color-scheme` decides; the corner-pinned toggle no
  longer adds a horizontal scrollbar.

## What this commits later tasks to

- **M0.32** owns story content. If it adds a story that renders prose (headings, lists,
  links), it reopens whether `_typography.scss` is folded into the frame — and if so, does
  the restructure to make `_typography.scss` nestable rather than copying rules.
- **M0.33**'s CI wiring runs `workshop:build`, which now compiles `components.tsx`'s
  `@ladle/react` import — no `tsc` coverage of it, by design; the build is the check.
- A component that pins itself to a different edge, or needs the frame **not** to clip
  (an intentionally overflowing menu, a wide table), revisits `overflow: hidden` on the
  frame — most likely by moving the clip to an opt-in per-story parameter.
