# M0.24 — port build-image.yml with new GHCR tag

**Status:** decided · **Date:** 2026-09-09

The task: copy resume-2026's `build-image.yml` — the reusable `workflow_call`
job that builds the shared `testing` container image once and publishes its
content-addressed ref as an output — changing the GHCR tag to land under this
repo's namespace, and wire the two callers (`pr-gate.yml`, `merge-queue.yml`)
to `uses:` it instead of the ad hoc stand-ins M0.20/M0.21 shipped.

## Decided

- **The tag needed no literal change.** resume-2026's workflow already
  computes `ghcr.io/${repo_lower}/testing:${hash}` from `github.repository`
  lowercased — so ported as-is it publishes to
  `ghcr.io/aurora-arctic/sorrel-and-salt/testing:<hash>` with nothing
  hardcoded to edit. This is the same approach `build-db-image.yml` (M0.18)
  already uses for the `/db` image. "No resume-2026 tag references remain" is
  satisfied because there never were any literal ones — the namespace is
  entirely `github.repository`-derived. The workflow is otherwise a
  byte-for-byte port (same `hashFiles('Docker/Dockerfile.node',
'package-lock.json')`, same `imagetools inspect` skip-if-exists check, same
  `type=gha` layer cache, same action versions).

- **`pr-gate.yml`'s `build-image` job becomes `uses:
./.github/workflows/build-image.yml`, keeping its job-level
  `concurrency:` block.** M0.20 stood this job in as an inline
  `runs-on: ubuntu-latest` build tagged `testing:pr-gate-<run id>` (scoped,
  never reused). It's now the real content-addressed call. The
  `pr-gate-build-image-<pr number>` / `cancel-in-progress: false` concurrency
  group stays on the caller job — matching resume-2026's own `pr-gate.yml`,
  which keeps that group precisely because `build-image` pushes to a shared
  layer cache a mid-push cancel can corrupt, while the sibling check jobs get
  their own cancellable groups.

- **`merge-queue.yml`'s `build-image` job becomes the same `uses:`, with no
  concurrency group** — again matching resume-2026's `merge-queue.yml`. M0.21
  gave its inline stand-in a `merge-queue-build-image-<run id>` group so a
  queue entry's throwaway tag wouldn't collide with a concurrent PR gate's.
  With both callers now on the one content-addressed tag that collision is
  the intended behaviour (identical inputs → identical tag → shared build),
  and the reusable workflow's own skip-if-exists check keeps a superseded
  queue run cheap without a group.

- **The two smoke workflows (`lint-format-typecheck-check.yml`,
  `build-audit-check.yml`) keep their own ad hoc `smoke-<run id>` image
  builds.** They are deliberately independent regression checks for the
  reusable per-check workflows (M0.16's "Rules this sets"), not callers that
  were waiting on `build-image.yml`. Rewiring them is out of this task's
  scope.

- **`makefile`'s `act-*` targets are untouched.** Local `act` runs build the
  `testing` target directly (`act-image`) and never call `build-image.yml`
  or reach GHCR — the makefile header already says audit and the published
  build-image are left out of `act`, and that stays true.

## Verified

- `npx js-yaml` parses `build-image.yml`, `pr-gate.yml`, `merge-queue.yml`
  with no errors.
- `grep -rn 'resume-2026\|mjoynes-wombat-web'` over the three touched
  workflows finds only the pre-existing prose mention in `pr-gate.yml`'s
  header comment — no tag or path references.
- `npm run lint` / `format:check` / `typecheck` / `check:stories` all exit 0
  (YAML/docs-only change, unaffected).
- **Not verifiable pre-merge:** the first real `pr-gate.yml` run calling the
  reusable `build-image.yml` — opening this PR triggers it (the diff touches
  the workflow files themselves), confirming the `build-image` job builds and
  pushes `ghcr.io/aurora-arctic/sorrel-and-salt/testing:<hash>`, every
  downstream check pulls that exact tag via
  `needs.build-image.outputs.image`, and a second run with the same
  Dockerfile.node/package-lock.json hash skips the build via the
  `imagetools inspect` check. `merge-queue.yml`'s path is unverifiable until
  the merge queue is enabled (M7.A.1).

## Rules this sets

- Any workflow that needs the shared testing image now `uses:
./.github/workflows/build-image.yml` and reads
  `needs.build-image.outputs.image` — the ad hoc per-run image build is only
  for the two M0.16/M0.17 smoke workflows that are independent by design.
- A reusable-workflow caller job may still carry its own `concurrency:` block
  (as `pr-gate.yml`'s `build-image` does) — the group guards the caller
  against siblings, the called workflow runs unchanged underneath it.
