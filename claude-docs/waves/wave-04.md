# Wave 04 — Seed and harness

The payoff wave. Every one of these tasks writes rows into the tables Wave 3 created, which is why none of them could run before it, and together they retire all three workarounds the original order forced into shipped code ([`TASKS.md`](../TASKS.md), "Execution order").

**M4.3 is pulled ahead of M1.22**, which consumes its 63 categories, and **M4.3a for the same reason**: M1.22's ingredients carry `form` values from the vocabulary M4.3a seeds. M1.21 and M1.22 in turn block M1.27, which is what makes M1.9 a clone rather than a setup routine. **MB.40 sits after M1.22 and before M1.23**: it is DDL on `spell_ingredients`, empty and unqueried until Wave 13, so it lands as early as the schedule allows after it was minted, and ahead of M1.23, the first writer of that table, whose demo scenario seeds one custom row against the reshaped key. It is the repo's first contract migration, taken against zero rows. **MB.41 sits after M1.23 and before M1.28**: it moves the whole suite into `tests/`, so it wants every Wave 4 test file that is going to exist already written, and it must precede M1.28, which creates `tests/acceptance/` and would otherwise create it beside a `src/` suite it does not match.

**MB.27 and MB.42 close the wave.** Both are CI-only and depend on nothing here. Where MB.42 sits barely matters: its fix is a Dockerfile change, so that the CI images no longer carry a source layer, and `pr-gate.yml` builds the testing image content-addressed from the PR's own Dockerfile, so it is live on its own PR and on every run after. It was missing from this row until MB.43's pass; the MB index had carried it as Wave 4 all along.

**Retired from this row.** MB.26 (MB.29): with RLS deferred to the public launch, there is no read-side wrapper to land ahead of a caller that no longer exists. MB.44 (2026-09-19, by MB.42's rework): with the fix live on its own PR nothing waits on a release, and the coverage excludes it was minted to remove went in MB.42 itself. A release is still worth cutting on its own terms (`/create-release`), but nothing here is gated on it. MW.4 is retired (MB.31).
