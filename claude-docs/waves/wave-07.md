# Wave 07 — GraphQL

The one milestone that runs whole. M3 sits after the schema and the auth surface exist and ahead of all feature work, so that every request, admin included, uses the one endpoint, context and auth path CLAUDE.md rule 1 allows from the first resolver on. M3.8's "representative service" and M3.10's `me` both have real targets now. Within it, M3.2's builder and context block every resolver from M4 on, and M3.5's codegen lands before any client-side query work. M3.6's pagination helper, M3.8's access boundary and M3.9's enforcement of it land before feature work. M3.6 and M3.9 are code sweeps, a mechanism plus a guard that every later list query and service adopts in its own PR ([`TASKS.md`](../TASKS.md), "The sweep-task rule"). Landing either late means retrofitting bounds onto queries already written, or a boundary that erodes one convenient import at a time. The DataLoaders are deliberately not here: each sits with the schema it loads, as M4.8's `categoriesByIngredient`, M6.11's `membersByWorkspace`, MB.9's `ingredientsById` and MB.10's `usersById`.

**MB.73 lands straight after M3.2**, minted on request once M3.1's route existed. It touches only the route's IDE branch, so nothing later waits on it, and the sooner the served IDE exists the sooner every M3 task is checked by hand through it. **MB.43 follows M3.10** because it needs M3.1's route to hold the error mapping, and it must precede Wave 8: M5.9 is the first task to render a server-returned field error and M8.8 the first to raise one, so landing it later is a retrofit of both.

**MB.54 and MB.71 follow MB.43, moved from Wave 6** when starting MB.54 found its mutation had no route to reach. `setEmail(email): User!` returns M3.10's `User`, its refusal of an address already held is a field error MB.43 maps, and rule 1 leaves it no other transport. **MB.71 lands after MB.54 and MB.67**: it adds the link flow to the `/account` surface MB.54 opens, and its one generic `account_not_linked` sentence replaces the squat-specific one MB.67 would otherwise add ([`design-decisions/mb.71-plan.md`](../design-decisions/mb.71-plan.md)). **MB.74 through MB.77 follow MB.71.** MB.74 scoped Better Auth's plugin roster and sits here because this is when it was done; MB.75 is the rate limiter's table and precedes MB.76, which turns it on; MB.77 follows MB.71, since its last-used mark answers the sentence MB.71 writes ([`design-decisions/mb.74-better-auth-plugins.md`](../design-decisions/mb.74-better-auth-plugins.md)). MB.88, minted on request during MB.71, closes Wave 8 instead: nothing in this wave needs it, and it was still open when the wave closed, so MB.103's reorder moved it there from this row.

**MB.79 and MB.80 are doc-only**, depend on nothing, and sit here because this is when they were done. MB.79 records subscription billing as a v2 feature and the Stripe plugin's fit. MB.80 re-scopes the compendium as public and search-indexable, amends M5.2, M5.5, M8.5, M8.6, M8.18 and M8.19 in place, and minted MB.81–MB.82 into Wave 8 and MB.83–MB.85 into Wave 12 ([`design-decisions/mb.80-public-compendium.md`](../design-decisions/mb.80-public-compendium.md)).

**MB.86 follows M3.9 and stacks on its branch.** M3.9 puts `server-only` on every service and adds two guards that name `src/services`, which MB.86 adopts and re-points at `src/modules/*/services` when it regroups `src/` into five domain modules. It sits before Wave 8 because moving six services and thirteen schema files is an afternoon, and moving them after Wave 8 has added the real services is a wave ([`design-decisions/mb.86-modular-monolith.md`](../design-decisions/mb.86-modular-monolith.md)). **MB.87 follows M3.10 and stacks on its branch**, for MB.86's reason: M3.10 adds three finders to `repository.ts`, and the file is split into a folder before Wave 8 adds a finder per service ([`design-decisions/mb.87-plan.md`](../design-decisions/mb.87-plan.md)). **MB.89 is housekeeping**, independent of the rest of the wave: it moves the board from Asana to GitHub Issues and an org Project, and is the last task tracked on Asana, placed here because that is when it ran ([`design-decisions/mb.89-plan.md`](../design-decisions/mb.89-plan.md)). MW.7 is retired (MB.31).
