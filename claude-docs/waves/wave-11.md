# Wave 11 — Ingredient services

M9's data layer moves ahead of M8's UI, once M4's ingredients and M6's workspaces exist. This is the move that fixes M8.13, M8.14 and M8.18, all of which need stock data that M9 owns. **M8.3a follows M8.3** because it depends on the identity rule M8.3 implements: promoting a folk name to the display name is safe only because identity lives on `canonical_key` rather than on the label. **MB.9's `ingredientsById` loader lands here** because M8.5 and M9.4 both assume batched ingredient resolution and nothing built it. **M8.4 is retired** (M8.5): under rule 8 the browser never holds the whole list, so the compendium query filters in SQL, and the search UI in M8.9 through M8.12 refetches it rather than filtering through a client-side `filterIngredients()`. MW.11 is retired (MB.31).
