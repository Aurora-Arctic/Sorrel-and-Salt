# Design sync notes

## Setup gotchas

- [GENERAL] A multi-entry Vite library has no single entry or `.d.ts`. `.design-sync/index.ts` is the entry: an explicit export list (each component's default export by name, its named exports, `export type *`, then `_context` and `__providers`). It is built as the `index` entry in `.design-sync/vite.config.ts`, so it shares chunks with the components, and `tsc -p .design-sync/tsconfig.dts.json` emits `dist/types/.design-sync/index.d.ts` from the same file; `buildCmd` then copies `.design-sync/dist-package.json` to `dist/package.json` (`types`). Replaces the hand-written make-barrel.mjs. Symptom of a missing entry: "exported PascalCase symbols: 0". A name two components both export is a TypeScript error here; `export *` used to drop it silently (this left `StockIcon`, IconTip's glyph vs StockBadge's, undefined and broke IconTip: "Element type is invalid ... undefined"). `STORAGE_KEY` (CardDensitySwitch, ThemeToggle) is exported by neither list for that reason; nothing reads it from the bundle.
- [GENERAL] - Bundled Next.js internals read `process.env` at load -> "process is not defined", empty window.SorrelAndSalt. Fix: `.design-sync/process-shim.ts` sets a stand-in `process`; its own `_process-shim` entry in `vite.config.ts`, imported first by `.design-sync/dist-index.mjs` (copied to `dist/index.mjs`; the list itself builds as `dist/core.mjs`). A shim inside index.ts runs after the chunks above it, even with Rolldown's `strictExecutionOrder`, and a Vite `define` does not work because the driver's bundler inlines `next/*` from node_modules afterwards. Check by loading `ds-bundle/_ds_bundle.js` in happy-dom after `_vendor/react*.js`.
- [GENERAL] - `next/navigation` hooks throw "expected app router to be mounted". Fix: `resolve.alias` in `.design-sync/vite.config.ts` points `next/navigation` at `.design-sync/next-navigation.ts` (inert hooks that read Next's own contexts); the config's `external` lets that one id through, because Rollup checks `external` before the alias. The source-storybook fork stubs it in the decorator bundle.
- [GENERAL] - Contexts duplicated between the shipped bundle and source-compiled preview/decorator code (symptoms: "No QueryClient set", "useFormContext null", missing providers). Fix: `.design-sync/vite.config.ts` adds the `index` entry, which exports `__providers` (src/app/providers) and `_context` (.design-sync/context-modules.ts: lib/navigation, Modal route-modal-provider, ClickFeedback status-region, CovenSwitchTargets context, react-hook-form, react-query, next/navigation). index.ts flattens `_context` onto the global; `storyImports.shim` in config points stories at it; the fork shims `app/providers` and `status-region` in the decorator bundle. A new context-bearing module imported by `.storybook/` or stories must be added to both lists.
- `.storybook/preview.tsx` imports `.scss`: the source-storybook fork passes `STORY_LOADERS` to the decorator bundle. [GENERAL]
- titleMap keys may be whole titles because "Admin / Nav" and "Coven / Nav" share a last segment (fork). [GENERAL]
- [GENERAL] - Local chromium cannot launch (musl, arm64): run validate/compare with `NODE_OPTIONS="--import /app/.design-sync/remote-chromium.mjs"`, which swaps `chromium.launch` for `connect` to the `playwright-server` service (`PLAYWRIGHT_WS_ENDPOINT`).
- `cssEntry: sorrel-and-salt.css` so CSS comes from the library build, not Storybook.
- Unmapped/excluded stories: 3 email stories, Foundations, Feedback Main Body / Navigation Bar / Pending Link (hook-only or not components).

## Re-sync risks

- Adding a context-bearing module that `.storybook/` or a story imports (see above).
- New `src/components/*/index.tsx`: add a line to `.design-sync/index.ts` (default export by name plus named exports, and `export type *`); a name clash is a TypeScript error, rename or omit one side. titleMap may need an entry.
- Validator warnings left: RENDER_BLANK ImpersonationBanner, FONT_REMOTE (Lexend, Cormorant Unicase).
- Combobox has 17 stories but compare captures 6 (STORY_CAP, `--max-stories` is a CLI flag, not config); the other 11 are ungraded, so a fully matching Combobox is only partially verified. Raise with `--max-stories 17` for a deliberate pass (done for the first sync, 2026-10-23).
- Field, SkeletonFade, ClickFeedback excluded by the owner (2026-10-23): their dist exports only hooks or a field family, so there is nothing for a card to render.
- compare.mjs caps a capture at 2000x2000 (`compare.mjs:433`), so a `viewport` over 2000 high does nothing. ChipColorField States is 3023px tall in Storybook: its last ~1000px is never captured, and it grades close, not match. IngredientCard States (3745px in Storybook) shows 10 of its 18 cards for the same reason. Splitting a tall States story is the only fix that keeps the harness unedited.

Fix: `.design-sync/context-modules.ts` imports `.storybook/{theme,story-frame,typography,layout,primitives}.scss`, so they land in the library CSS (`cssEntry`).
- 40 GRID_OVERFLOW components: `wide` -> cardMode "column"; `escape` -> cardMode "single" plus primaryStory (Modal and ThemeToggle use `States`). Set in `config.json` `overrides`.
- [GENERAL] Tall or wide stories cut off in the card: the ds capture is the viewport only (900x700 default) while Storybook captures the whole `#storybook-root`, and the card chrome insets the frame about 24px. Fix: `viewport` override (Notice 1000x850, IngredientCard 1000x2000).
- Accepted deltas (not bugs): Modal's backdrop shows as a grey border around the frame. The frame is no longer narrower than Storybook's for the components named in the "Frame size" note below (MB.273); a component not named there still renders 24px inset on every side.
- No solo story loads remote images (ASSETS_BLOCKED count 0; IngredientCard uses SVG icons only), so the remote-image canary was not exercised. The http(s) URLs in AdminInvitations, IngredientEntry and IngredientForm stories were not checked.
- [GENERAL] No current tab or switcher value ("Select Coven") in nav stories: the old stub always returned '/', but stories set the path through `.storybook/navigation.tsx` (WorkshopPathname fills Next's PathnameContext). Fix: `.design-sync/next-navigation.ts` is a stub whose usePathname/useParams/useSearchParams/useRouter read Next's own contexts (default path '/admin/users', as preview.tsx sets); `_context` exports those contexts; `storyImports.shim` points the stories' imports of them at the bundle, and the source-storybook fork does the same for the decorator bundle (and its `next/navigation` stub is now the bundle's). One context instance everywhere.
- [GENERAL] Shell-frame stories showed white page ground with faded light text: story-frame.scss makes the frame transparent around `.app-shell`/`.public-frame` and leaves the colour to the body, but the card's own `<style>body{background:#fff}` won. Fix: `.design-sync/preview-host.scss` (imported in context-modules.ts) sets `html > body` to the page token, which outranks the bare `body` rule and follows the decorator's theme (dark default).
- [GENERAL] Capture is viewport-only and the converter has no size-to-content knob (compare.mjs reads only the card's `viewport="WxH"`, default 900x700). Whole-page or tall stories need `overrides.<Name>.viewport`: IngredientCardList 1000x1200, CompendiumCards 1000x1200, LeaveWorkspaceButton 1000x1300, IconTip 900x1990, MenuButton 900x760, Combobox 900x900, ChipColorField 900x3060, PrivilegeLedger 1000x1100, ReceivedInvitations 900x860 (ChipColorField ignored: capture clamps at 2000 high, see Re-sync risks).
- Wave 1 regrade after the rebuild: all 28 match except ChipColorField States and IngredientCard States (close, 2000px clamp). Non-general: ChipColorField/IconTip/MenuButton/Combobox/IngredientCardList/CompendiumCards/LeaveWorkspaceButton cut-offs were the viewport above; CompendiumList/CovenCards column wrapping is the accepted frame-inset delta; CreateWorkspaceForm shell frame is shorter than Storybook's (graded close); AdminInvitations' only http URL is a `new URL()` base, so no remote images; GroupForm/GroupedValueForm render fully (RENDER_THIN no longer flagged after the fixes).

## Phase 3 fixes (compare wait, preview fake fetch, TabSwitchContext, dist build)

- [GENERAL] **compare settleMs (patch to a staged script).** `.ds-sync/storybook/compare.mjs` cannot be forked (no `libOverrides` seam). It was patched to read `.design-sync/config.json` and wait `overrides.<Name>.settleMs` ms at the end of `settleRender`, on both the Storybook and the preview side; every component without the key waits 0. Reason: FacetPanel's stories open a menu from `window.setTimeout(..., 500)`, and networkidle fires before that timer, so the preview was captured with the menu closed. Only FacetPanel sets it (1000). The key is hashed into FacetPanel's grade key. **After every re-stage of `.ds-sync/`, re-apply it from /app:** `git apply -p0 --unsafe-paths .design-sync/compare-settle.patch` (no `patch` binary here). Check first with `git apply --check -R -p0 --unsafe-paths .design-sync/compare-settle.patch`: exit 0 means it is already applied. Without it, FacetPanel's menus compare closed against open.
- [GENERAL] **Preview fake fetch (msw).** The workshop answers a story's requests with an msw service worker. A preview page has none, and the bundled stub makes msw inert, so stories using `.storybook/mock-api.ts` (`useMockHandlers`, `beforeEach` with `msw.use`) got no answers. Fix, in previews only: (a) `.design-sync/mock-fetch/msw-browser.ts` replaces `msw/browser`; its `start()` sets `window.__dsFetch`, which answers with msw's own `getResponse(handlers, request)` and passes other requests to `window.__dsRealFetch` (the page wrapper from the fetch-hook entry below forwards `window.fetch` to `__dsFetch`); (b) `.design-sync/overrides/story-imports.mjs` wraps the bundled `storyImportPlugins` so `msw/browser` goes to (a) and `msw` and `@mswjs/*` resolve to the real packages; (c) `.design-sync/overrides/preview-gen-storybook.mjs` wraps `generatePreviewSource` so a story module that mentions `mock-api` gets `composeMocked`, which runs `startMockWorker` and the meta and story `beforeEach` before render (`compose()` never does). (b) and (c) are declared in `cfg.libOverrides`. The decorator bundle and `_ds_bundle.js` still get the inert stub: `grep -c msw ds-bundle/_ds_bundle.js` must print 0. Affected previews are about 1 MB each: AdminInvitations, GroupedValueForm, IngredientSearch, SignInMethods, IngredientForm, InvitationAcceptance, InviteDialog, ImpersonationBanner, StockDialog, SignInPanel. Limits: (1) the worker is page-global: a card page mounting several mocked stories at once is last-wins, so only the single-story `?story=` view (what compare captures) is exact; (2) a story's `play` function is not run, so a state a story reaches by clicking in `play` is not reached (ImpersonationBanner Stopping was graded mismatch earlier; the cause was the getResponse argument bug below, not `play`, and it now matches).
- [GENERAL] **Fetch hook (`emit-fetch.patch`).** Better Auth's client in `_ds_bundle.js` keeps the `window.fetch` it finds at bundle load, so replacing `window.fetch` later never reached it. Fix: `.ds-sync/lib/emit.mjs` emits, before BOTH `_ds_bundle.js` script tags (the single-story/grid template and the second template), an inline script: `var nf=window.fetch;window.__dsRealFetch=nf;window.fetch=function(){return (window.__dsFetch||nf).apply(this,arguments)}`. The shim sets and clears `window.__dsFetch`. `__dsRealFetch` is the shim's pass-through; without it the pass-through would call the wrapper again and loop. `.ds-sync/` is gitignored and a re-stage overwrites it, so the edit is kept as `.design-sync/emit-fetch.patch`. Re-apply after a re-stage, from /app: `git apply -p0 --unsafe-paths .design-sync/emit-fetch.patch` (the container has no `patch`). Check whether it is applied: `git apply --check -R -p0 --unsafe-paths .design-sync/emit-fetch.patch`; exit 0 means applied. Re-apply `compare-settle.patch` the same way.
- [GENERAL] **Shell offset.** The preview frame pads a story by 24px; an app-shell story is meant to touch the viewport edges. `.design-sync/preview-host.scss` has `.ds-single:has(.app-shell){margin:-24px}`, which cancels the padding when the story contains `.app-shell`. ImpersonationBanner Over The Shell matches because of it. It does not cover the signed-out frame (CompendiumCards States is still inset). Stories with no `.app-shell` are handled per component by the "Frame size" note below.
- [GENERAL] **msw `getResponse` argument order.** msw 2.15 is `getResponse(handlers, request, ctx?)`. The shim first called `getResponse(request, handlers)`, which threw "handlers is not iterable" on every request that reached it; this was behind the failure callout in ImpersonationBanner Stopping and the five IngredientForm stories with unanswered requests. Fixed to `getResponse(current, request.clone())`. Grades of every msw-using component taken before the fix were redone: AdminInvitations, GroupedValueForm, IngredientSearch, InviteDialog, StockDialog, SignInMethods, SignInPanel, IngredientForm, InvitationAcceptance, ImpersonationBanner.
- [GENERAL] **TabSwitchContext shim.** TabbedPage's story imports `TabSwitchContext` from `src/components/TabbedPage/tab-switch`; unshimmed it bundled a second copy and `TabSwitchContext.Provider` was undefined in the preview. Fix: `.design-sync/context-modules.ts` exports it, and `"TabbedPage/tab-switch"` is in `storyImports.shim` in config.json, so the story and the bundle share one context. Needs the dist build below to reach dist.
- [GENERAL] **dist is built by hand: `package-build.mjs` does not run `buildCmd`.** A stale dist ships silently (this is how TabSwitchContext was missing after the first rebuild). Before every `package-build.mjs` run, from /app: `export PATH=$PWD/node_modules/.bin:$PATH; (vite build --config .design-sync/vite.config.ts && tsc -p .design-sync/tsconfig.dts.json && cp .design-sync/dist-package.json dist/package.json) > .reports/design-sync-dist.log 2>&1; echo dist $?` (needs exit 0; `vite` is not on PATH without the export). Then `grep -c <new export> dist/index.mjs` for anything added to `context-modules.ts`. Then the build: `node .ds-sync/package-build.mjs --config .design-sync/config.json --node-modules node_modules --entry dist/index.mjs --out ./ds-bundle > .reports/design-sync-build.log 2>&1`. A stray esbuild goroutine dump at the end of that log is from an earlier killed run and is harmless when "wrote ./ds-bundle" printed; use `grep -a` on it.

## Wave 2-3 findings (folded from lane learnings)

- [GENERAL] **Frame size (MB.273).** The preview page pads the body 24px, outside the story frame's own 3rem gutter, and Storybook captures the bare `#storybook-root`. So every preview was 48px narrower than Storybook's, which wrapped columns and folded SectionNav into More, and any story taller than the 700px default capture was cut. Fix in three parts. (1) `.design-sync/context-modules.ts` adds `ds-solo` to `<html>` on a `?story=` page, which is what compare captures; a card's own page keeps its padding. (2) `.design-sync/preview-host.scss` cancels the padding there with `margin: -24px` on `.ds-single`, only when the page loads one of these preview scripts: AdminNav, CompendiumList, ContextRow, CovenCards, EntryMarks, IngredientEntry, ProviderMark, PublicFrame, SectionNav, ThemeToggle, Welcome. A rule on every `.ds-single` would move every other component's capture. A component added to the list must be checked with a scoped compare. (3) `viewport` overrides in `config.json` so tall stories are captured whole: CompendiumList 900x713, EntryMarks 900x955, ContextRow 900x1015, IngredientEntry 900x2000. A viewport applies to both sides, so it can never widen the frame; only the CSS does that. The SCSS is compiled into `dist`, so after editing it re-run the `vite build` step of the dist build before `package-build.mjs`; `package-build.mjs` alone reuses the old CSS.
- [GENERAL] Viewport is read from the first line of the card html (`viewport="WxH"`), written only by `package-build.mjs`. A config viewport change gives `CONFIG_STALE` in `preview-rebuild.mjs` and needs a full rebuild; `compare.mjs --force` then recaptures. A duplicate key in `overrides` replaces the earlier one: merge into the existing entry.
- [GENERAL] Whole-form/page stories taller than the capture (default 900x700, cap 2000x2000) grade close: IngredientForm (2581, 3560, 2674 tall; candidate 900x2000, Copy Skipped needs 900x900), ChipColorField, IngredientCard.
- [GENERAL] Stories that open state with a timer or a press on mount (FacetPanel 500ms click) need `overrides.<Name>.settleMs`; networkidle fires first.
- [GENERAL] Preview fake fetch leaves some GraphQL operations unanswered (IngredientForm: Categories select, Name, Variants spinners; Edit Source "Loading the source"; delete dialog "Used by 3 covens."; Substitute Summary hover card; Variant Added list). Compare which operations the stories' `answerQuery`/`useMockHandlers` cover against what the fake fetch matches. A story's `play` function is not run.
- [GENERAL] Compare captures at most 6 stories per component (STORY_CAP); IngredientForm has 19, so 13 are ungraded unless `--max-stories 19`.
- [GENERAL] SectionNav Phone/Tablet stories: neither side applies the story's phone/tablet viewport (both 900 wide). Not a preview defect.

## MB.123 re-sync (2026-10-30)

- [GENERAL] **Fragment shim.** The fork `.design-sync/overrides/source-storybook.mjs` builds the React shim as a Proxy over `window.React` with an extra object; the upstream `lib/source-storybook.mjs` pins `Fragment: undefined` in that object, and the Proxy's `in` check then answers `undefined` for `Fragment` instead of the page's. Every card failed with "Element type is invalid … got: undefined" once `.storybook/preview.tsx` rendered a `<Fragment key>`.
