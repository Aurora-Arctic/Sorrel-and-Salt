# create-feature-task

Turn a feature idea into a tracked `M<wave>.<n>` task: an issue in a wave milestone and its entry in `claude-docs/tasks/`. Nothing is written until the user approves both the draft and the milestone.

Shared mechanics (drafting rules, the approval gate, minting, the doc edits) are in [`../create-bug-task/reference-mint.md`](../create-bug-task/reference-mint.md); this file holds only what is specific to features.

## Steps

1. **Get the feature in the user's own words first.** If they passed text with the command, use it. Otherwise send a `PushNotification` (status `proactive`) saying input is needed, then ask in plain chat, in one line and nothing else: "What is the feature? Describe it in your own words, as much as you like." This is the one question that is not an AskUserQuestion, because a dialog cannot take a paragraph. Wait for the reply. Never take it from the IDE selection, an open file such as `claude-docs/backlog.md`, or earlier conversation: those are not the request, so ask even when something looks like a match. Do not add options, examples or follow-up questions to it. Whatever the reply already says (who it is for, the area, the size) is settled: never ask it again.
2. **Ask only for what the description left out, with AskUserQuestion**, never as a block of questions in chat. One call of up to four short questions, each with 2–4 options (the automatic "Other" takes free text), skipping any the description answered; if it answered all of them, skip the call. The questions, in this order: who it is for (site admin, coven owner, member, viewer); which area it touches, always with exactly these four options and never reworded or swapped: "Sign-in & Account", "Coven & Grimoire", "Public Facing", "Admin & Compendium"; whether it is new screens, new behaviour on an existing screen, or behind the scenes; and how big it feels (under 2h, a sitting, more).
3. **Propose what the user should be able to do** inside an AskUserQuestion, built from the description and the answers: a numbered list in the question text itself, one item per line, ending "Is this right?". Do not describe the list in a separate message or a sentence, and never leave an item blank (infer it and mark it "(assumed)"). Options: "Looks right" and "Needs changes", with corrections through "Other". Never offer an option that only tells the user to pick "Other".
4. **Check it is in scope.** Read `CLAUDE.md`'s "Out of scope for v1" and the `DESIGN.md` section the feature touches (grep the `## ` heading; never a whole doc). If it is out of scope or contradicts a rule, say so and stop for the user's call.
5. **Suggest a milestone, from the idea alone and before any draft.** List the open milestones with `gh api "repos/Aurora-Arctic/Sorrel-and-Salt/milestones?per_page=100" --jq '.[]|select(.state=="open")|"\(.title)\t\(.description|split("\n")[0])"'`, read the `claude-docs/waves/wave-<NN>.md` of the likeliest one or two, and recommend the open wave whose theme and prerequisites fit best. Give the reason in a sentence, name the runner-up, and say where in the wave's order it would sit. Ask via AskUserQuestion with the recommended wave first (labelled "(Recommended)"), the runner-up second, and "Other" for any other milestone.
6. **Draft for review, after the milestone is chosen and not before**, following `reference-mint.md` "Drafting": the user story, the acceptance criteria and a suggested name. Also propose an estimate in hours. Apply the table-then-behaviour rule: a feature needing both a `CREATE TABLE` and a service is two tasks, so propose the split. Show the whole draft (name, story, criteria, estimate, milestone) as text in this step, then go straight to the approval question: nothing is drafted or shown while the milestone is still being decided.
7. **Wait for approval with AskUserQuestion**, per `reference-mint.md` "Approval", straight after the draft is shown.
8. **Mint**, following `reference-mint.md` "Minting" with these values:

| Value     | For a feature                                                                                                                                                                                                                                                                                                                            |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Id        | The next free `M<wave>.<n>`, where `<wave>` is the approved milestone's wave number without the leading zero (Wave 9 gives `M9.<n>`, Wave 12 gives `M12.<n>`); never an `MB.` id. `<n>` continues the highest existing `M<wave>.` id anywhere in `claude-docs/tasks/`, since older tasks of that milestone number already use the series |
| Type      | `Task`                                                                                                                                                                                                                                                                                                                                   |
| Milestone | The approved wave milestone                                                                                                                                                                                                                                                                                                              |
| Labels    | `tracked`                                                                                                                                                                                                                                                                                                                                |
| Docs      | The entry in `claude-docs/tasks/m<wave>.md` (created with a `## M<wave> — <wave name>` heading, and added to `TASKS.md`'s file table, if missing), a row in `TASKS.md`'s wave table, and the id on the first line of the milestone's description                                                                                         |
| After     | `node scripts/task-board.mjs reorder` (dry run), then `--apply` once the moves look right                                                                                                                                                                                                                                                |
